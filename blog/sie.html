sie

Open-source inference server and production cluster for all the models your agent needs.

Forked from superlinked/sie

The Problem Agents that rely on multiple LLMs or specialized models typically need a separate server for each capability (embeddings, OCR, safety, etc.). Managing those servers, scaling them, and wiring a unified API adds operational overhead and latency.

What This Does SIE (Superlinked Inference Engine) provides a single self‑hosted inference service that can load > 100 models on demand and expose them through an OpenAI‑compatible API (/v1/embeddings, /v1/chat/completions, etc.). The repository ships the full production stack:

Server code – Python package sieserver (declared in the root pyproject.toml). Model catalog – static definitions under packages/sieserver/models/. Gateway & autoscaling – Helm chart in deploy/helm/sie-cluster/ with KEDA, Grafana dashboards, and Prometheus rules. Example agents – ready‑to‑run demos in examples/agent-action-monitor/, examples/contract-review-agent/, and examples/document-ocr/.

Key files: examples/agent-action-monitor/mock-prod/app.py (Flask entry point), examples/contract-review-agent/contractreviewagent/app.py (FastAPI wrapper), examples/document-ocr/web/server.ts (Node/Express UI).

How To Use It

Setup

Python 3.12 is required – the repo uses uv for reproducible installs uv python install 3.12 uv sync --frozen --all-packages # installs all workspace members

Or, for a quick container run (GPU‑enabled):

docker run --gpus all -p 8080:8080 \ -v sie-hf-cache:/app/.cache/huggingface \ ghc # image built from examples/agent-action-monitor/Dockerfile

To build the Docker image locally:

cd examples/agent-action-monitor docker build -t sie-demo -f Dockerfile .

Configuration

Environment variables are documented in .env.example files (e.g., examples/agent-action-monitor/.env.example). Model cache path can be overridden with HFHOME or by mounting a volume (/app/.cache/huggingface). Helm values (deploy/helm/sie-cluster/values.yaml and cloud‑specific overrides) control replica counts, GPU usage, and secrets such as HFTOKEN (templated in templates/hf-token-secret.yaml).

Running

Local server (Python)

pip install "sie-server[local]" # wheel published on PyPI sie-server serve # starts the inference gateway

Example agent – start the mock production API:

cd examples/agent-action-monitor/mock-prod uv run app.py # runs Flask app defined in app.py

Kubernetes – deploy the full stack:

helm upgrade --install sie-cluster deploy/helm/sie-cluster/ \ -f deploy/helm/sie-cluster/values.yaml

Real‑World Use A corporate knowledge‑assistant can run a single SIE cluster behind its chat UI. The UI calls /v1/chat/completions for planning, /v1/embeddings for retrieval, and /v1/responses for content safety, all routed through the same ingress (templates/ingress.yaml). The cluster auto‑scales via KEDA based on queue length, keeping cost proportional to traffic.

example client request (Python) import openai client = openai.OpenAI(baseurl="https://sie.mycompany.com/v1") resp = client.chat.completions.create( model="qwen3.6-27b", messages=[{"role": "user", "content": "Summarize the latest earnings report"}], ) print(resp.choices[0].message.content)

Code Health & Issues Medium – No CI/CD – No .github/workflows or other pipeline files; automated testing is not gated. Low – Missing license header in source files – Root LICENSE is Apache 2.0, but individual files lack explicit header comments. Low – Secret placeholders – .env.example contains keys but no enforcement; developers must ensure real secrets are injected securely. Low – Mixed language stack – Python server, TypeScript UI, and Rust Cargo.toml (unused) increase maintenance surface. Low – Limited test coverage for Helm charts – Tests exist for Python components (25 test files) but no validation of Kubernetes manifests. Low – Documentation gaps – README gives quick‑start commands, but detailed model‑catalog docs are under packages/sieserver/models/ without generated API reference.

Overall the codebase compiles and runs locally; unit tests exercise most Python paths, and Dockerfiles are functional.

The Bottom Line SIE delivers a coherent, production‑ready inference layer that consolidates many model‑serving patterns into a single API and includes a ready‑made Kubernetes deployment. It is well‑structured for teams comfortable with Python, Docker, and Helm, but the lack of CI automation and mixed‑language overhead mean additional effort is needed to harden the pipeline for enterprise use. Consider adopting it if you need a unified inference backend and are prepared to add CI/CD and security hardening.
