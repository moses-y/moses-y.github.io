LibreTranslate

Free and Open Source Machine Translation API. Self-hosted, offline capable and easy to setup.

Forked from LibreTranslate/LibreTranslate

The Problem

Organizations needing machine translation often face a choice between proprietary cloud APIs (Google, Azure, DeepL) that require sending data to third parties, or building custom translation infrastructure from scratch. The former creates data privacy risks and recurring per-character costs; the latter is impractical for most teams.

What This Does

LibreTranslate provides a self-hosted REST API and web UI for machine translation, powered entirely by the open-source Argos Translate library. The core application lives in libretranslate/app.py (Flask routes) and libretranslate/main.py (CLI entry point). It exposes endpoints for translation, language detection, and language listing, all defined in libretranslate/tests/testapi/.

The project ships with Docker support (docker-compose.yml, docker/Dockerfile) and a Kubernetes manifest (k8s.yaml). It includes rate limiting (libretranslate/flood.py), API key management (libretranslate/apikeys.py), and a suggestion system (libretranslate/suggestions.py). The web frontend is a Vue 2 single-page app served from libretranslate/templates/index.html.

Real-World Use

A company with sensitive documents deploys LibreTranslate behind an internal load balancer using the provided docker-compose.yml. They restrict access via --api-keys and point their internal tools at http://translate.internal:5000/translate with a simple POST:

No data leaves their network, and there are no per-character costs.

Code Health & Issues

The codebase is structurally sound with CI (run-tests.yml, publish-docker.yml), 11 test files, a license, and a lockfile. However, several concerns are visible: Medium - No input sanitization visible in libretranslate/app.py route handlers beyond basic type checking. The API accepts arbitrary strings; injection via malformed payloads is possible if the app is exposed publicly. Low - libretranslate/secret.py generates a fallback secret from hashlib.md5(uuid.getnode()) if no --api-keys file is provided. uuid.getnode() returns the MAC address, which is trivial to guess in many environments. Low - The test suite (testapi/testapi_translate.py etc.) only covers happy-path API calls. No tests for rate limiting, suggestion submission, or error states like unsupported language pairs. Low - The locales/ directory contains 70+ translation files (.po) but no corresponding test verifying that all UI strings render correctly. Missing translations will silently fall back to the .pot template.

The Bottom Line

LibreTranslate is a pragmatic, well-structured self-hosted translation solution that solves a real privacy and cost problem. It's production-ready for internal use behind a firewall, but the lack of input validation and weak secret generation make public internet deployment risky without a reverse proxy. Best suited for teams that need offline-capable translation and can accept the translation quality ceiling of Argos Translate (which lags behind cloud providers for many language pairs).
