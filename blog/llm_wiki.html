llm wiki

Abstract

LLM Wiki is a cross-platform desktop application that turns your documents into an organized, interlinked knowledge base — automatically. Instead of traditional RAG (retrieve-and-answer from scratch every time), the LLM incrementally builds and maintains a persistent wiki from your sources。

The Problem

Most document-based AI tools use RAG: retrieve relevant chunks, then answer from scratch on every query. That approach re-derives knowledge repeatedly, wastes tokens, and produces inconsistent answers. LLM Wiki instead compiles documents into a persistent, interlinked wiki once, then keeps it current incrementally—so queries run against a maintained knowledge base rather than raw source material.

What This Does

LLM Wiki is a cross-platform desktop app (Tauri + React) that ingests documents, uses an LLM to generate structured wiki pages with [[wikilink]] cross-references, and maintains that wiki over time. Key features include a two-step chain-of-thought ingest pipeline with caching, a knowledge graph with community detection, vector search via LanceDB, and a Chrome web clipper.

The architecture follows Karpathy's LLM Wiki pattern: raw sources (immutable) → wiki (LLM-generated) → schema (rules/config). The wiki directory is Obsidian-compatible. The frontend lives in src/ (React/TypeScript), the backend in src-tauri/ (Rust commands), and the browser extension in extension/.

How To Use It

Setup:

git clone https://github.com/moses-y/llm_wiki
cd llm_wiki
npm install
npm run tauri dev

Configuration: LLM provider settings live in src/components/settings/sections/llm-provider-section.tsx and src/lib/llm-providers.ts. The app supports OpenAI-compatible endpoints and Claude Code CLI. Embedding configuration is in src/lib/embedding.ts. No environment variables are required; settings are stored per-project.

Running: The Tauri app builds from src-tauri/. The Chrome extension in extension/ loads unpacked from extension/manifest.json.

Real-World Use

A researcher imports a folder of PDFs and markdown notes. The ingest pipeline (src/lib/ingest.ts) reads each file, the LLM generates wiki pages with source traceability, and src/lib/enrich-wikilinks.ts adds cross-references. The knowledge graph (src/components/graph/graph-view.tsx) reveals clusters via Louvain detection. When the researcher adds new documents, the incremental cache in src/lib/ingest-cache.ts ensures only changed content is re-processed.

Code Health & Issues

Static analysis found 33 findings (5 high, 27 medium, 1 low). Key issues:

  • High - Oversized files - src/lib/ingest.ts (769 lines), extension/Readability.js, src/components/chat/chat-message.tsx. Split by responsibility.
  • High - Deep nesting - src-tauri/src/clip_server.rs, src-tauri/src/commands/fs.rs, src/components/graph/graph-view.tsx (max depth 10). Use early returns.
  • High - Duplicated code - 90 repeated 6-line blocks across 33 files, including chat-message.tsx and file-preview.tsx. Extract shared helpers.
  • Medium - Empty catch blocks - extension/Turndown.js silently discards errors.
  • Medium - High branching - src/lib/sweep-reviews.ts (125 branches over 321 lines). Consider strategy dispatch.

SDLC observations: CI uses unpinned GitHub Actions (dtolnay/rust-toolchain@stable, tauri-apps/tauri-action@v0)—pin to commit SHAs. Tokio and zip have published advisories; upgrade. No Dependabot configured. Three PDFium binaries (6.7–7.2MB each) bloat the repo; use LFS. CI runs npm install instead of npm ci.

The Bottom Line

LLM Wiki is a well-architected implementation of a genuinely different approach to knowledge management—compiling rather than retrieving. The test suite (64 files) and clean module graph suggest disciplined development. The main risks are maintainability (oversized files, duplication) and supply-chain hygiene (unpinned actions, outdated dependencies). Worth using if you want a self-hosted, Obsidian-compatible alternative to RAG-based tools.

Pin third-party GitHub Actions to a commit SHAhigh3 occurrences
.github/workflows
dtolnay/rust-toolchain@stable, tauri-apps/tauri-action@v0, Swatinem/rust-cache@v2
A tag can be moved, so the action running with your token and secrets is whatever its owner last pushed; this is how tj-actions/changed-files leaked secrets from thousands of repos.
Fix: Replace each @vN with the 40-character commit SHA, keep # vN as a comment, and let Dependabot bump the SHAs.
Upgrade the pinned dependency carrying a published advisoryhigh11 occurrences
tokio@1 CVE-2021-45710 (high) +7 more; zip@2 CVE-2025-29787 (high) +1 more; tauri@2 CVE-2026-42184 (medium)
The pinned version is the one that installs, so a published advisory against it describes this deployment rather than a hypothetical one, and the advisory is also a public description of how to exploit it.
Fix: Upgrade to the fixed version named in the advisory, then commit the lockfile.
Declare least-privilege permissions for GITHUB_TOKENmedium
.github/workflows/ci.yml
1 workflow(s) declare no permissions
With no declaration the token inherits the repository default, so any injected step can push commits or mint releases from inside your own CI.
Fix: Add permissions: contents: read at the top of the workflow and widen per job only where needed.
Enable Dependabot or Renovatemedium
2 manifest(s), no update bot configured
Without a bot a published advisory sits unpatched until someone audits by hand, which across 1,322 repositories means never.
Fix: Commit .github/dependabot.yml covering the repo ecosystems plus github-actions.

.github/workflows

A fresh resolution in CI means the tested dependency set is not the locked one, so the failure only appears after merge.
Fix: Use npm ci, yarn install --immutable, or pnpm install --frozen-lockfile.

This is the one gate that would catch a known-vulnerable package before it reaches a build, and no repository in the sample had it.
Fix: Add dependency-review-action on pull_request, or osv-scanner on push and a schedule.

The token stays in .git/config for every later step, so a malicious postinstall script reads a pushable credential without one ever being passed to it.
