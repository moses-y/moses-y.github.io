OpenCat Quadruped Robot

An open source quadruped robot pet framework for developing Boston Dynamics-style four-legged robots that are perfect for STEM, coding & robotics education, IoT robotics applications, AI-enhanced robotics application services, research, and DIY robotics kit development.

Forked from PetoiCamp/OpenCat-Quadruped-Robot

The Problem

Building a quadruped robot from scratch requires solving complex gait kinematics, real-time servo control, and sensor fusion — work that takes months even for experienced robotics engineers. Most hobbyists and researchers end up reinventing the same low-level motor coordination instead of focusing on their actual application.

What This Does

OpenCat provides a production-tested Arduino/ESP32 firmware layer (OpenCat.ino) that handles walking gaits, balance, and servo PWM generation out of the box. The pyUI/ directory gives you a Python desktop application for calibrating servos (Calibrator.py), composing movement sequences (SkillComposer.py), and uploading firmware (FirmwareUploader.py). The OpenCatPythonAPI/ directory exposes a serial command API (petoiRobotExample.py, allSkills.py) for controlling the robot from Python — useful for integrating with computer vision pipelines or ROS nodes.

The SkillLibrary/ contains pre-written movement sequences (e.g., BittleMoonWalk.md, BittleHighbar.md) that define joint angle trajectories. These are plain-text skill files you can edit or create without recompiling firmware. The ModuleTests/ directory (78 files) covers individual sensor and actuator tests — ultrasonic, IR, IMU, buzzer — so you can validate hardware before integrating it into a full robot behavior.

Real-World Use

The Bottom Line

OpenCat is a mature, well-structured framework for quadruped robots, backed by years of real-world deployment on Petoi hardware. The codebase is practical — it prioritizes working hardware over software purity. It's best suited for educators, researchers, and makers who want a proven motion stack and are comfortable with Arduino toolchains. Teams needing automated testing or CI should add that themselves.
