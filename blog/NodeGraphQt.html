NodeGraphQt

A node graph UI framework written in python using Qt.

Forked from jchanvfx/NodeGraphQt

The Problem Building interactive node‑based editors (e.g., compositing, shader graphs) from scratch requires handling Qt graphics items, port connections, layout, and custom property widgets. Maintaining consistency across host applications (Nuke, Silhouette, etc.) is time‑consuming and error‑prone.

What This Does NodeGraphQt supplies a ready‑made Qt widget hierarchy that implements a fully functional node graph. Core logic lives in NodeGraphQt/base/ (graph.py, node.py, port.py) and the Qt rendering classes in NodeGraphQt/qgraphics/ (nodebase.py, pipe.py, port.py). High‑level UI components such as the node palette, property bin, and search dialog are under NodeGraphQt/customwidgets/ and NodeGraphQt/widgets/. Example scripts in examples/ (e.g., basicexample.py) demonstrate typical usage patterns.

How To Use It

Setup Install the published package (recommended) pip install NodeGraphQt

Or install directly from source pip install -e .

The setup.py and setup.cfg define the package metadata; requirements.txt lists runtime dependencies (Qt.py, Qt.pyqt5, etc.).

Configuration No runtime configuration files are required for the core library. Host‑specific adapters (e.g., docs/hostapps/exappnuke.rst) illustrate how to embed the widget in an external Qt application; those adapters are documentation only.

Running The simplest entry point is the example script:

python examples/basicexample.py

basicexample.py imports NodeGraphQt.widgets.nodegraph.NodeGraph and constructs a graph with a few sample nodes. For custom node definitions, see examples/nodes/basicnodes.py and the base classes in NodeGraphQt/nodes/ (basenode.py, groupnode.py).

Real‑World Use A VFX pipeline can embed the graph as a Qt widget inside a larger tool (e.g., Nuke). A minimal integration might look like:

from NodeGraphQt import NodeGraph from NodeGraphQt.widgets import NodeGraphWidget

graph = NodeGraph() viewer = NodeGraphWidget(graph) add custom nodes here viewer.show()

The graph can be saved/loaded via graph.savetofile(path) and graph.loadfromfile(path), enabling persistence of user‑built node networks.

Code Health & Issues Low – No test suite – No tests/ directory; CI runs only documentation builds (.github/workflows/sphinxdocbuild.yml). Untested code paths increase regression risk. Low – Unpinned dependencies – requirements.txt lists version‑agnostic packages; without a lockfile (requirements.lock or poetry.lock) builds are not reproducible across environments. Medium – Limited type hints – Core modules (base/graph.py, qgraphics/node_base.py) lack static typing, reducing IDE assistance and static analysis reliability. Low – Potential Qt version mismatch – The project depends on Qt.py, which abstracts over PyQt5/PySide2; mismatched runtime bindings can cause subtle UI bugs. Low – Documentation‑only CI – CI workflows publish docs and PyPI but do not run linting or security scans (e.g., bandit). Low – No explicit license file – The repository includes LICENSE.md, but the file content is not shown; ensure it matches the intended open‑source license.

Overall the codebase is well‑organized, with clear separation between model (base/) and view (qgraphics/, widgets/). Inline documentation in docstrings and the extensive Sphinx docs (docs/) aid discoverability.

The Bottom Line NodeGraphQt provides a mature, feature‑complete Qt node‑graph framework that can be dropped into Python‑based VFX tools with minimal boilerplate. Its strengths are the extensive UI components and thorough documentation; shortcomings are the lack of automated tests and unpinned dependencies, which may affect long‑term maintenance. Suitable for teams that need a ready UI foundation and can allocate effort to add test coverage.
