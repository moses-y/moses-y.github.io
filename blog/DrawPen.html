The Problem

Users need a lightweight, cross‑platform way to draw annotations on‑screen (pen, highlighter, laser, pointer) without installing heavyweight graphics software. Existing tools are either paid, platform‑locked, or lack the quick‑toggle global shortcuts that power‑users expect.

What This Does

DrawPen is an Electron‑based desktop app that runs on macOS, Windows and Linux. The UI lives under src/renderer/ and is built with React components such as src/renderer/apppage/components/components/Whiteboard.js and ToolBar.js. The main process (src/main/index.js) creates the native window, registers global shortcuts, and loads the renderer entry point src/renderer/apppage/index.html. Asset bundles (icons, fonts, gifs) are stored in src/assets/ and assets/static/. Build configuration is in tools/forge/forge.config.js (Electron‑Forge) and the Webpack pipelines (tools/webpack/main.js, renderer.js). Release pipelines are defined in .github/workflows/.

How To Use It

Setup

Clone the repo git clone https://github.com/DmytroVasin/DrawPen.git cd DrawPen

Install exact Node version (nvmrc) and dependencies

nvm use # respects .nvmrc npm ci # uses package-lock.json

Build / Package

The project uses Electron‑Forge. The standard make target is defined in package.json scripts and exercised by the CI workflow (make.yml). Run:

npm run make # produces installers for the host OS

Run from source (useful for development)

npm start # launches the Electron app using src/main/index.js

Configuration

No external config files are required. Global shortcuts are hard‑coded in src/main/index.js (e.g., CMD/CTRL+SHIFT+A toggles draw/pointer mode). UI‑level settings (color, thickness, toolbar position) are persisted by the app itself; the source does not expose a JSON/YAML config to edit.

Running the binary

Pre‑built installers are available from the README badges. For Linux on Wayland, the README advises the runtime flag --ozone-platform=x11; this flag is passed directly to the Electron binary (drawpen --ozone-platform=x11).

Real‑World Use

A support engineer can start the app, press Ctrl‑Shift‑A to enable annotation, and use P, T, H, etc., to switch tools while presenting a remote demo. The toolbar can be hidden (Ctrl‑T) to keep the screen clean, and the whiteboard can be toggled (Ctrl‑E) for quick sketching. Because the app is a single native binary, it integrates easily into automated provisioning scripts (curl -L …/DrawPen.Setup.exe -o DrawPen.exe && ./DrawPen.exe).

Code Health & Issues

Med – No test suite – No files under tests or test/; CI only runs make (see .github/workflows/make.yml). Untested code paths increase regression risk. Low – Limited type safety – Pure JavaScript throughout (src/*/.js). Absence of TypeScript or Flow means no compile‑time checking for API contracts. Med – Global shortcut handling – Shortcut registration lives in src/main/index.js without defensive checks for duplicate bindings; could cause conflicts on systems with existing hotkeys. Low – Asset duplication – Icons are stored both in assets/static/ and src/assets/; could lead to version drift. Low – Linting/formatting – No visible ESLint or Prettier config; style inconsistencies may arise. Low – Dependency hygiene – package-lock.json is present, but no automated dependency audit step in CI; security updates rely on manual maintenance. Low – Documentation gaps – README covers installation and shortcuts but lacks contribution guidelines for extending components; CONTRIBUTING.md exists but is not linked from the UI code.

Overall the repo compiles and packages cleanly; the Electron‑Forge setup and Webpack configs are complete and functional.

The Bottom Line

DrawPen delivers a functional, cross‑platform screen annotation tool with a minimal footprint and straightforward install options. The codebase is serviceable for small teams or personal use, but the lack of automated tests and limited type safety mean it is not ready for high‑risk or large‑scale deployments without additional quality‑gate work. Adding a test suite and basic linting would substantially improve maintainability.
