TTS Audio Suite

A ComfyUI custom node integration for local multi-engine multi-language Text-to-Speech and Voice Conversion. Supports: RVC, Echo-TTS, Qwen3-TTS, Cozy Voice 3, Step Audio EditX, IndexTTS-2, Chatterbox (classic and multilingual), F5-TTS, Higgs Audio 2 and VibeVoice with unlimited text length, SRT timing, Character support, and many audio tools

Forked from diodiogod/TTS-Audio-Suite

The Problem

Running serious TTS work in ComfyUI usually means juggling several one-off custom nodes, each with its own model download locations, prompt syntax, and failure modes. Subtitle workflows make it worse: aligning generated audio to an SRT file, preserving character voices, and editing specific words after generation typically requires manual stitching across incompatible tools.

What This Does

TTS-Audio-Suite is a ComfyUI extension that consolidates twelve TTS/VC engines behind a unified node interface. The engines/adapters/ folder holds one adapter per engine (f5ttsadapter.py, qwen3ttsadapter.py, rvcadapter.py, etc.), so the rest of the suite talks to a consistent API regardless of the underlying model. The engines/chatterbox/ and engines/chatterboxofficial23lang/ directories contain full vendored model implementations, which explains the 116-file engine footprint.

Beyond generation, the suite handles the audio-production pipeline: SRT transcription and timing (docs/SRTIMPLEMENTATION.md), character grouping (engines/chatterbox/charactergrouper.py), streaming inference (engines/chatterbox/streamingmodelmanager.py), and voice conversion. It also supports inline edit tags for post-hoc speech editing and an integrated RVC training workflow.

How To Use It

Setup: Install as a standard ComfyUI custom node by cloning into ComfyUI/customnodes/. Dependencies are managed per-engine; the suite does not ship a single requirements.txt, so expect to install engine-specific packages manually. Model files must be downloaded separately — docs/MODELDOWNLOADSOURCES.md lists sources and docs/MODELLAYOUTS.md specifies the expected folder structure.

Configuration: No central config file. Model paths are configured through node parameters in the ComfyUI graph. The engine metadata lives in docs/Dev reports/ttsaudiosuiteengines.yaml, which also generates the comparison tables in the README.

Running it: Launch ComfyUI normally. The suite registers its nodes (TTS, VC, SRT tools) into the node palette. Workflows are built visually; there is no CLI entry point.

Real-World Use

A typical workflow: feed a script into the ChatterBox TTS node with a character list, generate per-character audio, run the SRT timing node to produce subtitles, then pass the result through Step Audio EditX to fix a mispronounced word in the middle of a long take. The charactergrouper.py module keeps voices consistent across segments, and the SRT node preserves control tags for downstream editing.

Code Health & Issues Med – Vendored model code is a maintenance burden. engines/chatterbox/ and engines/chatterboxofficial23lang/ duplicate hundreds of model files. Upstream fixes require manual sync, tracked in docs/UpstreamEngineTracking/. Med – Six test files for 118 Python files. docs/Dev reports/pytestimplementationreport.md documents test coverage, but the ratio is thin for a project with this much engine-specific logic. Low – Documentation is extensive but sprawling. 72 markdown files include dev reports, refactoring summaries, and integration plans. Useful, but hard to navigate for a new user. Low – No lockfile. Dependency versions are unpinned, which risks breakage when engines update their model APIs.

The Bottom Line

This is a serious, actively-maintained TTS toolkit with real depth: twelve engines, SRT workflows, voice conversion, and editing tools all under one ComfyUI roof. The vendored model code and thin test coverage are real costs, but for anyone doing production audio work in ComfyUI, the breadth and integration quality outweigh those concerns.
