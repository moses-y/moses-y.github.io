The Problem

Diagnosing slow HTTP requests is usually guesswork. Standard tools like curl report total time but hide where the time goes—DNS resolution, TCP connect, TLS handshake, server processing, or body transfer. Teams debugging latency regressions or tuning performance baselines need phase-level visibility without building custom instrumentation.

What This Does

httptap is a Python CLI that breaks an HTTP request into five phases—DNS, connect, TLS, wait, and transfer—and renders them as a waterfall timeline, compact summary, or metrics-only output. Core logic lives in httptap/analyzer.py (phase decomposition), httptap/implementations/ (per-phase timing via dns.py, tls.py, timing.py), and httptap/render.py (the Rich-powered display). The CLI entry point is httptap/cli.py, with formatting and export handled by httptap/formatters.py and httptap/exporter.py.

Output modes include a full waterfall table, a compact one-line summary, and a metrics-only format for scripting. JSON export is supported for regression analysis. An SLO threshold checker (httptap/slo.py) flags requests that exceed defined latency budgets, and exit codes reflect pass/fail state for CI integration.

How To Use It

Setup: Install via pip install httptap or uv tool install httptap. The repo uses uv as its build tool (uv.lock present) and pyproject.toml for packaging. A Dockerfile exists for containerized use. Homebrew installation is also documented.

Configuration: No required environment variables. SLO thresholds are passed as CLI flags, not read from a config file. The httptap/slo.py module defines the threshold-checking logic.

Running it: httptap https://example.com httptap https://example.com --format compact httptap https://example.com --format metrics httptap https://example.com --json > output.json httptap https://example.com --slo-dns 100ms --slo-tls 500ms

Real-World Use

A backend team debugging a slow API endpoint runs httptap https://api.internal/v1/orders --format waterfall and sees DNS at 5ms, connect at 20ms, TLS at 15ms, but wait at 850ms. That isolates the problem to server-side processing, not network infrastructure. The same team pipes --format metrics into a CI job that fails if the wait phase exceeds 1s, catching regressions before deployment.

Code Health & Issues

Med – No lockfile for dependencies (pyproject.toml only). Non-reproducible builds across environments. uv.lock exists, which mitigates this if the team standardizes on uv. Low – 102 files but only 21 test files. Coverage is configured (codecov.yml) and CI runs tests, but the test-to-source ratio is thin for a tool with this many modules. Low – The repo carries heavy governance overhead (CODEOWNERS, GOVERNANCE.md, SECURITY.md, assurance-case.md) for a 0-star fork. Some of this is inherited from the upstream project and may be boilerplate. Positive – CI is well-configured: GitHub Actions workflows for CI, CodeQL, CodSpeed, dependency updates, pre-commit, and release. OpenSSF Scorecard and Best Practices badges indicate security hygiene was taken seriously.

The Bottom Line

httptap is a focused, well-engineered tool for phase-level HTTP latency analysis. It solves a real debugging problem cleanly and supports scripting and CI integration. The heavy governance and docs suggest a mature upstream project, but the missing lockfile and thin test coverage are minor concerns. Teams doing regular HTTP performance work will find it immediately useful.
