SAM Sovereign Agent Mesh

Forked from google/sam

The Problem Deploying a trustworthy, self‑healing network for autonomous AI agents is difficult. Operators need a way to bootstrap peer‑to‑peer connectivity, enforce strong identity and policy checks, and expose a uniform tool‑invocation surface without hand‑crafting Kubernetes objects or custom TLS plumbing.

What This Does sam implements a Sovereign Agent Mesh that provides zero‑configuration discovery and zero‑trust communication for lightweight sam-node processes. The control‑plane server (cmd/sam-control-plane/main.go) stores node identities, authorisation policies, and routes MCP (Mesh Control Protocol) requests. cmd/sam-router/main.go runs libp2p bootstrap and relay services that forward traffic between nodes. cmd/sam-node/main.go launches a local side‑car that registers with the control plane, establishes encrypted libp2p links, and exposes an HTTP‑compatible MCP endpoint for agents.

All components are written in Go (96 files) and orchestrated with Helm charts under charts/sam-mesh/ and Dockerfiles (Dockerfile.sam‑node, Dockerfile.sam‑router, etc.). The repository also ships example MCP services (e.g., development/examples/calc-mcp/) that demonstrate how an agent can call a remote tool through the mesh.

How To Use It

Setup – Build the binaries or containers. The repo supplies a Makefile and Dockerfiles, so either of the following works:

Build Go binaries locally make build # targets compile cmd/ into ./bin/ or build Docker images docker build -f Dockerfile.sam-control-plane -t sam-control-plane . docker build -f Dockerfile.sam-router -t sam-router . docker build -f Dockerfile.sam-node -t sam-node .

Configuration – Minimal config is required. The control plane reads internal/controlplane/config.go which defaults to development/kind/mesh-config.yaml. For a quick local deployment, run the Kind script:

cd development/kind ./run.sh # creates a Kind cluster, applies the mesh manifests

If you prefer a non‑Kubernetes run, start each component with its default flags:

./bin/sam-control-plane & ./bin/sam-router & ./bin/sam-node -config development/kind/sam-node-config.yaml

Running – The mesh becomes reachable at the node’s MCP address (default http://127.0.0.1:8080/mcp). An agent can invoke a tool with a simple HTTP POST; the example calc-mcp service shows the request shape in development/examples/calc-mcp/calcserver.py.

curl -X POST http://127.0.0.1:8080/mcp \ -d '{"tool":"calc/add","args":{"a":2,"b":3}}'

Real‑World Use A SaaS platform that runs many LLM‑based workers can spin up a sam-node per worker. Each node registers with a shared sam-control-plane, receives a signed biscuit token (internal/identity/biscuit.go), and discovers peers automatically. When a user request requires a specialized tool (e.g., code review), the platform routes the call through the mesh to the appropriate node, leveraging the built‑in rate‑limiter (internal/node/ratelimiter.go) and policy checks.

client := http.NewRequest("POST", "http://localhost:8080/mcp", payload) resp, := http.DefaultClient.Do(client) // resp contains tool output from the selected peer node

Code Health & Issues High – Secrets in repo – charts/sam-mesh/templates/secrets.yaml contains placeholder values that could be replaced with real credentials; committing real secrets would be a security risk. Medium – Limited test coverage for CLI flags – cmd/ binaries have no dedicated unit tests; most tests focus on internal packages (internal/node/). CI runs go test ./... but flag parsing bugs could slip through. Medium – Platform‑specific code paths – Files like cmd/sam-node/daemonizeunix.go and daemonize_windows.go are conditionally compiled; no cross‑OS CI matrix is evident, so Windows behaviour is unverified. Low – Documentation gaps – README provides a high‑level overview but lacks explicit command‑line flag documentation; users must read source (internal//config.go) to discover required env vars. Low – Helm chart defaults expose plain text secrets – The secrets.yaml template renders values directly into Kubernetes secrets without encryption; Helm users must supply a secure secret management process.

Overall the repo includes a full CI pipeline (.github/workflows/.yaml), static analysis (.golangci.yml), and a vulnerability scan (govulncheck.yml). Tests (44 files) exercise core mesh logic, and the code follows Go module best practices (go.mod, go.sum).

The Bottom Line sam delivers a functional, Go‑native mesh for AI agents with strong identity guarantees and ready‑made Docker/Helm deployment options. It is most suitable for teams comfortable with Go and Kubernetes who need a self‑service, zero‑trust communication layer. Before production use, audit the Helm secrets, add Windows CI, and expand CLI test coverage.
