docext

An on-premises, OCR-free unstructured data extraction, markdown conversion and benchmarking toolkit. (https://idp-leaderboard.org/)

Forked from NanoNets/docext

The Problem Enterprises that need to process invoices, passports, or any unstructured document often rely on OCR pipelines that are noisy, require cloud APIs, and add latency. Maintaining a self‑hosted, OCR‑free extraction stack that also benchmarks model performance is a non‑trivial integration effort.

What This Does docext provides three on‑premise capabilities:

PDF/Image → Markdown – core conversion lives in docext/core/pdf2md/pdf2md.py and is exposed through the Flask service in docext/app/app.py. Structured extraction – the extraction logic is in docext/core/extract.py and uses vision‑language models via docext/core/vllm.py. Benchmark suite – the benchmark driver docext/benchmark/benchmark.py orchestrates dataset loaders (docext/benchmark/vlmdatasets/.py) and metric calculators (docext/benchmark/metrics/.py).

Configuration for benchmark runs is stored in configs/benchmark.yaml. The package is installable with setup.py and ships a requirements.txt that pins the runtime libraries.

How It Is Wired The entry point for the web service is docext/app/app.py. When the module is executed, it parses CLI arguments from docext/app/args.py, instantiates a Flask app, and registers routes that call:

docext/app/pdf2md.py → docext/core/pdf2md/pdf2md.py → docext/core/vllm.py for model inference. docext/app/utils.py for auxiliary file handling.

The benchmark driver (docext/benchmark/benchmark.py) imports the hub module docext/benchmark/vlmdatasets/ds.py. This module has the highest incoming import count (16) and therefore represents the widest blast radius: changes to dataset loading affect most benchmark tasks. The benchmark also imports docext/benchmark/tasks.py (which in turn pulls eight metric modules). No circular imports were detected.

How To Use It

Clone the repo git clone https://github.com/moses-y/docext.git cd docext

Build the container (Dockerfile uses vllm/vllm-openai:v0.8.2) docker build -t docext:latest .

Run the service docker run -p 5000:5000 docext:latest python -m docext.app.app --host 0.0.0.0 --port 5000

Optional local install*

python -m pip install -r requirements.txt python -m pip install -e . python -m docext.app.app --host 127.0.0.1 --port 5000

The benchmark can be invoked directly:

python -m docext.benchmark.benchmark --config configs/benchmark.yaml

No environment variables are referenced in the source; all required settings are in configs/benchmark.yaml or passed as CLI flags.

Real‑World Use A finance department can run the Docker image behind their internal firewall, POST a PDF to http://localhost:5000/convert and receive a markdown document with embedded tables, signatures, and confidence scores. The same model can be benchmarked nightly against the docvqa and chartqa datasets to track regression.

Measured findings (static analysis) HIGH – cognitiveload – Deep nesting (up to 12 levels) in docext/benchmark/vlmdatasets/ds.py, docext/core/pdf2md/pdf2md.py, docext/benchmark/benchmark.py. MEDIUM – resourcesafety – File opened without a context manager in docext/benchmark/vlmdatasets/ds.py. MEDIUM – clarity – Hub module docext/benchmark/vlmdatasets/ds.py is imported by 16 other modules. MEDIUM – resilience – Broad except clauses in docext/benchmark/metrics/grits.py. MEDIUM – cognitiveload – Oversized file docext/benchmark/benchmark.py (635 lines).

Code‑health audit HIGH – testing – No test suite (despite two test files being present). MEDIUM – dependency updates – Dependabot/Renovate not configured. MEDIUM – container reproducibility – Docker base image vllm/vllm-openai:v0.8.2 is not pinned by digest. MEDIUM – vulnerability gating – CI workflow lacks a dependency‑vulnerability scan. LOW – workflow timeout – .github/workflows/codeql.yml does not set timeout-minutes.

Additional observations: the repository includes a license (Apache‑2.0) and a CI definition, but lacks a lockfile (e.g., requirements.txt is not version‑pinned) and the test count is ambiguous.

The Bottom Line docext delivers a self‑hosted OCR‑free extraction and benchmarking stack with clear entry points and Docker support, making it a practical foundation for on‑prem document pipelines. The codebase suffers from high cognitive load, duplicated logic, and limited automated testing, so teams should allocate effort to refactor the hub modules and introduce a reliable test suite before heavy production reliance.
