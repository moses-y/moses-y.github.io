The Problem

Power users of YouTube Music often need features the official client omits—offline caching with custom download rules, granular audio processing, and live synced lyrics across devices. Maintaining a personal build that adds these capabilities without fragmenting the user experience is non‑trivial.

What This Does

Metrolist is a full‑featured Android YouTube Music client built with Kotlin and Gradle. The core source lives in app/src/main/kotlin/com/metrolist/music/. Playback is handled by MusicService.kt and PlayerConnection.kt, while the equalizer stack lives in app/src/main/kotlin/com/metrolist/music/eq/, including BiquadFilter.kt and ParametricEQ.kt. Lyrics are sourced from a registry of providers (LyricsProviderRegistry.kt) such as YouTubeLyricsProvider.kt and LrcLibLyricsProvider.kt. Database entities—Song.kt, Playlist.kt, Album.kt, etc.—are under app/src/main/kotlin/com/metrolist/music/db/entities/, and the DAO layer is in DatabaseDao.kt. The app also ships three flavor source sets (main, foss, gms, izzy) that toggle Google‑services or Fdroid‑compatible manifests (AndroidManifest.xml under each set). CI pipelines under .github/workflows/ (build.yml, buildpr.yml, buildquick.yml, release.yml) compile and sign the APKs, but no test targets are present.

How To Use It

Setup: Open the project in Android Studio (or run ./gradlew assembleDebug from the repo root). The README does not ship build commands; the project expects the Android Gradle Plugin and a compatible JDK. Configuration: No API keys or environment variables are committed. YouTube Music login is performed inside the app; a VPN or proxy is required if YouTube Music is unavailable in your region. Running it: After building, install the debug APK on a device/emulator. The entry point is MainActivity.kt.

Real‑World Use

A developer wanting to prototype a custom music‑player UI can fork Metrolist, replace the EqualizerService.kt processor with a personal DSP pipeline, or swap the lyrics providers in LyricsProviderRegistry.kt to target a different lyric source. The modular DI graph in di/AppModule.kt makes swapping services straightforward.

Code Health & Issues

Medium – No test files detected – repository‑wide; CI runs only builds, so logic paths (e.g., database migrations, equalizer presets) are untested. Medium – Fragmented source sets – four flavor directories (main, foss, gms, izzy) increase merge surface and may hide configuration drift. Low – ProGuard rules present (app/proguard-rules.pro) and CI lint (app/lint.xml) indicate some static‑analysis hygiene, but baseline coverage is unknown. Low – No licensing or secret scanning – the repo contains a LICENSE file but no .env or key files; however, the absence of a CODEOWNERS or contribution guide may slow onboarding.

The Bottom Line

Metrolist offers a well‑structured Kotlin codebase with extensive playback, equalizer, and lyrics features, making it a solid starting point for anyone building or customizing a YouTube Music client. The main drawback is the lack of tests and sparse build documentation, so it’s best suited for developers comfortable with Android Gradle workflows rather than end‑users seeking a drop‑in replacement.
