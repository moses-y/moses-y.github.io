The Problem

Real‑estate websites often field repetitive, factual queries (e.g., “What is the deposit amount?”). Answering each manually strains support staff and leads to inconsistent information.

What This Does

The repository implements a Flask‑based chatbot that matches a user’s question to a pre‑populated Q&A set using TF‑IDF vectorisation and cosine similarity.

app.py creates the Flask app, loads the data from data/qadata.py, and exposes two routes – / (rendered by templates/index.html) and /get (JSON API called by static/js/script.js). The knowledge base lives in data/qadata.py (a list of dictionaries) and is persisted in feedbackdata.json/querylogs.json for later analysis. Front‑end assets (templates/.html, static/css/style.css, static/js/script.js, and image files) provide a responsive chat UI with suggestion buttons defined in the HTML templates.

How To Use It

Clone and enter the repo git clone https://github.com/moses-y/Real-Estate-Chatbot.git cd Real-Estate-Chatbot Create a virtual environment python -m venv venv source venv/bin/activate # Windows: venv\Scripts\activate Install Python dependencies pip install -r requirements.txt Provide required secret (NGROK token) – the repo includes a placeholder file Create a local config file as described in the README: echo "NGROKAUTHTOKEN = \"yourngrokauthtokenhere\"" > config.py Start the Flask server python app.py

The server listens on http://127.0.0.1:5000; opening that URL loads templates/index.html which pulls the JavaScript from static/js/script.js to drive the chat.

If you intend to run the static demo on GitHub Pages, simply push the index.html and static/ folder to the gh-pages branch; no server is required for that view.

Real‑World Use

A property‑listing portal can embed the chatbot widget by copying the templates/index.html markup into its own page and pointing the AJAX call in script.js to the portal’s Flask instance (e.g., https://myportal.com/chat/get). The backend can replace the static qadata.py with a database query to keep answers up‑to‑date.

Example integration snippet

from flask import Flask, request, jsonify from mydb import fetchfaq # custom DB layer

app = Flask(name)

@app.route("/get", methods=["POST"]) def getanswer(): query = request.json["msg"] answer = fetchfaq(query) # replace TF‑IDF lookup return jsonify({"answer": answer})

The Bottom Line

The project delivers a functional, Flask‑based real‑estate chatbot with a clear data flow and minimal front‑end code, suitable for quick prototyping or small‑scale deployments. However, the presence of hard‑coded secrets, lack of tests, CI, and a proper license make it risky for production use without remediation. Teams needing a ready‑made demo can adopt it quickly; production teams should first address security, testing, and deployment hygiene.

Fix: Read it from the environment with a safe default: DEBUG = os.environ.get("DEBUG") == "1".
