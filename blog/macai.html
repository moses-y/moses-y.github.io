macai

All-in-one native macOS AI chat application for virtually any AI provider

Forked from Renset/macai

The Problem MacOS users who need a native chat client for multiple LLM providers must juggle web UIs, browser extensions, or separate CLI tools. Each service often requires its own authentication flow, UI quirks, and storage handling, leading to fragmented workflows and inconsistent user experience.

What This Does macai delivers a single, native macOS app that aggregates ChatGPT, Claude, Gemini, Grok, Perplexity, Ollama, OpenRouter and any OpenAI‑compatible endpoint. The UI lives in macai/UI/, with core chat logic in macai/UI/Chat/ChatViewModel.swift and macai/Utilities/ChatService.swift. Provider‑specific networking is isolated under macai/Utilities/APIHandlers/ (e.g., ChatGPTHandler.swift, ClaudeHandler.swift). API metadata (base URLs, default models, token field names) are defined in macai/Configuration/APIServiceTemplates.json and consumed by APIServiceFactory.swift. All user data—including chat history and preferences—are persisted via Core Data (macai/Store/macaiDataModel.xcdatamodeld) and optionally synced through iCloud (macai/macai.entitlements).

How To Use It

Setup Clone & open the Xcode project: git clone https://github.com/Renset/macai.git cd macai open macai.xcodeproj The CI workflow (.github/workflows/swift-xcode.yml) shows a successful build with the macai scheme, so the same command works locally: xcodebuild -scheme macai -configuration Release clean build

Configuration Add API credentials in the app UI under Preferences → API Services. The UI reads/writes the JSON template (macai/Configuration/APIServiceTemplates.json) via APIServiceTemplateProvider. For iCloud sync, ensure the app’s entitlements (macai/macai.entitlements) are enabled in your Apple Developer account and that the “iCloud” capability is turned on in the Xcode project.

Running After a successful build, launch the app from Xcode or run the generated binary located in DerivedData/.../Build/Products/Release/macai. The entry point is macai/macaiApp.swift, which sets up the App struct, injects ChatStore (core data wrapper) and presents ContentView.swift.

Real‑World Use A developer can script the launch of a local Ollama model and then point macai to it:

start Ollama model ollama serve & launch macai (built binary) open -a ./macai --args --api-service Ollama --model llama3

Within macai, the conversation persists across devices via iCloud, and the same UI can switch to OpenAI or Claude by selecting a different service in the preferences pane.

Code Health & Issues Low – Missing explicit API‑key validation – Handlers such as ChatGPTHandler.swift assume a non‑empty token; no guard against empty strings is visible. Medium – Core Data migration complexity – V1ToV3Migration.swift hints at multiple schema versions; tests for migration (DatabaseMigrationTests.swift) exist but no automated migration verification in CI. Low – UI‑only error handling – UI error bubbles (ErrorBubbleView.swift) display messages, but network‑level errors are not bubbled up to a central logger. Low – License present – LICENSE.md is included and referenced in the README. Low – Test coverage – 13 test files cover API handlers, PDF parsing, and migration; CI runs swift test successfully. Low – Dependency hygiene – No external package manager files; all code is self‑contained, reducing supply‑chain risk.

Overall the repository follows typical Xcode conventions, includes unit tests, CI, and a clear project structure. No obvious secret files or hard‑coded credentials are present.

The Bottom Line macai is a well‑structured, native macOS client that consolidates many LLM APIs behind a clean SwiftUI interface. It is ready for production use by teams needing a unified chat experience on macOS, provided they add their own token validation and monitor Core Data migrations. The project is suitable for developers comfortable with Xcode and Swift, and for power users who prefer a local UI over browser‑based consoles.
