The Problem

Interview preparation often relies on static question lists that lack hands‑on context. Candidates need reproducible, environment‑specific exercises that mirror real engineering tasks, especially for DevOps and cloud tooling.

What This Does

tech‑vault aggregates curated interview questions and executable challenges across several domains (DevOps, DSA, system design). The bulk of the repo lives under devops‑challenges/, where each numbered folder (q16, q37, …) contains a self‑contained scenario with source code, infrastructure as code, and Docker artefacts. Example: devops‑challenges/code/q16/ provides a Flask app (app.py) together with a Dockerfile, requirements.txt, and a unit test (tests/test_app.py). Example: devops‑challenges/code/q37/ demonstrates a full‑stack microservice composed of a Python backend (backend/app.py), a Node.js frontend (frontend/src/index.js), and supporting Docker/K8s manifests (docker-compose.yml, Tiltfile).

The repository also supplies ancillary tooling (misc/go/random.go, misc/py/randomiser.py) that generate random questions for practice, and a README that links to an external web UI (tech‑vault-web.vercel.app).

How To Use It

Setup

Install Docker (required for every runnable challenge). For Python‑only challenges, create a virtual environment and install dependencies:

cd devops-challenges/code/q16 python -m venv .venv . .venv/bin/activate pip install -r requirements.txt

Note: Other challenges provide a Dockerfile; building the image is the preferred path.

Configuration

Most challenges are self‑contained; no external secrets are required. When a challenge references environment variables (e.g., devops‑challenges/code/q39/config.env), copy the sample file and edit values as needed before running the script.

Running

Python only:

python app.py # entry point for q16 Dockerised (e.g., q16):

docker build -t q16 . docker run -p 5000:5000 q16 Compose / multi‑service (e.g., q37):

cd devops-challenges/code/q37 docker-compose up --build Test execution (where provided):

cd devops-challenges/code/q16 pytest tests

The README.md in each challenge folder usually contains the exact commands; follow those when present.

Real‑World Use

A hiring team can spin up any challenge in isolation to evaluate a candidate’s ability to provision infrastructure, write code, and debug containerised services. For example, a senior DevOps interview could ask the candidate to modify devops‑challenges/code/q34/charts/my‑python‑app/values.yaml to change replica count, then run helm install against a local Kind cluster, confirming the deployment respects the new value.

helm upgrade --install test-app devops-challenges/code/q34/charts/my-python-app \ --set replicaCount=3

Code Health & Issues

Low – Missing Python lockfile – devops‑challenges/code/q16/requirements.txt has no requirements‑*.txt or pipfile.lock; reproducibility is limited. Low – Sparse CI coverage – Only devops‑challenges/code/q42/.github/workflows/ci.yml defines a CI pipeline; most challenges lack automated testing or linting. Low – Inconsistent documentation – While many challenge folders include a README.md, several (q2, q30) rely on top‑level notes only, making onboarding for new contributors uneven. Low – Mixed language lock files – Go modules (devops‑challenges/code/q42/tests/go.mod) are present, but no go.sum is committed, exposing version drift. Low – No secret scanning – Repository contains .env‑style files (config.env) without redaction checks; a CI secret‑scan step would improve security posture.

Overall, the codebase is organized and each challenge is runnable, but the lack of lockfiles and CI for most modules reduces reliability for production‑grade usage.

The Bottom Line

tech‑vault delivers a practical, hands‑on library of interview challenges that can be executed directly via Docker or local Python environments. It is well‑structured for learning and assessment, but teams should add lockfiles, broaden CI coverage, and enforce secret scanning before using it as a benchmark for hiring pipelines. Suitable for interview preparation, training workshops, and small‑scale skill assessments.
