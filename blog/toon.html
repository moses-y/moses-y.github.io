The Problem

LLM tokens carry cost, and standard JSON is verbose for prompt input. Uniform arrays of objects—common in LLM contexts—inflate token counts because each object repeats keys like "id", "name", "companion". The repository acknowledges this: the README benchmarks JSON against TOON and YAML, showing TOON's compactness goal for LLM-facing data.

What This Does

TOON is a compact, human-readable encoding of JSON that minimizes tokens while preserving structure. It combines YAML-style indentation for nesting with a CSV-style tabular layout for uniform arrays, making it easier for models to parse and validate. The core library lives in packages/toon/, with packages/toon/src/index.ts as the main entry point, packages/toon/src/encode/normalize.ts handling value normalization, and packages/toon/src/decode/decoders.ts implementing the parser/evaluator. A CLI wrapper at packages/cli/src/index.ts provides run, encode, and decodeStream commands. Benchmarks reside in benchmarks/src/, notably benchmarks/src/questions/index.ts which drives evaluation task generation.

How To Use It

Setup: Install dependencies with pnpm install (the repo uses pnpm, as shown in package.json and pnpm-workspace.yaml). The workspace comprises packages/toon and packages/cli.

Configuration: No environment variables or keys are required; TOON is a pure format transformation.

Running it: To encode JSON to TOON, invoke the CLI:

pnpm cli encode --input input.json --output output.toon

or use the API:

import { encode } from '@toon-format/toon';
const toon = encode(yourJsonData);

The CLI entry point is packages/cli/src/index.ts:130 (the run function); the core encode function lives in packages/toon/src/index.ts:48.

Real-World Use

A prompt engineer preparing few-shot examples for an LLM can replace verbose JSON with TOON to reduce token count and improve model adherence to structure. For instance, a uniform array of hike records:

[
  {"id":1,"name":"Blue Lake Trail","distanceKm":7.5,"elevationGain":320,"companion":"ana","wasSunny":true},
  {"id":2,"name":"Ridge Overlook","distanceKm":9.2,"elevationGain":540,"companion":"luis","wasSunny":false}
]

encodes to TOON as:

1  Blue Lake Trail    7.5  320  ana  true
2  Ridge Overlook     9.2  540  luis false

The encode function in packages/toon/src/index.ts handles this transformation losslessly, and the decoder reconstructs the original JSON. This is useful when every token counts toward cost, and the data conforms to TOON's sweet spot: uniform arrays of objects with the same shape.

The Bottom Line

TOON delivers a real token-reduction win for LLM prompts involving uniform object arrays, with a working TypeScript SDK and CLI. The codebase is structurally sound but has cognitive-load hotspots—oversized files, high branching density, and duplicated logic—that should be addressed before wide adoption. It’s worth using when your data fits TOON’s format and you’re token-constrained; otherwise, stick with JSON.
