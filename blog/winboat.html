The Problem

Running Windows applications on Linux has historically required either dual-booting, maintaining a full virtual machine with a separate desktop, or relying on compatibility layers like Wine that don't support all software. Each approach forces users to choose between convenience and compatibility.

What This Does

WinBoat runs Windows inside a Docker or Podman container as a VM, then uses FreeRDP's RemoteApp protocol to render individual Windows applications as native Linux windows. The guestserver/main.go handles communication with the Windows guest, while the Electron frontend (src/renderer/) provides a dashboard for managing apps and configuration. The UI uses Vue with Tailwind CSS, and container orchestration logic lives in src/renderer/lib/containers/.

The system mounts your Linux home directory into the Windows VM for file sharing, and supports automated Windows setup through scripts in guestserver/scripts/. The src/renderer/views/SetupUI.vue handles the initial installation wizard.

Real-World Use

A developer needs to run a Windows-only ERP application alongside their Linux development tools. With WinBoat, they install the app inside the container once, then launch it from the dashboard. FreeRDP surfaces the application window directly on their Linux desktop, with the home directory mounted for file access.

Code Health & Issues

Med - No test files found beyond a single test file. The src/renderer/lib/ modules handling container orchestration, USB passthrough, and QMP communication have no visible test coverage. Untested virtualization management code is a reliability risk. Low - Hardcoded paths and registry files (guestserver/RDPApps.reg, guestserver/nssm.exe) are committed to the repo. Binary files (nssm.exe) in source control are a security and auditing concern. Low - The data/usb.ids file (USB vendor/device ID database) is committed. This is a static data file that should be fetched at build or runtime to stay current. Low - CI is configured via .github/workflows/release.yml but no linting or testing workflows are visible. Code quality gates are absent.

The Bottom Line

WinBoat offers a polished approach to Windows-on-Linux integration, combining containerized VMs with RemoteApp for a native-feeling experience. The project is in beta with minimal test coverage and some source control hygiene issues, but the architecture is sound and the feature set is practical for developers who need specific Windows applications without a full VM desktop.
