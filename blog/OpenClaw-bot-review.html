OpenClaw bot review

A lightweight web dashboard for viewing all your OpenClaw Bots/Agents/Models/Sessions status at a glance.

Forked from xmanrui/OpenClaw-bot-review

The Problem When running multiple OpenClaw agents across platforms such as Feishu and Discord, keeping track of which bot uses which model, platform connectivity, gateway health, and token consumption becomes increasingly manual and error‑prone. There is no single place to view session stats, test bindings, or configure alerts, forcing operators to juggle logs, config files, and separate UIs.

What This Does OpenClaw‑bot‑review is a lightweight Next.js dashboard that aggregates status from ~/.openclaw/openclaw.json and local session files, presenting a unified UI. Key areas implemented in the code base include: Bot overview – app/page.tsx renders a card wall of agents drawn from lib/config-cache.ts; each card shows name, emoji, model, platform bindings, and gateway health. Model list – app/api/model‑ routes (app/api/config/agent-model/route.ts, app/api/config/route.ts) expose provider and model metadata (context window, max output, reasoning support) via lib/openclaw‑skills.ts. Session management – app/sessions/page.tsx and per‑agent routes (app/api/sessions/[agentId]/route.ts) list DM, group, and cron sessions with token usage and connectivity status. Statistics – app/stats/page.tsx and API routes (app/api/stats-all/route.ts, app/api/stats‑models/route.ts) generate SVG charts for token consumption and average response times. Skill management – app/skills/page.tsx and app/api/skills/route.ts list built‑in, extension, and custom skills with search/filter. Alert center – app/alert‑monitor.tsx and app/api/alerts/ routes let users define rules (model unavailable, bot no response) and send Feishu notifications via lib/pixel‑office/notificationSound.ts. Gateway health – app/gateway‑status.tsx polls app/api/gateway‑health/route.ts every 10 s and offers a one‑click jump to the upstream OpenClaw web UI. Platform test – app/api/test‑platforms/route.ts and app/api/test‑dm‑sessions/route.ts provide one‑click connectivity checks for Feishu, Discord, etc. Auto‑refresh – configurable interval (manual, 10s, 30s, 1min, 5min, 10min) stored in state and used by the refresh logic in app/layout.tsx. i18n & theme – lib/i18n.tsx switches Chinese/English; sidebar includes a dark/light theme switcher. Pixel office – animated pixel‑art characters (lib/pixel‑office/engine/renderer.ts, lib/pixel‑office/sprites/) walk, sit, and interact with furniture defined in lib/pixel‑office/layout/. Live config – all pages read directly from ~/.openclaw/openclaw.json; the OPENCLAWHOME env var lets point to an alternate path.

How To Use It

Setup Clone the repository git clone https://github.com/xmanrui/OpenClaw-bot-review.git cd OpenClaw-bot-review

Install dependencies (npm) npm install

Configuration By default the dashboard reads ~/.openclaw/openclaw.json. To use a custom path set OPENCLAWHOME; the docker run example in README.md demonstrates mounting a host directory:

docker run -d --name openclaw-dashboard -p 3000:3000 -e OPENCLAWHOME=/opt/openclaw -v /path/to/openclaw:/opt/openclaw openclaw-dashboard

Running it Development: npm run dev (starts Next.js at http://localhost:3000). Production build: npm run build then npm start. Docker: build with docker build -t openclaw-dashboard . (Dockerfile at repo root) and run as shown above.

Environment variable – OPENCLAWHOME (optional) points at the directory containing the OpenClaw JSON config; otherwise the default ~/.openclaw/openclaw.json is used.

Real‑World Use A midsize team operating bots on both Feishu and Discord can point the dashboard at their shared openclaw.json. The agent‑card wall instantly shows which models each bot is bound to, while the gateway‑health indicator turns red if the upstream gateway fails, prompting a one‑click jump to the OpenClaw UI for deeper diagnostics. The team sets an alert rule for “model unavailable”; when triggered, a Feishu message is sent via the configured webhook. During off‑hours, the pixel‑office animation provides a visual cue of agent activity without needing to open logs. Periodic npm test runs (9 test files exist) can be executed locally to verify that session‑status APIs return expected shapes.

Code Health & Issues No CI/CD pipeline – the repository lacks a .github/workflows directory or any automated build/test gate; there is no configured CI to run the 9 test files or lint on push. Test coverage not wired – while 9 test files are present (e.g., under test-results/ and app/test), they are not executed automatically; a contributor must invoke npm test manually. Configuration outside repo – the dashboard depends on ~/.openclaw/openclaw.json (or a path set via OPENCLAW_HOME). Sensitive credentials or API keys live in that external file, which is not version‑controlled; ensure the path is backed up and access‑controlled.
