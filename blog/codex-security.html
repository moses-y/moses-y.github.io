The Problem

Code repositories accumulate security vulnerabilities that are easy to miss in manual review and hard to track across branches or over time. Existing scanners often produce noise, lack CI integration, or require separate tooling for triage, remediation, and policy enforcement. Teams need a single pipeline that finds, validates, and fixes issues without switching contexts.

What This Does

codex-security provides a CLI and TypeScript SDK (sdk/typescript/src/cli.ts, sdk/typescript/src/index.ts) that scans repositories for vulnerabilities, analyzes changes, and tracks findings. It includes a bundled plugin (sdk/typescript/bundledplugin/) with pre-built skills—such as security-scan, fix-finding, and triage-finding—each with agent configurations, reference docs, and validation scripts. The SDK exposes a CodexSecurity class (see src/index.ts) with methods like run() and close(). Authentication supports both ChatGPT sign-in and API keys, configurable via flags or environment variables. Docker support (Dockerfile, compose.yaml) and CI workflows (.github/workflows/node-ci.yml, container-ci.yml) are included.

Real-World Use

A team sets up a CI pipeline that runs npx codex-security scan . on every pull request. Findings are stored in the workbench state directory; the scan-comparison module (src/scan-comparison.ts) can diff results against a baseline. Developers use the fix-finding skill to generate remediation patches, and the track-findings skill to create Jira tickets or GitHub advisories automatically. The CLI’s --auth api-key flag enables non-interactive runs in build systems.

Code Health & Issues

The codebase is structurally sound: 30 test files exist under sdk/typescript/tests-ts/, CI workflows are configured, a license is present, and a lockfile (pnpm-lock.yaml) is committed. No obvious red flags. However, several concerns are worth noting: Medium — The bundled plugin contains 40+ Python scripts and 13 skill directories. This increases maintenance surface and may cause version drift between the TypeScript SDK and the Python runtime. Scripts like deepscanworkbench.py and snapshot_sqlite.py have no dedicated tests visible. Low — The repo is a direct fork of openai/codex-security with 0 stars on the fork. If the parent is actively maintained, this fork may lag behind in updates or patches. Low — The .mcp.json and .app.json files in the bundled plugin suggest integration with MCP and a custom plugin system. These are not documented in the top-level README, which could confuse new users.

The Bottom Line

This is a well-structured, production-oriented security scanning tool with strong CI and SDK support. It is best suited for teams already using OpenAI’s Codex ecosystem who want an integrated find-fix-track workflow. The bundled plugin adds depth but also complexity; organizations with simple scanning needs may find a lighter tool easier to maintain. The fork status and zero stars are not a concern if the parent repo remains active.
