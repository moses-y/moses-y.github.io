ADR

ADR secures enterprise AI agents through observability, security benchmarking, and threat detection. Deployed at Uber.

Forked from uber/ADR

The Problem

Enterprise AI agents (Claude Code, Cursor, Codex, customer-facing support bots) operate with tool access to internal systems. Security teams lack observability into what these agents do, how they interpret instructions, and whether they execute unsafe operations. Existing security tools don't account for prompt injection, tool misuse, or data exfiltration by AI agents.

What This Does

ADR is a production-deployed security system for AI agents. It provides four capabilities: observability (collecting agent telemetry from 7+ coding tools across macOS, Linux, Windows), benchmarking (300+ security tasks against 133 MCP servers covering 17 attack techniques), detection (two-tier architecture with high-recall triage and deep reasoning), and prevention (not in open-source release).

The Detection/ directory contains the core detection logic and benchmark infrastructure. The dual-agent detector lives in Detection/benchmark/adrbench20251017151604.jsonl and related benchmark scripts. The Detection/contextproviders/ directory holds policy stores (policystore.yaml), threat repositories (threatrepository.yaml), and source code analyzers for MCP servers. The Sensor/ directory (not shown in detail) handles telemetry collection and normalization.

Real-World Use

Deployed at Uber for employee-facing AI coding tools. The benchmark evaluates detector performance across realistic enterprise scenarios: banking, Slack, travel booking, and workspace environments. Each suite includes injection vectors and user tasks that simulate real attack patterns. The configdetector.yaml and configbenchmark.yaml files control detection and evaluation parameters.

Code Health & Issues High - No test files detected across the entire repository. The Detection/ directory contains 139 Python files with zero test coverage. This is a significant risk for production use given the system handles security-critical decisions. Medium - The Detection/contextproviders/data/ directory contains hardcoded policy and threat data in YAML files. These appear to be synthetic benchmarks, but the pattern suggests configuration may be mixed with code rather than injected via environment or secrets management. Medium - The benchmark data (adrbench20251017151604.jsonl, adrbench20251022_190150.jsonl) is packed as JSONL files. The README mentions an "inflate packed benchmark" step, but the inflation tool is not visible in the file listing. Low - CI is configured (.github/workflows/ci.yml), and Dependabot is enabled (.github/dependabot.yml). Pull request templates exist. These indicate reasonable SDLC practices despite the test gap. Low - The repo includes synthetic benchmark fixtures with fake credentials per the data notice. This is appropriate for a security benchmark but requires careful handling to avoid confusion with real credentials.

The Bottom Line

ADR addresses a real, growing problem in enterprise AI security with a production-proven system at Uber. The architecture is sound—observability, benchmarking, detection, and prevention form a coherent stack. The lack of tests is concerning for a security product, and the prevention component is missing from open-source. Teams already deploying AI coding agents at scale will find the observability and detection components immediately useful; smaller teams should weigh the integration effort against the maturity of the test suite.
