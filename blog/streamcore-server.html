streamcore server

Open-source realtime voice agent server in Go with WebRTC (WHIP), barge-in, streaming STT/LLM/TTS pipelines, plugin system, multi-language SDKs, SIP telephony, ESP32 support & fully local mode.

Forked from streamcoreai/streamcore-server

The Problem Building a voice agent prototype is straightforward, but transitioning to a reliable product requires solving intricate realtime media infrastructure challenges that are orthogonal to agent prompts. Once NAT traversal, audio encoding, and turn-taking logic must be production-grade, the development focus shifts from AI logic to systems engineering. StreamCore was built to absorb this complexity, positioning itself as the dedicated media runtime layer.

What This Does StreamCore provides a Go-based media runtime handling the full realtime audio path. Core functionality is concentrated in internal/: the pipeline logic in internal/pipeline/pipeline.go manages streaming STT, LLM, and TTS integration; internal/vad/vad.go provides adaptive voice activity detection with turn-debouncing; and internal/audio/rtp.go and internal/audio/opus.go handle RTP/Opus encoding and decoding. The system supports WebRTC transport via Pion, WHIP signaling, and a built-in STUN/TURN server, eliminating the need for an external coturn container. A plugin system exists under plugins/, currently supporting integrations for Gmail, weather, and math calculations via TypeScript, while external Python dependencies for ASR and TTS are managed under external/vibeVoice/.

How To Use It Setup: The repository is built for containerized deployment. A Dockerfile is present at the root, and infrastructure/aws/ec2/docker-compose.yml provides a local development stack. Infrastructure as code is defined using Terraform in infrastructure/aws/ec2/, including main.tf and variables.tf. For local Go development, go.mod and go.sum are present; the entry point is main.go.

Configuration: Configuration is managed via config.toml.example. The README notes optional JWT authentication on the /whip endpoint, utilizing a short-lived token endpoint for signaling security.

Running it: To run the server locally, the entry point is main.go. For production or cloud deployment, the Terraform configuration in infrastructure/aws/ec2/ can be applied to provision infrastructure on AWS EC2.

Real-World Use StreamCore fits between a client device and AI services in a voice agent workflow. Audio flows from the client via WebRTC/WHIP into the server, where internal/stt/ processes streaming speech-to-text (with implementations for OpenAI and Deepgram). The transcript feeds into the agent logic, potentially querying internal/rag/rag.go for retrieval-augmented generation, before being passed to internal
