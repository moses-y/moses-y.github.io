The Problem

Robotics research and education requires significant boilerplate for kinematics, dynamics, and visualization. Researchers often hand-roll transformation math, inverse kinematics solvers, and robot model loaders, which leads to inconsistent results and wasted effort. This toolbox consolidates those primitives into one Python package.

What This Does

robotics-toolbox-python is a Python framework for robot kinematics, dynamics, and trajectory generation. It provides spatial math operations, robot model definitions (DH and ETS-based), inverse kinematics solvers, and visualization backends. The repo includes a companion rtb-data package with robot-specific data files.

The core library lives in the root package with 46 Python files. The examples/ directory (34 files) shows real usage patterns: pumajtraj.py for trajectory generation, ikineevaluate.py for inverse kinematics benchmarking, and rnecompare.py for dynamics validation. The docs/ folder contains extensive Sphinx documentation and Jupyter notebooks covering kinematics, dynamics, and symbolic computation.

The rtb-data/rtbdata/armerxarm/ subpackage demonstrates the data format: it bundles URDF/Xacro files, STL meshes, ROS launch files, and Python model definitions for the xArm 6 robot.

How To Use It

Setup: Install via pip. The pyproject.toml declares dependencies (numpy, scipy, matplotlib, spatialmath-python). No lockfile is present, so use pip install roboticstoolbox-python or pin versions manually for reproducible builds.

Running it: The primary entry point is the Python API. Start with the examples:

pip install roboticstoolbox-python python examples/pumajtraj.py python examples/robots.py

The examples/readme.py file mirrors the README's quickstart. For interactive exploration, the docs provide JupyterLite notebooks that run in-browser without local setup.

Configuration: No environment variables or config files are required for basic use. Robot models are loaded from the package's built-in definitions or from URDF files via the ERobot class.

Real-World Use

A typical workflow: load a robot model, compute forward kinematics, solve inverse kinematics, and generate a trajectory.

import roboticstoolbox as rtb from spatialmath import SE3

robot = rtb.models.DH.Panda() T = SE3(0.5, 0.0, 0.3) * SE3.RPY([0, 0, 0]) sol = robot.ikineLM(T) traj = robot.jtraj(robot.qz, sol.q, 50)

Code Health & Issues

Low - No dependency lockfile - pyproject.toml declares version ranges but no pinned versions, so builds are not fully reproducible across environments. Low - Branch structure - This repo is a fork of petercorke/robotics-toolbox-python (3,360 stars upstream). The 0-star fork status suggests this is either a personal copy or a work-in-progress branch; verify it tracks upstream before relying on it. Low - Test coverage - Only 3 test files exist, which is thin for a library this size. The upstream project has more extensive tests, so this fork may lag on test coverage. Low - Bundled data package - rtb-data contains STL meshes and URDF files. Verify licensing of these assets if you redistribute them; the LICENSE files are present but should be reviewed.

CI is configured via GitHub Actions (.github/workflows/ci.yml), and the project uses release-please for automated versioning. The documentation is extensive and well-structured.

The Bottom Line

This is a mature, well-documented robotics library with a solid API design and active upstream maintenance. The fork status is the main concern - if you need production support, use the upstream repo directly. For research, education, or prototyping, this is a practical choice that saves substantial implementation time. The missing lockfile and thin test suite are minor issues for a library of this scope.

codecov/codecov-action@v7, googleapis/release-please-action@v5, pypa/gh-action-pypi-publish@release/v1, pypa/cibuildwheel@v4.1.1
A tag can be moved, so the action running with your token and secrets is whatever its owner last pushed; this is how tj-actions/changed-files leaked secrets from thousands of repos.
