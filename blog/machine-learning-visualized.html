machine learning visualized

ML algorithms implemented and derived from first-principles in Jupyter Notebooks and NumPy

Forked from gavinkhung/machine-learning-visualized

The Problem Teams that teach or demonstrate machine‑learning fundamentals often rebuild the same notebooks, plots, and derivations for every course or blog post. Keeping the source, the visual output, and the publishing pipeline in sync is error‑prone and time‑consuming, especially when the notebooks live in separate repositories.

What This Does machine-learning-visualized is a Jupyter Book wrapper that assembles a set of algorithm notebooks (linear regression, logistic regression, perceptron, neural networks, etc.) into a single, publishable website and optional EPUB. The book configuration lives in config.yml and the table of contents in toc.yml. The actual notebooks are not stored here; they are fetched on demand by the shell script downloadnotebooks.sh, which clones the algorithm‑specific repos listed in the README (e.g., gavinkhung/neural-network).

Key artefacts:

Dockerfile.book – builds an image that runs jupyter-book inside a container. Dockerfile.pandoc – builds a Pandoc image used to convert the merged notebook to EPUB. compose.yml – provides a Docker‑Compose service (jupyter-book) that wraps the book build. .github/workflows/ci.yml – GitHub Action that runs the build on each push/PR, publishing the HTML output.

All visual assets (GIFs, PNGs) are stored under gifs/ and book/combinedfiles/, and the final PDF/EPUB artefacts are pre‑generated in book/.

How To Use It

Setup

Install Python dependencies (no lockfile – reproducibility depends on requirements.txt) pip install -r requirements.txt Make the notebook‑download script executable chmod +x ./downloadnotebooks.sh

Pull the notebooks

./downloadnotebooks.sh

The script clones each algorithm repository into the corresponding chapter/ folder, creating the Jupyter notebooks required for the book build.

Build the book

Option 1 – Local Jupyter‑Book CLI

pip install -U jupyter-book # already covered by requirements.txt jupyter-book build .

Option 2 – Docker Compose

docker compose run --rm jupyter-book # uses Dockerfile.book docker compose down --remove-orphans --volumes --rmi local

Option 3 – Stand‑alone Docker

docker build -f Dockerfile.book -t jupyter-book . docker run --rm -v "$(pwd)":/usr/src/app jupyter-book

The HTML output appears in _build/html/index.html.

Create EPUB (optional)

brew install --cask mactex # macOS only; required for LaTeX conversion nbmerge $(ls chapter/\.ipynb | sort) -o book/combined.ipynb jupyter nbconvert --to latex book/combined.ipynb docker build -f Dockerfile.pandoc -t my-pandoc . docker run --rm -v $(pwd):/data my-pandoc pandoc book/combined.tex -o book/combined.epub --mathml --embed-resources --standalone

Real‑World Use A university data‑science lab can clone this repo, run the download script, and publish a course‑wide visual textbook on an internal static‑site server. The workflow integrates with CI/CD: each commit automatically rebuilds the HTML book via the GitHub Action, ensuring students always see the latest derivations without manual publishing steps.

Example snippet from .github/workflows/ci.yml name: Build book run: jupyter-book build .

Code Health & Issues

Med – No test suite – No tests/ directory or pytest config; core build steps are untested. Low – No lockfile – requirements.txt pins versions loosely; reproducible builds rely on Docker images only. Low – License present – LICENSE file exists, satisfying open‑source compliance. Low – CI only builds book – GitHub Action runs the book build but does not lint notebooks or check for broken links. Low – Missing notebook version control – Notebooks are external; if upstream repos change API, the build may break without detection.

Overall the repository is well‑structured for its purpose, with Docker support and a clear CI pipeline. The lack of automated tests and dependency pinning are the primary maintenance risks.

The Bottom Line machine-learning-visualized provides a clean, Docker‑enabled pipeline to assemble and publish a visual ML textbook from external notebooks. It is suitable for educators or documentation teams who need a reproducible publishing flow, but they should add a test harness and lockfile to improve reliability for long‑term use.
