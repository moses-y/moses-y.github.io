Local Knowledge Graph

No description available

Forked from punnerud/Local_Knowledge_Graph

The Problem Local LLM deployments (e.g., Ollama) give powerful reasoning capabilities but lack a built‑in way to visualise the step‑by‑step thought process. Teams that need to audit or explain model output have no lightweight, on‑premise tool to turn a chain‑of‑thought into an interactive graph.

What This Does LocalKnowledgeGraph wraps a locally‑running Llama model and renders each reasoning step as a node, linking nodes with cosine similarity edges derived from an embedding model. The Flask web UI lives in src/mpelkg/templates/index.html and the core logic is in:

src/mpelkg/graph.py – builds the graph structure. src/mpelkg/reasoning.py – drives the step‑wise prompting. src/mpelkg/store.py – caches model responses and embeddings.

The package exposes a CLI (src/mpelkg/cli.py) and a Flask factory (src/mpelkg/app.py). Installing the wheel (mpe-lkg) registers the entry point mpe-lkg which starts the server on port 5100.

How To Use It

Setup Install the package from PyPI pip install mpe-lkg

Ensure Ollama is running locally and has at least one chat model ollama pull llama3.2:3b # any chat model ollama pull nomic-embed-text # optional embedding model

The pyproject.toml declares the runtime dependencies; no lockfile is present, so reproducible builds rely on the version constraints in that file.

Configuration All tunables are environment variables, documented in the README and read by src/mpelkg/app.py:

VariableDefaultPurpose
OLLAMAURLhttp://localhost:11434Ollama endpoint
LKGCHATMODELautoOverride the chat model
LKGEMBEDMODELautoOverride the embedding model
LKGHOST / LKGPORT127.0.0.1 / 5100Server bind address
LKGDEBUGoffEnable Flask debugger

Export any needed overrides before starting, e.g.:

export LKGCHATMODEL=llama3.2:3b export LKGEMBEDMODEL=nomic-embed-text

Running From a terminal:

Start the UI (installed entry point) mpe-lkg

Or run the source shim python app.py

The server listens on http://localhost:5100. For programmatic use:

from mpelkg import createapp, health

print(health()) # {'ok': True, 'models': [...]} createapp().run(port=5100)

The CLI also provides a health check (mpe-lkg doctor) that exits non‑zero on failure, useful for CI scripts.

Real‑World Use A data‑science team can embed this service in a notebook to audit model reasoning:

import requests, json, os

os.system("mpe-lkg &") # launch in background resp = requests.post( "http://127.0.0.1:5100/api/ask", json={"question": "Why is the sky blue?"} ) print(json.dumps(resp.json(), indent=2)) Open http://127.0.0.1:5100 to view the interactive graph.

The visual graph helps non‑technical stakeholders see how the model arrived at its answer and spot any logical gaps.

Code Health & Issues Low – Missing LICENSE – repository root lacks a license file; downstream users have unclear redistribution rights. Low – No lockfile – pyproject.toml lists dependencies without a poetry.lock/requirements.txt; builds may yield different versions. Medium – Limited input validation – src/mpelkg/backends.py forwards user prompts directly to Ollama; malformed JSON could cause server errors. Medium – Minimal type hints – most modules lack static typing, reducing IDE assistance and static analysis confidence. Low – Documentation gaps – only a high‑level README; internal APIs (graph.py, store.py) have no docstrings. Positive – Test coverage – 9 test files (tests/) exercise graph math, layer handling, Ollama integration, and rendering. Positive – CI pipeline – GitHub Actions for Linux, macOS, Windows and PyPI publishing demonstrate a functional SDLC.

The Bottom Line LocalKnowledge_Graph provides a straightforward, on‑premise Flask UI for visualising LLM reasoning, with a clean install path and functional CI. It is suitable for teams that already run Ollama locally and need an audit trail for model output. The main drawbacks are the missing license, lack of a dependency lockfile, and modest internal documentation; these should be addressed before adopting in regulated environments.
