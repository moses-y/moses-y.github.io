The Problem This repository addresses the need for local, transparent LLM reasoning visualization. It allows users to query a local Llama model via Ollama and observe the reasoning process rendered as a knowledge graph based on semantic similarity between steps. It is designed for environments where data cannot leave the local machine.

What This Does The core application resides in src/mpelkg/, structured as a Flask app (src/mpelkg/app.py) with separate modules for the knowledge graph (src/mpelkg/graph.py), data storage (src/mpelkg/store.py), and reasoning logic (src/mpelkg/reasoning.py). The frontend (src/mpelkg/templates/index.html) visualizes the graph using vis-network and marked (vendor scripts in src/mpelkg/static/vendor/). Configuration is handled via environment variables as documented in the README, with defaults for the Ollama URL and port. The embedding model selection directly impacts graph edge quality; measured data in docs/claims/edgespread.json compares all-minilm (384 dimensions, coefficient of variation 0.28) against nomic-embed-text (768 dimensions, coefficient of variation 0.13), providing concrete data for model selection.

How To Use It Setup requires Ollama running locally with a chat model and optionally an embedding model (ollama pull llama3.2:3b). Install the package via pip install mpe-lkg or, from source, git clone and pip install -e . as documented in the README. Configuration is achieved through environment variables; the .env or shell environment should set OLLAMAURL (default http://localhost:11434), LKGHOST (127.0.0.1), and LKGPORT (5100). To start the server, run mpe-lkg (the CLI entry point) or execute python app.py from the root. Open http://localhost:5100 in a browser to interact with the interface.

Real-World Use A technical writer drafting documentation can use this tool to verify the consistency of an LLM's reasoning across multiple paragraphs. By querying the model with specific technical questions, the resulting knowledge graph highlights where the model's semantic steps diverge or converge, providing a visual audit trail of the model's internal logic without transmitting data to external services.
