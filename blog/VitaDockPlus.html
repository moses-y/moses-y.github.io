VitaDockPlus

Abstract

VitaDock+ is a Linux distribution for Raspberry Pi used to create a PlayStation Vita docking station for video output to a TV.

Forked from SilentNightx/VitaDockPlus

The Problem Setting up a PlayStation Vita docking station on Raspberry Pi requires integrating video output, GPIO-controlled mode switching, udev hardware events, and systemd service management across dozens of scripts and rules. The repository contains no test coverage and no CI/CD gate, so changes to udev rules or systemd services carry risk of breaking boot behavior with no automated validation.

What This Does VitaDock+ is a Raspberry Pi Linux distribution that transforms the board into a Vita dock for TV video output. Key files and responsibilities:

  • home/pi/run.sh, 1stboot.sh, autorun.sh – boot-time entry points that configure console mode, launch the Vita session, and start services.
  • etc/systemd/user/vita.service, switch.service – systemd units managing the dock session and input switching.
  • etc/udev/rules.d/91-vita.rules through 99-com.rules – trigger on Vita/device attachment, invoke corresponding scripts.
  • home/pi/gpioBTDiscovery.py – GPIO-based Bluetooth discovery; the only analyzed Python module (of 2 total).
  • home/pi/pi-power-button/listen-for-shutdown.py – monitors power button state for graceful shutdown.
  • home/pi/vitadock.conf – central configuration file for display modes, audio source, and GPIO mappings.
  • home/pi/*.sh (30 shell scripts) – handle display mode switching (switchbt.sh, enableBTDiscovery.sh, runswitch.sh), audio configuration (enableAux.sh, disablelowlatency.sh), and runtime feedback.

How It Is Wired Execution starts at boot via 1stboot.sh or run.sh. udev rules detect Vita USB/serial attachment and fire the associated rule (91-vita.rules etc.), which invokes shell scripts to reconfigure display timings and audio. Systemd services (vita.service) manage the main process lifecycle. GPIO input flows through gpioBTDiscovery.py or switchbt.sh to change modes or audio source. The except-wide swallow in gpioBTDiscovery.py is the only code-path risk identified: any GPIO or Bluetooth error is caught and silenced, masking hardware or permission failures.

How To Use It

  • Setup: Flash the latest VitaDock+ image via Raspberry Pi Imager to a 4GB+ SD card. Insert into Pi, connect display, power, and Vita (with vita-udcd-uvc installed).
  • Configuration: Edit home/pi/vitadock.conf to select display mode (960x544@30FPS, 864x488@60FPS, or plugin-controlled) and audio source (BT or AUX).
  • Running it: Boot Pi; use GPIO buttons or the on-screen menu (controlled via switchbt.sh, runswitch.sh) to toggle modes. For headless setup, 1stboot.sh runs once on first boot to expand partitions and apply config.

No package.json, pyproject.toml, or Dockerfile exists; the project is a custom OS image, not a pip-installable or containerized app.

Real-World Use A user deploys a Raspberry Pi 4 (4GB) as a Vita dock for TV output. They connect a hacked Vita with vita-udcd-uvc, plug in a Bluetooth dongle or AUX cable, and use a momentary GPIO button wired to pins monitored by listen-for-shutdown.py and gpioBTDiscovery.py. Switching from 30FPS to 60FPS mode is done via the menu, which rewrites cmdline.txt templates stored in home/pi/Templates/Enable/ and home/pi/Templates/Disable/. Audio latency is acceptable via BT on Pi 4/5; Pi Zero 2 W shows higher latency making games unplayable per tested models.

The Bottom Line VitaDock+ delivers a functional Pi-based Vita dock with broad hardware support and documented mode-switching, but the absence of tests, CI, and specific exception handling in the GPIO/Bluetooth code means production deployments require manual caution, especially when modifying udev rules or systemd units. It’s suitable for hobbyists and tinkerers comfortable with Raspberry Pi imaging and shell-based config; teams needing reliability or frequent changes should add test coverage and pin-specific exception handling before integrating into stricter pipelines.
