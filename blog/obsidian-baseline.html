The Problem

Obsidian users who want a clean, modern look often start from a community theme and then spend time tweaking CSS variables, adjusting layouts, and fixing mobile quirks. Without a well‑structured baseline, each user must recreate the same foundation, leading to duplicated effort and inconsistent results.

What This Does

obsidian-baseline supplies a ready‑to‑use CSS/SCSS foundation for Obsidian vaults. The source lives under src/ (81 SCSS files) and is compiled to theme.css at the repository root, which Obsidian can load directly. Documentation in docs/ explains the migration tool (docs/migration/) and the Marketplace of preset Style Settings (docs/marketplace/).

Key files: src/theme.scss – entry point that imports all component and color‑scheme SCSS. theme.css – the compiled stylesheet that Obsidian consumes. docs/install.html – step‑by‑step install instructions for end users. manifest.json – Obsidian‑compatible manifest declaring the theme’s ID, version (versions.json), and required API version.

The theme bundles a large palette of color schemes (src/color‑schemes/.scss) and UI feature toggles (src/features/.scss) that can be exposed through the third‑party Style Settings plugin.

How To Use It

Download the compiled theme – either clone the repo or fetch the latest release ZIP. The file you need is theme.css at the repository root. Install in Obsidian # Assuming you are inside your vault folder mkdir -p .obsidian/themes/baseline cp /path/to/theme.css .obsidian/themes/baseline/

Then open Obsidian → Settings → Appearance → Manage → Browse → select Baseline. Optional: Enable Style Settings integration Install the community plugin Style Settings (Obsidian → Settings → Community plugins). The theme’s SCSS variables are exposed automatically; presets can be imported from the Marketplace (docs/marketplace/preset/.json). Migrate from another theme (if applicable) Open docs/migration/index.html in a browser, follow the instructions, and use the JSON mapping files (docs/migration/mapping.json) with the Style Settings Migration Tool.

No build step is required for end users because the repo already ships a compiled theme.css. Developers who wish to customize the SCSS must compile it manually (e.g., with sass), but the repo does not provide a build script.

Real‑World Use

A knowledge‑worker maintains a vault on both desktop and mobile. They install Baseline as the base theme, then import the minimal.json preset from docs/marketplace/preset/minimal.json via Style Settings. The result is a consistent look across devices with a single click, while the theme’s built‑in mobile SCSS (src/app/mobile.scss) ensures proper spacing on small screens.

Code Health & Issues

Med – No automated tests – The repository contains no test files (.spec. or similar). UI changes are not regression‑checked. Med – Missing CI pipeline – .github/ only holds issue templates and a release workflow; there is no CI job that lints SCSS, runs a build, or validates the manifest. Low – No explicit build script – SCSS sources (src/.scss) are not compiled by an npm script or Makefile; developers must invoke sass manually, increasing the chance of version drift. Low – Single‑license file – LICENSE.txt is present, so licensing is clear. Low – Documentation coverage – 73 markdown/html files provide thorough user guides; however, developer‑oriented docs (e.g., contribution guide) are absent.

Overall the codebase is well‑organized: logical separation of color schemes, UI components, and feature toggles. The manifest (manifest.json) and version file (versions.json) are correctly formatted for Obsidian.

The Bottom Line

obsidian-baseline delivers a polished, mobile‑ready theme with extensive customization hooks, making it a solid starting point for any Obsidian vault. The main drawbacks are the lack of automated testing and a build pipeline, which means contributors must manage SCSS compilation manually. It is best suited for users comfortable with manual theme tweaks or teams that can add their own CI/testing around the SCSS sources.
