MyBrain

All-in-one productivity app and AI assistant with Tasks, Notes, Calendar, Diary and Bookmarks.

Forked from mhss1/MyBrain

The Problem

Most productivity apps keep tasks, notes, calendar, and bookmarks in separate silos. Users waste time switching between tools, and there’s no unified way to query or act on personal data. MyBrain solves this by combining all four domains with an AI assistant that can read and write across them.

What This Does

MyBrain is an Android app built entirely in Kotlin using Jetpack Compose and a multi-module Clean Architecture. The ai/ module defines an agent that can create tasks (TaskToolSet), notes (NoteToolSet), calendar events (CalendarToolSet), and bookmarks (BookmarkToolSet) via a chat interface. The agent uses an abstract AiRepository (with a stub EmptyAiClient for offline fallback) and a SendAiMessageUseCase that orchestrates tool calls.

The calendar/, bookmarks/, and app/ modules follow an MVI pattern with separate domain, data, and presentation layers. The core/database/ module provides Room DAOs (TaskDao, NoteDao, BookmarkDao, DiaryDao, AlarmDao) with versioned schemas. The app uses Koin for DI, Ktor for network calls, and Jetpack Glance for a home‑screen calendar widget.

Real‑World Use

A user opens the assistant and types “Remind me to buy groceries tomorrow at 5pm and add it to my shopping list note.” The SendAiMessageUseCase parses the intent, calls TaskToolSet to create a task with a due date, and NoteToolSet to create a note titled “Shopping list.” The result appears in the chat as structured cards (AiResultItemCards). No manual navigation needed.

Code Health & Issues Low test coverage – 9 test files exist (e.g., ExampleUnitTest, ExampleInstrumentedTest), but all are placeholders. No meaningful unit or integration tests for use cases, repositories, or ViewModels. This is a medium risk for regressions. Database schema migrations – 5 schema versions in app/schemas/ and core/database/schemas/. No migration tests visible. A potential high risk if users upgrade across multiple versions. AI client stub – EmptyAiClient is a no‑op; the real client (likely Ktor‑based) is not implemented in this fork. The AI feature is non‑functional without a backend. CI present – GitHub Actions build workflow exists (.github/workflows/build-android.yml). No lint or test stages, only build. Low risk for build breakage. License and contribution docs – GPL v3, CONTRIBUTING.md, and issue templates are present. Good hygiene.

The Bottom Line

MyBrain is a well‑architected Android app that genuinely unifies personal data management with an AI agent. The codebase is cleanly modular and follows modern Android practices. However, the AI assistant is incomplete (no real client), and the lack of meaningful tests makes it risky for production use without significant investment in quality assurance. Best suited for developers who want to extend a solid foundation rather than deploy as‑is.
