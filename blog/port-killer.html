The Problem

Developers routinely juggle multiple local services, Kubernetes port‑forward sessions, and Cloudflare Tunnels. Switching between terminals, hunting PIDs, and manually killing processes wastes time and risks breaking dependent services.

What This Does

PortKiller is a cross‑platform desktop app that consolidates port oversight and process control. Port discovery & filtering – platforms/linux/src/scanner.py (Linux) and the macOS PortScanner.swift enumerate listening TCP ports and expose them in a searchable table. One‑click kill – both platforms provide graceful and force‑kill actions through platforms/linux/src/main.py and the macOS PortForwardProcessManager.swift. Kubernetes port‑forward management – Linux service platforms/linux/src/services/k8s.py and macOS manager platforms/macos/Sources/Managers/KubernetesDiscoveryManager.swift create and monitor kubectl port-forward sessions, with auto‑reconnect and connection‑log tracking. Cloudflare Tunnel integration – macOS services platforms/macos/Sources/Services/CloudflaredDiscoveryService.swift and platforms/macos/Sources/Services/CloudflaredService.swift list active tunnels and expose ingress rules; the UI sections platforms/macos/Sources/Views/CloudflareTunnels/ let you view status without leaving the app. Native UI per platform – macOS uses SwiftUI (platforms/macos/Sources/PortKillerApp.swift, platforms/macos/Sources/Views/); Windows ships a Visual Studio solution (platforms/windows/PortKiller.sln); Linux is a Python‑based CLI (platforms/linux/src/main.py).

A package.json and bun.lock at the repo root manage the Node‑based build tooling and ensure reproducible dependency installation.

Real‑World Use

A developer runs a local PostgreSQL instance on port 5432, a React dev server on 3000, and a kubectl forward to a staging DB. PortKiller surfaces all three ports in a single window. When the React server misbehaves, the developer selects port 3000 and clicks Force Kill; the app terminates the node process and automatically refreshes the list. Later, the developer toggles a Watched Port flag for 5432; if the process dies, a macOS notification (or Windows toast) fires, allowing rapid remediation without switching terminals.

Code Health & Issues

Dependency reproducibility – bun.lock is present, so Node installs are reproducible. No Python lockfile or requirements.txt is visible, so the Python component (platforms/linux/) may require manual pinning of packages. CI coverage – Seven GitHub Actions workflows (.github/workflows/) cover Linux, Windows, and release publishing; builds are exercised on every push. Test suite – Five test files exist: platforms/linux/tests/testscanner.py, testk8s.py, and macOS XCTest‑style Swift tests (CloudflaredDiscoveryServiceTests.swift, PortFilterTests.swift, ProcessTypeTests.swift). Coverage is modest but present. Separation of concerns – The macOS codebase is heavily modular (managers, services, models, UI components). Linux code is more compact but follows a similar service pattern. Missing docs – No explicit configuration guide for Cloudflare credentials or Kubernetes kubeconfig path; users must supply these externally. No lockfile for Python – Potential non‑reproducible environments if the Python dependencies are installed via pip without a requirements.txt or pyproject.toml.

The Bottom Line

PortKiller delivers a unified, cross‑platform window for port monitoring, killing, Kubernetes forwarding, and Cloudflare tunnel status. The macOS Swift UI is polished and well‑structured; the Linux Python CLI is functional but lacks a dependency lockfile. It’s a solid daily‑driver for developers who frequently juggle multiple services and need quick, visual process control, especially on macOS. Teams that rely heavily on Kubernetes port‑forwards or Cloudflare Tunnels will appreciate the integrated view, while those needing strict reproducible Python environments may need to add a requirements.txt/pyproject.toml.
