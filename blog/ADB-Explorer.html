ADB Explorer

A fluent UI for ADB on Windows

Forked from Alex4SSB/ADB-Explorer

The Problem

ADB's command-line interface is functional but hostile for file management. Browsing device storage, transferring files, and editing on-device content requires memorizing commands and juggling multiple terminal windows. ADB-Explorer replaces that workflow with a Windows-native GUI, giving developers and power users a visual file manager for connected Android devices.

What This Does

ADB-Explorer is a WPF desktop application that wraps the ADB protocol in a Fluent-designed interface. The ADB Explorer/ folder contains the full application: Controls/ holds the UI components (file explorer, device list, terminal, settings), Helpers/ contains the ADB integration layer (AdbHelper.cs, DeviceHelper.cs, FileHelper.cs), and Models/ defines the data structures for devices and packages. The app supports file push/pull, archive extraction (ArchiveExtract.cs), trash operations (TrashHelper.cs), and QR pairing (QrGenerator.cs).

The project is a fork of Alex4SSB/ADB-Explorer (945 stars) and is published to the Microsoft Store. CI runs via GitHub Actions (.github/workflows/verify-release-visibility.yml), and the README references a Weblate translation project.

How To Use It

No build instructions, Dockerfile, or package manifest are present in the file listing, so the exact build command is not documented in the repo. The project is a Windows .slnx solution targeting WPF, so dotnet build or Visual Studio would be the expected path, but that is an inference. Setup: Download the installer from the Microsoft Store link in the README, or build from source using Visual Studio 2022+ with the .NET desktop workload. Configuration: App settings persist in %LocalAppData%\AdbExplorer\settings.json. The file can be edited manually but must preserve its JSON structure; an unrecognized entry is overwritten, and deleting the file resets defaults. Running it: Launch the installed app. The main entry point is App.xaml.cs, which initializes the WPF application. ADB platform-tools must be available on the system; the README links to an official versions list (OFFICIALADBVERSIONS.md).

Real-World Use

A developer debugging an app on a physical device can use ADB-Explorer instead of typing adb pull and adb push repeatedly. The GUI provides drag-and-drop file transfer, a built-in terminal for adb commands, and a package manager for install/uninstall. For a QA engineer testing multiple devices, the device list and battery status views (Models/Battery.cs) give a quick health check without shelling out.

The Bottom Line

ADB-Explorer is a mature, well-organized WPF application that solves a real pain point for Android developers on Windows. The lack of tests and a license are the main concerns for adoption. For individual developers and small teams who want a GUI for ADB file management, it is a solid choice; for enterprise use, the missing license and test coverage warrant caution.
