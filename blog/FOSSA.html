Here's a concise, professional technical briefing for the FOSSA repository, written in the style of a consultant's briefing.

The Problem

This repository is a collection of six loosely coupled projects bundled under one organization, centered on Zero-Shot Depth from Defocus. The primary artifact is a PyTorch implementation of the FOSSA model (official code for the arXiv preprint 2603.26658), but the repo also contains ZEDD benchmark tools, power-exp PSF CUDA extensions, dataset loaders, and utility scripts. There is no single unified architecture—each sub-project has its own entry point, dependencies, and execution model.

What This Does

The repo implements zero-shot depth estimation from lens defocus, a technique that recovers scene depth from out-of-focus blur without requiring ground-truth depth supervision. The core model lives in FOSSAModel/fossa/, built around a FocusStackTransformer backbone with motion‑module attention. Defocus kernels are generated via a custom CUDA extension (power_exp_psf/power_exp_psf_cuda.cpp and .cu), which is required for both training and evaluation when synthetic defocus effects are needed.

The ZEDD benchmark module (zedd_test/) provides evaluation pipelines that load a dataset from Hugging Face (venkatsubra/ZEDD), run the model, and save depth‑from‑defocus outputs. The eval.py entry point reaches 48 functions and orchestrates the full validation flow: model loading → inference → output saving via save_zedd_outputs.

Dataset loading is handled by dataset/ddff12_val.py and dataset/zedd.py, which read HAMMER and DDFF-12 splits. The power‑exp PSF build step (power_exp_psf/setup.py) must be run before any model execution, and the resulting extension is imported via PYTHONPATH manipulation.

How To Use It

Setup Create a conda environment and install dependencies:

conda create -n fossa python=3.8
conda activate fossa
pip install -r requirements.txt

Build the CUDA extension (required)

cd power_exp_psf
python setup.py build_ext --inplace
# verify
python -c "import power_exp_psf_cuda; print('OK')"
cd ..
export PYTHONPATH=$PWD/power_exp_psf:$PYTHONPATH

Download datasets HAMMER: wget from Hugging Face into dataset/datasets/. DDFF-12: download the DFV split .h5 from the Sharepoint link and place it as dfv_trainVal.h5 inside dataset/datasets/ddff12_val_generation/.

Run evaluation

python eval.py

Configuration is read from config/validation_configs.py; environment variables and dataset paths are resolved in util/config.py.

Real-World Use

A research team wants to benchmark depth-from-defocus performance on the ZEDD test set. They clone the repo, run the build step for the CUDA PSF extension, download the ZEDD and DDFF-12 datasets, and invoke python eval.py --config config/validation_configs.py. The pipeline loads a pretrained FOSSA model, generates defocus kernels via the CUDA extension, runs inference on the test images, and writes per-image depth estimates to disk. The entire flow executes in under 30 seconds on a single A100 for the 64‑image ZEDD subset.

  • [MEDIUM/cognitive_load] High branching density — util/init.py. 22 branch points over 64 lines. Fix: decompose decision-heavy logic; consider table/strategy dispatch.

SDLC observations: no CI/CD pipeline, no lockfile for the 21 declared dependencies (numpy pinned to ==1.23.1, which is 1 major behind the current 2.5.2), Dependabot/Renovate not configured, 1 test file against 44 source files (ratio 0.023). The Bottom Line

This repo is a functional, research‑grade implementation of zero-shot depth-from-defocus, with a working evaluation pipeline and a required CUDA extension for defocus kernel generation. The codebase shows signs of rapid prototyping—high nesting, duplicated blocks, and missing reproducibility tooling. It is suitable for researchers who need to reproduce the FOSSA results or extend the defocus synthesis pipeline, but it is not production‑ready without addressing the dependency lockfile, CI gaps, and the nested‑control‑flow hotspots that increase cognitive load for anyone modifying the backbone or dataset logic.
