odysseus

Self-hosted AI workspace.

Forked from arcahyadi/odysseus

The Problem

Organizations that need a private, self-hosted AI workspace often end up stitching together multiple tools—chat, email, document editing, research agents, model management—each with its own UI, auth, and data store. This creates integration overhead, security gaps, and a fragmented user experience. Existing open-source alternatives tend to focus on chat alone or require cloud dependencies.

What This Does

Odysseus provides a unified, Docker-based AI workspace that combines chat with local or API-hosted models, a cookbook for hardware-aware model recommendations (routes/cookbookroutes.py, services/hwfit/), deep multi-step research (routes/researchroutes.py), a document editor (routes/documentroutes.py), email via IMAP/SMTP (routes/emailroutes.py, routes/emailpollers.py), notes and tasks (routes/noteroutes.py, routes/taskroutes.py), calendar sync, and an MCP server framework (mcpservers/). The backend is Python/Flask (98 Python files), the frontend appears React-based (detected via analysis), and deployment is handled through docker-compose.yml with GPU support (docker-compose.gpu-nvidia.yml, docker-compose.gpu-amd.yml). Authentication, session management, and 2FA are built in (core/auth.py, core/sessionmanager.py). The project also ships CLI scripts (scripts/odysseus-*), GitHub Actions CI/CD (.github/workflows/), and integrations with Claude and Codex (integrations/).

Real-World Use

A research team can deploy Odysseus on a server with a local GPU. They use the cookbook to download a suitable model, then start a research session: the agent reads web sources, generates a report, and saves it as a document. Meanwhile, the same user triages email, checks calendar, and runs a scheduled agent task—all from one interface. The docker compose up -d --build command from the README brings up the entire stack, with the admin password printed in logs.

Code Health & Issues Low test coverage (1 test file across 200 source files) — a significant risk for a project of this scope. Many routes (routes/ has 54 files) are untested. CI hygiene is good: container scanning (container-trivy.yml), dependency review, secret scanning, and issue/PR description checks are configured. Dependencies are pinned (requirements.txt, package-lock.json, pyproject.toml). No obvious secrets in the repository. No structural red flags: license (AGPL-3.0), CODEOWNERS, CONTRIBUTING.md, SECURITY.md, THREATMODEL.md are present. The codebase is well-organized with clear separation of concerns (routes, services, core, integrations). Forked from a small project (25 stars); the current repo has 0 stars, so community and external review are minimal.

The Bottom Line

Odysseus is a feature-rich, well-structured self-hosted AI workspace that covers an unusually broad set of use cases. It is suitable for teams that want an all-in-one private AI environment and are comfortable contributing tests and hardening for production. The lack of test coverage and small community are the main concerns—this is a tool for early adopters, not a drop-in replacement for mature SaaS products.
