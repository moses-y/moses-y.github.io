Liam ERD – Technical Briefing

The Problem

Developers often need to understand and communicate complex database schemas. Manual diagramming is time‑consuming and error‑prone, especially when schemas evolve across branches or commits.

What This Does

liam is a React/Next.js application that renders interactive Entity‑Relationship diagrams directly from a database schema file. The core UI lives under frontend/apps/app/app/ (e.g., erd/p/[...slug]/erdViewer.tsx renders the diagram, while erd/p/[...slug]/page.tsx supplies routing). Schema parsing utilities such as frontend/apps/app/app/erd/p/[...slug]/utils/githubUrlHandler.ts convert repository URLs into fetchable schema sources. The project ships a CLI (@liam-hq/cli) for initializing private‑repo support, referenced in the README’s “Quick Start”.

How To Use It

Install dependencies – the repo uses pnpm (see .github/actions/pnpm-setup/action.yml). pnpm install Configure environment – three .env files are present in frontend/apps/app/: .env – default development values .env.local – local overrides (contains secrets in this fork – see Code Health below) .env.production – production settings

At minimum set NEXTPUBLICAPIURL and NEXTPUBLICSUPABASEKEY (names inferred from typical Next.js patterns; confirm in the files). Run the dev server – the Next.js entry point is the app directory; start it with: pnpm dev # runs next dev for the frontend Generate a diagram – for a public repo, edit the schema URL as shown in the README (prepend https://liambx.com/erd/p/). For a private repo, run the CLI: npx @liam-hq/cli init

The CLI writes the required tokens into the .env files. Access – open http://localhost:3000/erd/p/<owner>/<repo>/<branch>/ to view the interactive ER diagram.

Real‑World Use

A SaaS team can embed Liam ERD in their internal developer portal. When a new feature branch adds tables, the CI pipeline (.github/workflows/database-ci.yml) can trigger a schema export, push the file to the repo, and the portal automatically shows the updated diagram at the branch‑specific URL, giving designers and DBAs instant visual feedback without manual diagram updates.

Code Health & Issues

High – Secret leakage – .env, .env.local, and .env.production are tracked in the repo, exposing API keys and tokens. Immediate remediation: move these files to .gitignore and add a sample template (.env.template is already present). Med – Test coverage – only 8 test files exist for a 200‑file codebase. Critical paths (e.g., schema fetching, auth flow) lack unit tests, raising regression risk. Med – CI gaps – GitHub Actions include linting, CodeQL, and e2e tests, but the frontend-ci.yml workflow does not enforce a “build” step that compiles TypeScript; failures may surface only at runtime. Low – Documentation depth – README provides high‑level usage, but detailed API docs for internal services (services/getAuthUser.ts, services/getBranches.ts) are missing, which could impede onboarding. Low – License compliance – Apache‑2.0 license is declared, and a LICENSE file exists, satisfying legal requirements.

Overall the repository follows modern front‑end conventions (TypeScript, ESLint/Stylelint, Biome config) and the CI pipeline is reasonably comprehensive aside from the noted build step.

Bottom Line

Liam ERD delivers a functional, interactive ER diagramming front‑end built on React/Next.js, with solid CI scaffolding. The primary blocker is the accidental commit of environment secrets; removing them and improving test coverage are the most urgent actions. The solution is well‑suited for teams that already host schemas in Git and need quick visual validation across branches.
