Jarvis AI Assistant - Voice-powered AI assistant for Mac

Forked from akshayaggarwal99/jarvis-ai-assistant

The Problem Professionals who need fast, accurate dictation on macOS must either pay for a cloud service (privacy‑risk, recurring cost) or use a heavyweight desktop app that is difficult to customise. Jarvis aims to replace that niche with a locally‑runnable, open‑source voice assistant that can capture text from any window with a single key‑press.

What This Does Jarvis is a macOS‑focused Electron‑React application that listens for a configurable hot‑key (default Fn), records audio, runs it through a speech‑to‑text engine, and injects the cleaned result into the active app. The core pipeline lives in src/:

Audio capture – native modules in src/audio/ (fast-audio-recorder.ts, native-audio-recorder.ts) and the C++ addon packages/whisper-addon/src/addon.cpp. Transcription – src/input/transcription/transcription-manager.ts selects either the local Whisper model (via the addon) or a cloud provider (Deepgram) defined in src/core/providers/. Post‑processing – src/input/assistant-processor.ts and src/input/processors/command-processor.ts apply filler removal, punctuation, and optional LLM‑based re‑phrasing (Ollama or Gemini).

The UI (src/App.tsx, src/components/) displays status, settings, and a dashboard (src/components/dashboard/). Platform‑specific code for macOS menubar integration lives in ios/ (Swift) and the native build scripts under build/.

How To Use It

Setup Clone the repo git clone https://github.com/your‑fork/jarvis-ai-assistant.git cd jarjar‑ai‑assistant

Install Node dependencies npm ci

Build the native Whisper addon (requires CMake, a C++ compiler, and the system‑wide ffmpeg binary) cd packages/whisper-addon npm ci npm run build # defined in packages/whisper-addon/package.json; invokes CMake via the Makefile in /build cd ../..

The presence of package-lock.json, npm ci, and a CMakeLists.txt in packages/whisper-addon confirms these commands.

Configuration API keys for Deepgram and Gemini are read from environment variables referenced in src/config/env.ts. Set them before launching, e.g.:

export DEEPGRAMAPIKEY=yourkey export GEMINIAPIKEY=yourkey

Model selection (Whisper size, Ollama model) is stored in the user defaults UI; no additional config files are required.

Running npm start # launches the Electron main process, which loads src/index.tsx → src/App.tsx

The app registers the hot‑key, shows a menubar icon, and is ready to accept voice input.

Real‑World Use A sales professional can press Fn, dictate a follow‑up email, and have Jarvis automatically remove filler words, correct grammar, and insert the result into Outlook. The workflow is:

// inside src/input/assistant-processor.ts const cleaned = await transcriptionManager.transcribe(audioChunk); const final = await llmService.enhance(cleaned, {model: 'ollama'}); outputManager.insertIntoActiveApp(final);

The same pipeline can be repurposed for ticket creation, code comments, or short‑form reports.

Code Health & Issues

Missing CI/CD – Med – No .github/workflows or other CI config; automated testing is not gated. Sparse test coverage – Med – Only three test files (.test.ts) are present; core audio and IPC pathways lack tests. Native build fragility – High – The Whisper addon depends on a local C++ toolchain and ffmpeg binaries (assets/ffmpeg). Failure to match the host architecture will break the build. Hard‑coded hot‑key – Low – The Fn key is registered in src/input/fn-key-monitor.ts without a user‑configurable fallback. License present – Low – MIT license is included, satisfying open‑source compliance. Documentation – Low – README covers UI usage but lacks developer‑orientation docs (e.g., how to add a new LLM provider).

The Bottom Line Jarvis delivers a functional, locally‑run dictation assistant with a clear separation between audio capture, transcription, and LLM post‑processing. It is a solid fit for solo developers or small teams that value privacy and are comfortable managing native build dependencies. The main drawbacks are limited automated testing and the need for a manual native‑module build, which may hinder adoption in larger, CI‑driven organisations.
