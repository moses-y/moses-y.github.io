easy agent

Fully recreating Claude Code from scratch, so anyone can learn how it works.

Forked from ConardLi/easy-agent

The Problem

Building a Claude Code-style terminal coding agent from scratch is a large, multi-system project: model streaming, tool execution, permission control, session management, MCP, plugins, and a terminal UI all have to work together. Most existing implementations are either closed-source or too tangled to learn from. Easy Agent exists to make that architecture readable and teachable.

What This Does

Easy Agent is a TypeScript/Node.js terminal-native coding agent that recreates Claude Code's workflow in a modular codebase. It implements the full pipeline: streaming model conversations (src/services/api/streaming.ts), local file and shell tools (src/tools/bashTool.ts), permission modes (src/permissions/permissions.ts), session persistence (src/session/storage.ts), MCP support (src/services/mcp/), skills (src/services/skills/), sub-agents (src/agents/), and a React/Ink UI (src/ui/).

The repo is organized as a 37-stage roadmap. Each stage has a self-contained snapshot in step/ (e.g., step/step4.js is the core agentic loop, step/step8.js is the QueryEngine), so you can follow the system's evolution from a single model call to a full agent. The src/ tree is the consolidated implementation of those stages.

How It Is Wired

Control flows through src/entrypoint/cli.ts, which boots the app and routes into the core orchestration. The two highest-blast-radius modules are src/tools/Tool.ts (53 modules depend on it, 1 import) and src/core/queryEngine.ts (12 dependents, 42 imports, instability 0.78). queryEngine.ts is the multi-turn orchestration hub; any change there ripples across the agent loop, permissions, and tool dispatch.

The import graph shows 23 modules in circular dependencies, including src/tools/index.ts. That cycle costs a reader trying to trace control flow: you cannot follow a linear path from entry to tool execution without circling back. src/core/queryEngine.ts is also 959 lines, which makes localized changes hard to isolate.

The system's entry points are src/agents/builtIn/index.ts, src/entrypoint/cli.ts, src/hooks/index.ts, src/plugins/index.ts, and src/sandbox/index.ts. The step/ directory is the teaching path; src/ is the production code.

How To Use It

git clone https://github.com/moses-y/easy-agent cd easy-agent npm install npm run build

The CLI entry point is src/entrypoint/cli.ts. The README states the package is at Stage 36 release candidate, with eagent pending first npm publication. Configuration lives in src/config/schema.ts and src/config/sources.ts; no environment variables are documented in the repo. The scripts/ directory contains verification scripts (e.g., scripts/verify-auto-mode.ts) that exercise specific subsystems.

Real-World Use

A developer learning how a production-grade agent is built would trace the 37-stage step/ snapshots, then inspect the consolidated src/ tree to see how the pieces compose. A team wanting a self-hosted, terminal-native coding agent with permission modes and MCP support could run this directly, though it is not yet published to npm.

The Bottom Line

This is a serious, well-structured educational codebase with real production features—MCP, sandboxing, multi-agent teams—organized so a reader can follow the build order. The main risks are the hub modules and import cycles that make changes ripple widely, and the absence of any test suite. Use it to learn how Claude Code works or as a foundation for a self-hosted agent; don't treat it as a drop-in production tool until it is published and tested.
