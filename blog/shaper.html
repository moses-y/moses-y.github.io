shaper

Visualize and share your data. All in SQL. Powered by DuckDB.

Forked from taleshape-com/shaper

The Problem

Teams building internal dashboards often face a choice between slow, drag-and-drop BI tools or hand-rolled frontend apps that require significant engineering effort. Shaper targets that gap by letting analysts define dashboards entirely in SQL, with the visualization layer inferred from query annotations rather than configured through a GUI.

What This Does

Shaper is a self-hosted dashboard server with a Go backend (server/) and a React/TypeScript frontend (ui/). The core idea is that you write SQL with special type casts—::BARCHARTSTACKED, ::XAXIS, ::CATEGORY—and Shaper renders the result as a chart. The SQL layer runs on DuckDB, with support for multiple data sources. Key capabilities include scheduled tasks (server/core/scheduletask.go), PDF/PNG/CSV/Excel export (server/pdf/), JWT-based row-level security, and embeddable dashboards via a JS/React SDK (npm-package/).

The repo is well-structured: server/core/ holds domain logic, server/web/handler/ contains HTTP handlers, and server/dev/ provides a developer CLI for local workflows. The UI uses TanStack Router (evident from routeTree.gen.ts) and includes a full set of chart components (ui/src/components/charts/). A pip-package/ directory provides Python bindings, and the Dockerfile enables containerized deployment.

How To Use It

Setup: The quickest path is Docker: docker run --rm -it -p5454:5454 taleshape/shaper

Then open http://localhost:5454/new in your browser.

Configuration: The server stores state in a local database and supports S3 for snapshots (server/snapshots/s3.go). Authentication is JWT-based (server/core/auth.go). The README references a deployment guide but doesn't document specific environment variables in the repo—you'd need to consult the external docs at taleshape.com/shaper/docs/deploy-to-production/.

Running it: For development, the server/dev/ package exposes a CLI (server/dev/dev.go) for local workflows. The npm package (npm-package/index.js) provides a JS SDK for embedding dashboards. The Python package (pip-package/shaperpkg/cli.py) offers a CLI for Python users.

Real-World Use

A common scenario: a data team maintains a DuckDB warehouse and wants to publish weekly sales reports without building a custom frontend. They write SQL queries with chart annotations, schedule them via server/core/scheduletask.go to generate PDFs, and share password-protected links (server/web/handler/keys.go). For external customers, they embed dashboards in their product using the React SDK with JWT-scoped row-level security.

Code Health & Issues Med - Monorepo complexity - The repo mixes a Go server, React UI, npm package, and Python package in one tree. The root package.json and package-lock.json suggest Node tooling at the root, but the primary server is Go—this dual-toolchain setup could confuse contributors. Med - External docs dependency - The README points to taleshape.com for setup, deployment, and getting-started guides. If those pages change or go down, the repo becomes harder to onboard into. Low - Test coverage is uneven - Tests exist for core logic (server/core/test.go) and some handlers (server/web/handler/test.go), but the UI layer has no test files. The CI workflow (.github/workflows/ci.yml) presumably runs the Go tests. Low - Commercial tie-in - The README prominently promotes managed hosting through Taleshape. That's fine for sustainability, but it means the open-source repo may not receive the same attention as the commercial offering.

The Bottom Line

Shaper is a legitimate, well-architected open-source tool for SQL-first dashboarding. The Go backend is cleanly separated, the DuckDB integration is pragmatic, and the embedding story is solid. It's best suited for teams already comfortable writing SQL and wanting to avoid a full BI platform. The main caveat is that setup and configuration details live outside the repo, so plan to consult the external docs.
