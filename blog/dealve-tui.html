The Problem

Finding the best price for a PC game typically means checking multiple storefronts manually—Steam, GOG, Epic, Humble—then cross-referencing historical price data to judge whether a "deal" is actually good. That's tedious and error-prone. dealve-tui consolidates this into a single terminal interface backed by IsThereAnyDeal's price-tracking API.

What This Does

dealve-tui is a Rust workspace with three crates: core/ (shared domain models and error types), api/ (IsThereAnyDeal API client), and tui/ (the Ratatui-based terminal application). The tui/src/main.rs entry point boots the app, while tui/src/onboarding.rs handles first-run setup for the API key. The UI layer in tui/src/view/ provides a deals list, game details pane, and a price-history chart.

The API client in api/src/client.rs handles authentication and requests, with endpoints defined in api/src/endpoints.rs. Configuration lands in ~/.config/dealve/config.json, managed by tui/src/config.rs.

How To Use It

Setup: Rust 1.70+ is required. Install from crates.io or build from source:

cargo install --locked dealve-tui

Or clone and build:

git clone https://github.com/kurama/dealve-tui cd dealve-tui cargo install --locked --path tui

Configuration: You need a free IsThereAnyDeal API key, obtainable from their site. The first launch walks you through setup interactively. The repo includes .env.example at the root for reference, but the actual config is stored in ~/.config/dealve/config.json after onboarding.

Running it:

dealve

Real-World Use

A gamer who wants to buy a specific title can launch dealve, search for the game, and see current prices across Steam, GOG, Epic, and Humble Bundle in one view, with historical price data to determine if the current price is genuinely low. The pricechart.rs view renders that history graphically in the terminal. For someone tracking multiple wishlist titles, the deals list view provides a single scan surface—no browser tabs required.

Code Health & Issues

The repo shows solid hygiene: dual MIT/Apache licensing, a CI pipeline (.github/workflows/ includes build, lint, test, and release jobs), a PR template, and issue templates. A Cargo.lock is present, and .pre-commit-config.yaml suggests linting discipline. Med - No visible integration tests for the API client - api/ has only an example (api/examples/testconnection.rs), and the 2 test files likely cover core logic only. The API layer handles network I/O, auth, and parsing; that's where regressions hurt most. Med - No rate-limit handling visible in the API client - IsThereAnyDeal has rate limits; without explicit handling in api/src/client.rs, users hitting limits will get opaque failures. Low - Error handling in the TUI layer - tui/src/update.rs and tui/src/tasks.rs handle async work; the error paths there could be thin, but there's no evidence of panics or unwraps from the structure alone. Low - Single maintainer risk - forked from a 243-star project; verify the fork is actively maintained before depending on it.

The Bottom Line

A well-structured Rust TUI that solves a real problem for terminal-centric gamers. The three-crate separation is clean, CI is solid, and the onboarding flow lowers the setup barrier. It's a niche tool—if you live in the terminal and buy PC games, it's worth installing. If you're not a terminal user or not a PC gamer, it has nothing for you.
