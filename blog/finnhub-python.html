The Problem

Developers building financial applications need programmatic access to market data—stock quotes, fundamentals, earnings, news, and technical indicators—without maintaining raw HTTP integrations. Finnhub's REST API covers this domain, but raw API calls require handling authentication, pagination, and endpoint-specific quirks. A maintained client library removes that boilerplate.

What This Does

finnhub-python is an official Python client for the Finnhub API. The core logic lives in finnhub/client.py, which exposes a Client class with methods mapped to API endpoints—stockcandles(), companyprofile2(), quote(), earningscalendar(), and roughly 40 others. finnhub/exceptions.py defines API error types, and finnhub/init.py exports the package surface.

The repo is a fork of the upstream project (1,063 stars) with 19 files total. It's generated partly by OpenAPI tooling (.openapi-generator/), but the client itself is hand-maintained. setup.py and setup.cfg handle packaging; requirements.txt lists runtime dependencies; tox.ini and .travis.yml define test and CI configuration. The README documents every client method with a runnable example.

How To Use It

Setup: Install via pip. The README documents pip install finnhub-python; for local development, pip install -e . from the repo root works given setup.py is present.

Configuration: You need a Finnhub API key. There's no config file—pass it directly to the client constructor: finnhub.Client(apikey="YOUR API KEY"). The free tier has rate limits; paid tiers expand access.

Running it: The library is used as an imported module, not a standalone service. examples.py in the repo root is the reference script—it demonstrates every endpoint. A minimal invocation:

import finnhub client = finnhub.Client(apikey="YOUR API KEY") print(client.quote('AAPL'))

Real-World Use

A portfolio-tracking service that ingests daily price data and corporate actions could use this client as its data layer. The stockcandles() method fetches OHLCV series for backtesting; companyearnings() and stockdividends() feed fundamental screens. Since the client returns plain dicts, results drop directly into pandas DataFrames or a database.

Code Health & Issues

Low - No lockfile: requirements.txt declares dependencies without pinned versions, so builds are non-reproducible. pip freeze output would pin them, but it's not committed. Low - Single test file: One test file exists but the repo gives no evidence of test coverage depth or whether tests run in CI (.travis.yml is present but unverified). Low - Generated-code smell: The .openapi-generator/ directory and gitpush.sh suggest partial codegen; manually maintained client code alongside generated artifacts can drift over time. Low - No explicit Python version support: setup.py likely declares pythonrequires, but the analysis doesn't confirm it. Python 2 support was dropped upstream, but verify before adopting. Med - API key handling: The README shows hardcoding the key in source. Production users must inject it via environment variables or a secrets manager—the library doesn't enforce this.

The codebase is otherwise clean: a clear module layout, documented public API, and a comprehensive README.

The Bottom Line

A solid, well-documented client for Finnhub's API—appropriate for production use if you pin dependencies and manage your API key properly. The fork adds no visible changes over upstream, so most teams should depend on the PyPI package directly rather than this repo. Best suited to Python-based fintech applications needing quick, maintained access to market data.
