ForgeCAD

Multi-backend code-first parametric CAD in JavaScript/TypeScript with live params, constraints, assemblies, and exact STEP/BREP export.

Forked from ForgeCAD/forgecad-public-kit

The Problem

Traditional CAD tools lock geometry inside binary files, making version control, automation, and AI integration difficult. Parametric models require proprietary scripting languages or clunky constraint UIs. Engineers who want to treat CAD as code—with diffs, CI, and generative design—are forced into awkward workflows.

What This Does

ForgeCAD is a code-first parametric CAD system for JavaScript/TypeScript. Models are plain .forge.js files that run in the browser or CLI. The API is globally available—no imports needed—and param() creates live sliders in the UI. It uses a multi-backend architecture: Manifold for interactive preview, CadQuery/OpenCascade for exact STEP/BREP export. The examples/api/ folder shows core patterns: constrained sketches (constrained-sketch-basics.forge.js), assemblies (assembly-gear-coupling.forge.js), and export (brep-exportable.forge.js). Benchmarks in examples/bench/ and examples/bench-v2/ evaluate how well LLMs generate ForgeCAD code.

Real-World Use

An engineer designs a parametric bracket with adjustable width, depth, and height. They define param("Width", 120, { min: 60, max: 220, unit: "mm" }), build geometry with roundedRect().extrude(), add a pocket, and export STEP for CAM. The script lives in Git, gets reviewed in PRs, and regenerates on branch updates. No binary files, no GUI lock-in.

Code Health & Issues

The repo is structurally clean: MIT license, CI (3 workflows), 10 tests, and a lockfile. No obvious red flags. However, the core engine is developed in a private repository—this is a community mirror with examples, benchmarks, and docs. The 10 tests are likely benchmark harnesses, not unit tests for the API surface. Error handling patterns are not visible in the examples. The heavy reliance on examples/ (187 files) as documentation means users must infer API behavior from code snippets. For a production evaluation, you would need access to the private engine repo.

The Bottom Line

ForgeCAD is a well-architected code-first CAD system that genuinely solves the "CAD as code" problem. The multi-backend approach (fast preview + exact export) is pragmatic. It’s best for teams that already use Git, CI, and parametric workflows. If you need a GUI-first CAD or a fully open-source engine, this isn’t it—but if you want to treat CAD models like software, ForgeCAD is a credible option.
