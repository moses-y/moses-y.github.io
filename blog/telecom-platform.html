The Problem

Enterprises that need private 5G/LTE networks must stitch together a core network, subscriber provisioning, charging, and API exposure. Existing vendor stacks are either monolithic, locked‑in, or lack programmatic control, forcing teams to build and maintain many disparate components.

What This Does

The Telecom‑as‑a‑Service (TaaS) Platform delivers a Go‑centric micro‑service stack that implements BSS functions, eSIM ES2 integration, and real‑time charging.

The API surface lives in apps/api-server/cmd/server.go and related files (serverdeps.go, servermetrics.go, serverroutes.go). These launch the HTTP server, register routes, and wire middleware such as JWT auth (internal/middleware/auth.go) and rate‑limit (internal/middleware/ratelimit.go). Carrier‑specific ES2 handling is in apps/carrier-connector/internal/handlers/ and the ES2 client (apps/carrier-connector/internal/es2/client.go). Billing logic resides under apps/api-server/internal/payment/ and uses Redis‑backed rate limiting (internal/middleware/redisratelimit.go). Service discovery, MQ, and caching are abstracted in internal/discovery/, internal/mq/, and internal/cache/, respectively, matching the architecture described in the README.

How To Use It

Setup

Install Go (>=1.26) and Rust (>=1.95) as required by the repo git clone https://github.com/yourorg/telecom-platform.git cd telecom-platform

Pull Go module dependencies

go mod tidy # root go.mod (if any) cd apps/api-server && go mod tidy cd ../carrier-connector && go mod tidy

Build the API server (Makefile defines a build target) make build # invokes go build -o bin/api-server ./apps/api-server/cmd

If the Makefile lacks a build target, run: go build -o bin/api-server ./apps/api-server/cmd

Configuration

Copy the example env file and edit per your deployment:

cp apps/api-server/.env.example apps/api-server/.env Required keys (as shown in .env.example): DATABASEURL, REDISURL, JWTSECRET, TRAEFIKENDPOINT, VAULTADDR, etc.

The carrier connector reads static JSON files (apps/carrier-connector/configs/carriers.json, currencies.json). Adjust them to match the carriers you intend to support.

Running

From the repository root ./bin/api-server # starts the API server on the port defined in .env Or, for development with hot reload: cd apps/api-server && air # if you add the air tool; not bundled

The server registers routes under /api/v1/ as defined in internal/handlers/. Swagger UI is served from apps/api-server/docs/swagger.yaml via the built‑in route.

Real‑World Use

A manufacturing plant installs the platform on a private edge node. After provisioning the API server, an automation script creates a subscriber:

// Go client snippet client := NewAPIClient("https://api.telecom.com", "my-jwt-token") sub, err := client.CreateSubscriber(context.Background(), Subscriber{ IMSI: "001010000000001", Name: "RobotArm-01", PlanID: "plan-basic", })

The subscriber is then provisioned on the eSIM carrier via the carrier‑connector service, and usage events flow through the charging engine for real‑time billing.

Code Health & Issues

Low – Missing Dockerfile – No container build instructions; deployment must be scripted manually. Medium – Incomplete Rust integration – Cargo.toml is present but no Rust source files; build will fail without additional code. Low – Environment coupling – .env.example lists many variables; missing validation in internal/config/config.go could cause runtime panics if unset. Low – Test coverage gaps – 14 test files exist, but core payment gateway (gatewaystripe.go) lacks unit tests. Low – CI configuration – GitHub Actions workflow (.github/workflows/ci.yml) runs go test ./...; no static analysis (e.g., golangci-lint) enforced. Low – License present – LICENSE file included, satisfying legal requirements.

Overall the repository follows Go module conventions, includes a CI pipeline, and provides a reasonable test suite for many handlers. The main risk is the unfinished Rust component and reliance on manual environment setup.

The Bottom Line

The TaaS platform offers a solid, Go‑based foundation for private cellular network BSS and eSIM integration, with clear module boundaries and CI support. It is ready for teams comfortable managing Go services and external dependencies, but will require additional work to complete the Rust packet‑gateway piece and to containerize the stack for production‑grade deployments.
