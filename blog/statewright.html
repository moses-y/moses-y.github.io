The Problem

AI agents with unrestricted tool access repeatedly fail in predictable ways: re-reading files, editing during review, deploying before tests pass. The standard fix—bigger models or longer prompts—helps inconsistently. Post-hoc observability tells you what went wrong; it doesn't prevent it.

What This Does

Statewright enforces a state machine over agent tool access. Each phase (planning, implementing, testing) exposes only the tools relevant to that step. Call a disallowed tool and the system rejects the call and tells you what's available and how to transition. The core engine in crates/engine/src/ handles state transitions, guards, and validation with no LLM dependency—it's deterministic Rust. The agent binary in crates/cli/src/ wraps an Ollama client loop that enforces these constraints at runtime.

The MCP gateway in crates/mcp-gateway/src/ intercepts tool calls at the protocol level, classifying requests (bash, edit, read) and blocking disallowed operations before they reach the model. The crates/agent/src/toolenforcer.rs and crates/agent/src/validator.rs files handle the per-phase tool filtering. Plugins for Claude Code (plugins/claude-code/), Codex (plugins/codex/), and Cursor (plugins/cursor/) let you drop this into existing workflows.

Real-World Use

Start a bugfix workflow in Claude Code via /statewright start bugfix. The agent enters planning with read-only tools, transitions to implementing when ready (edit tools unlock), then to testing (only test commands permitted). A 46-second workflow from start to completion is documented in the README. The crates/cli/fixtures/ directory contains test scenarios including a buggy calculator, pytest issues, and sympy bugs used for evaluation.

Code Health & Issues

Medium - The crates/mcp-gateway/src/bashclassifier.rs classifies bash commands by intent. This is inherently heuristic and likely has false positives/negatives for edge-case shell commands. No fuzz testing visible. Low - Experiment results in experiments/pi-context-ablation/ reference a 5-task SWE-bench subset, not the full benchmark. The README is transparent about this, but the numbers are easy to misinterpret. Low - The docs/outreach/techpoint-xtern-june-2026/ directory contains a full Node.js application with its own package.json and tests, mixed into the Rust codebase. This increases cognitive load for contributors. CI is configured (.github/workflows/ci.yml), tests exist (21 test files), and a license is present. No structural red flags.

The Bottom Line

Statewright addresses a real, specific problem—agent tool misuse—with a simple, testable mechanism. The architecture is clean: a deterministic Rust engine, language-agnostic MCP gateway, and editor-specific plugins. It's most valuable for teams running agents on production codebases where uncontrolled tool access is a liability. The 13GB model floor is an honest limitation worth noting before adoption.
