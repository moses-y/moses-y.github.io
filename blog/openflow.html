OpenFlow — open-source, local-first voice dictation (Wispr Flow alternative). Fork of Handy (MIT).

Forked from avijeett007/openflow

The Problem

Voice dictation tools like Wispr Flow require cloud processing, sending audio to remote servers. This creates privacy risk, latency, and dependency on a third-party provider. Existing local alternatives often lack polished UX, cross-platform support, or the ability to mix local and remote backends for different processing stages.

What This Does

OpenFlow is a Tauri 2 desktop app (macOS + Windows) that captures microphone audio, runs speech-to-text, and optionally applies AI cleanup before pasting the result into the focused application. The core audio pipeline lives in src-tauri/src/audiotoolkit/ — a Rust module handling recording, VAD (Silero V4), resampling, and visualization. The src-tauri/src/backends/ directory defines the STT backend abstraction, with stthttp.rs handling remote/self-hosted endpoints.

The app supports three backend modes (local, self-hosted, remote) set independently for STT and cleanup, a wake-word mode, per-app AI cleanup tone via prompt overrides, and a local analytics dashboard (src-tauri/src/commands/analytics.rs). API keys are stored in the OS keychain, not config files.

Real-World Use

A developer who wants privacy for internal conversations can run STT locally via a small on-device model while routing cleanup through a self-hosted OpenAI-compatible endpoint. The catalog/catalog.json file defines available models and endpoints. The app's per-app tone feature means code review comments get different cleanup prompts than Slack messages.

Code Health & Issues

The repo is structurally sound — CI configured (GitHub Actions), tests present (3 test files), license file (MIT), and lockfiles for both Cargo and Bun. No obvious secrets in the repo. Low - Unsigned builds on macOS require users to run xattr commands or right-click to bypass Gatekeeper. Documented in README but creates friction for non-technical users. Low - The backends/stt_http.rs file handles remote endpoints but error handling for network failures during dictation isn't visible from structure alone — mid-utterance failures could lose audio. Low - 43 Rust files with 3 test files suggests limited test coverage relative to codebase size, particularly for the audio pipeline and VAD logic.

The Bottom Line

A well-structured, privacy-first dictation tool that gives users genuine control over where transcription and cleanup run. The Tauri + Rust foundation is solid, and the per-app tone feature is genuinely useful. Best suited for developers and technical users who want local-first voice input without sacrificing flexibility — not polished enough for enterprise deployment, but production-quality for personal or small-team use.
