MIA

Memory Intelligence Agent

Forked from ECNU-SII/MIA

The Problem Deep‑research agents quickly run out of context window or waste compute on irrelevant past observations. Existing pipelines store every interaction verbatim, forcing the executor to sift through bloated memory and leading to poor reasoning on long‑form tasks.

What This Does MIA implements a Manager‑Planner‑Executor loop that curates a non‑parametric memory store, learns retrieval strategies at test time, and hands compact, task‑focused prompts to the executor.

The core library lives under Executor-Train/Train/verl/. Key modules include: manager‑like logic in verl/interactions/ (e.g., gsm8kinteraction.py, weatherinteraction.py). Planning and continual test‑time learning in verl/experimental/agentloop/ (agentloop.py, toolagentloop.py). Model merging and distributed training utilities in verl/modelmerger/ (fsdpmodelmerger.py, megatronmodelmerger.py).

Model definitions for LLaMA, Qwen2, and multi‑modal variants are under verl/models/ with Megatron‑style parallel layers (parallelattention.py, parallelmlp.py).

Training scripts and configuration live in verl/trainer/ with YAML files such as generatedppotrainer.yaml and ppotrainer.yaml. The entry point for training is verl/trainer/mainppo.py; for evaluation, verl/trainer/maineval.py.

How To Use It

Setup cd Executor-Train/Train bash install.sh # installs required packages, sets up torch distributed env python -m pip install -e . # editable install registers the verl package

install.sh pulls in dependencies listed in setup.py (PyTorch, transformers, etc.).

Configuration Training hyper‑parameters are in verl/trainer/config/ppotrainer.yaml. Model‑specific configs live under verl/models//megatron/ (e.g., llama/megatron/checkpointutils/llamaloader.py). Runtime environment is described by verl/trainer/runtimeenv.yaml.

Edit the YAML files to point to your data paths, checkpoint directories, and compute resources (e.g., FSDP or Megatron engine settings).

Running Training (PPO) python -m verl.trainer.mainppo \ --config verl/trainer/config/ppotrainer.yaml \ --outputdir /path/to/checkpoints

Evaluation python -m verl.trainer.maineval \ --config verl/trainer/config/evaluation.yaml \ --modeldir /path/to/checkpoint Model merging (if using multiple checkpoints) python -m verl.modelmerger \ --config verl/trainer/config/model/hfmodel.yaml \ --output mergedmodel.pt

The main.py in verl/modelmerger/ exposes a CLI that reads the same YAML schema used by the trainer.

Real‑World Use A research lab can plug MIA into an autonomous literature‑review pipeline. The manager stores extracted citation snippets, the planner refines a retrieval policy based on recent evaluation reward signals, and the executor generates a draft summary. Example:

from verl.experimental.agentloop.toolagentloop import ToolAgentLoop loop = ToolAgentLoop(planconfig="configs/mmsearchtoolconfig.yaml") summary = loop.run(query="latest advances in quantum error correction") print(summary)

The loop automatically pulls relevant memory entries, updates its retrieval policy, and produces a concise report.

The Bottom Line MIA provides a full‑stack framework for memory‑augmented agents, with concrete training/evaluation pipelines and support for large‑scale Megatron/FSDP models. It is best suited for teams that already operate distributed GPU clusters and can invest in adding tests and CI. For solo developers or production‑grade deployments, the lack of test coverage, CI, and a proper license file are significant gaps to address before adoption.
