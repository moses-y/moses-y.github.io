The Problem The README describes Ordinus as a "local-first desktop app that lets you compose AI agents from your own Codex / Claude CLIs into scheduled workflows — all your data stays on your machine." The pain point it addresses is the fragmentation of AI agent workflows — users need to manually compose roles, manage conversations, and wire tasks into scheduled workflows across different AI CLIs, without a unified local interface. There's no existing local command center that orchestrates multiple AI agents with persistent conversation spaces, workboards, and scheduled execution while keeping data entirely on-premises.

What This Does Ordinus is a 200-file Electron desktop application (app/ directory) that provides a local-first command center for AI agent workflows. The app consists of three core UI components: Agents (composable roles with profiles and conversation spaces), Workflow Designer (a DAG-based visual editor that compiles to runnable plans), and Workboard (runtime task monitoring and steering). Agent definitions and skills live in .claude/skills/ and .codex/skills/ directories, each with SKILL.md files and openai.yaml configuration. The application persists data via SQLite, with 50+ migration files in app/resources/db/migrations/ indicating a evolving schema for workspaces, conversations, and agent memory. Connections integrate with external services—Google (Gmail/Calendar/Drive), WhatsApp, and X/Twitter—all running under the user's own account with encrypted credential storage on the local machine.

How To Use It Setup: The project uses npm as package manager (evidenced by app/package.json and app/package-lock.json). Install dependencies with: npm install

The Electron app is built with Vite (app/electron.vite.config.ts) and Electron Builder (app/electron-builder.yml). For local development, run npm run dev or open the app via the Electron main process.

Configuration: No .env file is present in the root, but Google MCP integration lives in app/resources/google-mcp/ with its own package.json and server.mjs. The README indicates the app connects to user accounts (Google, WhatsApp, X) with credentials stored encrypted on the machine. No API keys are required in the repo—connections operate under the user's existing accounts. The .env or environment configuration file is not evident from the structure; the app likely reads credentials from the OS keychain or encrypted local storage upon first connection.

Running it: The entry point is the Electron application built from app/. For macOS, after installing the unsigned DMG, strip the quarantine attribute: xattr -dr com.apple.quarantine /Applications/Ordinus.app open /Applications/Ordinus.app

On Windows, run the installer and launch from the Start Menu. No CLI startup command is documented beyond launching the GUI; the app's main process starts automatically on launch.

Real-World Use A knowledge worker could define an "Article Writer" agent using a skill template from .claude/skills/, configure it to pull research from a Google Drive folder via the Google connection, and wire it into a workflow DAG with a "Code Reviewer" agent in the Workflow Designer. The compiled plan executes on the local runtime, with the Workboard showing provider output in real time. For example, a scheduled workflow could run nightly: the Article Writer agent fetches source material from Google Docs, composes an article, and posts a summary to a Slack channel via webhook—all without data leaving the machine.
