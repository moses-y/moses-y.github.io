NexusRAG

Abstract

Hybrid RAG system combining vector search, knowledge graph (LightRAG), and cross-encoder reranking — with Docling document parsing, visual intelligence (image/table captioning), agentic streaming chat, and inline citations. Powered by Gemini or local Ollama models.

The Problem

Enterprise knowledge bases often collapse after ingestion: PDFs lose layout, images and tables disappear, and retrieved answers lack provenance. Teams that need accurate citations, visual context, and multi‑modal retrieval end up stitching together separate tools, which introduces latency and maintenance overhead.

What This Does

NexusRAG delivers a single pipeline that preserves document structure, extracts visual assets, builds a lightweight knowledge graph (LightRAG), and ranks results with a cross‑encoder. The backend lives in backend/app/ (FastAPI entry point backend/app/main.py) and the UI in frontend/src/. Core services include:

backend/app/services/documentparser/doclingparser.py and markerparser.py – parse PDFs/Docs while keeping headings, page numbers, and images. backend/app/services/vectorstore.py – stores BGE‑M3 embeddings for fast ANN search. backend/app/services/knowledgegraphservice.py – builds the LightRAG entity graph. backend/app/services/reranker.py – cross‑encoder re‑ranking. frontend/src/components/rag/ChatPanel.tsx – streaming, agentic chat with inline citations.

The widest blast radius lies in the three “oversized” modules (ChatPanel.tsx, backend/app/api/chatagent.py, backend/app/api/rag.py – each >1 600 lines) because they house routing, orchestration, and UI logic; changes ripple across both API and front‑end.

How It Is Wired

Startup – docker-compose.yml brings up three containers: backend (built from Dockerfile.backend), frontend (from Dockerfile.frontend), and an optional mcp-server. Request flow – The UI calls frontend/src/lib/api.ts, which hits FastAPI routes defined in backend/app/api/router.py. /chat → backend/app/api/chatagent.py → backend/app/services/nexusragservice.py → document retrieval (ragservice.py → vectorstore.py, knowledgegraphservice.py) reranking (reranker.py) LLM generation (services/llm/.py). Citation stitching – backend/app/services/ragservice.py attaches 4‑char IDs derived from ParsedDocument metadata; the front‑end renders them via MemoizedMarkdown.tsx. State – Global stores (ragPanelStore.ts, workspaceStore.ts) keep chat history and selected workspace, feeding back into API calls.

No circular imports were detected (0 cycles), and the import graph contains 102 internal modules with 18 edges, confirming a relatively flat dependency tree.

How To Use It

Clone the repo git clone https://github.com/moses-y/NexusRAG.git cd NexusRAG Create a .env from the example (adjust keys for Gemini/Ollama) cp .env.example .env Build and start all services docker compose up --build -d

The backend becomes reachable at http://localhost:8000/docs (FastAPI OpenAPI UI). The front‑end is served on http://localhost:3000 (Vite dev server).

To run the backend locally without Docker:

Python 3.10+

python -m venv venv && source venv/bin/activate pip install -r backend/requirements.txt uvicorn backend.app.main:app --host 0.0.0.0 --port 8000

Configuration lives in backend/app/api/config.py and the .env.example file (model provider, document parser choice, DB URL).

Real‑World Use

A product team can point NexusRAG at a corpus of technical manuals. When a sales engineer asks “What safety warnings apply to the XYZ actuator?” the system: Retrieves relevant sections (preserving page numbers). Augments with a KG node for “XYZ actuator” and any linked hazard entities. Returns a response like “Refer to §3.2.1 (page 42) …” with a clickable link that opens the viewer at the exact location.

The same flow works for image‑heavy datasheets because extracted figures are indexed and shown in ImageGallery.tsx.

The Bottom Line

NexusRAG provides a well‑integrated, multi‑modal RAG stack with citation and KG support, but the codebase suffers from maintainability hotspots and lacks the safety nets (tests, CI, licence) needed for production use. It is a solid foundation for teams willing to invest in refactoring and adding automated quality checks.
