ta

Technical Analysis Library using Pandas and Numpy

Forked from bukosabino/ta

The Problem Financial analysts and data‑science teams need a reliable way to generate technical‑analysis features (e.g., Bollinger Bands, RSI, MACD) from OHLCV time‑series. Manually coding each indicator is error‑prone and slows model‑building pipelines.

What This Does The ta package implements 43 common technical indicators on top of pandas and numpy. Core logic lives in the ta/ module:

ta/momentum.py, ta/trend.py, ta/volatility.py, ta/volume.py – each defines a set of Indicator classes (e.g., RSIIndicator, MACDIndicator) and functional wrappers (rsi(), macd()). ta/utils.py supplies helper functions for moving averages, scaling, and safe NaN handling. ta/wrapper.py provides a thin façade that can ingest a DataFrame and append all supported indicators in one call.

Documentation (docs/ta.rst) and a handful of notebooks in examplestouse/ (e.g., allfeaturesexample.py) demonstrate practical usage.

How To Use It

Setup – The repository uses classic setuptools and a requirements.txt for dependencies. From the repository root:

Create a clean virtual environment (recommended) python -m venv .venv source .venv/bin/activate

Install the library in editable mode pip install -e . Optional: install test/dev extras pip install -r requirements-test.txt

Configuration – No external configuration files are required for the core library. Indicator functions accept only a pandas.DataFrame with columns ['Open','High','Low','Close','Volume'].

Running it – The most common entry point is the ta.wrapper.addalltafeatures function. A minimal example:

import pandas as pd from ta.wrapper import addalltafeatures

Load a CSV with OHLCV columns df = pd.readcsv('test/data/cs-accum.csv')

Append every supported indicator (default settings) dffeatures = addalltafeatures(df, fillna=True)

print(dffeatures.head())

For a ready‑made script, see examplestouse/allfeaturesexample.py, which loads a sample CSV, calls addalltafeatures, and plots a few results.

Real‑World Use A typical workflow in a quant research pipeline:

import pandas as pd from ta.wrapper import addalltafeatures from sklearn.ensemble import RandomForestRegressor Load market data prices = pd.readparquet('s3://bucket/dailyprices.parquet') Engineer technical features features = addalltafeatures(prices, fillna=True) Train a model X = features.drop(columns=['Close']) # target excluded y = features['Close'].shift(-1) # next‑day price model = RandomForestRegressor(nestimators=200) model.fit(X.iloc[:-1], y.iloc[:-1])

The generated feature set can be fed directly into any scikit‑learn model or downstream time‑series framework.

Code Health & Issues Low – No lockfile – requirements.txt is present but there is no requirements‑.txt lock (e.g., pip‑freeze). Reproducible builds rely on CI‑installed versions only. Low – Limited type hints – Source files (ta/*.py) contain few or no type annotations, which hampers static analysis for large teams. Medium – Test coverage gaps – 40 test files exist, but integration tests focus on the wrapper only; edge cases (e.g., missing columns, extreme NaNs) are not explicitly exercised. Low – Documentation sync – The README lists 43 indicators; the actual source defines 42 (e.g., KeltnerChannel is missing). Minor mismatch that could confuse new users. None – Licensing – LICENSE is present (MIT), satisfying distribution requirements. Low – CI configuration – CircleCI config (.circleci/config.yml) runs unit tests, but the badge in the README points to the upstream repo; the fork’s CI status is not displayed, making health monitoring less transparent.

Overall the code follows standard Python packaging conventions, uses prospector and black for style, and ships with a full test suite.

The Bottom Line The ta library delivers a straightforward, pandas‑centric API for generating a wide range of technical‑analysis features, backed by a solid test base and clear documentation. Its primary drawbacks are the lack of a dependency lockfile and sparse type hints, which may affect reproducibility and large‑scale integration. It is well suited for data‑science teams building feature‑rich trading models, especially when rapid prototyping is a priority.
