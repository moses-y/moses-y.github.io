job application agent

Privacy-first Codex skill for discovering, validating, completing, and tracking job applications

Forked from vaibhavarora14/job-application-agent

The Problem

Job seekers using AI coding assistants face a credibility gap: agents can generate applications but cannot verify credentials, detect duplicates, or maintain a private application ledger. The result is spammy, unverifiable submissions that reflect poorly on the candidate and waste hiring teams' time. There is no standardized way for an agent to discover roles, validate fit, fill forms with trusted data, and track outcomes—all while keeping profile data local and under the candidate's control.

What This Does

The Job Application Agent is a privacy-first Agent Skill that handles the full application lifecycle. The installer/ directory contains the deployment logic (installer/src/cli.mjs, installer/src/installer.mjs, installer/src/runner.mjs, installer/src/scheduler.mjs) that places the skill at ~/.agents/skills/job-application-agent and copies it to vendor directories like ~/.cursor/skills if present. The main skill code lives in job-application-agent/ with SKILL.md defining the contract, while scripts/ handles core operations: job-application.mjs orchestrates the application workflow, secret-store.mjs manages OS-backed profile storage, and telemetry-client.mjs sends privacy-preserving telemetry. The telemetry-worker/ provides a dashboard interface—telemetry-worker/src/worker.mjs is the worker process, telemetry-worker/src/public-stats.mjs exposes statistics, and telemetry-worker/public/ serves the UI at telemetry-worker/public/index.html with dashboard.js and styles.css. Telemetry schema and validation live in scripts/telemetry-schema.mjs and scripts/telemetry-client.mjs, with tests in telemetry-worker/tests/. GitHub Actions workflows in .github/workflows/ handle CI/CD: validate.yml, publish-npm.yml, staging-telemetry.yml, and deploy-telemetry.yml.

How To Use It

Setup: The canonical install command documented in README.md is:

npx job-application-agent@latest install

This reads package.json for the npm package name and version, then uses the installer scripts to place the skill in the agent skills directory. Confirm the installation with:

npx job-application-agent@latest status

Configuration: No environment variables or API keys are required for core functionality. Profile data is stored via scripts/secret-store.mjs using OS-backed secure storage (Keychain on macOS, Credential Manager on Windows, secret service on Linux). The windows-profile-store.ps1 script handles Windows-specific profile storage integration. Candidate profile data, the canonical résumé, and application ledgers remain outside the replaceable skill directory, as noted in the README.

Running it: Invoke the CLI from bin/job-application-agent.mjs to start a workflow. The job-application.mjs script handles discovery, qualification, and form filling using verified profile and résumé facts. The agent pauses for authentication, CAPTCHA, legal attestations, demographic questions, unclear eligibility, sensitive identifiers, and unverifiable claims—per the safety-by-design approach documented in the README.

Real-World Use

A senior engineer using a coding agent to pivot into devrel roles can run npx job-application-agent@latest install to set up the skill, then invoke the agent with targeting criteria (seniority: senior, location: remote, compensation: $150k+). The agent uses scripts/job-application.mjs to browse career pages and ATS platforms, scores matches against the candidate-defined profile, and fills application forms using only facts from the locally stored résumé. After every ten submissions, telemetry-worker/src/public-stats.mjs reviews results and proposes targeting adjustments. The local ledger in installer/ records only visibly confirmed submissions, enabling the engineer to review outcomes and adjust search criteria without exposing profile data.

Code Health & Issues Tests & CI: 14 test files exist across installer/tests/, telemetry-worker/tests/, and job-application-agent/tests/. CI is configured via four GitHub Actions workflows in .github/workflows/, covering validation, npm publishing, and telemetry staging/deployment. License is present at LICENSE (MIT). package-lock.json ensures reproducible installs. Security: SECURITY.md is present. The privacy model keeps profile data in OS-backed storage and browser auth in the browser, as documented in job-application-agent/references/BROWSER_UPLOADS.md and ANALYTICS.md. Observability: Telemetry schema is defined in scripts/telemetry-schema.mjs with corresponding tests. The dashboard at telemetry-worker/public/index.html provides a public stats endpoint. Missing: No .env files or secrets in the repo. No evidence of input validation bypass or unsafe patterns in the reviewed structure.

The Bottom Line

This is a well-structured, privacy-first Agent Skill that fills a genuine gap for candidates using AI assistants. The separation of concerns between the skill (job-application-agent/), installer (installer/), and telemetry dashboard (telemetry-worker/) is clean, and the OS-backed local storage approach addresses the primary privacy concern. It is best suited for individual job seekers or small teams who need disciplined, trackable application workflows without sacrificing data privacy. Teams requiring enterprise-grade SSO, custom ATS integrations, or large-scale bulk applying will find the local-first design constraining.
