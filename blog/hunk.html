The Problem

Agent-authored changesets often produce large, unstructured diffs that are difficult to review efficiently in terminal environments. Developers working with AI agents need a focused review interface that presents changes alongside contextual annotations, rather than raw git output. This project addresses that gap by providing a dedicated review-first terminal interface.

What This Does

Hunk is a review-first terminal diff viewer built on OpenTUI and Pierre diffs. The codebase organizes around several key areas: src/core/ contains the fundamental logic: git.ts, diffPaths.ts, cli.ts, and terminal.ts handle VCS interaction, diff path computation, command-line parsing, and terminal presentation respectively. src/opentui/ implements the user interface layer with HunkDiffView.tsx, HunkDiffView.test.tsx, and related components for diff visualization, file navigation, and review streaming. packages/session-broker-/ provides session broker functionality across bun, core, and node runtimes, with broker state management in brokerState.ts and wire protocol in brokerWire.ts. examples/ directories demonstrate workflows including multi-app refactors (2-mini-app-refactor), agent review demos (3-agent-review-demo), and UI polish scenarios (4-ui-polish).

The project uses React for its UI components and GitHub Actions for CI across .github/workflows/ci.yml, benchmarks.yml, pr-ci.yml, and other workflow files.

How To Use It

Setup: The package is installed globally via npm i -g hunkdiff or through Homebrew with brew install modem-dev/tap/hunk. The root package.json and three packages/session-broker-/package.json files indicate an npm/pnpm-based build system. A lockfile is absent, which the heuristic analysis flags as potentially causing non-reproducible builds.

Configuration: Environment configuration lives in .envrc. For Jujutsu workspaces, set vcs = "jj" in config; for Git, set vcs = "git". The .github/dependabot.yml suggests automated dependency update tooling is configured.

Running it: Entry points include hunk diff to review current repo changes (including untracked files), hunk show for the latest commit, and hunk diff before.ts after.ts for direct file comparison. The --watch flag enables auto-reload as the working tree changes. Example entry files include examples/2-mini-app-refactor/after/src/main.ts and examples/3-agent-review-demo/after/src/index.ts.

Real-World Use

In a team using AI code review workflows, a developer opens hunk diff --watch in one terminal to display the current changeset. The review UI presents a sidebar with file navigation and inline diff view. When an agent proposes changes, the developer invokes hunk skill path to load a skill file, then applies the agent's modifications within the live Hunk session. The --agent-context flag facilitates live-session integration as documented in docs/agent-workflows.md. The split-view layout (evidenced by src/opentui/HunkDiffView.tsx and src/opentui/HunkFileNav.tsx) allows simultaneous code comparison and annotation review.

Code Health & Issues

Dependencies without lockfile: package.json files across the root and packages/ directories declare dependencies but no lockfile (bun.lock exists at root, but package-lock.json or yarn.lock is not evident) - this risks non-reproducible installs across environments. Test coverage: 41 test files are present across src/core/, packages/, and examples/, with test files like src/core/git.test.ts, src/core/cli.test.ts, and various brokerState.test.ts/brokerWire.test.ts files. CI is configured via GitHub Actions. SDLC: A CONTRIBUTING.md, LICENSE (MIT), and CHANGELOG.md are present. Dependabot configuration suggests ongoing dependency maintenance. No obvious secrets or unsafe patterns visible in the file listing.

The Bottom Line

Hunk delivers a capable review-first terminal diff viewer with solid UI construction and agent-integrated workflows. The codebase is structured and documented, with test suites and CI in place. The absence of a lockfile is the primary reproducibility concern; otherwise the project appears well-maintained for its stated purpose. Teams actively using AI-assisted code review and requiring terminal-based diff inspection will find it practical; solo developers or teams not using agent workflows may not derive significant benefit.
