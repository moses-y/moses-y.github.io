The Problem

Developers using Claude‑Code, Codex, or similar AI harnesses spend most of their time stitching together hooks, rules, and custom agents. The glue code proliferates, becomes hard to reason about, and performance degrades as session data grows. Maintaining a coherent, version‑controlled set of skills, instincts, and security checks is therefore a constant source of friction.

What This Does

The repository implements Everything Claude Code (ECC) – a self‑contained harness that bundles reusable skills, hooks, and rules for multiple AI agents. Core assets live under .opencode/ (TypeScript entry point index.ts) and scripts/ (the CLI driver claw.js). Hooks such as .cursor/hooks/adapter.js and .cursor/hooks/before-shell-execution.js intercept editor actions, while rule files in .cursor/rules/ encode coding‑style, security, and performance policies. The agents/ folder contains ready‑made agent prompts (e.g., agents/code-reviewer.md). Documentation (≈360 Markdown files) and test suites (62 tests) are shipped alongside the code.

How It Is Wired

Execution begins at scripts/claw.js (function main at line 278). main calls 57 functions across the codebase, most notably readFile, log, and a cascade of utility helpers from scripts/lib/utils.js.

  • scripts/lib/utils.js is the most‑connected module (27 functions, imported by six other files) and defines path helpers such as getClaudeDir and getSessionsDir. Because it is a hub, any change here can affect the entire CLI flow.
  • scripts/lib/session-aliases.js and scripts/lib/session-manager.js handle alias resolution and session persistence, each exposing five‑plus functions that read/write files (e.g., loadAliases, saveAliases).
  • Hook orchestration lives in .cursor/hooks/. The adapter (.cursor/hooks/adapter.js) is imported by 15 other modules, making it another blast‑radius hotspot. It routes editor events to specific hook implementations (before-shell-execution, after-file-edit, etc.).
  • The internal call graph shows 332 resolved function‑to‑function edges. The most frequently invoked internal utilities are readFile (11 callers) and log (11 callers).
  • Files that touch the outside world are limited to 31 functions that perform filesystem I/O. The shortest external path is main → readFile → fs.readFileSync. No network calls are evident in the static graph, so the runtime impact is confined to local file operations.

No circular dependencies appear, reducing the risk of hidden coupling. However, hub modules (utils.js, adapter.js) and several oversized test files (tests/ci/validators.test.js) represent the primary “change‑impact” zones.

How To Use It

# Clone the repo
git clone https://github.com/moses-y/everything-claude-code.git
cd everything-claude-code

# Install Node dependencies (npm is the lockfile format)
npm ci   # respects package-lock.json in the repo root and .opencode/

# Optional: install TypeScript for the .opencode package
npm install -g typescript   # needed only if you modify .opencode sources

# Run the CLI driver (the documented entry point)
node scripts/claw.js --help

Configuration files live under .opencode/ (opencode.json) and .cursor/ (hooks.json). The CLI reads those files to locate skill definitions (.agents/skills/…) and to load hook pipelines. No environment variables are required out‑of‑the‑box; the system operates on the local filesystem.

Real‑World Use

A development team integrates ECC into their CI pipeline to enforce coding standards on every pull request. The CI workflow invokes node scripts/claw.js run-tests which triggers the hook chain, validates rule compliance, and writes a session report under ~/.claude/sessions/. The report can be consumed by a downstream audit service without any network code changes.

Code Health & Issues

  • HIGH – Discarded exit codes mask failures (maintenance.yml line 23).
  • HIGH – continue-on-error on correctness steps hides test failures (ci.yml line 195).
  • MEDIUM – No Dependabot/Renovate config (.github/dependabot.yml missing).
  • MEDIUM – Large binary (assets/images/longform/01-header.png, 5.4 MiB) should be moved to Git LFS.
  • MEDIUM – Checkout step keeps token; set persist-credentials: false (ci.yml).
  • MEDIUM – postinstall script fetches remote resources; consider moving to explicit build step (package.json).
  • LOW – Add timeout-minutes to jobs in maintenance.yml to avoid runaway runs.

The repository includes a full test suite, CI definitions, a LICENSE, and lockfiles, indicating reasonable hygiene. Duplicate hook implementations and oversized test files (e.g., tests/ci/validators.test.js with 1,669 lines) are flagged by the static analysis and should be refactored for maintainability.

The Bottom Line

ECC provides a concrete, file‑based framework for stitching AI‑agent hooks, skills, and rules together, with clear entry points and modest external side effects. Its main drawbacks are a few high‑impact hub modules and some maintenance‑level technical debt (pinned actions, large binaries). Teams needing a configurable, locally‑runnable harness for Claude‑Code or Codex will find a solid foundation, but should allocate effort to reduce hub complexity and clean up duplicated hook logic before extensive customization.

Pin third-party GitHub Actions to a commit SHAhigh3 occurrences
.github/workflows
pnpm/action-setup@v4, oven-sh/setup-bun@v2, softprops/action-gh-release@v2
A tag can be moved, so the action running with your token and secrets is whatever its owner last pushed; this is how tj-actions/changed-files leaked secrets from thousands of repos.
Fix: Replace each @vN with the 40-character commit SHA, keep # vN as a comment, and let Dependabot bump the SHAs.
Stop discarding the exit code of steps whose failure mattershigh
.github/workflows/maintenance.yml
lines 23 discard failure
The job reports green while the artifact it was supposed to produce was never produced, so a crash becomes a successful run built on stale data.
Fix: Let the step fail, or test the specific expected condition instead of discarding all exit codes.
Remove continue-on-error from steps that gate correctnesshigh
.github/workflows/ci.yml
line 195 on a correctness step
A failing test suite reports a green check, which is precisely the path this audit exists to close.
Fix: Delete continue-on-error, or move a genuinely advisory step into a separate non-required job.
Enable Dependabot or Renovatemedium
2 manifest(s), no update bot configured
Without a bot a published advisory sits unpatched until someone audits by hand, which across 1,322 repositories means never.
Fix: Commit .github/dependabot.yml covering the repo ecosystems plus github-actions.
Move large binaries to Git LFS or out of the repositorymedium
assets/images/longform/01-header.png
1 blobs over 5MB: 01-header.png 5.4MB
One repository here carries twenty blobs over 5MB including a 10.9MB spreadsheet, so every clone and every CI checkout pays for data nobody diffs.
Fix: Track those extensions with LFS, or move datasets to object storage and fetch them in a setup step.
Set persist-credentials: false on checkoutmedium
.github/workflows/ci.yml
checkout keeps the token, then dependencies are installed
The token stays in .git/config for every later step, so a malicious postinstall script reads a pushable credential without one ever being passed to it.
Fix: Add with: persist-credentials: false, and pass an explicit token only to the step that pushes.
Review the install lifecycle script and disable scripts in CImedium
package.json
postinstall (fetches from the network)
Install scripts are the execution vector for every npm compromise from event-stream onward, and a postinstall that fetches a binary makes the build depend on a URL nobody reviews.
Fix: Move the work into an explicit build step, or set ignore-scripts in CI and run it by name.

3 workflow(s) declare no job timeout
A wedged step runs to the six-hour platform default, which on a two-hourly schedule means three runs overlap behind it.
Fix: Add timeout-minutes with a realistic bound to each job.
