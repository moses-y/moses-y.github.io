ClawLibrary

ClawLibrary is a 2D pixel-game-style control interface for OpenClaw. It turns OpenClaw's generated assets, runtime activity, and assets related working state into a visual library interface that can be browsed, previewed, and monitored in real time.

Forked from shengyu-meng/ClawLibrary

The Problem OpenClaw developers need a way to inspect the thousands of generated pixel assets and the live state of the engine without digging through raw folders or console logs. Without a visual index, tracking which assets are in use, debugging asset‑related crashes, or coordinating art updates becomes time‑consuming and error‑prone.

What This Does ClawLibrary provides a browser‑style UI that maps OpenClaw resources to “rooms” rendered in a 2‑D pixel‑game style. The UI loads definitions from src/data/asset.manifest.json, layout data from src/data/map.logic.json, and live telemetry via scripts/openclaw-telemetry.mjs. Core UI code lives in src/ui/ (e.g., palette.ts, locale.ts) and the runtime scene is implemented in src/runtime/scene/LibraryScene.ts. Asset art is stored under public/assets/generated/ and can be previewed directly in the interface.

How To Use It

Setup git clone https://github.com/shengyu-meng/ClawLibrary.git cd ClawLibrary npm install npm run validate # runs type‑checking and lint npm run dev # starts Vite dev server

The dev server defaults to http://127.0.0.1:5173/. For LAN access, the README notes: CLAWLIBRARYSERVERHOST=0.0.0.0 npm run dev

If OpenClaw is installed in a non‑standard location, edit clawlibrary.config.json (or create a .env from .env.example) and set OPENCLAWHOME / OPENCLAWWORKSPACE.

Configuration clawlibrary.config.json – defines paths to the OpenClaw workspace and optional authentication. .env (optional) – can override OPENCLAWHOME, OPENCLAWWORKSPACE, and CLAWLIBRARYACCESSPASSWORD.

Running The entry point is src/main.ts, which bootstraps Vite and loads src/remap.ts to translate OpenClaw telemetry into UI state. After npm run dev, the UI is reachable at the URL printed by Vite.

Real‑World Use A studio pipeline can launch ClawLibrary alongside the OpenClaw server. As artists iterate on sprite sheets in public/assets/generated/actors/…/sheets/, they open the UI, navigate to the “image atelier” room, and instantly see the updated textures. QA engineers monitor the “runtime monitor” room to verify that the game engine is loading the expected assets during automated tests, reducing the need to parse log files.

// Example: programmatically trigger a refresh from OpenClaw import { sendTelemetry } from './scripts/openclaw-telemetry.mjs'; sendTelemetry({ type: 'asset-load', assetId: 'cat-claw-emoji-v1' });

The Bottom Line ClawLibrary delivers a functional, visual asset browser that integrates live OpenClaw telemetry, making asset debugging and art iteration faster. It is ready for small‑to‑medium teams that can tolerate the current lack of CI and limited test suite, but larger or security‑sensitive projects should add automated testing and CI pipelines before adopting.
