The Problem

Technical writing on Twitter/X is scattered and ephemeral. Threads get buried in timelines, and there is no structured way to browse, categorize, or reference past content. Anyone who writes long-form system design content on a platform like X needs a maintainable index that turns a stream of posts into a browsable library.

What This Does

This repository is a catalog of system design and backend engineering articles published as X threads. articles.json is the source of truth—a structured data file containing each article's title, description, URL, and date. The README is generated from that JSON via generatereadme.py, which renders the articles into a categorized table organized by topic (HLD, LLD, Backend Engineering, Microservices, etc.).

The design is deliberately simple: one data file, one generator script, one output document. The README currently lists roughly 57 articles across 7 categories, each linking directly to the original X thread. The LICENSE file and README round out the repository.

How To Use It

Setup: No dependencies or installation required. The repository contains only a Python script, a JSON data file, and documentation.

Configuration: All content lives in articles.json. Each entry requires a title, description, URL, and date. Categories are inferred from the JSON structure.

Running it: Execute the generator to regenerate the README after editing articles:

python generatereadme.py

The script reads articles.json and writes the categorized tables into README.md. There is no CI, no test suite, and no other entry point.

Real-World Use

A consultant or educator who publishes regular technical threads on X can use this as a content management pattern. The workflow is straightforward: publish a thread, add an entry to articles.json, run the generator, and commit. The README serves as a public, always-up-to-date table of contents that readers can browse without scrolling a timeline.

For example, adding a new article would look like:

{ "title": "Design a Payment System", "description": "High-level design for a payment processing platform.", "url": "https://x.com/author/status/123456789", "date": "2026-07-01", "category": "HLD" }

Code Health & Issues Med - No tests - generate_readme.py has no test coverage. A malformed JSON entry or a missing field will fail silently or produce a broken README. The script is simple enough that this is tolerable, but a basic validation test would prevent bad output. Med - No CI/CD - There is no pipeline to regenerate or verify the README on commit. A contributor could merge a broken articles.json and the README would drift out of sync. Low - Single maintainer assumption - The repo has no contribution guidelines or issue templates. Fine for a personal project, but it limits collaboration. Low - Date formatting - Dates in the JSON appear to be ISO-format strings. If the script assumes a specific format, inconsistent entries will break the sort order in the README.

The repository is otherwise clean: no secrets, no build artifacts, no dependency bloat.

The Bottom Line

A practical, minimal solution for a narrow problem: turning a stream of X threads into a structured, browsable index. The generator script is straightforward, and the JSON schema is simple enough to extend. It is well suited for an individual writer who wants a low-maintenance content catalog; it is not a general-purpose publishing tool, and teams would want CI and tests before adopting it as a shared workflow.
