The Problem

Developers building autonomous AI agents need a quick reference for repeatable design patterns (memory handling, tool orchestration, safety, etc.). Existing documentation is scattered across blogs and talks, making it hard to locate concrete implementation ideas or visual examples.

What This Does

The repo supplies a card‑based visual viewer for 99 agentic patterns.

  • pattern‑snippets/ holds the HTML cards, language‑specific JSON (en.json, ko.json) and supporting assets.
  • docs/ contains the Markdown source for each pattern (e.g., docs/patterns/agent‑first‑tooling‑and‑logging.md).
  • index.js is the JavaScript entry point that builds the static site; pattern‑snippets/index.html loads the viewer in the browser.
  • Build helpers (pattern‑snippets/build.js, loader.js, i18n.js) generate the final HTML page from the JSON cards and inject the selected locale.

How To Use It

# Clone the repository
git clone https://github.com/moses-y/awesome-agentic-patterns
cd awesome-agentic-patterns

# Install JavaScript dependencies (package.json)
npm ci       # uses package-lock.json for reproducible install

# Build the static viewer
make build   # runs `node index.js` → writes `pattern-snippets/index.html`

# Open the viewer locally
open pattern-snippets/index.html   # macOS; use your OS's file opener

Configuration: Locale files live under pattern-snippets/locales/. Switching language is handled at runtime by the i18n module; no external env‑vars are required.

Running the site: The generated index.html is a self‑contained static page; it can be served by any HTTP server (e.g., python -m http.server in pattern-snippets/).

Real‑World Use

A product team can embed the generated HTML into an internal wiki to give engineers instant visual access to pattern “cards”. When a new pattern is added (new JSON + card HTML under pattern-snippets/patterns/), a single make build regenerates the viewer without code changes.

Code Health & Issues

  • Duplicated code blocks – pattern-snippets/build.js, loader.js, i18n.js share 13 identical 6‑line snippets. Fix: extract shared helpers into a common module. (high/clarity)
  • Deep nesting – scripts/deploy_git_based.py reaches 7 levels of indentation, making the control flow hard to follow. Fix: refactor with early returns or split into smaller functions. (medium/cognitive_load)
  • Dependabot missing – two manifest files (package.json, requirements.txt) have no automated update bot. Fix: add .github/dependabot.yml. (medium)
  • No dependency‑vulnerability scan in CI – GitHub Actions workflow lacks a scan step. Fix: integrate dependency-review-action or osv-scanner. (medium)
  • Workflow timeout not set – .github/workflows/deploy-pages.yml omits timeout-minutes. Fix: add a reasonable timeout (e.g., timeout-minutes: 30). (low)
  • Tests (24 files) and CI (GitHub Actions) are present; license (LICENSE) and lockfiles are committed; no secrets detected.

The Bottom Line

The repository delivers a well‑organised, static visual catalog of agentic design patterns with minimal runtime complexity—each helper is isolated, making updates straightforward. The main drawbacks are minor code duplication, a deeply nested deployment script, and missing automated dependency management. It is suitable for teams that need a lightweight, searchable reference for AI‑agent architectures and are comfortable adding a few housekeeping steps to harden the CI pipeline.
