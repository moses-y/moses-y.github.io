The Problem

Developers who want an out‑of‑the‑box autonomous LLM agent often spend hours wiring memory, scheduling, and external tool integrations. The effort is amplified when the codebase is monolithic, hard to test, and fragile to small changes.

What This Does

babyagi3 supplies a ready‑made loop: input → LLM → action → execution → output. The core lives in main.py (entry at line 120) which boots the agent, loads config.yaml, and dispatches to the Agent class in agent.py. Tool implementations live under tools/ (34 files) and are registered via tools/__init__.py (the hub module with 29 dependents). Persistent memory is handled by memory/store.py (2066 lines, 137 functions, DB + crypto ops) and memory/embeddings.py. Scheduling, background jobs, and webhook handling are in scheduler.py and server.py. Send/receive channels (email, SendBlue, voice) are in listeners/ and senders/.

How It Is Wired

Execution starts in main.py:120 → calls run_all_channels → schedule_post_init_tasks. The shortest external side‑effects are:

  • Filesystem – INIT_STATE_FILE.unlink during post‑init.
  • Network – httpx.get in execute → fn (e.g., fetching remote content).
  • Database – self.conn.commit in run → log_message → create_event.

Key functions with the widest blast radius:

  • tool_error (called from 47 places) – defined in tools/__init__.py.
  • Schedule (46 callers) – defined in scheduler.py.
  • now_iso (38 callers) – utility in utils/.

memory/store.py is the primary persistence layer (reads/writes DB, encrypts data) and is invoked by Agent.execute, Agent.check_health, and the metrics collector. tools/__init__.py is the hub; any change ripples to 29 modules, making it a stability hotspot. A circular import exists among metrics/__init__.py, agent.py, and memory/integration.py, which inflates the instability of those modules.

How To Use It

# Clone and install
git clone https://github.com/moses-y/babyagi3 && cd babyagi3
uv sync            # or: pip install -e .

# Provide an LLM key (pick one)
export ANTHROPIC_API_KEY="sk-ant-..."
# or
export OPENAI_API_KEY="sk-openai-..."

# Run the agent
python main.py

Configuration lives in config.yaml (owner name/email, optional channel keys) and can be overridden by the environment variables listed above. The setup wizard will prompt for missing values and store secrets in the system keyring.

Testing is available via uv run pytest -q (18 test files under tests/). CI runs on every push using the workflow in .github/workflows/ci.yml.

Real‑World Use

A small business could launch an internal assistant that auto‑summarizes incoming support emails, stores the summaries in memory/store.py, and schedules follow‑up reminders via scheduler.py. The assistant would call tools/optional/http_utils.py to fetch relevant KB articles and reply through senders/email.py.

The Bottom Line

babyagi3 delivers a functional autonomous agent with clear separation of memory, scheduling, and tool integration, but the codebase suffers from large, tightly coupled modules, circular imports, and several maintainability concerns. It is suitable for teams that need a quick prototype and are comfortable refactoring the hub and oversized files before production use.

Pin third-party GitHub Actions to a commit SHAhigh
.github/workflows
astral-sh/setup-uv@v4
A tag can be moved, so the action running with your token and secrets is whatever its owner last pushed; this is how tj-actions/changed-files leaked secrets from thousands of repos.
Fix: Replace each @vN with the 40-character commit SHA, keep # vN as a comment, and let Dependabot bump the SHAs.
Declare least-privilege permissions for GITHUB_TOKENmedium
.github/workflows/ci.yml
1 workflow(s) declare no permissions
With no declaration the token inherits the repository default, so any injected step can push commits or mint releases from inside your own CI.
Fix: Add permissions: contents: read at the top of the workflow and widen per job only where needed.
Enable Dependabot or Renovatemedium
1 manifest(s), no update bot configured
Without a bot a published advisory sits unpatched until someone audits by hand, which across 1,322 repositories means never.
Fix: Commit .github/dependabot.yml covering the repo ecosystems plus github-actions.
Gate pull requests on a dependency vulnerability scanmedium
.github/workflows
no dependency scan in CI
This is the one gate that would catch a known-vulnerable package before it reaches a build, and no repository in the sample had it.
Fix: Add dependency-review-action on pull_request, or osv-scanner on push and a schedule.
Set timeout-minutes on the workflow jobslow
.github/workflows/ci.yml
1 workflow(s) declare no job timeout
A wedged step runs to the six-hour platform default, which on a two-hourly schedule means three runs overlap behind it.
Fix: Add timeout-minutes with a realistic bound to each job.
