OCRFlux

OCRFlux is a lightweight yet powerful multimodal toolkit that significantly advances PDF-to-Markdown conversion, excelling in complex layout handling, complicated table parsing and cross-page content merging.

Forked from chatdoc-com/OCRFlux

The Problem PDF-to-Markdown conversion breaks down on multi-column layouts, cross-page tables, and embedded figures. Teams needing clean, readable Markdown from complex PDFs often stitch together OCR, layout engines, and post-processing scripts—resulting in fragile pipelines and inconsistent output.

What This Does OCRFlux is a multimodal toolkit built around a 3B parameter vision-language model. It handles whole-file PDF parsing, per-page text extraction with natural reading order, complicated table and equation support, automatic header/footer removal, and cross-page table/paragraph merging.

Key files by function: ocrflux/inference.py – core VLM inference and PDF/image processing ocrflux/pipeline.py – likely orchestrates the end-to-end conversion flow ocrflux/imageutils.py – image preprocessing and page segmentation eval/ – 12 evaluation scripts (evalpagetomarkdown.py, evaltabletohtml.py, plus data generation scripts like genelementmergedetectdata.py) .github/workflows/docker.yml – CI/CD pipeline for Docker builds Dockerfile and pyproject.toml – build and container configuration

The repository claims state-of-the-art Edit Distance Similarity (EDS) gains over baselines like olmOCR-7B, Nanonets-OCR-s, and MonkeyOCR on their released benchmarks, and markets the ability to run on a single GTX 3090 due to the 3B parameter size.

How To Use It Setup: The presence of pyproject.toml indicates the project is intended to be pip- or uv-installable. No lockfile is present, so dependency versions may vary between installs. Dockerfile exists for containerized builds, and .github/workflows/docker.yml configures the CI pipeline.

Configuration: The README references Hugging Face model releases (OCRFlux-3B) and evaluation datasets. Environment variables or API keys for Hugging Face or inference endpoints are likely required but not explicitly named in the provided excerpt.

Note: Installation and runtime commands are not fully documented in the provided materials. The pyproject.toml and Dockerfile are the primary evidence for build configuration; exact pip or docker invocation would need verification against the full README or project source.

Real-World Use A documentation team needs to convert a 200-page technical PDF with multi-column layouts, embedded code tables, and cross-page figure captions into a single Markdown file. They run the model via ocrflux/inference.py on each page, then use ocrflux/pipeline.py to merge tables and paragraphs across page boundaries. The resulting Markdown requires minimal manual cleanup, preserving reading order and table structure that typical PDF-to-Markdown tools lose.
