The Problem

Investigators often rely on ad‑hoc spreadsheets to track people, connections, and evidence. Spreadsheets lack relational integrity, audit trails, and visual network mapping, which leads to data inconsistency, version‑control headaches, and limited collaboration.

What This Does

GHOST‑osint‑crm provides a self‑hosted full‑stack web application that replaces spreadsheets with a relational database (PostgreSQL) and a React UI. The backend API lives in backend/server.js and exposes routes such as backend/routes/people.js, backend/routes/entityNetwork.js, and backend/routes/geocoding.js. The frontend consumes these endpoints via the React code under frontend/ (e.g., the network diagram uses ReactFlow components). Configuration defaults are supplied in backend/.env.example and frontend/.env.example; Docker orchestration is defined in docker-compose.yml, backend/Dockerfile, and frontend/Dockerfile.

How To Use It

Setup

Clone and enter the repo git clone https://github.com/yourorg/GHOST-osint-crm.git cd GHOST-osint-crm

Build and start containers (Docker Compose uses the two Dockerfiles) docker compose up --build -d

The compose file pulls the backend image (built from backend/Dockerfile) and the frontend image (built from frontend/Dockerfile), then runs PostgreSQL (defined in the compose file).

Configuration

Backend: copy backend/.env.example to backend/.env and set at least DATABASEURL, JWTSECRET, and GEOCODINGAPIKEY. Frontend: copy frontend/.env (note: the repository contains a placeholder file; replace any real secrets).

Both files are referenced in the Docker entrypoint scripts (backend/docker-entrypoint.sh) and the React build process.

Running

The API server starts automatically via node backend/server.js inside its container. The UI is served by an Nginx container (frontend/nginx.conf). Access the application at http://localhost (or the host you mapped in docker-compose.yml). Admin accounts can be created with the supplied scripts: docker exec -it ghost-backend node backend/scripts/createAdminUser.js

Real‑World Use

A private investigator could ingest a case CSV, run backend/scripts/createAdminUser.js to set up a user, then use the UI to: Add suspects via the People page (backend/routes/people.js). Upload addresses; the backend auto‑geocodes them using backend/services/improvedGeocodingService.js. Visualize connections on the Entity Network page, which pulls data from backend/routes/entityNetwork.js and renders with ReactFlow.

All actions are logged by backend/middleware/auditLog.js, providing an audit trail for internal review.

Code Health & Issues

High – Secrets in repo – frontend/.env contains placeholder values; if real keys are present they are exposed. Medium – Input validation gaps – Validation middleware (backend/middleware/validation.js) is present, but some routes (e.g., backend/routes/geocoding.js) lack explicit checks for malformed inputs. Medium – Rate limiting – backend/middleware/rateLimiters.js exists, but no configuration is shown; default limits may be insufficient for production. Low – Logging consistency – backend/utils/logger.js is used, yet some scripts (backend/scripts/) call console.log directly, bypassing structured logs. Low – Test coverage – 9 test files exist (.test.js) covering middleware and services, but no end‑to‑end tests for the API routes. Low – CI configuration – GitHub Actions workflow (.github/workflows/publish-images.yml) builds Docker images but does not run the test suite; adding a test step would improve quality gates.

The Bottom Line

GHOST‑osint‑crm delivers a functional, containerized OSINT case management system with relational storage, geocoding, and interactive network visualizations. It is well‑structured for solo or small‑team deployments but requires careful secret handling, additional input validation, and stronger CI testing before being trusted in production or regulated environments. Suitable for investigators who can manage their own hosting and security posture.
