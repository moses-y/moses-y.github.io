sample geospatial agent on aws

An AI agent that analyzes satellite imagery for any location on Earth using natural language. Ask about vegetation health, water bodies, or wildfire damage — get real results from Sentinel-2 imagery, rendered on an interactive map.

Forked from aws-samples/sample-geospatial-agent-on-aws

The Problem

Geospatial analysis traditionally requires specialized GIS software, raster processing expertise, and manual data sourcing. Teams needing vegetation health, water body extent, or burn severity assessments often wait days for analysts to download Sentinel-2 scenes, compute indices, and produce visualizations. This repo eliminates that bottleneck by letting anyone ask questions in plain English and get rendered results in minutes.

What This Does

This is a three-component deployment that turns natural language queries into satellite imagery analysis. The geoagent/ directory holds a Python agent built on Bedrock AgentCore Runtime with Claude Sonnet 4.6. It exposes tools for NDVI, NDWI, NBR computation, OSM boundary lookups, and Amazon Location Service geocoding — all orchestrated through geoagent/utils/tools.py and geoagent/utils/ndviutils.py.

The react-ui/ frontend provides a MapLibre GL map with a chat sidebar (ChatSidebar.tsx) and a split-pane comparison view (CompareView.tsx) for before/after analysis. The titiler-cdk/ stack deploys a TiTiler raster tile server, and frontend-cdk/ wires everything behind CloudFront with Cognito authentication. Deployment is fully scripted: the README gives a three-part walkthrough that takes roughly 15 minutes.

Real-World Use

A conservation analyst types "Compare water levels for Folsom Lake, California 2021 vs 2022." The agent geocodes the location, fetches two Sentinel-2 scenes, computes NDWI, and returns rendered tiles. The UI shows a side-by-side comparison in CompareView.tsx with the water index overlaid on true-color imagery. The use-cases/ directory contains three pre-built scenarios — Amazon deforestation, LA fires, and Lake Mead drought — each with config, geometry, and narrative files that demonstrate the workflow.

Code Health & Issues Medium — No test files detected anywhere in the repository. The agent logic in geoagent/utils/, the API handlers in react-ui/backend/src/index.ts, and the tool definitions have zero unit or integration tests. This makes regression risk high after any change. Medium — No CI/CD pipeline. No .github/ directory or CI config file exists. Deployment is manual via shell scripts (deploy.sh, deployfinch.sh). There is no automated gate for builds, linting, or security scanning. Low — Hardcoded credentials risk. The deployment workflow stores environment variables in shell session state and writes them to .env files (geo_agent/.env, react-ui/.env.example). If these files are accidentally committed or persist in CI logs, credentials could leak. Low — No version pinning in requirements.txt. The Python dependencies list packages without pinned versions, which can cause deployment failures when upstream releases break compatibility.

The Bottom Line

This is a well-structured, deployable demo that solves a real problem — making satellite imagery analysis accessible via natural language. The architecture is clean, the use cases are concrete, and the deployment scripts are thorough. It is not production-ready: the lack of tests and CI means every deployment is a manual gamble. Use it as a reference architecture or a prototype, but budget for testing and pipeline work before putting it in front of users.
