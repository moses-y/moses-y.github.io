device activity tracker

A phone number can reveal whether a device is active, in standby or offline (and more). This PoC demonstrates how delivery receipts + RTT timing leak sensitive device-activity patterns. (WhatsApp / Signal)

Forked from gommzystudio/device-activity-tracker

The Problem Organizations that rely on WhatsApp or Signal for confidential communications have no built‑in way to detect whether a target phone is actively being used, idle, or offline. An adversary can infer user behavior simply by measuring the round‑trip time (RTT) of delivery receipts, exposing privacy‑sensitive activity patterns.

What This Does The repository implements the proof‑of‑concept described in “Careless Whisper: Exploiting Silent Delivery Receipts to Monitor Users on Mobile Instant Messengers.”

Backend logic lives in src/ – src/server.ts starts an Express server, src/tracker.ts handles RTT probing, and src/signal-tracker.ts contains the WhatsApp‑specific probe implementation. The React front‑end in client/src/ (e.g., App.tsx, Dashboard.tsx, ContactCard.tsx) visualises real‑time RTTs, classifies the device state (online 🟢, standby 🟡, offline 🔴), and stores historical measurements. Dockerisation (Dockerfile, client/Dockerfile, docker-compose.yml) isolates both services, exposing the UI on CLIENTPORT (default 3000) and the API on BACKENDPORT (default 3001).

How To Use It Clone & prepare git clone https://github.com/gommzystudio/device-activity-tracker.git cd device-activity-tracker cp .env.example .env # edit .env if you need non‑default ports Run with Docker (recommended) docker compose up --build # builds both backend and React client

Access the UI at http://localhost:3000. The QR‑code flow for WhatsApp authentication is rendered automatically. Run manually (for development) npm install # installs root deps (none for backend) cd client && npm install && cd .. npm run start:server # executes src/server.ts via ts-node (see package.json scripts) npm run start:client # runs React dev server (client/src/index.tsx)

After the backend is listening, open the front‑end, scan the QR code, and enter the target phone number (e.g., 491701234567).

Real‑World Use A security‑research team can deploy the container on a dedicated monitoring host, point the UI to a list of test numbers, and collect activity timelines for risk assessments. Example workflow:

Start containers docker compose up -d

In a browser, navigate to http://localhost:3000 → Scan QR, add target number → Observe live RTT chart; export CSV via the UI (implemented in Dashboard.tsx)

The exported data can feed into SIEM dashboards to flag anomalous device‑state changes.

Code Health & Issues Medium – Missing CI/CD – No .github/workflows or other pipeline files; builds and tests are not gated automatically. Low – No lockfile – client/package.json and root package.json lack package-lock.json/pnpm-lock.yaml, making reproducible installs nondeterministic. Low – Limited test coverage – Only a single React component test (client/src/App.test.tsx) and setup file exist; core tracker logic (src/tracker.ts, src/signal-tracker.ts) is untested. Low – Secrets handling – .env.example hints at required variables (ports, possibly WhatsApp credentials) but the repo does not enforce validation; accidental commit of real secrets would be a risk. Low – Documentation gaps – README covers Docker usage but does not list required environment variables beyond ports, nor does it describe the expected format of WhatsApp authentication data. Info – License present – MIT license (LICENSE) is included, allowing commercial use with attribution.

The Bottom Line The project delivers a functional demonstration of RTT‑based device‑activity tracking for WhatsApp/Signal, with a usable UI and Docker deployment scripts. However, the lack of CI, lockfiles, and comprehensive tests limits confidence for production‑grade deployments. It is suitable for security researchers or proof‑of‑concept pilots, but organizations should harden the build pipeline, add unit/integration tests for the tracking core, and ensure secret management before any operational use.
