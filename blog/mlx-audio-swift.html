The Problem

Running modern speech models (TTS, STT, audio codecs) on Apple Silicon usually means bridging Python MLX code into a Swift app or shelling out to a server. That adds latency, packaging pain, and a second runtime. This repo is a native Swift SDK that runs those models directly on-device via MLX, so a macOS/iOS app can do text-to-speech, speech-to-text, and audio tokenization without leaving the process.

What This Does

mlx-audio-swift is a modular Swift package. Sources/MLXAudioCore holds base types, DSP helpers (DSP.swift), and audio session management (AudioSessionManager.swift). Sources/MLXAudioCodecs implements codecs — SNAC, Vocos, Mimi, Encodec, DACVAE — that convert audio to/from tokens. Sources/MLXAudioTTS implements TTS models (Soprano, Qwen3, LlamaTTS, PocketTTS, Marvis), and Sources/MLXAudioSTT implements ASR (GLMASR, Qwen3ASR). Examples/VoicesApp is a working SwiftUI app exercising TTS with voice selection.

Models load from HuggingFace Hub by name, e.g. SopranoModel.fromPretrained("mlx-community/Soprano-80M-bf16"). Generation is async and supports streaming via generateStream, yielding .token, .audio, and .info events.

How To Use It

Add the package via Swift Package Manager:

dependencies: [
    .package(url: "https://github.com/Blaizzy/mlx-audio-swift.git", branch: "main")
]

Import only what you need: MLXAudioTTS, MLXAudioCore, etc. No environment variables are required — models download automatically from HuggingFace. The Examples/VoicesApp needs its .xcconfig files; Local.xcconfig.template suggests copying it to Local.xcconfig for local keys. Requirements are macOS 14+ / iOS 17+ on Apple Silicon. There is no CLI entry point; usage is programmatic via the model APIs.

Real-World Use

A macOS dictation utility that transcribes microphone audio with GLMASRModel, then reads the result back with SopranoModel.generate(...), streaming tokens to a status label while audio plays through AudioPlayerManager. Both models run locally with no network round-trip after the initial HuggingFace download.

The Bottom Line

Solid, genuinely modular Swift SDK for on-device speech on Apple Silicon, with a real example app and CI. The duplicated codec layers and oversized model files will make adding a new model tedious, and the CI token posture needs hardening before this runs in shared repos. Best for Swift teams that want native, offline TTS/STT without a Python sidecar.
