The Problem: Teams managing Proxmox VE infrastructure face a fragmentation problem: raw API calls are low-level and error-prone, shell scripts lack discoverability, and custom glue code must be maintained separately for each operational workflow. This forces AI agents and automation operators to reconstruct authentication, error handling, and job tracking for every new task, increasing operational overhead and risk.

What This Does: ProxmoxMCP-Plus consolidates Proxmox VE control into two surfaces. The MCP surface (src/proxmoxmcp/server.py) exposes tools for LLM clients via the Model Context Protocol, while the OpenAPI surface provides HTTP endpoints for standard automation. Core operational workflows are implemented in src/proxmoxmcp/tools/ — including VM management (vm.py), snapshot handling (snapshots.py), backup operations (backup.py), and ISO handling (iso.py). Security and command policy are enforced through src/proxmoxmcp/security/commandpolicy.py, and job tracking with progress polling is managed by src/proxmoxmcp/services/jobs.py. Configuration is read from proxmox-config/config.json, with example setup in proxmox-config/config.example.json.

How To Use It: Setup begins by copying the example configuration: cp proxmox-config/config.example.json proxmox-config/config.json

Then edit proxmox-config/config.json with Proxmox host, port, authentication credentials, and optional SSH/job settings. Install dependencies via: pip install -r requirements.txt or via the pip package pip install proxmox-mcp-plus

The entry point is src/proxmoxmcp/server.py, which can be started with the configured Proxmox connection. For Docker deployments, the Dockerfile and docker-compose.yml provide containerized execution.

Real-World Use: A common scenario is automated snapshot rollback after a failed update. An LLM agent can invoke the createsnapshot and rollbacksnapshot tools from src/proxmoxmcp/tools/snapshots.py, which return a Job ID that src/proxmoxmcp/services/jobs.py polls for completion. If the update fails, the agent calls rollbacksnapshot using the saved Job ID to restore the prior state, with all actions auditable through the job tracking system.

Input validation flows through src/proxmoxmcp/tools/definitions.py and the command policy in src/proxmoxmcp/security/commandpolicy.py, but the depth of validation across all tool entry points should be verified case-by-case.
