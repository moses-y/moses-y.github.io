The Problem

AI coding assistants typically operate as black boxes with opaque permission models and remote telemetry. Teams needing local, auditable code automation require control over which models handle their code, what operations are permitted (file writes, shell commands, network access), and durable session persistence without external dependency.

What This Does

Zero is a terminal-based coding agent that runs locally and respects explicit permission boundaries. The core agent logic resides in internal/agent/ (140+ files), handling loop execution, permission validation, compaction, and task state management. A permission system (internal/acp/) governs file writes, shell commands, and network access through escalation policies and guardrails. The cmd/ directory provides 17 CLI entry points, including zero/main.go for the TUI interface and zero-linux-sandbox/main.go for native sandboxing on Linux. Sessions are stored on disk and are searchable, resumable, and explicitly not uploaded as telemetry by Zero.

How To Use It

Setup: Three paths are documented. For immediate evaluation: go run ./cmd/zero (requires Go 1.26.5+ per go.mod). For production deployment, the npm wrapper npm install -g @gitlawb/zero installs a platform-specific binary from GitHub Releases. Alternatively, make targets in the root Makefile provide build shortcuts: go build -o zero ./cmd/zero and go build -o zero-linux-sandbox ./cmd/zero-linux-sandbox.

Configuration: Provider and model selection occurs through the TUI setup wizard or via zero se command. Environment variables and provider keys are managed per the chosen provider (25+ supported including OpenAI, Anthropic, Gemini, Ollama). The go.mod and go.sum files pin dependencies; no .env or secret files are present in the repository.

Running it: The primary entry is zero for interactive TUI use, or zero exec "fix the failing test in ./pkg" for scriptable runs. The zero exec command supports --output-format stream-json for JSON-lined tool output, and isolated worktrees for spec-first CI runs.

Real-World Use

A developer can clone a repository and run zero to enter the TUI, where they select a model provider and begin an editing session. The agent inspects the repo structure, proposes edits, and each write operation passes through the permission gate defined in internal/acp/permission.go. For CI integration, zero exec --output-format stream-json < turns.jsonl enables headless runs that exit with meaningful codes for pipeline integration. Teams can fork and audit the internal/agent/ logic to verify no code leaves the local environment.

Code Health & Issues

Tests & CI: 104 test files exist across internal/agent/, internal/agenteval/, and cmd/ subcommand test files. GitHub Actions workflows (.github/workflows/ci.yml, pr-auto-review.yml, etc.) run on pull requests. License: MIT license declared in LICENSE and referenced via badge in README.md. Dependency hygiene: go.mod and go.sum are present and version-pinned; no obvious vulnerable dependencies detected at the module level. Structural organization: Clear separation between internal/agent (core logic), internal/acp (permission/contract layer), internal/agenteval (evaluation/benchmarking), and cmd/ (CLI entry points). No structural red flags: Tests/CI/license/lockfile are present where expected. The codebase demonstrates disciplined Go module practices.

The Bottom Line

Zero offers a rare combination of local execution, model-agnostic flexibility, and explicit permission boundaries for teams that cannot send code to remote APIs. The extensive test coverage (104 files), active CI configuration, and permissive MIT license suggest a mature, auditable codebase. It is well-suited for individual developers or security-conscious teams needing a self-hosted coding agent that respects local boundaries
