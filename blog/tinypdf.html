tinypdf

Minimal PDF creation library. <400 LOC, zero dependencies, makes real PDFs.

Forked from Lulzx/tinypdf

The Problem

Generating PDFs programmatically usually means pulling in a heavy dependency like jsPDF (229 KB, 2 dependencies) or pdf-lib. For the common case—putting text, shapes, and JPEG images on a page—that's a lot of overhead. tinypdf targets that 95% use case with zero dependencies and a 3.3 KB footprint.

What This Does

tinypdf is a minimal PDF creation library written in TypeScript. The core implementation lives in src/index.ts (under 400 LOC) and exports three functions: pdf() for document creation, measureText() for width calculation, and markdown() for converting markdown to PDF. A test suite in src/index.test.ts covers the main API.

The library supports text (Helvetica, hex colors, alignment), rectangles, lines, JPEG images, clickable links, multi-page documents, and custom page sizes. It deliberately excludes custom fonts, PNG/SVG, forms, encryption, and compression. The buildStream() method emits a ReadableStream<Uint8Array> for documents too large to hold in memory.

How To Use It

Setup: Install via npm. The package.json declares no runtime dependencies; bun.lock is present for the Bun package manager.

npm install tinypdf

Running it: Import the pdf function from src/index.ts and build a document. The README documents the full API:

import { pdf } from 'tinypdf' import { writeFileSync } from 'fs'

const doc = pdf() doc.page((ctx) => { ctx.rect(50, 700, 200, 40, '#2563eb') ctx.text('Hello PDF!', 60, 712, 24, { color: '#ffffff' }) ctx.line(50, 680, 250, 680, '#000000', 1) }) writeFileSync('output.pdf', doc.build())

There is no CLI or server component; this is a library consumed programmatically. The examples/invoice.ts and examples/showcase.ts files show realistic usage.

Real-World Use

This fits server-side document generation: invoices, receipts, shipping labels, tickets, certificates, and reports. A typical workflow is an API endpoint that receives order data, builds a PDF with tinypdf, and returns it as an HTTP response via buildStream(). The markdown-to-PDF function covers quick formatting with headers, lists, and rules.

Code Health & Issues Med - No CI/CD pipeline - No .github/ or CI config exists, so there's no automated build/test gate. The test suite in src/index.test.ts runs only when a developer invokes it locally. Low - No lockfile for npm - bun.lock is present, but no package-lock.json or pnpm-lock.yaml. Since there are zero runtime dependencies, this is a minor concern. Low - No input validation - The API accepts raw coordinates, colors, and JPEG bytes without visible validation. Malformed input (e.g., non-hex color strings, out-of-bounds coordinates) could produce corrupt PDFs rather than clear errors. Low - Narrow image support - JPEG only. PNG, a common format for logos and screenshots, is unsupported and will fail silently or produce a broken document.

The codebase is small and focused, which mitigates several structural risks. The test file exists and the README documents behavior clearly.

The Bottom Line

tinypdf is a well-scoped, zero-dependency library that solves the common PDF generation case with a fraction of the footprint of alternatives. It is not a general-purpose PDF tool—no custom fonts, PNG, or forms—so evaluate whether your requirements fit before adopting it. For straightforward text-and-image documents, it is a solid, lightweight choice.
