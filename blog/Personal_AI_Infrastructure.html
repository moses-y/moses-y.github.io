The Problem

This repository represents four self-contained projects—Releases, Packs, Tools, and Bundles—rather than a unified codebase. At 1,548 files with 2137 functions and 622 classes across TypeScript, Vue, and Shell, the structure reflects a portfolio of AI-enabled tools rather than a single product. For a technical client, the challenge is navigating this fragmented architecture to identify where value can be extracted or risk managed.

What This Does

The repository organizes around four domains: Releases (955 files, 187 code files) distributes versioned AI skill packages; Packs (541 files, 156 code files) contains modular skill implementations including browser automation, agent frameworks, and observability; Tools (10 files, 4 code files) provides CLI and hook-system utilities; and Bundles (5 files, 1 code file) offers opinionated installations. Recurring techniques across projects include browser-skill patterns (iframeClick/iframeFill in Packs/pai-browser-skill/src/skills/Browser/index.ts), hook-system orchestration (Packs/pai-hook-system/src/hooks/lib/IdealState.ts), and agent factory logic (Packs/pai-agents-skill/src/skills/Agents/Tools/AgentFactory.ts). The code touches databases (7 functions), files (11 functions), models (5 functions via replicate.run/anthropic), and outbound networks (3 functions).

How To Use It

Setup: No Dockerfile or single build command exists across the four projects. Each project requires its own package management—the package.json files in Packs/pai-agents-skill/src/skills/Agents/Tools/, Packs/pai-browser-skill/src/skills/Browser/, and Packs/pai-observability-server/src/Observability/apps/client/ imply pnpm or npm install steps. No lockfile is committed; verify dependency reproducibility before production use.

Configuration: Environment variables are defined in .env.example at the root. The observability server requires database setup referenced in its package.json and vite.config.ts configs. Browser-skill packs reference Claude Code API tokens in .github/workflows/claude.yml.

Running it: To invoke the primary entry point, execute the main function from Bundles/Official/install.ts. For pack development, use the individual pack directories' build scripts. For observability, start the server from Packs/pai-observability-server/src/Observability/apps/server/src/index.ts.

Real-World Use

The Bottom Line

This is a portfolio-grade collection of four loosely coupled AI infrastructure projects rather than a single product. The browser-skill and hook-system patterns are the most reusable technical assets, and the code health audit reveals significant SDLC gaps: unpinned GitHub Actions, missing lockfile, minimal test coverage, and committed secrets in fork-triggerable workflows. Teams seeking modular AI skill packs with browser automation capabilities can extract value here, but should expect to establish their own CI/CD, dependency management, and secret-handling practices. The repository is best suited for organizations wanting to assemble custom AI tooling from proven primitives, not those needing an out-of-the-box integrated system.
