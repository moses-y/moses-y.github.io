GEA

Group Evolving Agents: Open-Ended Self-Improvement via Experience Sharing

Forked from UCSB-AI/GEA

The Problem

Software agents that write code typically operate in isolation. Each agent starts from the same base prompt, attempts a task, and either succeeds or fails without learning from other agents' attempts. This wastes successful strategies and repeats known failures. GEA addresses this by treating a group of agents as a single evolutionary unit, allowing them to share experiences and improve collectively over time.

What This Does

GEA is a research framework for open-ended self-improvement of coding agents. The core loop is implemented in GEAouter.py, the entry point, which orchestrates a group of agents working on SWE-bench tasks. Each agent attempts to fix real GitHub issues from Django and Sphinx, producing patches stored under initial/predictions/. The codingagent.py file defines the base agent behavior—how it reads a task, generates a patch, and writes results.

The system evaluates each patch against the target repository's test suite, with results logged in initial/logs/runevaluation/. Successful patches and their associated reasoning are then shared back into the group's collective experience, which subsequent agents use to inform their own attempts. This experience-sharing mechanism is the key differentiator from single-agent self-improvement approaches. The project builds on the Darwin Gödel Machine and uses SWE-bench and Polyglot benchmarks for evaluation.

How To Use It

Setup: Requires Python 3, Docker, and API keys for OpenAI and Anthropic. The README documents a standard venv + pip install -r requirements.txt flow. Docker must be functional (docker run hello-world). The SWE-bench dependency is cloned and installed separately.

Configuration: Set OPENAIAPIKEY and ANTHROPICAPIKEY as environment variables in ~/.bashrc.

Running: Execute python GEAouter.py from the repo root.

export OPENAIAPIKEY='...' export ANTHROPICAPIKEY='...' python3 -m venv venv source venv/bin/activate pip install -r requirements.txt cd swebench && git clone https://github.com/princeton-nlp/SWE-bench.git && cd SWE-bench && git checkout dc4c087c2b9e4cefebf2e3d201d27e36 && pip install -e . && cd ../../ python GEAouter.py

Real-World Use

This is a research tool, not a production service. A practical use case: an ML research team studying multi-agent coordination and self-improvement. They would run GEA on a subset of SWE-bench tasks, inspect the generated patches under initial/predictions/ to see how well agents solve real bugs, and analyze the experience-sharing dynamics to understand when group collaboration helps versus when it adds overhead. The analysis/ scripts support plotting and quantitative evaluation of these runs.

Code Health & Issues Medium - No CI/CD pipeline: No .github/ or CI config exists. The 42 test files are evaluation scripts for SWE-bench tasks, not unit tests for the GEA framework itself. Changes to GEAouter.py or codingagent.py have no automated gate. Medium - Heavy Docker coupling: The entire evaluation pipeline runs inside Docker containers per task. This makes the system resource-intensive (one container per bug) and fragile if Docker is unavailable or misconfigured in a deployment environment. Low - Repository hygiene: The repo contains 191 files of evaluation logs and predictions under initial/, which inflates the repo size and mixes generated artifacts with source code. These should be gitignored or stored separately. Low - Research-stage maturity: The paper is on arXiv and the codebase is built on a prior research project (DGM). Expect rough edges in error handling and configuration, and no production hardening.

The Bottom Line

GEA is a legitimate research contribution to multi-agent self-improvement, with a clear architecture and reproducible evaluation pipeline. It is not production software—no CI, no unit tests, heavy Docker use, and research-grade code quality. Use it if you are studying agent coordination or open-ended self-improvement; skip it if you need a maintainable agent framework for real workloads.
