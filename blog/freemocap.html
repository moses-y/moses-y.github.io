The Problem

Freemocap is a motion capture system with a complex interdependent codebase where circular imports span three modules in the path-and-filenames subsystem, and a 1,728-line calibration file creates a single point of failure for any change involving camera setup. The project's entry points touch 132+ functions each, meaning a modification to calibration or recording flow ripples across the entire system.

What This Does

The repository contains three sub-projects: freemocap (176 files, the core package), experimental (91 files, including a React UI and benchmarks), and ipython_jupyter_notebooks (4 notebooks). Primary frameworks are React, Flask, FastAPI, OpenCV, and YOLO, with Python (179 files) and TypeScript/TSX (44 files) as the dominant languages. The package is installable via pip install -e . from a pyproject.toml and launches through python -m freemocap or the freemocap CLI script.

How It Is Wired

Execution flows from main → qt_gui_main → get_freemocap_data_folder_path [filesystem via freemocap_data_folder_path.mkdir], or from run → save_dictionary_to_json [filesystem via json_file_path.write_text]. The path-and-filenames subsystem forms a cycle: file_and_folder_names.py ←→ path_getters.py ←→ save_and_load_gui_state.py, meaning any import change in one propagates to the others. The freemocap_main_window widget orchestrates session start/stop, video handling, and signal callbacks, while recording_info_model owns per-session state (active_tracker, file_prefix, path). Calibration work funnels through freemocap_anipose.py, which is called from 8 other files and itself contains the deepest nesting and broadest exception handling. The UI service layer (experimental/react_fastapi/) provides FastAPI endpoints for camera detection and WebSocket frame streaming, but the core processing pipeline (freemocap/core_processes/process_motion_capture_videos/) handles YOLO-based video tracking, folder-level recording, and headless processing. Duplicated 6-line blocks appear in 12 files across the benchmark and process modules, indicating shared logic that could be extracted into helpers.

How To Use It

Setup: Create a Python 3.10–3.12 environment (3.11 recommended) and install the package in editable mode:

conda create -n freemocap-env python=3.11
conda activate freemocap-env
git clone https://github.com/moses-y/freemocap
cd freemocap
pip install -e .

Configuration: No environment variables or secret keys are required for basic operation. The freemocap/system/paths_and_filenames/path_getters.py module resolves data-folder paths at runtime. The freemocap/utilities/download_sample_data.py makes outbound network calls if sample datasets are needed.

Running it: Launch the GUI:

python -m freemocap

or use the CLI script freemocap after installation. For headless processing of a recording folder:

python -m freemocap --headless <folder_path>

Real-World Use

A research team needing to process video recordings of marker-based motion capture can clone the repo, install in a conda environment, and use the GUI to select video folders. The system auto-detects cameras via YOLO/OpenCV, runs triangulation through freemocap_anipose.py, and saves skeleton data as NumPy arrays. For automated pipelines, the headless entry point processes folders without UI interaction, outputting calibrated 3D data ready for downstream analysis. The process_recording_folder function handles event-driven cancellation via KillEventException, enabling integration into scheduled jobs.

The Bottom Line

Freemocap is a functional, well-structured motion capture system with a capable GUI and headless pipeline, but its circular imports, outsized calibration module, and sparse test coverage mean changes to core flow require careful ripple analysis. It's suitable for research teams willing to invest in understanding the dependency graph, but not for teams needing rapid, safe iteration on calibration or recording logic without risk of hidden breakage.
