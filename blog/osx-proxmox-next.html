osx proxmox next

One-command macOS VM on Proxmox 9 — TUI wizard, auto-download, AMD+Intel, Sonoma/Sequoia/Tahoe

Forked from lucid-fabrics/osx-proxmox-next

The Problem Setting up a macOS virtual machine on Proxmox currently requires manual OpenCore configuration, SMBIOS generation, ISO handling, and a series of error‑prone qm commands. Users spend several hours troubleshooting each new VM, and the process is not reproducible without careful note‑taking.

What This Does osx-proxmox-next replaces the manual workflow with a guided, six‑step TUI wizard that runs directly on the Proxmox host. The core logic lives in the Python package under src/osxproxmoxnext/:

app.py – orchestrates the wizard flow and ties UI screens together. cli.py – provides the command‑line entry point (osx-next-cli) used by the documentation and CI. Service modules such as proxmoxservice.py, downloadservice.py, and preflightservice.py encapsulate interactions with the Proxmox API, remote file retrieval, and hardware detection.

Documentation and assets for the wizard are stored in docs/, which is built with Docusaurus (docs/package.json, docs/tsconfig.json). The repository also ships a thin installer script (install.sh) and a convenience wrapper (scripts/osx-proxmox-next.sh) that invoke the Python CLI after installing dependencies.

How To Use It Clone & Install – The project uses a standard pyproject.toml build system. From a clean environment:

git clone https://github.com/lucid-fabrics/osx-proxmox-next.git cd osx-proxmox-next # Install Python dependencies (uses pip by default) pip install -e . # Optional: install the documentation tooling if you need the web UI cd docs && npm ci && cd -

The root install.sh performs the same steps and also verifies that npm is available for the docs site. Configuration – The CLI reads Proxmox connection details from command‑line flags or environment variables (PROXMOXHOST, PROXMOXUSER, PROXMOXTOKEN). Additional options (ISO storage location, macOS version, Apple‑services enablement) are documented in docs/docs/guides/cli-reference.md. No hard‑coded secrets are present in the repository. Run the Wizard – Execute the entry point:

osx-next-cli wizard # launches the TUI wizard

Alternatively, the wrapper script can be used:

scripts/osx-proxmox-next.sh wizard

The wizard walks through pre‑flight checks, OS selection, storage configuration, VM creation parameters, a dry‑run preview of the generated qm commands, and finally the automated installation. Post‑install Checks – The doctor sub‑command validates the newly created VM:

osx-next-cli doctor --vmid <VMID>

See docs/docs/guides/cli-reference.md for the full flag set.

Real‑World Use A sysadmin managing a homelab with a Proxmox 9 cluster can automate macOS CI agents:

Create a VM for a nightly macOS build osx-next-cli wizard --os sonoma --cpu auto --ram 8G --iso-dir local:isos \ --dry-run false --apple-services true Verify health osx-next-cli doctor --vmid 105

The wizard handles OpenCore download, SMBIOS generation, and storage provisioning, leaving the admin with a ready‑to‑run macOS node in under ten minutes.

Code Health & Issues Low – No LICENSE file – repository root lacks a license, making redistribution uncertain. Medium – Limited runtime validation – service modules (e.g., proxmox_service.py) assume successful API responses; missing explicit error handling could cause uncaught exceptions on network failures. Low – Test coverage – 31 test files exercise most modules, and GitHub Actions (.github/workflows/test.yml) run the suite on each PR, indicating a healthy CI pipeline. Low – Dependency hygiene – Python dependencies are defined in pyproject.toml; however, the Node side (docs/package.json) is not pinned with a lockfile beyond package-lock.json, which could lead to reproducibility issues for the docs site. Low – Documentation completeness – The Docusaurus site provides step‑by‑step guides, but there is no generated API reference for the Python package, which could hinder deeper integrations.

The Bottom Line osx-proxmox-next delivers a functional, well‑tested automation layer that reduces macOS VM provisioning on Proxmox from hours to minutes. The codebase is organized, has solid test coverage, and includes CI. The primary concerns are the missing license and modest error handling around external API calls. Teams that need repeatable macOS VM creation on Proxmox will find the tool immediately valuable; solo users should be comfortable reviewing the small gaps before production use.
