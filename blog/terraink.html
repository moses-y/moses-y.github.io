The Problem

This repository lacks automated quality gates: no test suite, no CI/CD pipeline, and no dependency lockfile means changes ship without signal that existing behavior is preserved, and builds are non-reproducible across environments.

What This Does

TerraInk is a cartographic poster engine that generates custom city map posters from OpenStreetMap data. Users search locations via geocoding, select or build themes through a color palette system, and export high-resolution PNG posters at defined dimensions. The source lives primarily in src/ (130 files), with 117 TypeScript and 42 TSX files handling theming (src/features/theme/), map rendering (src/features/map/), markers (src/features/markers/), and export pipelines (src/features/export/). Poster generation flows through src/core/http/index.ts for API calls and src/core/cache/ for local storage. Two functions make outbound network calls (nominatimAdapter.searchLocations, nominatimAdapter.geocodeLocation) and one writes files (pdfExporter pipeline). The project uses Bun as its runtime, Vite for dev/build, and MapLibre GL for vector tile rendering.

How To Use It

Setup: bun install (bun.lock present; project uses Bun as runtime). Configuration: No environment variables are required for basic operation; src/core/config.ts centralizes project config. Running it: bun run dev (via vite.config.js) starts the development server; bun run build produces a production build. The app runs at http://localhost:5173. Exporting: Use the export UI (src/features/export/ui/) or invoke compositeExport programmatically from src/features/poster/infrastructure/renderer/index.ts.

Note: The README documents these commands verbatim.

Real-World Use

A user opens the app, searches “Austin, TX” via the geocoder (src/features/location/infrastructure/nominatimAdapter.ts), selects a curated theme or defines a custom palette using the src/features/theme/ui/ColorPicker.tsx, adjusts map layer visibility and typography controls, then clicks “Export Poster.” The system geocodes the location, renders the MapLibre vector map with selected styles, overlays text with chosen Google Fonts, and writes a PNG file via the pdfExporter/pngExporter pipeline. The result is a print-ready city map poster at the specified dimensions.

The Bottom Line

The codebase is functional and well-structured for a solo developer project, with a clear feature set and a working map-rendering pipeline. However, the absence of tests, CI, and a lockfile makes it unsuitable for team or production use without significant investment in quality gates. It’s appropriate for individual exploration or forking with the intention to add those gates; teams should expect to implement a test suite, CI workflow, and pinned Docker bases before shipping changes confidently.
