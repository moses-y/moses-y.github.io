The Problem: Ari addresses the pain point of customers needing immediate order status or return policy answers without waiting for human agent availability. The chatbot autonomously interprets intent via Google Gemini, queries the database using SQLAlchemy, and references policy data, all through a Gradio interface. This reduces support load for routine inquiries while maintaining accurate, data-driven responses.

What This Does: The system routes user queries through intent-specific agents located in src/agents/, each backed by dedicated services in src/services/. src/llm/geminiservice.py handles LLM calls, while src/db/database.py manages SQLAlchemy model interactions and database schema defined in src/db/models.py. Order status lookups flow through src/agents/orderstatusagent.py and src/services/orderservice.py, return policy queries use src/agents/returnpolicyagent.py with data/policies.json, and human handoff is coordinated by src/agents/humanrepagent.py via src/services/contactservice.py. Conversation state is managed by src/core/conversation.py and src/core/state.py, feeding into the Gradio UI at src/ui/gradioapp.py.

How To Use It: Clone the repo, then: git clone https://github.com/moses-y/ecommerce-chatbot.git cd ecommerce-chatbot python -m venv venv && source venv/bin/activate pip install -r requirements.txt

Create a .env file based on .env.example and add your Google Gemini API key. Run the app with: python app.py

or build and run via Docker using docker-compose.yml and the provided Dockerfile. The entry point is app.py, which initializes the conversation flow and launches the Gradio interface.

Real-World Use: A customer messages Ari: "What’s the status of order A1B2C3D4?" The chatbot detects the intent via geminiservice.py, triggers orderstatusagent.py, which calls orderservice.py to query the database through SQLAlchemy models in src/db/models.py. The resulting status is returned instantly in the Gradio chat window. For return questions, the flow reads from data/policies.json via policyservice.py. A minimal code snippet of the intent-to-action flow is represented by the agent routing in src/agents/baseagent.py and the conversation manager in src/core/conversation.py.

Code Health & Issues: Low - Dependencies declared in requirements.txt without a lockfile (e.g., requirements.lock or uv.lock), risking non-reproducible builds across environments. Med - No input validation before database queries in agent routes; unvalidated user IDs or order IDs could cause SQL errors or injection risks if SQLAlchemy ORM usage isn't strictly parameterized.
