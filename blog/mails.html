The Problem

AI agents that need to communicate via email must handle sending, receiving, attachment parsing, and searchable storage without writing bespoke SMTP/IMAP code. Most SDKs are heavyweight or tied to a single provider, making it hard to swap back‑ends or run offline.

What This Does

mails implements a lightweight email layer for agents. The CLI entry point lives in src/cli/index.ts and forwards commands to core modules such as src/core/send.ts, src/core/receive.ts, and src/core/storage.ts. Provider logic is isolated under src/providers/ (e.g., src/providers/send/cloudflare.ts, src/providers/send/resend.ts, src/providers/storage/sqlite.ts).

A Cloudflare Worker (worker/src/index.ts) acts as the inbound routing service and optionally as a remote API for self‑hosted deployments. The worker bundles its own providers (worker/src/providers/) and database migrations (worker/migrations/0001addprovidercolumn.sql).

All TypeScript source files (66) compile via the tsconfig.json at the repo root for the CLI and worker/tsconfig.json for the Worker.

How To Use It

Setup

Install globally (npm) or with bun npm install -g mails # or bun install -g mails One‑off execution without install npx mails

The package.json scripts are not defined, so the CLI is the only built artifact.

Configuration

Copy the example env file and fill in the required keys:

cp .env.example .env edit .env EMAILPROVIDERS=cloudflare,resend CLOUDLARIFYAPIKEY=… RESENDAPIKEY=…

The CLI reads this via src/core/config.ts. Provider order can be overridden with the EMAILPROVIDERS variable.

Running the CLI

Typical commands are defined in src/cli/commands/:

CommandFilePurpose
mails sendsrc/cli/commands/send.tsSend an email, supports --to, --subject, --body, --attach
mails inboxsrc/cli/commands/inbox.tsList stored messages with keyword search
mails claimsrc/cli/commands/claim.tsClaim a free @mails.dev mailbox (hosted service)
mails syncsrc/cli/commands/sync.tsPull remote inbox into local storage

Invoke any command directly, e.g.:

mails send --to user@example.com --subject "Hello" --body "Test" --attach ./file.pdf

Deploying a Self‑Hosted Worker

cd worker npm install # or bun install – uses worker/package.json npx wrangler publish # requires wrangler.toml in worker/

The Worker reads its own env vars from worker/.dev.vars.example (e.g., RESENDAPIKEY). After deployment, point the CLI to the remote endpoint by setting MAILSAPI_URL (handled in src/core/api-url.ts).

Real‑World Use

An autonomous sales‑assistant agent can claim a mailbox (mails claim), send prospect outreach (mails send), and later retrieve replies (mails inbox --search "meeting"). The agent extracts verification codes using src/core/types.ts utilities, which are exercised in test/unit/extract-code.test.ts. All interactions are logged in the local SQLite DB (src/providers/storage/sqlite.ts) for offline analysis.

import { send, inbox } from "mails";

await send({ to: "lead@company.com", subject: "Intro", body: "…" }); const replies = await inbox({ query: "meeting" });

Code Health & Issues

Low – Missing LICENSE file – repository root lacks a LICENSE, despite badge in README; legal reuse unclear. Low – No npm lockfile – package.json present but no package-lock.json or pnpm-lock.yaml, which can cause non‑reproducible installs for npm users. Medium – Environment‑variable exposure – .env.example shows required secrets, but no runtime validation in src/core/config.ts; missing explicit error messages for absent keys. Medium – Worker CI missing – GitHub Actions workflow (.github/workflows/release.yml) only builds a release; there is no test step for the Worker, so worker/src/ code is not exercised automatically. Low – Duplicate lockfile formats – Both bun.lock (root) and worker/bun.lock exist; using npm vs. bun may lead to version drift. Low – Documentation gaps – README covers CLI usage but does not document required Cloudflare binding (env.EMAIL.send) or self‑hosted token flow; the latter is only hinted at in docs/.

Overall, the test suite is extensive (35 files, covering CLI, core, and e2e flows) and passes locally, indicating good functional coverage.

The Bottom Line

mails provides a focused, provider‑agnostic email stack for AI agents, with a usable CLI and a Cloudflare Worker for inbound routing. The code is well‑structured and heavily tested, but the lack of a clear license, missing npm lockfile, and limited CI for the Worker are practical concerns. Teams that need programmable email with optional self‑hosting can adopt it quickly, provided they perform their own security review and add a license file.
