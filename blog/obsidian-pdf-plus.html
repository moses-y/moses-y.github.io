The Problem

Obsidian's built-in PDF viewer is read-only. Users who want to annotate PDFs must either leave Obsidian for external tools like Zotero, or install plugins that store annotations in proprietary JSON formats—data that becomes unreadable if the plugin breaks. Obsidian PDF++ solves this by making PDF annotations native to Obsidian's markdown workflow: highlights are created by linking to text selections, and sidenotes are stored as pure markdown files.

What This Does

PDF++ is an Obsidian plugin that extends the native PDF viewer rather than replacing it. The core mechanism lives in src/lib/highlights/—it transforms backlinks to PDF files into highlight annotations, with geometry calculation in geometry.ts and extraction logic in extract.ts. Annotations can be distributed across the vault instead of being confined to a single file.

The plugin also ships a substantial Vim keybinding layer (src/vim/—13 files covering modes, search, visual selection, and ex-commands) and quality-of-life improvements to the PDF viewer. The src/patchers/ directory (9 files) shows this is a deep integration: it patches Obsidian's internal PDF view, workspace, and clipboard manager. The README is explicit that this relies on private Obsidian APIs, so updates to Obsidian carry a real breakage risk.

How To Use It

Setup: The repo is an Obsidian plugin, not a standalone app. Install from Obsidian's community plugins list (search "PDF++"). For development, the package.json implies pnpm; build with pnpm install && pnpm run build.

Configuration: No environment variables. Settings are managed through Obsidian's settings UI and stored in the vault's .obsidian directory. Some features require the Style Settings plugin. The manifest.json declares plugin metadata and minimum Obsidian version.

Running it: Copy the built main.js, manifest.json, and styles.css into your vault's .obsidian/plugins/pdf-plus/ directory and enable it in Obsidian's community plugins settings. The entry point is src/main.ts.

Real-World Use

A researcher maintains a literature review in Obsidian. They open a PDF in Obsidian's viewer, select a passage, and link it to a note. The note is pure markdown—it contains a link with optional &color= or &rect= parameters—so the annotation survives even if the plugin is removed. They can also write annotations directly into the PDF file for sharing outside Obsidian, though the README notes limitations with this approach.

Code Health & Issues

High – No tests detected: No test files anywhere in the repo. Given the plugin patches Obsidian's private APIs (src/patchers/), untested paths are a genuine risk. The CI workflows (.github/workflows/) handle releases and issue validation but contain no test step. Med – Private API dependency: The README itself warns this breaks when Obsidian updates. This is an architectural constraint, not a bug, but it means the plugin requires active maintenance. Med – Large surface area: 80 TypeScript files covering highlights, Vim emulation, PDF composition, and backlink patching. The v1.0.0 refactor mentioned in the README suggests the author is aware of maintainability pressure. Low – Documentation gap: The README points to external docs that are "still a work in progress." The src/lib/ directory has no inline documentation beyond what the code provides.

The Bottom Line

PDF++ is a serious, well-architected plugin for a real pain point, and its markdown-native annotation approach is genuinely better than proprietary alternatives. The lack of tests and reliance on Obsidian's private APIs are real risks, but the author's stated commitment to a 1.0.0 refactor suggests awareness. Use it if you live in Obsidian and need PDF annotations that won't lock you in—just budget for occasional breakage when Obsidian updates.
