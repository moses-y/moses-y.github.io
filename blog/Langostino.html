The Problem

Building a real autonomous drone requires integrating flight controllers, sensors, AI models, and communication protocols—all running reliably on embedded hardware. Most open-source drone projects focus on either simulation or basic manual flight. There is no turnkey reference implementation that connects an AI flight policy to a physical drone's MSP (MultiWii Serial Protocol) interface with safety monitoring, sensor fusion, and emergency recovery built in.

What This Does

Langostino is a complete ROS2-based drone autonomy stack that runs on a Raspberry Pi onboard a physical quadcopter. The core system lives in src/swarmaiintegration/ and consists of eight ROS2 nodes that handle the full autonomy pipeline: fccommsnode.py manages serial communication with the flight controller, fcadapternode.py translates between MSP and ROS2 messages, lidarreadernode.py ingests sensor data, and aiflightnode.py runs the AI policy that outputs control commands. The safetymonitornode.py provides watchdog-style failsafes, and blackboxrecordernode.py logs telemetry for post-flight analysis.

The drone uses a custom INav firmware (inav-custom-firmware/inav8.0.1SPEEDYBEEF405V4.hex) with MSP override support enabled, allowing the AI system to inject attitude and throttle commands while the flight controller handles low-level stabilization. The utils/ directory contains modular components for altitude hold, yaw alignment, emergency landing, and coordinate transforms—each implemented as a separate Python module with clear interfaces.

Real-World Use

A developer building an autonomous delivery drone could take Langostino's hardware BOM, 3D-print the frame parts from assets/3DprintSTL/, flash the custom INav firmware, and deploy the ROS2 stack on a Raspberry Pi 5. The system is designed to accept any AI policy that outputs normalized roll, pitch, yaw, and throttle values. A typical workflow: run scripts/launch.sh to start all nodes, observe telemetry via the debug logger, and iterate on the AI model in aiflightnode.py without touching the flight controller interface.

Code Health & Issues

Medium - Missing CI/CD pipeline: No .github/ directory or CI configuration found. No automated build or test gate exists, which means regressions in the ROS2 node interfaces or MSP protocol handling could go undetected. Low - No dependency lockfile: requirements.txt and mapproxy/requirements.txt declare dependencies without pinned versions or a lockfile. Builds are not reproducible across environments. Medium - Untested safety-critical code: The safetymonitornode.py and emergencylanding.py modules have no dedicated test files. Given these handle failsafe behavior on a physical drone, this is a risk. Low - Stale test files: The two test files (rollflighttest.py, simpleflighttest.py) are in a tests/ directory but there is no test runner configuration or evidence they are executed regularly. Low - Large binary in repo: model/UID_3.zip (likely a trained AI model) is checked into version control. Binary assets should be managed separately or use Git LFS.

The Bottom Line

Langostino is the most complete open-source reference for connecting an AI flight policy to a real drone via MSP. The architecture is cleanly modular, the documentation is thorough, and the project includes working hardware designs and firmware. The lack of CI and test coverage for safety-critical code means this is better suited as a reference implementation or starting point than a production-ready system. Teams building autonomous drone prototypes should fork this, add their own AI policy, and invest in testing before flight.
