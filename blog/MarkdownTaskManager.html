Technical Briefing: MarkdownTaskManager

The Problem

Teams needing a task tracking system often require database setup, server infrastructure, or cloud dependencies. This introduces overhead for small teams, distributed workers, or offline scenarios. The constraint is finding task management that remains versionable, syncable, and editable with standard tools without external services.

What This Does

MarkdownTaskManager is a standalone web application contained in a single HTML file (task-manager.html) that uses the browser's File System Access API to read and write local Markdown files. The data files are kanban.md for active tasks and archive.md for completed work. The interface transforms these Markdown files into an interactive Kanban board with columns for To Do, In Progress, and Done, plus filtering and project management capabilities. The application runs entirely client-side in Chrome 86+, Edge 86+, or Opera 72+—Firefox and Safari are not supported due to File System API limitations. Source files include kanban.md and archive.md markdown templates, README.md and readmeFR.md documentation, and example configurations in examples/.

How To Use It

Setup: Copy task-manager.html to your project directory alongside kanban.md and archive.md. The README provides minimal markdown templates for both files specifying configuration sections for columns, categories, users, and tags. Open task-manager.html in a compatible browser, select the containing folder on first launch, and the application will initialize the markdown files if empty. For subdirectory setups, place kanban.md and archive.md in a .tasks/ folder and select that directory instead. To version tasks with Git, add kanban.md and archive.md to .gitignore if history is not desired.

Configuration: No environment variables or keys are required. The application configuration is embedded in the markdown files via headers and lists for columns, categories, users, and tags. The README.md documents the format with examples under ## ⚙️ Configuration.

Running it: No build step, server, or installation beyond opening the HTML file. The entry point is task-manager.html invoked via double-click or open task-manager.html from a terminal. The application memoryizes the selected folder path between sessions using local storage.

Real-World Use

A distributed development team can clone a repository containing task-manager.html, kanban.md, and archive.md to a shared drive. Each member opens the HTML file, selects the local project folder, and begins triaging tasks in the Kanban board. Because the data is plain Markdown, changes are immediately visible in Git diffs, editable in VS Code or any text editor, and syncable via any file synchronization method. A developer working offline on a train can complete tasks, and changes will sync when connectivity returns, with no merge conflicts beyond standard Markdown editing.

Code Health & Issues

No test files detected - repository-wide untested code paths. No Jest, pytest, or other test framework configuration is present. No CI/CD pipeline detected - no automated build/test gate in .github/ or equivalent. Pushes to the repository have no continuous integration coverage. Browser compatibility limitation - File System Access API availability restricts use to Chrome, Edge, and Opera 72+. Firefox and Safari users cannot access the local file feature. Single-file architecture risk - all application logic resides in task-manager.html. Modifications require editing a single large HTML file, which can become unwieldy for extensions or refactoring.

The Bottom Line

This is a practical local-first task manager for teams comfortable with Markdown workflows and Git versioning. It eliminates server overhead and keeps data portable, editable, and diffable. The browser restriction and absence of tests or CI are the primary constraints. It is well-suited for solo developers, small offline teams, or integration into existing Markdown-heavy workflows where a database-backed issue tracker is unnecessary overhead.

Verdict: Useful for Markdown-native teams operating within compatible browsers. Not recommended for teams requiring cross-browser support, automated testing, or CI/CD gates.
