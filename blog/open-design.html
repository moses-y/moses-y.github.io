The open-source Claude Design alternative. 🖥️ Local-first desktop app. 🖼️ Your coding agent becomes the design engine: prototypes, landing pages, dashboards, slides, images & video — real files, HTML/PDF/PPTX/MP4 export. 🤖 Claude Code / Codex / Cursor / DeepSeek Harness / OpenCode & 20+ CLIs via BYOK.

Forked from nexu-io/open-design

The Problem Design teams need a locally‑run AI assistant that can generate full‑stack design artifacts (HTML, PDFs, PPTX, video) without sending proprietary assets to cloud services. Existing Claude‑based tools are closed‑source and require an internet‑only workflow.

What This Does open-design ships a desktop‑first agent runtime built on the DeepSeek Harness (dsh) and other LLM back‑ends. The core daemon lives in apps/daemon/; its entry point is the compiled script apps/daemon/bin/od.mjs. The daemon implements a custom RPC protocol (apps/daemon/src/agent-protocol/) that drives “skills” defined under .claude/skills/…. Generated assets are written by the artifact helpers in apps/daemon/src/artifacts/ (e.g., standalone-html.ts, publication-guard.ts) and can be exported as HTML, PDF, PPTX, or MP4.

How To Use It Install Node (>=18) – the repo specifies .node-version nvm install $(cat .node-version) Install dependencies for the daemon cd apps/daemon npm ci # note: no package‑lock file, npm will generate a temporary lock Build the TypeScript source npm run build # defined in apps/daemon/package.json scripts Start the local agent node ./bin/od.mjs # launches the daemon listening on the RPC ports

Configuration lives in apps/daemon/src/app-config.ts and reads environment variables such as OPENDESIGNAPI_KEY (required for external model services). The skill definitions under .claude/skills/od-contribute/ include YAML model descriptors (agents/openai.yaml) and shell scripts for setup (install.sh). To add a new skill, place a folder under .claude/skills/ following the existing structure and reference it in apps/daemon/src/agents.ts.

Real‑World Use A product team can run the daemon on a secure workstation, invoke a skill that generates a landing‑page prototype, and immediately preview the HTML in the bundled iframe. The resulting files are saved to a local design-output/ directory and can be handed off to developers or marketers without ever leaving the corporate network.

Code Health & Issues Low – No test suite – The repository contains zero .test. files; CI runs lint and build steps but does not exercise runtime logic. Low – Missing lockfile – apps/daemon/package.json has no package-lock.json or pnpm-lock.yaml, making reproducible installs difficult. Medium – Sparse error handling – RPC modules (apps/daemon/src/agent-protocol//session.ts) propagate errors without explicit retries or fallback, which could cause daemon crashes on transient network failures. Low – Large CI surface – Over 70 GitHub Actions workflows exist, but none target unit or integration testing, suggesting CI is used mainly for release automation. Low – Documentation gaps – Quick‑start steps are present, yet the required environment variables for model APIs are not enumerated in a dedicated config file.

The Bottom Line open-design provides a functional, locally‑hosted AI design engine with a clear plugin model and export pipeline. It is usable for teams that can tolerate the lack of automated tests and must manage dependency reproducibility manually. The codebase is reasonably organized, but production deployments should add a test suite and lockfile to improve reliability and maintainability.
