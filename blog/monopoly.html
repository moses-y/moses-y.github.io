monopoly

Monopoly is a Python library & CLI that converts bank statement PDFs to CSV.

Forked from benjamin-awd/monopoly

The Problem

Bank statement PDFs are notoriously inconsistent. Each bank formats transactions, dates, and amounts differently, and some statements are scanned images requiring OCR. Anyone building personal finance tooling or accounting automation spends significant time writing one-off parsers per bank. Monopoly centralizes that work into a single library and CLI that normalizes any supported bank's statement into a standard CSV.

What This Does

Monopoly is a Python library and CLI that extracts transactions from bank statement PDFs and writes them to CSV. The core pipeline lives in src/monopoly/pipeline.py, with bank-specific parsers in src/monopoly/banks/ — one directory per institution (e.g., src/monopoly/banks/chase/chase.py). A detector in src/monopoly/banks/detector.py auto-identifies the bank from the PDF's properties, then routes it to the correct parser.

For image-based statements, src/monopoly/ocr.py and src/monopoly/gemini.py provide OCR support, with a generic fallback parser in src/monopoly/generic/ that infers transaction patterns from unstructured text. The CLI entry point is src/monopoly/cli/cli.py, and the package is published on PyPI as monopoly-core.

How To Use It

Setup: Install via pipx or pip. The repo uses pyproject.toml for dependencies and includes both pdm.lock and uv.lock for reproducible builds. System dependencies (poppler, ocrmypdf) are required per the README.

pipx install monopoly-core or with OCR support pipx install 'monopoly-core[ocr]'

Configuration: Password-protected PDFs are handled via a .env file. Copy .env.template to .env and set PDFPASSWORDS=["password1","password2"].

Running it: The CLI accepts a single PDF or a directory of PDFs. From the README:

monopoly src/monopoly/examples/examplestatement.pdf monopoly ./statements monopoly path/to/file.pdf --output ./out --preserve-filename

Real-World Use

A finance team receives monthly statements from multiple banks. They drop all PDFs into a statements/ directory, run monopoly ./statements, and get normalized CSVs that feed into their accounting system. The --preserve-filename flag keeps output names aligned with input files, making reconciliation straightforward. The library API in src/monopoly/ allows embedding this into a larger ingestion pipeline rather than relying solely on the CLI.

Code Health & Issues Low - Dependency lockfiles present but inconsistent: Both pdm.lock and uv.lock exist alongside pyproject.toml. This can cause confusion about which package manager is canonical. Not a functional bug, but a maintenance smell. Low - OCR dependency on external service: src/monopoly/gemini.py suggests Google Gemini API usage for OCR. This introduces a network dependency and potential cost for image-based statements. Verify whether this is optional or required for certain banks. Low - Test fixtures are real bank statements: tests/integration/banks/ contains actual PDFs (e.g., citibank/credit/input.pdf). These may contain sensitive data and could bloat the repo. Confirm they are synthetic before distributing. Med - AGPL-3.0 license: The README badge indicates AGPL-3.0. That's a strong copyleft license. Any company embedding this in a proprietary product must open-source their changes. Verify this is acceptable for your use case.

The repo is otherwise well-structured: 79 test files, CI workflows in .github/workflows/ (tests, performance, publish), and a Makefile for common tasks. The bank abstraction is clean — adding a new bank is a matter of creating a parser module and registering it.

The Bottom Line

Monopoly is a practical, well-tested tool for a narrow but painful problem: normalizing bank statement PDFs. The 20-bank coverage and auto-detection make it immediately useful for personal finance automation or small accounting teams. The AGPL license and external OCR dependency are the main considerations before adopting it in a commercial product.
