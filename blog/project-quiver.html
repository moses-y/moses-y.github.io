project quiver

Project Quiver documentation, designs, and project artifacts.

Forked from Arrow-air/project-quiver

The Problem Developers and operators need a unified, open‑hardware reference for a 25 kg modular quadcopter that can be rapidly assembled, customized, and field‑serviced. Existing platforms often lack complete mechanical, electrical, and documentation bundles, forcing teams to piece together disparate resources.

What This Does project-quiver is a documentation hub for the Quiver modular drone. The bulk of the repository lives under docs/ (165 files) and includes:

Assembly guides, wiring diagrams, and step‑by‑step photos (docs/Archive/PT3-Assembly-Guides/...). Bill‑of‑materials YAML files (bom/1000-airframe-structure.yaml, bom/2000-supporting-structure.yaml, etc.). Engineering reports with test data and CAD renderings (docs/Engineering-Reports/...).

The root also contains CI configuration (.github/workflows/.yml), a Makefile that drives linting tasks, and style enforcement files (.commitlintrc.yml, .cspell.config.yaml). No source code for CAD, PCB, or firmware is present in this fork; those artifacts are hosted elsewhere (the upstream Arrow‑Air repo).

How To Use It Clone the repo git clone https://github.com/your‑org/project-quiver.git cd project-quiver Run the provided lint checks (optional, validates markdown and spelling): make markdown # defined in .make/markdown.mk make cspell # defined in .make/cspell.mk Navigate the documentation – the primary entry point is README.md, which links to the hosted version at https://arrowair.com/docs/quiver. Locally you can open any guide, e.g.: open docs/Archive/PT3-Assembly-Guides/structural-assembly/structural-assembly.md Extract BOM data – the YAML files in bom/ can be parsed directly or fed into a procurement script. Example in Python: import yaml, pathlib bom = yaml.safeload(pathlib.Path('bom/1000-airframe-structure.yaml').readtext()) print(bom['components'])

No build or runtime commands exist in this repository because the mechanical and electrical designs are distributed as STEP, KiCad, and DXF files referenced from the documentation.

Real‑World Use A university UAV lab can clone the repo, follow the assembly guide (docs/Archive/PT3-Assembly-Guides/structural-assembly/structural-assembly.md), and use the BOM YAML to generate a purchase order. The same documentation can be bundled with a custom flight‑control firmware fork, ensuring that hardware revisions stay in sync with software updates.

Code Health & Issues Medium – Missing implementation – No source directories (src/, pcb/, etc.) are present despite the README referencing them. Users must obtain CAD/PCB files elsewhere. Medium – No automated tests – The repository contains only linting jobs (cadchecks.yml, sanitychecks.yml). No unit or integration tests for any code paths. Low – CI limited to static analysis – GitHub Actions run only checks on markdown and spelling; they do not verify BOM integrity or CAD file consistency. Low – Documentation drift risk – The live docs are hosted on Arrow‑Air’s website; the repo may become out‑of‑date if not regularly synced.

The Bottom Line project-quiver serves as a well‑organized, publicly accessible collection of design documentation and BOM data for the Quiver modular drone. It is valuable for teams that already have the CAD/PCB assets and need a single source of truth for assembly and parts procurement. However, the repository lacks the actual design files and any test coverage, so it should be used in conjunction with the upstream Arrow‑Air resources rather than as a standalone codebase.
