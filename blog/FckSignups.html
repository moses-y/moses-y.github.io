FckSignups

A list of tools that are open-source, in-browser, and require no-signups!

Forked from BraveOPotato/FckSignups

The Problem

Most web tools force users through registration walls, email verification, and data collection before delivering any value. For developers, designers, and privacy-conscious users, this friction is a barrier to quick tasks: converting a file, generating a mockup, or testing a regex shouldn't require creating yet another account.

What This Does

FckSignups is a curated directory of open-source, in-browser tools that require no signup. The frontend is a React + TypeScript single-page app (src/App.tsx) that renders a searchable, filterable grid of tools. Data lives in tools.json, which the app loads via the useTools hook (src/hooks/useTools.ts). Each tool entry follows a defined schema (src/types/index.ts) with fields like id, name, description, url, category, and optional tags, github, license, and stars.

The UI is componentized: ToolGrid renders cards, Controls handles search/filter, and SubmitToolModal lets users propose new tools. A cloudflare-worker/worker.ts exists as a serverless backend, likely for fetching GitHub star counts dynamically. A Python script (managementtools/addTool.py) automates adding new tools to tools.json.

How To Use It

Setup and running — the README documents the full flow:

git clone https://github.com/BraveOPotato/FckSignups.git && \ cd FckSignups && \ npm install && \ npm run dev

This starts the Vite dev server (vite.config.ts). There are no environment variables or API keys needed for local development. For the Cloudflare Worker, you'd need a Cloudflare account and wrangler configured (cloudflare-worker/wrangler.toml exists), but the core app runs standalone.

Real-World Use

A developer needing a quick QR code generator, JSON formatter, or image resizer can open the site, search by category or keyword, and click straight through to a working tool. The directory serves as a front-door aggregator — a "bookmark manager" for no-signup utilities. For maintainers, adding a tool means either editing tools.json directly or running python managementtools/addTool.py to append a validated entry.

Code Health & Issues Medium - No tests detected — no test files or test framework in package.json. Untested UI logic, especially the filter/search in Controls.tsx and data fetching in useTools.ts. Medium - No CI/CD pipeline — .github/ contains only an issue template, no workflows. No automated build or lint gate on commits. Low - Hardcoded fallback data — src/constants/fallbackData.ts suggests the app may ship with static data if the fetch fails. Verify this is intentional and not masking a broken data path. Low - Single Python script without tests — addTool.py mutates tools.json; no validation logic is evident, risking malformed entries. Low - No input validation on submissions — SubmitToolModal.tsx likely posts to an issue template, but there's no client-side schema enforcement beyond the TypeScript types.

The codebase is small and organized with clear separation of concerns (components, hooks, constants, types). The Cloudflare Worker is a sensible addition for live star counts, but it adds deployment complexity for a static directory.

The Bottom Line

FckSignups is a clean, well-structured directory app that solves a real friction point. It's simple to run locally and easy to extend via tools.json. The lack of tests and CI is acceptable for a community-curated list but would need addressing if this were to become a production service. Best suited for developers who want a self-hostable, no-signup tool aggregator or a template for building similar directories.
