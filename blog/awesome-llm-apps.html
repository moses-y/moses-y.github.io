Abstract

Collection of awesome LLM apps with AI Agents and RAG using OpenAI, Anthropic, Gemini and opensource models.

Forked from Shubhamsaboo/awesome-llm-apps

The Problem

This repository contains 7 self-contained LLM application projects that share no unified architecture, creating discoverability and integration challenges. Teams evaluating the stack must assess each project independently rather than understanding a coherent system. The collection spans autonomous game players, multi-agent teams, RAG tutorials, and voice agents—valuable individually but opaque as a portfolio.

How To Use It

Setup: This is a collection of 7 projects with no single install command. Each project has its own requirements.txt. For example, advanced_ai_agents/autonomous_game_playing_agent_apps/ai_tic_tac_toe_agent/requirements.txt and advanced_ai_agents/multi_agent_apps/agent_teams/ai_travel_planner_agent_team/backend/requirements.txt. Clone with: git clone https://github.com/moses-y/awesome-llm-apps

Configuration: Environment variables are project-specific. The travel planner team uses .env.example at advanced_ai_agents/multi_agent_apps/agent_teams/ai_travel_planner_agent_team/backend/.env.example. The legal agent team has similar examples. No single .env or config file spans all projects.

Running it: Choose a project directory and invoke its entry point. To run the tic-tac-toe agent: python advanced_ai_agents/autonomous_game_playing_agent_apps/ai_tic_tac_toe_agent/app.py. For the RAG blog search: python rag_tutorials/ai_blog_search/app.py. Each project's README documents its specific startup command.

The Bottom Line

This repository is a valuable portfolio of 7 independently viable LLM application projects—game-playing agents, multi-agent teams, RAG systems, and voice interfaces—that demonstrate practical patterns across OpenAI, Anthropic, Gemini, and open-source models. However, the absence of a unified architecture, critical dependency vulnerabilities in pinned packages, secrets in workflows, and missing lockfiles mean it should be evaluated project-by-project rather than as an integrated system. Teams should clone the specific projects relevant to their needs, upgrade the called-out dependencies, and remove the committed API key before running any CI or sharing code.
