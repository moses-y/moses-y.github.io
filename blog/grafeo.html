grafeo

Grafeo is a pure-Rust, high-performance graph database that can be embedded as a library or run as a standalone database, with optional in-memory or persistent storage. Grafeo supports both LPG and RDF and all major query languages.

Forked from GrafeoDB/grafeo

The Problem

Most graph databases force a choice between embedding and server deployment, or between LPG and RDF models. Teams that need both often run two systems. Grafeo addresses this by offering a single engine that supports both data models, multiple query languages, and both embedded and standalone operation.

What This Does

Grafeo is a pure-Rust graph database with a core engine under crates/ and bindings for seven languages. The bindings directory (crates/bindings/) contains implementations for Python (PyO3), Node.js (napi-rs), Go (CGO), C (FFI), C#, Dart, and WebAssembly. The Python binding includes bridges to networkx and a solvor module for algorithms, visible in crates/bindings/python/src/bridges/.

The engine supports LPG and RDF models with six query languages: GQL, Cypher, Gremlin, GraphQL, SPARQL, and SQL/PGQ. It offers MVCC transactions with snapshot isolation, in-memory or persistent storage, and vector search with HNSW indexing. The crates/bindings/common/src/ directory holds shared entity and error types used across bindings.

How To Use It

Setup: The repo is a Cargo workspace (Cargo.toml at root). Build the core library with cargo build --release. Each binding has its own package manager file: pyproject.toml for Python, package.json for Node, go.mod for Go, pubspec.yaml for Dart.

Build the Rust core cargo build --release

Python binding cd crates/bindings/python pip install .

Node binding cd crates/bindings/node npm install

Configuration: No environment variables are required. Storage mode (in-memory vs persistent) is selected at runtime through the database API, not config files.

Running it: As an embedded library, you instantiate a GrafeoDB object from the binding of your choice. The Python entry point is crates/bindings/python/python/grafeo/init.py; the Node entry is crates/bindings/node/index.js. A separate server component exists in a different repository (GrafeoDB/grafeo-server).

Real-World Use

A Python service that needs both graph traversal and vector similarity search:

from grafeo import GrafeoDB

db = GrafeoDB("mygraph", storage="persistent") db.execute("CREATE (n:Item {name: 'widget'})") results = db.query("MATCH (n:Item) WHERE n.name = 'widget' RETURN n") vectors = db.query("CALL vector.search('items', 0.8, 5)")

The same database file works across bindings, so a Rust service could share data with a Node.js analytics service.

Code Health & Issues

The repo is well-structured with 73 test files, CI configured in .github/workflows/ci.yml, a license, and a CHANGELOG.md. Code health is generally strong. Low - Go binding contains a prebuilt DLL (crates/bindings/go/libgrafeoc.dll.a), which is unusual for a source repo and should be verified against the Rust build. Low - The Node binding has per-platform npm packages (darwin-arm64, linux-x64-gnu, etc.) but no package.json for win32-arm64, which may limit Windows ARM support. Low - crates/bindings/go/grafeo_c.def suggests manual CGO exports; verify the generated header stays in sync with crates/bindings/c/grafeo.h.

No high-severity issues detected. The test coverage across bindings is substantial, and the CI pipeline includes benchmarking via CodSpeed.

The Bottom Line

Grafeo is a serious, well-engineered graph database with unusually broad language support and a dual LPG/RDF model. The multi-language binding strategy is the standout feature—few graph databases offer this breadth with a single Rust core. It suits teams that want one graph engine across heterogeneous services, though the project is young (0 stars on this fork) and the standalone server is still separate. Teams needing production-grade graph analytics with mature tooling should evaluate it against Neo4j or Memgraph first.
