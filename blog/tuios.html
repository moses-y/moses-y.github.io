The Problem

Developers who need to run multiple interactive shells inside a single terminal often resort to tmux or screen. Those tools lack modern UI features such as mouse‑driven pane resizing, native graphics (kitty/sixel), and a modal, vim‑like command palette, forcing users to maintain separate scripts for layout automation.

What This Does

TUIOS is a Go‑based terminal multiplexer that adds a full‑screen window‑manager experience inside any true‑color terminal. The core binary lives in cmd/tuios/main.go; a web‑frontend wrapper is provided by cmd/tuios-web/main.go. UI rendering relies on the Charm stack (bubbletea, lipgloss) and is implemented in the internal/app/ package (e.g., internal/app/commandpalette.go, internal/app/daemontilingtest.go).

Key capabilities—BSP tiling, multi‑workspace, clipboard handling, and a JSON control protocol—are described in the docs/ folder (docs/BSPTILING.md, docs/protocol.md). The repository also ships a tape‑scripting engine (docs/TAPESCRIPTING.md) for reproducible UI workflows.

How To Use It

Setup – Choose one of the supported delivery methods:

Homebrew (macOS/Linux)

brew install tuios

Nix

nix run github:Gaurav-Gosain/tuios#tuios

Docker (image built from Dockerfile at repo root)

docker run -it --rm ghcr.io/gaurav-gosain/tuios:latest

Go install (requires Go 1.22+)

go install github.com/Gaurav-Gosain/tuios/cmd/tuios@latest

Configuration – Default keybindings and themes are hard‑coded but can be overridden via the CLI config sub‑command defined in cmd/tuios/configcommands.go. Detailed options are listed in docs/CONFIGURATION.md. Hooks for session events are documented in docs/HOOKS.md and implemented in internal/app/agentalert.go.

Running – Launch the daemon (optional) and attach a client:

Start daemon (background manager)

tuios daemon start

Open a new client window

tuios attach

For a web UI, run the wrapper:

tuios-web

The entry point for the web server is cmd/tuios-web/main.go. All commands are verified by the test suite (cmd/tuios/.go and e2e/tui/.go).

Real‑World Use

A DevOps engineer can replace a tmux‑based workflow with a single tuios session that automatically tiles build logs, test runners, and a REPL. A typical script (using the tape engine) might look like:

tuios tape run examples/advanceddemo.tape

The tape records pane creation, command execution, and layout adjustments, enabling reproducible debugging sessions across team members.

Code Health & Issues

Low – Comprehensive test coverage – 95 test files, including end‑to‑end (e2e/tui/*.go) and unit tests for UI components. Low – CI pipeline – GitHub Actions defined in .github/workflows/ (docker‑publish, e2e‑tui, release) enforce build and test verification. Low – Dependency hygiene – Go modules (go.mod, go.sum) and a lockfile for NPM (clienttests/package.json) are present; no unchecked vendored binaries. Medium – Platform‑specific code – Separate files for Unix vs. Windows (sessioncommandsunix.go, sessioncommandswindows.go) increase maintenance overhead; no unified abstraction layer. Medium – Configuration discoverability – Runtime config is only accessible via CLI sub‑commands; no sample config file is shipped, which may hinder automated deployments. Low – Documentation completeness – 28 markdown docs cover most features, but the README lacks a quick‑start example for non‑Go users; could be improved. Low – License – SPDX‑compatible LICENSE file present, no hidden secrets detected.

No critical bugs are evident from static inspection; the extensive test suite and CI reduce risk of regressions.

The Bottom Line

TUIOS delivers a modern, mouse‑enabled terminal multiplexer with a rich feature set and solid engineering practices (tests, CI, Docker support). It is well‑suited for teams that need reproducible, scriptable terminal layouts and want to replace tmux with a more UI‑centric tool. Minor friction points are the lack of a bundled configuration template and platform‑specific code paths, but these do not outweigh the functional advantages for power‑users.
