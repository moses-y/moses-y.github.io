The Problem

Businesses building on WhatsApp's free consumer API face an inherent tension: the official Business API requires Meta approval, imposes per-conversation fees, and locks data into Meta's infrastructure. OpenWA replaces that with a self-hosted bridge to whatsapp-web.js, giving developers programmatic control over WhatsApp Web sessions without per-message costs or vendor dependency.

What This Does

OpenWA is a NestJS application (src/app.module.ts) that exposes a REST API and WebSocket gateway (src/modules/events/events.gateway.ts) for sending messages, managing sessions, and receiving webhooks. It supports multiple WhatsApp accounts concurrently, with per-session proxy configuration and CIDR whitelisting. A React dashboard (dashboard/src/App.tsx) provides visual session and webhook management.

The architecture is pluggable by design. Database, cache, and storage backends are swappable via configuration: src/common/cache/cache.service.ts abstracts Redis or in-memory caching, src/common/storage/storage.service.ts handles local or S3 storage, and the engine layer (src/engine/engine.factory.ts) allows adapter swaps. The SDK directory (sdk/javascript/src/index.ts, sdk/python/openwa/init.py) provides client libraries for the API.

Real-World Use

A customer support team running on a tight budget deploys OpenWA via Docker Compose (docker-compose.yml). They configure PostgreSQL for persistence, Redis for rate limiting, and local storage for media. Each support agent connects a personal WhatsApp number through the dashboard. Incoming messages trigger webhooks to a custom CRM, and bulk messaging (src/modules/message/bulk-message.service.ts) sends appointment reminders without per-message API costs.

Code Health & Issues

Med - No integration tests for the WhatsApp engine adapter (src/engine/adapters/whatsapp-web-js.adapter.ts). The adapter wraps an external WebSocket client; untested reconnection logic will fail silently in production. Med - Missing input validation on webhook payloads. src/modules/webhooks directory doesn't exist in the structure, and the webhook handling path is unclear from the file tree—this suggests incomplete error handling for malformed incoming data. Low - The SDK packages (sdk/javascript/, sdk/python/) are stubs with package.json/pyproject.toml but no tests or CI integration. They will drift from the API surface without automated validation. Low - No database migration tooling beyond raw SQL files in src/database/migrations/. The single migration file (1770108659848-AddMessageStatus.ts) suggests migrations are manual and not integrated into the deployment pipeline.

The Bottom Line

OpenWA is a well-structured, production-oriented WhatsApp API gateway with a genuinely pluggable architecture and a competent dashboard. It's suitable for teams that need self-hosted WhatsApp automation without Meta's pricing or approval process. The main risks are the untested WhatsApp Web adapter—the most failure-prone component—and the lack of integration tests for webhook handling. For a 0.1.4 release, the codebase is clean and the documentation is thorough.
