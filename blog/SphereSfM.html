The Problem Spherical cameras (Insta360, Ricoh Theta) produce EquiRectangular Projection (ERP) imagery that standard SfM pipelines like ColMap cannot process natively. SphereSfM fills this gap by extending ColMap’s framework to handle sphere camera models, enabling sparse reconstruction of ERP images for urban and street-level scenes. The repository’s scope is focused: sparse SfM for sphere images, with all pipeline steps documented in README.md and driven by ColMap binaries.

What This Does SphereSfM provides a ColMap-integrated SfM workflow for ERP spherical images. Core logic resides in lib/ (130 files), including lib/SiftGPU/ for GPU-accelerated feature extraction, lib/VLFeat/ for descriptor computation, and lib/PoissonRecon/ for mesh generation. Build infrastructure uses CMake (CMakeLists.txt, lib/CMakeLists.txt, docker/Dockerfile) and Docker for containerized compilation. The README documents a 5-step CLI pipeline: database creation (colmap databasecreator), feature extraction with --ImageReader.cameramodel SPHERE, spatial matching (colmap spatialmatcher), incremental mapper (--Mapper.spherecamera 1), and cubic conversion (colmap spherecubicreprojector). Each step maps to actual ColMap binaries extended by this package.

How To Use It Setup: Clone the repo and build via Docker or CMake. The docker/Dockerfile and docker/build.sh provide a containerized build path; locally, cmake and make drive compilation via the numerous CMakeLists.txt files under lib/. Configuration requires ColMap installed alongside this package; the CLI steps pull from README.md verbatim. Example workflow (from README): colmap databasecreator --databasepath ./colmap/database.db colmap featureextractor --databasepath ./colmap/database.db --imagepath ./images --ImageReader.cameramodel SPHERE --ImageReader.cameraparams "1,3520,1760" --ImageReader.singlecamera 1 colmap spatialmatcher --databasepath ./colmap/database.db --SiftMatching.maxerror 4 --SiftMatching.minnuminliers 50 --SpatialMatching.isgps 0 --SpatialMatching.maxdistance 50 colmap mapper --databasepath ./colmap/database.db --imagepath ./images --outputpath ./colmap/sparse --Mapper.barefinefocallength 0 --Mapper.barefineprincipalpoint 0 --Mapper.barefineextraparams 0 --Mapper.spherecamera 1 colmap gui --databasepath ./colmap/database.db --imagepath ./images --importpath ./colmap/sparse/0

Running it: Invoke ColMap binaries with the --Mapper.spherecamera 1 flag and ERP-specific ImageReader options, all configured per README.md step 1‑5.

Real-World Use A surveyor processing Insta360 footage of a city block can run these 5 ColMap steps to generate a sparse point cloud, then feed it into a downstream MVS pipeline (e.g., ColMap’s dense reconstruction) or convert to cubic format via colmap spherecubicreprojector for dense matching. The provided datasets (campus parterre, building, urban street) demonstrate the pipeline on real spherical imagery, with results exportable for further 3D modeling.
