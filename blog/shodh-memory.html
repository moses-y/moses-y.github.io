Technical Briefing: shodh-memory

The Problem

AI agents typically forget everything between sessions, repeating mistakes and losing context. Most memory systems delegate storage intelligence to LLM API calls — making them slow, expensive, and dependent on external services. This repository presents an alternative: algorithmic memory management using local embeddings, mathematical decay, and learned associations with zero LLM calls in the storage loop.

What This Does

shodh-memory is a collection of 12 self-contained projects providing persistent, learning memory for AI agents. The core (src/) contains 101 files organizing memory storage, retrieval, and graph operations around MemorySystem and MemoryConfig types. Twelve benchmarks (benches/) measure adaptive memory, cognitive load, graph statistics, and Hebbian reinforcement. Five integration projects (shodh-whatsapp/, shodh-telegram/, shodh-todoist/, mcp-server/, shodh-whatsapp/) embed the memory core into messaging and productivity platforms. Two data-only directories (python/, benches/) supply test harnesses and pipeline scripts. Execution begins at src/main.rs:141 (main), which reaches 151 functions; an alternate entry async_main at line 178 reaches 144 functions. The binary is ~17MB, fully offline, with no API keys or external databases required.

How To Use It

Setup: cargo build --release produces the binary; docker run -d -p 3030:3030 -v shodh-data:/data varunshodh/shodh-memory starts the MCP server. Python: pip install shodh-memory. Rust: add shodh-memory = "0.1" to Cargo.toml.

Configuration: No environment variables required for local use. For remote MCP deployment, .env.example documents SHODH_API_KEY (generated automatically). The MCP server config lives at .mcp.json.

Running it: claude mcp add shodh-memory -- npx -y @shodh/memory-mcp auto-downloads the backend binary. Python API: from shodh_memory import Memory; memory = Memory(storage_path="./my_data"); memory.remember("User prefers dark mode", memory_type="Decision"); results = memory.recall("user preferences", limit=5).

Real-World Use

An AI agent integrated via the MCP server retains user preferences across sessions without API calls. After the agent recalls "user prefers dark mode," the Hebbian reinforcement pathway (bench_reinforce_helpful in benches/) strengthens that memory's salience score, making it surface faster on subsequent recalls. Irrelevant memories decay via a time-weighted function — the consolidator (bench_consolidator_creation, bench_consolidator_with_thresholds) prunes below a configurable threshold. In a Telegram bot (shodh-telegram/src/index.ts), each user message passes through setup_memory_system → remember → graph insertion, so context persists across bot restarts. A Todoist integration (shodh-todoist/src/index.ts) records tasks as Memory entries with metadata, enabling natural-language recall of past commitments.

SDLC observations: 10 code-health findings (0 critical, 2 high, 6 medium, 2 low). The Bottom Line

shodh-memory delivers offline, learning memory for AI agents without API dependencies — a meaningful trade-off for privacy-constrained or air-gapped deployments. The codebase shows genuine technical ambition (Hebbian reinforcement, graph-based retrieval, decay functions) but carries structural debt from its fragmented 12-project layout and nested control flow in benchmark files exceeding 1000 lines. Teams needing rapid integration will favor the MCP server or pip package; groups requiring customization should budget refactor time for the oversized source files and duplicated benchmark logic.

.github/workflows
dtolnay/rust-toolchain@stable, Swatinem/rust-cache@v2, docker/setup-buildx-action@v3, docker/login-action@v3
A tag can be moved, so the action running with your token and secrets is whatever its owner last pushed; this is how tj-actions/changed-files leaked secrets from thousands of repos.
Fix: Replace each @vN with the 40-character commit SHA, keep # vN as a comment, and let Dependabot bump the SHAs.
