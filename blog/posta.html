posta

Self-hosted email delivery platform that enables applications to send emails via HTTP APIs while handling SMTP delivery, templates, storage, security, and analytics. Fully self-hostable alternative to services like SendGrid or Mailgun.

Forked from goposta/posta

The Problem

Teams that rely on transactional or marketing email often need to use third-party services like SendGrid or Mailgun, which means sharing sensitive email infrastructure and delivery data with external providers. Self-hosting email delivery typically requires stitching together multiple tools—an MTA, a queue system, a template engine, analytics—and managing deliverability, bounce handling, and security yourself. Posta packages all of this into a single, self-hosted platform.

What This Does

Posta provides an HTTP API for sending and receiving email, with built-in SMTP relay, template management, campaign support, and delivery analytics. The cmd/posta/ directory contains three entry points: main.go for the HTTP server, server.go for SMTP handling, and worker.go for async processing via Redis and Asynq. The internal/handlers/ directory (60+ files) exposes REST endpoints for email sending, template versioning, subscriber management, webhooks, and admin functions.

The platform handles both outbound and inbound email. Outbound features include transactional and batch sending, scheduled delivery, A/B testing, and bounce/complaint processing. Inbound email is received via an SMTP server, parsed, and forwarded to your application through webhooks or SSE streams. Templates support versioning, localization, and variable substitution. The internal/cron/ directory manages scheduled jobs like retention cleanup and daily reports.

Real-World Use

A SaaS company can deploy Posta behind its own infrastructure and send transactional emails (welcome emails, password resets, invoices) through a single API call:

The platform handles SMTP delivery, retries, bounce detection, and stores delivery events for analytics. Inbound email (e.g., support replies) can be received at the same domain and forwarded to a customer support system via webhooks.

Code Health & Issues

The codebase is well-structured and follows Go conventions. Tests exist in internal/config/, internal/cron/jobs/, internal/middlewares/, and internal/models/, though coverage is uneven—some handler packages appear untested. CI is configured via GitHub Actions, and a .golangci.yml linter config is present. No obvious secrets or credentials are in the repo.

Potential concerns: Medium - The internal/handlers/ directory has 60+ files with no test files. This is the core business logic and represents a significant testing gap. Low - internal/config/ and internal/cron/jobs/ have tests, but the test count (11 total) is low for a project of this scope. Low - The project depends on Redis and Asynq for async processing, which adds operational complexity for self-hosted deployments.

The Bottom Line

Posta is a serious, well-architected self-hosted email platform that covers the full delivery lifecycle—API, SMTP, templates, campaigns, analytics, and inbound processing. It is production-ready for teams that want full control over their email infrastructure and are willing to manage a Redis-backed queue. The testing gap in handlers is a concern for production confidence, but the overall structure and documentation are solid. Best suited for teams with Go expertise and operational capacity to run a self-hosted email system.
