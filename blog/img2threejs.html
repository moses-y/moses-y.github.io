img2threejs

Rebuild the object in a reference image as a code-only, procedural, quality-gated, animation-ready Three.js model. Token-efficient image-to-3D.

Forked from img2threejs/img2threejs

The Problem

Converting a single 2D image into a production-ready 3D model typically means photogrammetry, mesh extraction, or downloading pre-made assets—none of which yield clean, animatable, code-only geometry. You end up with heavy mesh files, no hierarchy, and no easy way to tweak proportions or materials programmatically.

What This Does

img2threejs takes one reference image and produces a TypeScript THREE.Group factory built from primitives, procedural shaders, and generated geometry. The pipeline lives in scripts/ and is a series of Python stdlib tools: probereferenceimage.py extracts landmarks and PBR hints, newprespecassessment.py writes a specification, and generatethreejsfactory.py emits the final Three.js code. Validation is handled by visualfeaturegate.py and validatesculptspec.py. The result is a runtime hierarchy with correct pivots and materials—no mesh files, no downloads. The references/ directory contains 13 specification documents (e.g., likeness-maximization.md, attachment-joint-correctness.md) that define the quality gates.

Real-World Use

A game studio needs a quick, lightweight 3D model of a product for an in-browser configurator. They photograph the object once, run the pipeline, and get a createProductModel.ts factory they can drop into a Three.js scene. The model is animation-ready (correct pivot points, named groups) and can be tweaked by editing constants in the generated code—no mesh re-export needed.

Code Health & Issues Med — No CI/CD pipeline — No automated build or test gate in .github/. The 5 test files in scripts/tests/testpipeline.py exist but aren't run automatically. Low — No dependency lockfile — scripts/requirements.txt lists dependencies without pinned versions, making builds non-reproducible. Low — Manual orchestration — The pipeline scripts (e.g., sculptpassorchestrator.py) appear to be run sequentially by hand; no single entry point or CLI tool ties them together. Good — Documentation — 6 doc files and 13 reference specs are thorough, though the volume suggests a complex workflow. Clean — No secrets or config files — Only .gitignore, LICENSE (MIT), and CONTRIBUTING.md are in root.

The codebase is well-documented and logically structured, but lacks automation and dependency management for production use.

The Bottom Line

A technically impressive, code-only approach to image-to-3D that produces clean, animation-ready Three.js models. The pipeline is manual and requires Python expertise to run, making it better suited for prototyping or one-off reconstructions than a turnkey service. If you need lightweight, tweakable 3D from a single photo and are comfortable with the manual workflow, this delivers.
