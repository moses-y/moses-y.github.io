The Problem

Developers and researchers need a repeatable, source‑grounded way to turn a natural‑language query into a structured research artefact (literature review, audit, replication plan, etc.). Manual searching, note‑taking and synthesis are fragmented and error‑prone, especially when the output must stay linked to original papers or code.

What This Does

feynman is a CLI‑driven AI research agent built on the Pi runtime. The core commands live under src/ (src/cli.ts, src/index.ts) and invoke a set of reusable Pi skills stored in .feynman/ and the skills/ directory. The web front‑end in website/ renders generated artefacts, while extensions/research-tools/ provides command‑specific helpers (e.g., header.ts, project.ts).

Key entry points:

  • src/cli.ts – parses sub‑commands (deepresearch, lit, audit, …) and dispatches to handlers such as handleAlphaCommand and handleModelCommand.
  • src/index.ts – exports a run function used by the bundled binary bin/feynman.js.

The CLI ultimately calls UI helpers in src/ui/terminal.ts (printing, colour handling) and model‑resolution logic in src/model/commands.ts and src/model/catalog.ts. All network or filesystem interactions are confined to the “setup/doctor”, “pi/web‑access”, and “system/executables” modules.

How It Is Wired

Execution starts at src/cli.ts:278 (main). main reaches 87 functions, the largest blast‑radius hub is src/cli (instability 0.92, imports 12 other modules). From main the flow is:

  1. Command parsing → calls a handler (handleAlphaCommand, handleModelCommand, handleSearchCommand, etc.).
  2. Handlers invoke model resolution (src/model/commands.ts → resolveAvailableModelSpec, selectOAuthProvider).
  3. UI output is funneled through src/ui/terminal.ts (printInfo, paint, rgb). printInfo is the most‑referenced function (12 callers).
  4. For web or repo access, src/pi/web-access.ts provides loadPiWebAccessConfig and formatRouteLabel.
  5. System binaries are located by src/system/executables.ts: resolveExecutable, called from four places.

The internal call graph shows 250 intra‑repo edges; no circular dependencies were detected. High‑instability modules (src/setup/setup, src/model/commands) import many utilities but are only imported by one other module, so changes there cascade widely. Low‑instability hubs (src/pi/web-access, src/system/executables) are pure providers with no outgoing imports.

How To Use It

# Clone the repo (use the exact URL)
git clone https://github.com/moses-y/feynman
cd feynman

# Install dependencies (npm works; the repo also supports pnpm)
npm ci

# Optional: copy example env (currently unused but present)
cp .env.example .env

# Run the CLI directly
node bin/feynman.js deepresearch "mechanistic interpretability"
# or via the TypeScript entry point
npx ts-node src/cli.ts lit "RLHF alternatives"

The binary reads skill definitions from ~/.feynman/agent/skills/ on first run; the install‑skills scripts referenced in the README are wrappers around the same logic.

Real‑World Use

A data‑science team wants a quick brief on recent RLHF literature. They run:

feynman lit "RLHF alternatives"

The CLI resolves the model (src/model/commands.ts), queries AlphaXiv via the Pi skill, formats the result with src/ui/terminal.ts, and writes a markdown artefact into outputs/. The artefact contains citations linked back to the original papers, ready for internal review.

Tests exist (tests/), CI runs via GitHub Actions, a LICENSE is present, and the lockfile is committed. No secrets were detected.

The Bottom Line

feynman delivers a functional, modular CLI for AI‑augmented research with a clear separation of concerns (command parsing, model handling, UI output). The codebase is healthy overall but suffers from duplicated logic, deep nesting in a few extension files, and lacks automated dependency hygiene. It is suitable for teams that need an extensible research automation layer and are comfortable managing the identified maintenance gaps.

Enable Dependabot or Renovatemedium
2 manifest(s), no update bot configured
Without a bot a published advisory sits unpatched until someone audits by hand, which across 1,322 repositories means never.

Gate pull requests on a dependency vulnerability scanmedium
.github/workflows
no dependency scan in CI
This is the one gate that would catch a known-vulnerable package before it reaches a build, and no repository in the sample had it.
Fix: Add dependency-review-action on pull_request, or osv-scanner on push and a schedule.
Set persist-credentials: false on checkoutmedium
.github/workflows/publish.yml
checkout keeps the token, then dependencies are installed
The token stays in .git/config for every later step, so a malicious postinstall script reads a pushable credential without one ever being passed to it.
Fix: Add with: persist-credentials: false, and pass an explicit token only to the step that pushes.
Review the install lifecycle script and disable scripts in CImedium
package.json
preinstall
Install scripts are the execution vector for every npm compromise from event-stream onward, and a postinstall that fetches a binary makes the build depend on a URL nobody reviews.
Fix: Move the work into an explicit build step, or set ignore-scripts in CI and run it by name.
Set timeout-minutes on the workflow jobslow
.github/workflows/publish.yml
1 workflow(s) declare no job timeout
A wedged step runs to the six-hour platform default, which on a two-hourly schedule means three runs overlap behind it.
Fix: Add timeout-minutes with a realistic bound to each job.
Add the repository convention files this project lackslow3 occurrences
missing .editorconfig, .gitattributes, a formatter config
Without them one contributor's editor writes tabs into a Python file, a shell script commits with CRLF and fails in the container, and a notebook diff is unreviewable.
Fix: Add .editorconfig, .gitattributes with text=auto eol=lf, and a formatter config.
