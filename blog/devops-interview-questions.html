DevOps Interview Questions

Forked from devops-interviews/devops-interview-questions

The Problem

Preparing for DevOps or SRE interviews is fragmented—most candidates rely on scattered blog posts, LeetCode-style questions, or memorized theory. This repo consolidates 115 hands-on, scenario-based questions collected from real interviews at 50+ companies (Google, Amazon, Meta, Apple, Red Hat, Datadog), each with a documented solution and video walkthrough. The value is in the format: each question is a real operational incident or task, not a trivia question.

What This Does

The repo is a structured collection of Markdown documents organized by domain: linux/ (29 files), git/ (22), kubernetes/ (21), programming/ (12), docker/ (11), cloud/ (10), networking/ (10), and security/ (1). Each file follows a consistent pattern—a problem statement, a step-by-step solution, and the underlying commands or configuration.

For example, kubernetes/image-pull-backoff-secrets.md walks through diagnosing ImagePullBackOff errors, linux/diagnose-nginx-cpu-bottleneck.md covers performance triage, and programming/github-actions-matrix-build-strategy.md explains CI/CD matrix builds. The README.md provides company-specific breakdowns and links to video solutions, making it a self-contained study resource.

How To Use It

This is a documentation repo, not a software project—there is no build step, CLI, or runtime. The primary entry point is README.md, which indexes all questions and links to video walkthroughs hosted externally.

Setup: Clone the repo. No dependencies, no environment variables, no configuration files.

git clone https://github.com/devops-interviews/devops-interview-questions.git cd devops-interview-questions

Navigation: Browse by domain folder (e.g., kubernetes/, linux/) or use the company table in the README to find questions from specific employers. Each file is self-contained, so you can read them in any order.

Missing pieces: There is no index file, no per-question difficulty rating, and no categorization beyond the folder structure. The README's company table is the closest thing to a curated path, but it doesn't map to the actual files—you'll need to match company names to question topics manually.

Real-World Use

This is a study aid, not a production tool. A candidate preparing for a senior SRE screen could work through the kubernetes/ directory systematically, recreating each scenario in a local cluster (minikube or kind) to build muscle memory. The git/ questions are directly applicable to daily work—recovering lost commits, stashing partial work, or cleaning history are tasks most engineers face weekly.

The lack of license and potential secrets are real concerns for redistribution, and the README's company attribution is vague (no evidence the questions are verbatim from those interviews). Use it as a structured study guide, verify the solutions in your own environment, and treat the company claims as marketing rather than fact.
