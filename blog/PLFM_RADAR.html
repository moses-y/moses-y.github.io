The Problem

The repository contains ~87 source files (firmware, Python GUI, simulations) with no CI/CD pipeline and no test suite. Any change can introduce a regression that goes undetected, and the deep nesting, duplicated blocks, and large monolithic files make safe modification difficult.

What This Does

PLFM_RADAR is an open‑source 10.5 GHz phased‑array radar (AERIS‑10) available in two range versions.

  • Hardware (files under 4_Schematics and Boards Layout/, 9_Firmware/9_1_Microcontroller/) implements a complete front‑end: AD9523 clock generator, ADF4382 synthesizers, ADAR1000 phase shifters, ADTR1107 LNA/PA chips, and a Xilinx XC7A100T FPGA that performs pulse compression, Doppler FFT, MTI and CFAR processing.
  • Firmware (9_Firmware/9_1_Microcontroller/9_1_3_C_Cpp_Code/main.cpp) drives power‑up sequencing, FPGA communication, and GPS/IMU handling.
  • Python GUI (9_Firmware/9_3_GUI/GUI_V*.py) provides a user‑friendly interface: GUI_V4.py (56 functions, 10 classes) is the most‑connected entry point, calling list_devices, generate_map, polar_to_geographic and reading/writing files.
  • Simulation & utilities (5_Simulations/, 8_Utils/Python/) expose functions such as array_factor, element_factor, generate_radar_csv, and RADAR_eq.py’s main (reaches 3 functions).

How To Use It

  • Clone the repository verbatim:
  git clone https://github.com/moses-y/PLFM_RADAR
  cd PLFM_RADAR
  • Python GUI: run the high‑level entry point
  python 8_Utils/Python/RADAR_eq.py

(The file defines main at line 303; no requirements.txt is present, so you may need to install common scientific Python packages (numpy, matplotlib, scipy) yourself.)

  • Firmware: the STM32 project lives under 9_Firmware/9_1_Microcontroller/9_1_3_C_Cpp_Code/. No build script is documented; you will need a toolchain (e.g., STM32CubeIDE, PlatformIO) and an appropriate debugger/programmer for the board.
  • Simulations: many .py files under 5_Simulations/ can be executed directly with Python; they import from numpy, matplotlib, and openems (external).

Real‑World Use

A drone‑software team wants to test beam‑steering algorithms. They launch python 8_Utils/Python/RADAR_eq.py, adjust the “frequency ramp” and “pulse length” sliders, and the GUI calls generate_multi_ramp_csv (not listed in the top‑level graph but present in the utils) to produce CSV data. The resulting CSV is fed into the FPGA‑embedded pulse‑compression pipeline, and the team visualises target tracks on the integrated map (generate_map in GUI_V4.py).

The Bottom Line

The repo delivers a functional, open‑source 10.5 GHz phased‑array radar with a capable Python GUI and solid firmware, but the absence of CI, tests, and large‑file management creates risk for any sustained development. It is well‑suited for hobbyists, researchers, or rapid prototyping where occasional manual verification is acceptable. Teams planning long‑term maintenance should budget time to add a test suite, CI workflow, and Git LFS for the simulation data dumps.
