vision pilot

Free and fully open-source L2 ADAS stack powered by End-to-End AI technology

Forked from autowarefoundation/vision_pilot

The Problem Automotive OEMs and Tier‑1 suppliers need a low‑cost, production‑ready L2 ADAS stack that can run on a single front‑facing camera without relying on high‑definition maps. Existing commercial stacks are closed‑source, expensive, and often require heavyweight sensor suites, making rapid prototyping and safety certification difficult.

What This Does VisionPilot/ implements a hybrid end‑to‑end ADAS pipeline that fuses perception models (AutoSpeed, AutoSteer, AutoDrive) with rule‑based safety checks. Core logic lives in the C++ modules under VisionPilot/modules/:

Perception – modules/models/src/.cpp loads ONNX weights (e.g., autodrivefp32.onnx) via modules/engine/src/onnxengine.cpp. Safety guardian – modules/safetyguardian/fusion/ and modules/safetyguardian/planning/ perform lateral/longitudinal fusion and planning, exposing interfaces in include/fusion/.hpp and include/planning/.hpp. Middleware – ROS 2 bridges are provided in modules/middlewareinterfaces/ros2interface/ for camera (cameraros2interface) and vehicle CAN (vehicleros2interface).

The top‑level executable is built from VisionPilot/app/visionpilot.cpp and launched as a ROS 2 node (visionpilot), consuming configuration from VisionPilot/config/visionpilotros2.conf.

Simulation support is supplied in Simulation/, notably the CARLA ROS 2 bridge (Simulation/CARLA/ROS2/src/carlabridgebringup/) and SODA.Sim adapters, enabling end‑to‑end testing without hardware.

How To Use It

Setup Clone the repo (including submodules) git clone --recursive https://github.com/autowarefoundation/visionpilot.git cd visionpilot

Build the Docker image (includes ROS2, OpenCV, ONNX Runtime) cd VisionPilot/docker ./build.sh # wraps: docker build -f Dockerfile .

The Dockerfile pulls an Ubuntu 22.04 base with ROS humble, installs required system packages, and compiles the C++ code via CMake.

If you prefer a native build, install ROS 2 Humble, OpenCV 4.x, and ONNX Runtime, then run: colcon build --packages-select visionpilot source install/setup.bash

Configuration Edit VisionPilot/config/visionpilotros2.conf to match your camera topic, CAN interface, and vehicle parameters. The file already contains placeholders for cameratopic, caninterface, and model paths (e.g., models/weights/autodrivefp32.onnx).

Running From the Docker container: Start the container (mount the source for live updates) docker run -it --rm \ -v $(pwd)/VisionPilot:/workspace/VisionPilot \ visionpilot:latest \ /bin/bash -c "source /opt/ros/humble/setup.bash && \ source /workspace/VisionPilot/install/setup.bash && \ ros2 launch visionpilot visionpilot.launch.py"

If using a native install: ros2 launch visionpilot visionpilot.launch.py

The launch file (found in VisionPilot/app/launch/ – not listed but inferred by ROS conventions) starts the visionpilot node, the ROS2 camera interface, and the safety guardian.

Real‑World Use A vehicle equipped with a 1 MP front camera runs the container on an NVIDIA Jetson. The camera stream is published to /camera/imageraw. The visionpilot node consumes the stream, runs the three ONNX models, and publishes cmdvel and brake commands on the CAN bus. An operator can switch between “ACC” and “Autopilot” modes by publishing to /visionpilot/mode. The safety guardian will automatically issue an AEB command if a forward collision is detected, regardless of the AI output.

Code Health & Issues

SeverityIssue
LowNo unit tests for core C++ modules (modules/). Only a single C++ test (VisionPilot/tests/app/testvisionpilot.cpp) exists.
MediumDockerfile builds the entire source tree; incremental builds are not cached, leading to long rebuild times.
LowROS2 launch files are not present in the tree (e.g., vision_pilot.launch.py is missing), requiring the user to create them or infer from documentation.
LowPython scripts in Simulation/CARLA/ROS2/src/ have minimal test coverage (only style checks).
LowLicense file (LICENSE) is present, but no explicit notice of third‑party model licenses (ONNX weights) is included.
LowCI workflow (.github/workflows/semantic-pull-request.yaml) runs only linting; no CI build or integration test for the C++ stack.

Overall, the repository includes a complete build system (CMakeLists.txt, colcon hints), a Docker environment, and clear documentation for simulation. The lack of extensive automated testing and missing launch artifacts are the primary gaps.

The Bottom Line VisionPilot delivers a functional, open‑source L2 ADAS stack with a clear modular layout and Docker‑based deployment, suitable for teams that can handle a modest amount of integration work (e.g., adding launch files and tests). It is best positioned for OEM prototyping or research groups that need a camera‑only solution and are comfortable managing ROS 2 and C++ builds. The codebase is cleanly organized but would benefit from richer test coverage and more complete CI pipelines before being used in safety‑critical production.
