The Problem

End users need to generate UIs from AI prompts, but unconstrained generation produces unpredictable JSON, broken schemas, and components that don't exist in the product codebase. This repo provides a constrained vocabulary so AI output is always valid, but the implementation has architectural fragilities that affect long-term maintainability.

What This Does

json-render sits between an AI prompt and a React UI, translating structured JSON into rendered components using a user-defined catalog. The core logic lives in packages/core/src/—catalog.ts, types.ts, validation.ts, and visibility.ts handle the parsing, schema validation, and conditional rendering guards. The React integration is in packages/react/src/, with contexts/data.tsx, contexts/validation.tsx, and contexts/visibility.tsx providing the data pipeline and streaming hooks. The entry point is apps/web/components/demo/index.ts, which demonstrates the useUIStream hook feeding a Renderer component with a component registry. The examples directory mirrors this pattern, with examples/dashboard/components/ui/index.ts serving as the secondary entry point.

The system is built on Zod schemas for component props and a catalog object that explicitly lists which components the AI may instantiate. When the AI generates JSON, the pipeline validates it against those schemas, applies visibility logic, and streams the result through the React renderer. It is purpose-built for dashboard and widget generation from natural language prompts.

How It Is Wired

Execution starts at apps/web/components/demo/index.ts, which invokes useUIStream with an API route at apps/web/app/api/generate/route.ts. That route presumably delegates to the core package’s generation logic. The demo component (apps/web/components/demo.tsx) renders the input field and Renderer tree, while apps/web/components/demo/types.ts and apps/web/components/demo/utils.ts are the hub modules: 25 other modules each depend on them, giving them an instability of 0.96 and 0 respectively. That high out-degree means any change to types or utils has a blast radius across a quarter of the codebase.

The import graph is a DAG of 124 modules and 137 edges, with no circular dependencies. The most connected source module is apps/web/components/demo/types (Ca 25, Ce 0), followed closely by apps/web/components/demo/utils (Ca 25, Ce 0). Both are classified as high-clarity hubs: 25 modules depend on each, and churn here is high-blast-radius. The recommendation is to keep them stable and small, moving volatile logic out.

Duplicated code is the next significant finding. 135 repeated 6-line blocks appear across 36 files, notably apps/web/app/docs/actions/page.tsx, apps/web/app/docs/catalog/page.tsx, and apps/web/app/docs/api/core/page.tsx. The fix is to extract shared helpers and DRY the repeated logic.

Deep nesting is a medium cognitive-load issue. apps/web/app/docs/layout.tsx, apps/web/components/demo.tsx, and apps/web/components/docs-mobile-nav.tsx all max at 6 indentation levels. Flattening with guard clauses or extracted blocks is the advised fix.

How To Use It

Setup: Install the two primary packages:

pnpm add @json-render/core @json-render/react

Both are published to the monorele’s package.json root. The repo uses pnpm with a turbo.json workspace config and a .npmrc at the root.

Configuration: No environment variables are required for basic operation. The .env.example files in apps/web/ and examples/dashboard/ exist but contain no defined vars in the extracted structure—likely placeholders. The next.config.js files in both apps/web/ and examples/dashboard/ configure the Next.js app router.

Running it: Start the dev server:

pnpm dev

from the root. This runs the turbo pipeline, starting apps/web on its default port. The playground is at http://localhost:3000. To generate UI from a prompt, the user provides typed input that calls send, which streams JSON to the /api/generate route, and the Renderer component renders the resulting tree against the registered component registry.

Real-World Use

A product team wants to let users build custom dashboards via natural language. They define a catalog of Card, Metric, and Button components with Zod schemas (packages/core/src/types.ts). The AI outputs JSON matching those schemas. The DataProvider wraps the app’s data, ActionProvider registers actions like export_report, and Renderer maps the JSON to DOM using the registry. The result is a live-updating dashboard that never diverges from the component library. If the AI tries to instantiate a component not in the catalog, the pipeline rejects it before render.

Code Health & Issues

The static analysis produced 7 findings across the SDLC:

  • [HIGH] Pin third-party GitHub Actions to a commit SHA - .github/workflows uses pnpm/action-setup@v4. A tag can move, so the action running with your token and secrets is whatever its owner last pushed. This is how tj-actions/changed-files leaked secrets from thousands of repos. Fix: replace @vN with the 40-character commit SHA, keep # vN as a comment, and let Dependabot bump the SHAs.
  • [MEDIUM] Declare least-privilege permissions for GITHUB_TOKEN - 1 workflow declares no permissions. Without declaration the token inherits the repo default, so any injected step can push commits or mint releases from inside your own CI. Fix: add permissions: contents: read at the top of the workflow and widen per job only where needed.
  • [MEDIUM] Enable Dependabot or Renovate - 7 manifests, no update bot configured. Without a bot a published advisory sits unpatched until someone audits by hand. Fix: commit .github/dependabot.yml covering the repo ecosystems plus github-actions.
  • [MEDIUM] Gate pull requests on a dependency vulnerability scan - no dependency scan in CI. This is the one gate that would catch a known-vulnerable package before it reaches a build. Fix: add dependency-review-action on pull_request, or osv-scanner on push and a schedule.
  • [MEDIUM] Set persist-credentials: false on checkout - checkout keeps the token, then dependencies are installed. The token stays in .git/config for every later step, so a malicious postinstall script reads a pushable credential without one ever being passed to it. Fix: add with: persist-credentials: false, and pass an explicit token only to the step that pushes.
  • [LOW] Set timeout-minutes on the workflow jobs - 1 workflow(s) declare no job timeout. A wedged step runs to the six-hour platform default, which on a two-hourly schedule means three runs overlap behind it. Fix: add timeout-minutes with a realistic bound to each job.
  • [LOW] Add the repository convention files this project lacks - missing .editorconfig, .gitattributes, a formatter config. Without them one contributor's editor writes tabs into a Python file, a shell script commits with CRLF and fails in the container. Fix: add .editorconfig, .gitattributes with text=auto eol=lf, and a formatter config.

The Bottom Line

The repository delivers on its promise: AI-generated JSON is constrained, validated, and rendered predictably against a user-defined component catalog. The architecture is clean for the happy path, with a clear entry point and a straightforward data-flow pipeline. However, the two high-impact hub modules (demo/types and demo/utils) have a blast radius of 25 dependent modules each, and the duplicated doc-page logic across 36 files signals technical debt that will compound as the catalog grows. The CI hygiene findings are standard for a newly open-sourced monorepo and are easily remediated. This is a solid choice for teams needing safe AI-to-UI generation, provided they invest in keeping the hub modules stable and the doc scaffolding DRY.
