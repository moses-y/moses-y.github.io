options portfolio backtester

Backtester for evaluating options and equity portfolio strategies over historical data. Includes tools for strategy sweeps, tail-risk hedge analysis, and signal-based timing research.

Forked from lambdaclass/options_portfolio_backtester

The Problem

Evaluating options strategies historically is slow and error-prone. Python-only backtesters struggle with contract-level inventory, Greeks aggregation, and realistic fill/cost models across thousands of legs. Most tools either oversimplify (treating options as linear instruments) or become too slow for parameter sweeps.

What This Does

This is a Rust-core backtester for options and equity portfolios, wrapped in Python for research workflows. The Rust engine in rust/obcore/src/ handles contract-level inventory (inventory.rs), fills (fillmodel.rs), costs (costmodel.rs), and risk (risk.rs). The Python layer in optionsportfoliobacktester/ exposes this through BacktestEngine, strategy presets (strategy/presets.py), and a tearsheet generator (analytics/tearsheet.py).

The repo includes research reproducing Spitznagel tail-hedge strategies (research/spitznagelspy/), with sweep scripts (fullsweep.py, parallelsweep.py) and findings documents. Data fetching (scripts/fetchdata.py) pins canonical parquet files by SHA-256 for reproducibility.

Real-World Use

A typical workflow: fetch SPY data with python scripts/fetchdata.py all --symbols SPY, then run a parameter sweep across put strikes and tenures using the convexity module (convexity/backtest.py). The engine handles rebalancing at configurable frequencies, external budgets for tail hedges, and outputs a balance history plus trade log. The tearsheet produces a single HTML file with equity curves, drawdowns, and options-specific P&L attribution.

Code Health & Issues Low - No structural red flags: CI configured, tests present (137 test files), license included, lockfile committed. Med - Python tests outnumber Rust tests 10:1. The Rust core at rust/ob_core/ has only one benchmark file and no unit test directory. Critical path bugs in Rust may surface late. Med - Data dependencies are fragile. The README warns about hash mismatches and fallback mirrors returning different bytes. Reproducibility depends on external data sources that may change without notice. Low - No documented performance benchmarks comparing Rust vs pure Python execution. The README claims parquet is "~30x faster" but doesn't specify the baseline or test conditions.

The Bottom Line

This is a serious options backtester for quantitative researchers who need contract-level accuracy and realistic execution models. The Rust core is the right call for speed, but the sparse Rust test coverage is a risk for production use. Best suited for strategy research and parameter sweeps where reproducibility matters more than operational reliability.
