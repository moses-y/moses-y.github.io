knowledge agent template

Open source file-system and knowledge based agent template. Build AI agents that stay up to date with your knowledge base

Forked from vercel-labs/knowledge-agent-template

The Problem

Building a knowledge-base AI agent typically means standing up a vector database, chunking pipeline, and embedding model. That infrastructure adds cost, latency, and maintenance burden. This template takes a different route: agents search files directly with grep, find, and cat inside isolated sandboxes, giving deterministic results with zero embedding infrastructure.

What This Does

This is a fork of vercel-labs/knowledge-agent-template (992 stars upstream) — a full-stack template for file-system-based AI agents. The core search logic lives in apps/app/server/utils/bot/ and apps/app/server/utils/chat/admin-tools/. The frontend is a Nuxt/Vue app with a chat interface, admin panel, and real-time tool visualization. Agents can be deployed as a web chat, GitHub bot, or Discord bot via pluggable adapters in apps/app/server/utils/bot/adapters/.

The admin agent is notable: it can answer operational questions ("what errors in the last 24 hours?") using internal tools like querystats, queryerrors, and runsql defined in apps/app/server/utils/chat/admin-tools/. A complexity router classifies each question and routes it to an appropriate model, aiming to cut cost on trivial queries. Sandboxes are pooled across users and conversations, with pre-built snapshots for fast startup.

How To Use It

Setup: The apps/app/package.json implies a standard Node/pnpm workflow. Install dependencies, then configure the environment.

Configuration: Required environment variables are documented in apps/app/.env.example — BETTERAUTHSECRET, GITHUBCLIENTID, GITHUBCLIENTSECRET. The README also references a docs/ENVIRONMENT.md for full setup. Database migrations exist in apps/app/server/db/migrations/postgresql/.

Running it: The app is a Nuxt server (apps/app/nuxt.config.ts). The README shows a one-click Vercel deploy button; a local dev server would be started via the standard Nuxt command, but the repo does not document the exact command.

cd apps/app install dependencies (pnpm implied by lockfile absence) pnpm install configure .env from .env.example, then: pnpm dev

Real-World Use

A team maintaining internal documentation across a GitHub repo and YouTube transcripts could fork this, add sources via apps/app/server/api/sources/index.post.ts, and deploy the chat app internally. The GitHub bot adapter (apps/app/server/utils/bot/adapters/github.ts) lets the same agent answer questions in GitHub Issues. The admin agent handles operational queries like "which endpoints are slowest?" without a separate monitoring dashboard.

Code Health & Issues Medium — No tests detected: The repo has 97 TypeScript files and zero test files. The sandbox and bot logic in server/utils/ is complex and untested. This is a significant gap for a template others will build on. Low — No lockfile: apps/app/package.json declares dependencies without a lockfile, so builds are not reproducible. Pin versions if you fork this. Low — Broad admin tooling: The runsql.ts admin tool gives the AI agent direct SQL access. That is powerful but risky if the admin panel is ever exposed beyond trusted users. Positive: CI is configured (.github/workflows/ci.yml, build.yml), issue templates exist, and the codebase is well-organized with clear separation between API routes, bot adapters, and sandbox utilities.

The Bottom Line

A solid, well-architected template for teams that want an AI agent over their existing files without vector-database overhead. The admin agent and multi-platform bot support are genuinely useful. The lack of tests and lockfile are the main concerns — acceptable for a template, but you should add both before production use. Best suited to teams already on the Vercel/Node stack.
