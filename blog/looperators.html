The Problem

Running multiple AI coding agents on a complex task forces you to manually shuttle context between them—copying output from one agent, pasting it as input to another, deciding when to trigger the next round, and judging when to stop. That works for one or two rounds, but breaks down when you want a reviewer agent to critique a coder agent across six laps, or three different models to debate a solution until they converge. You become the middleware.

What This Does

looperators replaces that manual orchestration with a directed graph. Agents sit as nodes on a canvas; edges define who triggers whom, what context moves between them, and when the loop terminates. The graph executes—when an upstream agent finishes, its output travels the edge to the next agent, and the result flows back. The shared/graph-core/ folder implements the scheduler, loop-view, and scope primitives that make this runtime work. The electron/runtime/workflows/ directory contains concrete loop patterns: classicWorkflows.ts, planCouncil.ts, and reviewWorkflow.ts.

The canvas is not a low-code builder. You chat with agents normally; when a loop pattern emerges in conversation, the matching graph appears automatically via src/components/canvas.tsx and src/hooks/use-draft-graph.ts. Power users can design loops directly in conversation. The system supports Claude Code, Codex, and Grok Build through adapter files in electron/runtime/providers/.

Real-World Use

Throw one problem at three models simultaneously—Codex, Claude Code, and Grok Build each draft a solution, read each other's output, challenge it, and revise until the discussion converges. The shared/plan-council.ts and electron/runtime/workflows/planCouncil.ts files implement this pattern. Code review is another ready-made loop: wire a coder and reviewer together with a stopping condition like "until the review is clean, at most 6 laps." The tests/acceptance/ directory contains scenario files (git-change-review.scenario.mjs, goal-fix-to-green.scenario.mjs) that validate these workflows.

Code Health & Issues

The codebase is structurally sound—tests present, CI configured via .github/workflows/ci.yml, license file included, and a clean dependency lockfile. A few observations: Med — macOS-only deployment risk. The release workflow targets only macos-arm64. Windows and Linux users cannot run this. The electron/main.ts entry point and native dependencies may have platform assumptions that aren't tested. Low — Alpha stability. The project tags itself alpha. The runtimeStateRecovery.ts and sessionCheckpoints.ts files suggest recovery logic exists but may not be battle-hardened. The acceptance tests in tests/acceptance/ are .mjs scripts, not unit tests—coverage depth is unclear. Low — No obvious secrets or config leaks. .gitignore is present, no hardcoded credentials visible in the file listing.

No showstoppers, but this is clearly early-stage software.

The Bottom Line

looperators solves a real pain point for anyone running multiple AI coding agents in concert. The graph-based orchestration is well-architected, and the ability to let loops emerge from conversation instead of requiring manual wiring is a smart design choice. It is macOS-only, alpha-quality, and best suited for developers already using Claude Code, Codex, or Grok Build who want to automate multi-agent workflows. Not ready for production pipelines, but worth evaluating for personal or team experimentation.
