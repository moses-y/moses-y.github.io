graphify

AI coding assistant skill (Claude Code, Codex, OpenCode, OpenClaw, Factory Droid). Turn any folder of code, docs, papers, or images into a queryable knowledge graph

Forked from Graphify-Labs/graphify

The Problem

Reading a large, unfamiliar codebase costs hours of manual browsing. Traditional documentation goes stale. LLM coding assistants re-read entire folders on every query, burning tokens and context windows. No tool surfaces hidden structure—cross-references, design rationale, community clusters—in a persistent, queryable form.

What This Does

graphify runs as a skill inside Claude Code, Codex, OpenCode, OpenClaw, or Factory Droid. It scans any folder—code, docs, PDFs, images—and builds a knowledge graph (graphify/ingest.py, graphify/build.py). The first pass uses tree-sitter AST parsing across 19 languages (tests/fixtures/ contains sample files for each). The second pass dispatches Claude subagents to extract concepts and relationships from non-code files.

The output lives in graphify-out/: an interactive graph.html, a plain-language GRAPHREPORT.md, and a persistent graph.json. Every edge is tagged EXTRACTED, INFERRED (with confidence score), or AMBIGUOUS. Clustering uses Leiden community detection on the graph topology—no embeddings, no vector DB (graphify/cluster.py). A SHA256 cache (graphify/cache.py) means re-runs only process changed files.

Real-World Use

Drop graphify on a repository with a /raw folder of papers, screenshots, and notes—Andrej Karpathy's documented workflow. The tool returns a graph that reduces token consumption by ~71.5x per query versus reading raw files, and persists across sessions. Add a .graphifyignore file to exclude vendor/ or nodemodules/.

Code Health & Issues Low - No dependency lockfile (pyproject.toml declares dependencies but no poetry.lock or requirements.txt). Builds are non-reproducible across environments. Low - 51 test files exist, and CI is configured (.github/workflows/ci.yml), but the test suite covers only unit tests on individual modules—no end-to-end tests that run the full pipeline against a real folder. Low - graphify/security.py exists but its scope is unclear from the README. No documented threat model for what happens when a malicious file enters the ingestion pipeline.

The codebase is well-structured with clear separation of concerns. Tests and CI are present, which is better than most open-source projects at this stage.

The Bottom Line

A practical, well-architected tool for teams that use LLM coding assistants on large or heterogeneous codebases. The two-pass design (deterministic AST + LLM extraction) is sensible, and the no-embeddings clustering avoids unnecessary complexity. Best suited for teams already using Claude Code or Codex who need persistent codebase understanding. Less useful for solo developers on small projects where manual browsing suffices.
