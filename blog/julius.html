The Problem

During penetration testing or attack‑surface mapping it is common to discover open HTTP ports that may be serving an LLM back‑end (Ollama, vLLM, LiteLLM, etc.). Manually probing each possibility is slow, error‑prone, and requires intimate knowledge of each service’s API quirks.

What This Does

julius is a Go‑based CLI that fingerprints LLM services by sending a small set of HTTP probes and matching the responses against a library of 60+ YAML‑defined signatures. Probe definitions live in probes/.yaml and are parsed by pkg/probe (probe.go, expand.go). The scanning engine (pkg/scanner/scanner.go) loads the signatures, performs concurrent requests, and scores matches (see pkg/runner/validate.go). Results are formatted by pkg/output (output.go) and displayed by the runner (pkg/runner/runner.go).

The entry point is cmd/julius/main.go, which wires the CLI (Cobra is used internally) to the runner and output layers.

How To Use It

Build / Install # Build locally make build # uses the Makefile in the repo # or install directly go install github.com/praetorian-inc/julius/cmd/julius@latest Configuration No runtime configuration is required. Service signatures are shipped in the repository under probes/. Custom signatures can be added as additional YAML files in that directory or supplied via the --probe-dir flag (documented in cmd/julius/main.go). Run the scanner # Single target julius probe https://target.example.com

Multiple targets (file or stdin)

cat hosts.txt | julius probe -f -

Output formats are selectable with --output json|jsonl|table (default: table). The CLI prints a table with columns TARGET, SERVICE, SPECIFICITY, CATEGORY, MODELS, and ERROR (see pkg/output/output_test.go for expected fields).

Real‑World Use

A red‑team operator discovers an open port 11434 on a host. Running:

julius probe http://10.0.5.12:11434

returns a row indicating ollama with specificity 100. The operator can then enumerate models (julius models …) or focus exploitation on that specific back‑end. The tool can be scripted into a larger asset‑discovery pipeline via its JSONL output.

Code Health & Issues

Bugs / Risks Low – pkg/runner/validate.go performs string matching without sanitising HTTP headers; malformed responses could cause false‑positive matches. Low – Concurrency is driven by Go routines without explicit timeout handling in some probe paths; a hung endpoint could delay the whole run. SDLC / Hygiene Low – All CI workflows (.github/workflows/.yml) run go test ./... and linting, and a license file is present. Low – No secret files are checked in; go.mod/go.sum are up‑to‑date. Medium – YAML probe files lack schema validation; a typo could break the scanner at runtime.

Overall the repository includes 74 test files covering core packages (pkg/probe, pkg/scanner, pkg/runner), a full CI pipeline, and a clear contribution guide.

The Bottom Line

julius provides a well‑tested, single‑binary solution for rapid LLM‑service fingerprinting, ideal for security teams that need to enumerate AI back‑ends without external dependencies. The codebase is clean, with comprehensive tests and CI, though users should be aware that probe YAML files are not schema‑validated and malformed services could affect scan speed. Deploy where fast, offline detection of LLM infrastructure is required.
