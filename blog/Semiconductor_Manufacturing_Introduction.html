The Problem

Students and industry newcomers often struggle to find a concise, multilingual reference that follows a silicon wafer from raw material to finished chip. Existing texts either demand deep physics knowledge or are fragmented across many sources. This repository delivers a single, beginner‑friendly book that omits heavy theory while covering every process step, terminology, and practical “know‑how” box.

What This Does

  • Stores 25 chapters in English, Traditional Chinese, Japanese, and Korean; each chapter is a README.md inside a language‑specific folder.
  • Provides validation tooling in scripts/:
  • check_book.py enforces file ordering, anchor consistency, and metadata presence.
  • check_translations.py verifies that every English section has counterpart translations.
  • list_figures.py extracts figure references for documentation builds.
  • CI (.github/workflows/check.yml) runs these scripts on every push, ensuring content integrity.
  • The images/ directory holds SVGs and PNGs referenced by the markdown, and the templates/ folder supplies a reusable chapter template.

How It Is Wired

Entry point: scripts/check_book.py.

  1. check_book.py scans the en/, ja/, ko/, zh‑TW/ directories, collecting README.md files.
  2. It parses each file with the markdown library, then calls validate_structure() from scripts/check_book.py.
  3. validate_structure() checks: - Section numbering matches the chapter list in en/README.md. - Anchor tags correspond to file names (#the-big-picture → 00-overview/README.md). - Required front‑matter keys (title, lang) exist.
  4. On failure, the script prints a diagnostic and exits with non‑zero status, halting the GitHub Actions job.

check_translations.py receives the same file list, then for each English file it verifies the existence of a file with the same relative path in each non‑English directory. Missing translations trigger a warning.

list_figures.py walks each markdown file, extracts ![alt](path) references, and writes a figures.json that can be consumed by a static site generator.

The CI workflow (.github/workflows/check.yml) has three jobs:

  • lint runs markdownlint on all markdown files.
  • check runs check_book.py and check_translations.py.
  • figure-list runs list_figures.py and checks that the generated JSON matches the expected output.

Because the repository contains only static content and scripts that perform file‑system operations, there is no external network or database dependency. The code paths are linear: main → validate_structure → file checks → exit. There are no cycles or shared mutable state beyond the file system.

How To Use It

# 1. Clone the repo
git clone https://github.com/moses-y/Semiconductor_Manufacturing_Introduction

# 2. Install the Python dependencies
# (no explicit requirements file; use pip to install markdown and PyYAML)
pip install markdown PyYAML

# 3. Run the validation scripts manually
python scripts/check_book.py
python scripts/check_translations.py
python scripts/list_figures.py

If all scripts exit with code 0, the book’s structure and translations are consistent. The list_figures.py output (figures.json) can be referenced by a website build system.

Real-World Use

An educational institution can import this repo into a static site generator (e.g., MkDocs). The figures.json generated by list_figures.py can be used to auto‑populate a gallery or index page. The validation scripts can be added to the institution’s CI pipeline to catch formatting or translation regressions before publishing.
