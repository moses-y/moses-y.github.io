Manta

🎉 Flexible invoicing desktop app with beautiful & customizable templates.

Forked from hql287/Manta

The Problem Small businesses and freelancers need a quick way to generate professional invoices without exposing their financial data to cloud services. Existing SaaS tools force data upload, while generic desktop editors lack invoice‑specific templates and multilingual support.

What This Does Manta is an Electron‑based desktop app that lets users compose invoices with drag‑and‑drop line items, customizable SVG logos, and a set of pre‑built templates. The UI lives under the app/ folder, e.g. app/components/form/ItemRow.jsx handles a single invoice line, while app/components/invoices/Invoice.jsx assembles the final document and exports PDF via the app/renderers/dialog.js module.

State management is built with Redux; reducers such as app/reducers/InvoicesReducer.jsx and actions in app/actions/invoices.jsx keep the form data immutable. Internationalisation lives in i18n/ (JSON per language) and is wired into components through the i18n/*/index.js loaders. The build pipeline is defined by electron-builder.yml (packaging for macOS, Windows, Linux) and CI is driven by .travis.yml.

How To Use It

Setup The repo contains a package.json (not listed in the tree but required for an Electron project). Assuming it is present, install dependencies with the standard Node toolchain:

Clone the repo git clone https://github.com/hql287/Manta.git cd Manta

Install Node modules npm ci # uses lockfile for reproducible install

If package-lock.json is missing, replace npm ci with npm install.

Configuration No runtime environment variables are required for a basic launch. Language packs are auto‑loaded from i18n/. Custom settings (default fields, logo path, etc.) are persisted by the electron-settings mock in mocks/electron-settings.js and the real electron-settings package at runtime.

Running Start the development version:

npm start # defined in package.json, launches electron with app/index.html

For a production build, the electron-builder.yml script is used:

npm run build # triggers electron-builder, outputs installers in ./dist

The entry point for the Electron main process is app.js; the React renderer mounts at app/index.jsx inside app/index.html.

Real‑World Use A freelancer could embed Manta in a local workflow:

generate a PDF invoice from the UI, then email it automatically open -a Manta # launch the app fill form, click Export → PDF optional script to attach the PDF to an email mail -s "Invoice #${NUM}" client@example.com < /path/to/invoice.pdf

All data stays on the user's machine, satisfying privacy requirements.

Medium – Mocked Electron modules – mocks/electron.js and mocks/electron-settings.js indicate test isolation but the production code may rely on runtime‑only APIs not exercised by unit tests. Low – Limited CI coverage – .travis.yml runs tests, but there are no linting or security audit steps (e.g., npm audit) configured. Low – No explicit type checking – The codebase is pure JavaScript/JSX; adding Flow or TypeScript would reduce runtime errors. Low – License present – GPL‑3.0 is included, satisfying legal compliance. Low – Documentation – README provides download links and feature list, but lacks a quick‑start guide; developers must infer npm scripts from the package configuration.

Overall, the test suite is extensive (63 test files, snapshot tests) and the directory layout cleanly separates UI, reducers, actions, and helpers.

The Bottom Line Manta delivers a self‑hosted invoicing tool with a polished UI, multilingual support, and PDF export, suitable for privacy‑conscious freelancers or small firms. The codebase is well‑structured and heavily tested, but the missing package.json in the snapshot and the reliance on mocked Electron modules mean a reviewer should verify the build scripts before production deployment. If the missing manifest is restored, the project is ready for local use or packaging with Electron Builder.
