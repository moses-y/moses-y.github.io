llm council

LLM Council works together to answer your hardest questions

Forked from karpathy/llm-council

The Problem When evaluating multiple large‑language‑model (LLM) providers, developers must manually query each API, compare outputs, and synthesize a final answer. This repetitive workflow is error‑prone and slows down rapid prototyping or research that requires side‑by‑side model comparison.

What This Does llm-council implements a lightweight web UI that orchestrates a “council” of LLMs via the OpenRouter gateway. The backend (backend/main.py) runs a FastAPI server that: Sends the user prompt to every model listed in backend/config.py (Stage 1). Feeds each model the other models’ responses for anonymous ranking (Stage 2). Passes the ranked set to a designated chairman model for a consolidated answer (Stage 3).

The frontend (frontend/src/App.jsx and supporting components under frontend/src/components/) displays each stage in separate tabs, letting users inspect raw replies, review rankings, and view the final synthesized response.

Key files: backend/council.py – core orchestration logic, async calls to OpenRouter via httpx. backend/openrouter.py – thin wrapper around the OpenRouter HTTP API. frontend/src/api.js – React‑side helper that calls /api/query on the FastAPI server.

How To Use It Install Python dependencies with uv (requires uv >= 0.4) uv sync # reads pyproject.toml, creates .venv Install frontend dependencies cd frontend npm install # uses package.json cd .. Provide OpenRouter credentials echo "OPENROUTERAPIKEY=sk-or-…" > .env (Optional) Adjust the council composition Edit backend/config.py → COUNCILMODELS / CHAIRMANMODEL Start both services (the repo supplies a convenience script) ./start.sh # runs backend with uv and frontend with npm run dev

If start.sh is unavailable or you prefer manual control:

Backend (FastAPI) on default port 8000 uv run python -m backend.main

Frontend (Vite dev server) on port 5173 cd frontend npm run dev

Open http://localhost:5173 in a browser to interact with the council UI.

Real‑World Use A data‑science team can embed this tool in a research notebook to benchmark new prompts across OpenAI, Anthropic, Google, and other providers. After a single click, the UI returns per‑model answers, peer‑review rankings, and a final aggregated response, reducing the manual copy‑paste cycle and providing a reproducible audit trail stored in data/conversations/ (JSON files).

Example: programmatically fetch the final answer for downstream processing import requests, json resp = requests.post( "http://localhost:8000/api/query", json={"prompt": "Explain transformer attention in 2 sentences"} ) final = resp.json()["final_answer"] print(final)

Code Health & Issues Med – No automated tests – repository lacks any tests/ folder or pytest configuration; core paths (backend/council.py, backend/openrouter.py) are unverified. Med – No CI/CD pipeline – no .github/workflows/ or similar; changes are not gated by builds or lint checks. Med – Missing license – root contains no LICENSE; downstream users have unclear redistribution rights. Low – Secrets handling – API key is read from a plain‑text .env file; the repo does not enforce .env exclusion beyond .gitignore, but accidental commit is possible. Low – Minimal error handling – backend/openrouter.py forwards raw HTTP responses; network failures or non‑2xx codes are not wrapped in custom exceptions, risking uncaught crashes. Low – Documentation gaps – README covers basic setup but omits details on required Python version, uv version, or how to run the backend in production (e.g., uvicorn command).

Overall code organization is clear, with separation between API wrapper, council orchestration, and React UI. Lint configuration (frontend/eslint.config.js) exists, but no corresponding Python linting (e.g., flake8) is present.

The Bottom Line llm-council delivers a functional prototype for multi‑LLM comparison with a simple FastAPI + React stack, suitable for quick experiments or internal demos. The lack of tests, CI, and a proper license limits its suitability for production or commercial adoption without additional engineering effort. Teams that need a sandbox for model side‑by‑side evaluation will find it useful; larger organizations should treat it as a reference implementation and extend it with proper testing, security reviews, and deployment tooling.
