vps audit

lightweight, dependency-free bash script for security, performance auditing and infrastructure monitoring of Linux servers.

Forked from nuver-labs/vps-audit

The Problem System administrators need a quick, repeatable way to surface common security and performance gaps on newly‑provisioned or unmanaged VPS instances. Manual checklist execution is error‑prone and time‑consuming, especially when the same baseline must be applied across dozens of servers.

What This Does The repository contains a single Bash script, vps-audit.sh, that runs a series of checks covering SSH configuration, firewall status, fail2ban, update level, running services, open ports, sudo logging, password policies, SUID binaries, and basic resource utilization (disk, memory, CPU, network connections).

Results are printed to the console with colour‑coded symbols (🟢 PASS, 🟡 WARN, 🔴 FAIL) and simultaneously written to a timestamped report file (vps-audit-report-<TS>.txt). The script is self‑contained; there are no external library dependencies beyond standard Linux utilities (e.g., grep, awk, netstat, ufw). Documentation lives in README.md, and licensing is declared in LICENSE.

How To Use It Download the script (the only executable artifact) wget https://raw.githubusercontent.com/vernu/vps-audit/main/vps-audit.sh # or curl -O https://raw.githubusercontent.com/vernu/vps-audit/main/vps-audit.sh Make it executable chmod +x vps-audit.sh Run with root or sudo (the script checks for privileged execution early) sudo ./vps-audit.sh

The script will perform all checks, display coloured output, and create a report file in the current directory. No additional configuration files are required; thresholds are hard‑coded near the top of vps-audit.sh and can be edited directly if custom limits are needed.

Real‑World Use A DevOps engineer managing a fleet of Ubuntu 22.04 droplets can embed the command in a cron job (e.g., weekly at 02:00) to generate vps-audit-report-$(date +%F).txt and ship it to a central log aggregation system. The report provides immediate visibility into drift from baseline hardening policies and flags resource saturation before it impacts service availability.

Code Health & Issues Medium – No automated tests – repository lacks any *_test.sh or CI‑run test suite; code paths are unverified. Medium – No CI/CD pipeline – .github/ only contains FUNDING.yml; there is no workflow file to lint, test, or validate the script on push. Low – Limited error handling – many commands assume the presence of utilities (ufw, netstat) and do not check exit codes; failures could produce misleading PASS results. Low – Hard‑coded thresholds – thresholds are embedded as scalar variables; no external config means changes require editing the script, increasing the risk of accidental modification. Low – Debian/Ubuntu scope – the script explicitly checks for apt‑based tools and UFW; it will fail or produce false negatives on other distributions without adaptation. Low – No versioning inside script – no internal version string or self‑update mechanism, making downstream users reliant on manual pulls.

No obvious security secrets are present; the script only reads system files and does not transmit data.

The Bottom Line vps-audit.sh offers a lightweight, zero‑dependency way to obtain a baseline security and performance snapshot on Debian/Ubuntu VPS instances. It is suitable for small‑to‑medium environments where rapid, ad‑hoc auditing is needed, but the lack of tests, CI, and flexible configuration limits its reliability for large‑scale, automated compliance pipelines. Consider augmenting with external validation or integrating into a broader monitoring framework before adopting as a production‑grade compliance tool.
