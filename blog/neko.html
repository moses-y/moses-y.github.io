The Problem

Remote browsing often requires heavy VPNs or insecure screen-sharing tools. Teams and individuals need a lightweight, self-hosted way to share a browser session—for watch parties, collaborative testing, or privacy—without exposing their local machine or relying on third-party services.

What This Does

Neko runs a full desktop environment (e.g., Chromium, Firefox) inside a Docker container and streams it to clients via WebRTC. The server is a Go binary (implied by the Dockerfile.tmpl and build script), while the client is a Vue.js app (client/src/app.vue) that connects using WebRTC. Multiple users can join the same session simultaneously. The repo provides pre-built Docker images for browsers like Brave, Chrome, Firefox, Edge, Opera, and Tor (apps/brave/Dockerfile, apps/firefox/Dockerfile), each with optional NVIDIA GPU support (Dockerfile.nvidia). CI/CD pipelines in .github/workflows/ build and publish images to Docker Hub and GitHub Container Registry. The client handles keyboard layouts, emotes, and chat (client/public/keyboardlayouts.json, client/public/emoji.json, client/public/chat.mp3).

Code Health & Issues

Low — The codebase is mature (forked from a 21k-star project). Tests exist (clienttest.yml, server_test.yml) and CI passes. No obvious security red flags like hardcoded secrets. Low — The client is Vue 2 (.babelrc, .eslintrc present) but not migrated to Vue 3. This is acceptable for a stable project. Medium — The number of browser-specific Dockerfiles (12+ variants) increases maintenance burden. Each has its own supervisord.conf and policies.json; a misconfiguration in one could break that image. Low — No dependency scanning in CI (e.g., Dependabot or Snyk) visible, though package-lock.json is committed.

Overall, the codebase is well-structured, with clear separation between server, client, and app configurations. No critical issues.

The Bottom Line

Neko is a production-ready, self-hosted virtual browser ideal for collaborative browsing, watch parties, and isolated testing. It’s well-documented, actively maintained, and easy to deploy. The main trade-off is the complexity of maintaining multiple browser images; for most teams, the Chromium or Firefox image will suffice.
