The Problem

When multiple AI agents run on different harnesses (Claude, Codex, Devin, opencode, etc.) they cannot see each other’s state, messages, or the recent history of conversations that led to a commit. This isolation hinders coordination, debugging, and auditability in teams that rely on continuous integration pipelines.

What This Does

Flopwire supplies a CLI (cmd/flopwire/main.go) and a set of MCP‑style plugins that give agents:

  • Presence & Messaging – peers, send, inbox (see cmd/flopwire/peers.go‑style commands in accept.go and admin.go).
  • Shared History – a local agent (cmd/flopwire/agent.go) indexes transcript files (see cmd/flopwire/messages.go) and exposes grep, search, sessions, and read.
  • Commit‑to‑Session Mapping – trace (cmd/flopwire/retrieve.go) returns the session that produced a given commit.
  • Rule‑Based Security – path rules in cmd/flopwire/credsource.go and redaction logic in cmd/flopwire/redact.go.

The CLI is cross‑platform; the installer (install.sh) downloads a prebuilt binary from the releases page. For local development, go build ./cmd/flopwire or make suffices.

Testing harnesscmd/flopwire/*_test.goEnd‑to‑end and unit tests that hit the same paths used by production.

A typical run starts with flopwire agent run. main.go hands the agent subcommand to agent.go, which creates a MCPRuntime instance. The runtime registers with the local bus (bus.go), spawns a file watcher (implemented in agent_diagnostics.go), and begins serving over the TLS server (servetls.go). All message traffic flows through the bus, which writes to the SQLite database (migrations/*.sql). The CLI commands for grep or send call the same bus and database layers, keeping the code path minimal and testable.

How To Use It

# 1. Install the binary
curl -fsSL https://flopwire.com/install.sh | sh

# 2. Configure environment (example)
cp .env.example .env
# edit .env to set FLOPWIRE_DB_PATH=/var/lib/flopwire/flopwire.db

# 3. Detect harnesses and start an agent
flopwire setup          # auto‑detects paths in $PATH
flopwire agent run       # keeps the local index alive

# 4. Use the tools
flopwire grep 'exit (code|status) [1-9]' --since 24h
flopwire search 'how did we handle rate limits?'
flopwire peers
flopwire send 4c19e0d2 -- "Heads‑up: the list endpoint returns a cursor now."

For development:

# Build locally
make build

# Run tests
make test

Docker images are built via docker build -t flopwire . (Dockerfile) or docker build -f Dockerfile.release -t flopwire:release ..

Real‑World Use

In a CI pipeline, a Codex job can call flopwire trace <commit> to find the session that produced the commit, then flopwire read <session> to pull the conversation that led to the change. A developer can run flopwire grep locally to see how a recent build failure was discussed. The plugin architecture allows adding new harnesses without touching the core in cmd/flopwire/.

The Bottom Line

Flopwire offers a pragmatic, self‑hostable bridge between heterogeneous AI agents. Its Go core is well‑tested, the CLI is straightforward, and the plugin ecosystem makes it extensible. Teams that already use Claude, Codex, or Devin can integrate Flopwire with minimal effort, but the codebase expects a Go environment and some familiarity with Unix tooling.

Pin third-party GitHub Actions to a commit SHAhigh6 occurrences
.github/workflows
pnpm/action-setup@v4, googleapis/release-please-action@v5, docker/setup-qemu-action@v3, docker/setup-buildx-action@v4
A tag can be moved, so the action running with your token and secrets is whatever its owner last pushed; this is how tj-actions/changed-files leaked secrets from thousands of repos.
Fix: Replace each @vN with the 40-character commit SHA, keep # vN as a comment, and let Dependabot bump the SHAs.

Dockerfile

An untagged or mutable base means today's build and last month's contain different libc and a different CVE set, with no record of which shipped.
Fix: Use image:tag@sha256:<digest> and enable Dependabot's docker ecosystem.
