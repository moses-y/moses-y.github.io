The Problem

Operations teams need to own and audit AI‑driven workflows, but most existing platforms keep the flow definition in code that only engineers can read or modify. This creates a bottleneck when business logic changes, when incidents need rapid triage, or when auditors require a clear decision trail.

What This Does

EpicStaff supplies a self‑hosted visual editor (Angular front‑end) backed by a Django service that stores each node, its Python payload, and execution state. The front‑end lives in frontend/ – e.g. frontend/src/app/app.routes.ts defines the SPA routing, while the widget that can be embedded elsewhere is built from frontend/public/epicchat-widget/main.js.

The back‑end is a standard Django project (Python files under the repo root) that exposes REST endpoints used by the editor and by external agents. Documentation such as docs/backend-runtime-fetch-audit.md and docs/rbac/apikeys.md describes the API contract and permission model.

How To Use It

Setup

The repository ships with Docker support for both front‑end and back‑end.

Clone and enter the repo

git clone https://github.com/EpicStaff/EpicStaff.git cd EpicStaff

Build and start services (frontend Dockerfile and compose file) docker compose -f frontend/docker-compose.frontend.yml up --build Back‑end Dockerfile is not listed but likely present; if a separate compose exists, use it analogously (e.g. docker compose -f docker-compose.yml up)

The top‑level Makefile provides shortcuts documented in docs/makefilecommands.md. Typical targets are:

make dev # spin up development containers make lint # run eslint/prettier checks make test # execute the two test suites

Configuration

Environment variables required by the Django service are referenced in the docs: DJANGOSECRETKEY – secret for Django cryptography. DATABASEURL – connection string for PostgreSQL (used for persistence, see docs/storage/STORAGEAPIREFERENCE.md). REDISURL – optional Redis for agent memory (see docs/knowledgeandrag/RAGQUICKSTARTGUIDE.md).

Place these in a .env file at the repository root; Docker compose files include envfile: .env (implicit from typical patterns). No sample .env is shipped, so you must create it.

Running It

After containers are up, the front‑end is reachable at http://localhost:4200 (Angular dev server defined in frontend/angular.json). The widget can be embedded by loading frontend/public/epicchat-widget/embed.js and initializing it per the client‑side API described in docs/epichatwidget/epicchat-widget-response-format.md.

The Django API is served on port 8000 by default (standard Django runserver). You can verify it with:

curl http://localhost:8000/api/health/

Real‑World Use

A retail operations team could deploy EpicStaff behind their internal network, expose the API to a warehouse‑management system, and let non‑technical staff edit the “order‑fulfillment” flow via the visual editor. The Python node payloads would call the existing ERP APIs, while the built‑in audit logs (persisted in PostgreSQL) satisfy compliance reviews.

Example Python payload stored in a node (documented in docs/codeagent.md) def checkstock(order): qty = externalapi.get_stock(order.sku) if qty < order.amount: raise Exception("Insufficient inventory") return {"status": "ok"}

The Bottom Line

EpicStaff delivers a functional visual AI‑workflow editor backed by a Django API, suitable for organizations that need non‑engineer ownership of agent logic and auditability. The front‑end is ready to run via Docker, but the back‑end requires a custom container build and explicit environment configuration. Teams with moderate dev resources can adopt it for internal workflow orchestration, while solo developers may find the setup overhead disproportionate.
