The Problem

StackChan is a desktop AI robot built on M5Stack's CoreS3 hardware. The challenge is controlling it from a mobile app: configuring Wi-Fi, binding the device, sending dance/motion commands, and managing an AI agent conversation. Without an official app, users are stuck with the factory firmware's limited interface.

What This Does

This repo contains the mobile app source for StackChan (app/), a Flutter project with native iOS (app/ios/Runner/) and Android (app/android/) shells. The Dart code in app/lib/ implements the full feature set: device discovery and binding (app/lib/model/bluemodel.dart, app/lib/util/blueutil.dart), Wi-Fi provisioning (app/lib/view/popup/devicewificonfig.dart), AI agent management (app/lib/model/XiaoZhi/agent.dart), and robot control including dance and motion commands (app/lib/view/home/dance.dart).

The app talks to the robot over BLE for setup and WebSocket (app/lib/network/websocketutil.dart) for real-time control and audio. Native code handles AR rendering on iOS (app/ios/Runner/View/StackChanArView.swift) and 3D model display on Android (app/android/app/src/main/res/raw/stackchanmodel.glb). The entry point is app/lib/main.dart.

How To Use It

Setup: This is a Flutter app. Build with flutter build ios or flutter build apk from the app/ directory. The Gradle wrapper (app/android/gradlew) handles Android builds. No CI configuration exists, so builds are local.

Configuration: No environment variables required. The app uses M5Stack's cloud services by default (see app/lib/network/urls.dart). Device binding requires the robot's MAC address, entered through the app's UI.

Running it: Launch the built app on a phone. The first-run flow (app/lib/view/popup/xiaozhiwelcomepage.dart) walks through device discovery and pairing. The app connects to the robot over BLE for setup, then switches to WebSocket for control.

cd app flutter pub get flutter run

Real-World Use

A user unboxes a StackChan robot, powers it on, and opens the app. The app scans for nearby BLE devices (app/lib/view/home/nearby.dart), the user selects theirs, enters Wi-Fi credentials via devicewificonfig.dart, and the robot connects to the network. The user then binds the robot to their account, selects an AI agent, and can control the robot's movements, trigger dances, or start a voice conversation through the WebSocket connection.

Code Health & Issues

Med - No CI/CD: No .github/ or CI config. No automated build or test gate. The single test file (app/ios/RunnerTests/RunnerTests.swift) is a stub. Med - Platform duplication: The model layer exists in both Dart (app/lib/model/) and Kotlin (app/android/.../model/) and Swift (app/ios/Runner/Model/). This creates three sources of truth that can drift. Low - Asset bloat: 50+ SVG assets and several .mov files (app/assets/setup1.mov, setup2.mov) are bundled. The videos in particular inflate app size. Low - No license file: The README references open-source but no LICENSE file is present in the root. Legal ambiguity for downstream use. Low - Local config committed: app/android/local.properties is typically machine-specific and should be gitignored.

The Bottom Line

This is a functional, feature-complete companion app for a niche hardware product. It's well-organized with clear separation between UI, models, and network layers. The lack of CI and sparse tests make it risky for external contribution, but for StackChan owners it's the only official way to unlock the robot's full capabilities. Suited to hobbyists and M5Stack users, not a general-purpose codebase.
