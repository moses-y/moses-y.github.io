Metasploit termux

Install Latest Metrasploit In Termux (2026). Features automatic Ruby 3.4+ Nokogiri/Gumbo patches, PostgreSQL auto-fix, and silent installation logic. Maintained by @h4ck3r0.

Forked from h4ck3r0/Metasploit-termux

The Problem

Metasploit was removed from official Termux repositories, leaving Android users without a supported installation path. Manual installs fail frequently because Metasploit's Ruby dependencies—particularly nokogiri and its gumbo C extension—break against newer Ruby versions (3.4+). Users also hit PostgreSQL initialization failures and stale PID files that prevent msfconsole from starting.

What This Does

metasploit.sh is the main entry point. It orchestrates the installation: it updates the Termux environment, installs Ruby 3.4.0, applies a patch to fix the gumbo header issue in nokogiri, initializes PostgreSQL, and cleans stale PIDs. The script logs errors to install.log instead of showing them on screen.

The .object/ directory contains the supporting logic. r.sh and re.sh handle Ruby installation and patching; l.sh and ml.sh handle library setup; b.sh and m.sh manage the build and Metasploit framework installation. Pre-built .deb files (ruby.deb, ruby1.deb) are bundled to avoid compiling Ruby from source—a practical choice for Termux's constrained environment.

How To Use It

The README documents the full flow verbatim:

apt update && apt upgrade -y apt install git -y git clone https://github.com/h4ck3r0/Metasploit-termux cd Metasploit-termux chmod +x * bash metasploit.sh

After installation, run msfconsole or msfvenom directly. No additional configuration is required—the script handles PostgreSQL setup automatically. The only manual step is disabling Android's battery optimization for Termux, since the installer and Metasploit are resource-intensive and Android may kill the process.

Real-World Use

A security researcher setting up a mobile penetration-testing lab on an Android device would use this to get a working Metasploit instance without a laptop. The script's silent mode is useful for unattended installs: logs go to install.log, so the user can start the install, walk away, and check the log afterward for failures. The stale-PID cleanup specifically addresses a common real-world failure where a crashed msfconsole leaves a PID file that blocks the next launch.

The Bottom Line

This is a practical, purpose-built installer that solves a real, painful problem: getting Metasploit working on Termux with Ruby 3.4. The bundled .deb files and the patch logic are the differentiators—they address specific failures that generic install scripts hit. The lack of tests and CI is acceptable for a single-maintainer utility script, but the unverified binary artifacts warrant caution. Use it if you need Metasploit on Android and trust the maintainer's build chain; audit the .deb files before running if you are in a security-sensitive environment.
