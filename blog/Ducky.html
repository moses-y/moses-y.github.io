Ducky

Abstract

Ducky is a powerful, open-source, all-in-one desktop application built with Python and PySide6. It is designed to be the perfect companion for network engineers, students, and tech enthusiasts, combining several essential utilities into a single, intuitive graphical interface. We welcome contributions from the community!

The Problem

Network engineers juggle a dozen separate tools—terminals, ping, traceroute, port scanners, DNS lookups, and WHOIS—each with its own interface and workflow. Ducky consolidates these into a single desktop application, eliminating context switching and the need to remember multiple command-line syntaxes.

What This Does

Ducky is a PySide6 desktop application that bundles networking utilities into one tabbed interface. The src/duckyapp/ directory contains the full application: main.py is the entry point, core/ holds the business logic (configmanager.py, sessionmanager.py, workers.py), and ui/ contains the PySide6 widgets, dialogs, and theming. The README documents tools including a multi-protocol terminal (SSH, Telnet, Serial), ping, traceroute, port scanner, subnet calculator, DNS lookups, WHOIS, and SMTP testing.

The application supports session save/load for the terminal and customizable themes. It targets Python 3.8+ and is packaged for Windows via installer.iss (Inno Setup) and buildinstaller.ps1.

How To Use It

Setup: Install dependencies from pyproject.toml. The project uses standard Python tooling—pip install . or pip install -e . should work. There is no lockfile, so builds are not fully reproducible.

Running: Execute python src/duckyapp/main.py from the project root. The application launches the GUI directly; no environment variables or configuration files are required for basic use.

pip install -e . python src/duckyapp/main.py

Windows packaging uses the provided buildinstaller.ps1 script, which invokes PyInstaller via ducky.spec and Inno Setup via installer.iss.

Real-World Use

A network engineer diagnosing a remote office connectivity issue opens Ducky and works through the workflow in one window: ping the gateway, run a traceroute to identify the failing hop, use the port scanner to verify a service is listening, then SSH into the device via the built-in terminal. Session save/load (sessionmanager.py) lets them persist the terminal session and return to it later without re-establishing the connection.

Code Health & Issues

Med - No CI/CD pipeline: No .github/ directory or CI config exists. There is no automated test gate, so regressions can slip in silently. Low - No dependency lockfile: pyproject.toml declares dependencies but no requirements.txt or lock file pins exact versions. Builds are not reproducible. Low - Single test file: Only one test file exists for a 14-file Python codebase. Core logic in workers.py and config_manager.py is likely untested. Low - No input validation visible: Tools like the port scanner and subnet calculator accept user input; without validation in the UI layer (widgets.py), malformed input could cause crashes or unexpected behavior.

The codebase structure is clean—clear separation between core, ui, and utils—and the README is thorough. The lack of CI and tests is the main concern for long-term maintainability.

The Bottom Line

Ducky is a well-organized, feature-rich networking utility that delivers real value for engineers who want a single GUI for common tasks. It is a fork of a more established project (893 stars upstream), so the code has community validation. The lack of CI and minimal test coverage means it is best suited for individual use or small teams willing to accept some regression risk. For a production environment, you would want to add automated testing and a pinned dependency set before relying on it.
