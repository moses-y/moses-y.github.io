The Problem

The Omnichord, a beloved electronic autoharp, was discontinued by Suzuki in 2015, leaving musicians with no affordable source for its distinctive chord strumming and harp sounds. Existing alternatives are either expensive vintage units, complex DIY builds, or software that fails to capture the tactile, playable feel of the original.

What This Does

minichord is a complete, open-source hardware and firmware project for a pocket-sized Omnichord-inspired instrument. It is a fork of BenjaminPoilve/minichord (438 stars) and contains everything needed to build the device from scratch: PCB manufacturing files, a full bill of materials (documentation/docs/ressources/BOMSMD.csv, BOMTH.numbers), 3D enclosure files, and firmware.

The repository is documentation-heavy, with 145 doc files and a fully built MkDocs site in documentation/site/. The core user-facing artifacts are the assembly guide (documentation/docs/assembly.md) and user manual (documentation/docs/usermanual.md). The firmware itself is referenced in the README as a PlatformIO project, but the actual source is not present in this fork—only the documentation and a web-based controller (documentation/site/minicontrol/javascript/index.js).

How To Use It

This is a hardware build project, not a software install. There is no build system for the instrument itself; you manufacture the PCB, source components, and flash the Teensy microcontroller. Setup: The only Python dependency is for the documentation site, declared in documentation/requirements.txt. Install with pip install -r documentation/requirements.txt. Configuration: No runtime configuration exists. Hardware assembly follows the guide in documentation/docs/assembly.md. Running it: The MkDocs site builds via documentation/buildsite.sh. The firmware flashing process is documented in the README but the actual .hex file and PlatformIO project are not in this fork. The web-based controller runs by opening documentation/site/minicontrol/index.html in a browser.

cd documentation pip install -r requirements.txt ./buildsite.sh

Real-World Use

A musician builds the device following the assembly guide, then uses the minicontrol web app (documentation/site/minicontrol/index.html) to edit presets and share them via sharedpresets.json. The device connects over MIDI, and users can swap custom chord voicings and strum patterns through the controller's JavaScript interface.

Code Health & Issues

Low - No dependency lockfile - documentation/requirements.txt pins no versions, so the MkDocs build is not reproducible. Low - Build artifacts committed - The documentation/site/ folder contains a fully built static site, duplicating the source docs and bloating the repo. Low - Missing firmware source - The README references firmware/firmware.hex and a PlatformIO project, but neither exists in this fork's file listing. Only documentation is present.

The Bottom Line

This is a well-organized documentation repository for a compelling hardware project, but it is incomplete as a source distribution—the firmware and hardware source files are absent. It is useful as a reference for the build process and the minicontrol web app, but anyone wanting to actually build the device should use the upstream repository, which contains the full source.
