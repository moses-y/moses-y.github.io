The Problem

AI‑coding agents often drift from proven engineering practices, producing code that lacks proper specification, testing, or performance checks. Teams need a reusable, enforceable set of “skills” that encode senior‑engineer workflows so agents can follow them automatically.

What This Does

agentskills ships 24 self‑contained skill packages (e.g., code-review-and-quality, test-driven-development) that map directly to stages of a software lifecycle. Each skill lives in skills/<skill-name>/SKILL.md and references shared checklists in references/. The repository also contains a full suite of evaluation fixtures (evals/fixtures/) that model real‑world scenarios (API design, CI/CD, performance audits, etc.) and a set of validation scripts (scripts/validate‑.js) that ensure skill definitions stay consistent.

Key files:

commands/.toml – declarative command definitions (/spec, /plan, /build, …) used by the external skills CLI. scripts/run-evals.js – driver that executes the evaluation fixtures against an agent. evals/README.md – description of the test matrix and how each case is scored.

How To Use It

Clone the repo

git clone https://github.com/moses-y/agentskills cd agentskills Install the supporting CLI (the repo expects the public skills CLI, not bundled here). The README recommends:

npx skills add addyosmani/agent-skills # installs all skills # or install a single skill npx skills add addyosmani/agent-skills --skill test-driven-development

If the CLI is not already available, the repository’s scripts/ folder provides the validation harness that can be run with Node. Run the built‑in evaluations (useful for sanity‑checking a new agent integration):

node scripts/run-evals.js # executes all eval fixtures

The script loads each fixture under evals/fixtures/ (e.g., browser-testing-with-devtools/server.js) and reports pass/fail against the skill definitions. Configuration – No explicit environment files are shipped. Skills that need external resources (e.g., API keys for a cloud provider) must be supplied by the consuming agent; the repo does not contain secret placeholders. Extending / customizing – Add a new skill by creating skills/<new‑skill>/SKILL.md following the existing anatomy (docs/skill-anatomy.md). Register a command in commands/ with a matching .toml file and update plugin.json if you want marketplace visibility.

Real‑World Use

A development team integrates the Claude Code agent. After installing the full skill set (npx skills add addyosmani/agent-skills), a developer writes a feature brief and runs /spec. The CLI expands the spec into a task plan (/plan) and triggers the build skill to generate incremental PRs. Each PR runs the test skill, which executes the fixture test suite (evals/fixtures/test-driven-development). When all tests pass, the review skill enforces the multi‑axis code‑review checklist before the PR is merged and finally the ship skill tags the release. All steps are auditable because each skill logs its gate outcomes.

Code Health & Issues

Low – Missing lockfile – evals/fixtures/ci-cd-and-automation/package.json declares dependencies without a package-lock.json or yarn.lock, making reproducible builds non‑deterministic. Low – No CI config for the repo itself – The only workflow present (.github/workflows/test-plugin-install.yml) validates plugin installation, but there is no pipeline that runs the 42 test files under evals/. Low – Documentation fragmentation – 22 Markdown docs exist, but several key operational files (e.g., a top‑level README for the CLI integration) are missing, requiring users to rely on external skills CLI docs.

No high‑severity security or licensing problems are evident from the file tree; the repository includes an LICENSE file.

The Bottom Line

agentskills provides a well‑structured collection of engineering best‑practice “skills” that can be plugged into AI coding agents via the public skills CLI. It excels at formalizing workflows and includes a rich set of evaluation fixtures. The main drawbacks are the lack of a lockfile for reproducible npm installs and the absence of an end‑to‑end CI pipeline for the repo itself. It is most useful for teams that already use a supported agent (Claude, Codex, etc.) and need a ready‑made, auditable process for guiding those agents through a full software lifecycle.
