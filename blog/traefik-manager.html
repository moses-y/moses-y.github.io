The Problem

Managing a Traefik reverse‑proxy by hand means editing multiple YAML files, restarting services, and tracking changes across homelab nodes. A mistake can take a service offline at night, and keeping backups or syncing configs between machines is tedious.

What This Does

traefik-manager supplies a self‑hosted web UI that talks to a lightweight Go agent (agent/main.go) deployed on each Traefik instance. The UI (Vue code under docs/.vitepress/theme/) lets users create, edit, enable or disable HTTP/TCP/UDP routes, middle‑wares, TLS certificates and static traefik.yml without touching YAML directly.

Core server logic lives in Python (app.py and the core/ package). Functions such as core/traefik.py query the Traefik API, while core/backups.py handles timestamped local backups and optional Git pushes. The Go agent provides a thin proxy for remote Traefik instances, exposing the same API over HTTP (agent/handlers.go).

All components are containerised; the top‑level Dockerfile builds the UI + Python server, and agent/Dockerfile builds the Go binary.

How To Use It

Setup

Clone the repo

git clone https://github.com/chr0nzz/traefik-manager.git cd traefik-manager

Build and start with Docker Compose (uses the provided compose file) docker compose up -d

Evidence: docker-compose.yml defines two services – the manager container (exposes port 5000) and an optional agent service. The repository also ships a Makefile with a make docker-build target that runs docker build -t traefik-manager ., confirming the intended build path.

Configuration

Copy the example env file and edit as needed:

cp .env.example .env Edit .env – at minimum set COOKIESECURE, TRAEFIKURL, and optional GIT credentials

Key variables referenced in core/config.py include TRAFFIKURL, APIKEY, and BACKUPPATH. The agent reads its own .env.example (agent/.env.example) for AGENTPORT and the shared secret used to authenticate the manager. Mount persistent volumes as shown in the README snippet:

volumes: /path/to/traefik/dynamic.yml:/app/config/dynamic.yml /path/to/traefik-manager/config:/app/config /path/to/traefik-manager/backups:/app/backups

Running

The manager runs automatically when the container starts (entrypoint defined in Dockerfile). For a native run without Docker:

Install Python deps (requirements.txt is inferred from imports) pip install -r requirements.txt # not explicit but typical for Flask/Django mix python app.py

The Go agent can be run directly for debugging:

cd agent go run main.go

Once the container is up, open http://<host>:5000 and follow the web‑based setup wizard.

Real‑World Use

A homelab with three Raspberry‑Pi nodes runs Traefik on each. Deploy the Go agent on every node (via its own Docker image) and point a single Traefik‑Manager instance to the agents’ URLs. The UI then presents a unified dashboard where the admin can add a new subdomain, assign it to a service on node 2, and enable a rate‑limit middleware—all with one click, while the manager automatically commits the change to a Git backup repository.

Example agent definition in docker-compose.yml

agent: image: ghcr.io/chr0nzz/traefik-agent:latest environment: AGENTSECRET=supersecret TRAEFIKURL=http://traefik-node2:8080

Code Health & Issues

Bugs / Risks Medium – core/crypto.py handles secret storage but lacks explicit zero‑ing of memory; in a high‑security environment this could retain keys in RAM. Low – UI component ComposeUpgrader.vue imports a remote image URL without fallback, which may break in offline setups. SDLC & Code Violations Low – No requirements.txt or pyproject.toml is present, so Python dependency management is implicit; this can hinder reproducible builds. Low – Tests exist for the Go agent (_test.go), but the Python/ Vue layers have no automated test suite. CI runs the Go tests but not UI or Python linting. None – License (GPL‑3.0) is included, CI workflows are defined (.github/workflows/.yml), and Dockerfiles are present, indicating a reasonable release process.

Overall the repository shows a coherent structure, clear entry points, and functional CI for the compiled component. The missing Python dependency file and lack of frontend tests are the most notable gaps.

The Bottom Line

traefik-manager delivers a practical UI plus a Go agent for centralized Traefik control, making homelab routing far less error‑prone. It is production‑ready for single‑node or small‑cluster setups, provided you accept the limited automated testing of the Python/Vue layers and add your own dependency lock file. Teams that need rapid UI‑driven configuration without building a custom front end will find it immediately useful.

Pin third-party GitHub Actions to a commit SHAhigh6 occurrences
.github/workflows
docker/setup-qemu-action@v3, docker/setup-buildx-action@v3, docker/login-action@v3, docker/metadata-action@v5
A tag can be moved, so the action running with your token and secrets is whatever its owner last pushed; this is how tj-actions/changed-files leaked secrets from thousands of repos.
Fix: Replace each @vN with the 40-character commit SHA, keep # vN as a comment, and let Dependabot bump the SHAs.
Commit a lockfile beside the manifesthigh
package.json
manifest with no lockfile in scope
An unlocked range means the artifact you tested and the artifact you ship can contain different transitive code, so a malicious patch release reaches production with no diff.
Fix: Run the package manager once and commit the generated lockfile.
Re-enable certificate verificationhigh
app.py
verify=False
With verification off the connection is encrypted to whoever answered, which is no protection at all: anyone positioned between the two hosts can present their own certificate, read the traffic and alter it, and the request will still succeed.
Fix: Remove the flag, and if the peer uses a private CA point the client at that CA bundle instead.
Replace the unsafe deserializer with a data-only formathigh2 occurrences
core/config.py
yaml.load without SafeLoader
pickle and yaml.load reconstruct arbitrary Python objects, which means the loader executes whatever the payload asks for, so any path where that data crossed a network or a user upload is remote code execution rather than a parsing bug.
Fix: Use yaml.safe_load, or JSON, and for model weights prefer a format that does not carry code.
Declare least-privilege permissions for GITHUB_TOKENmedium
.github/workflows/tests.yml
1 workflow(s) declare no permissions
With no declaration the token inherits the repository default, so any injected step can push commits or mint releases from inside your own CI.
Fix: Add permissions: contents: read at the top of the workflow and widen per job only where needed.
Enable Dependabot or Renovatemedium
4 manifest(s), no update bot configured
Without a bot a published advisory sits unpatched until someone audits by hand, which across 1,322 repositories means never.
Fix: Commit .github/dependabot.yml covering the repo ecosystems plus github-actions.
Pin the container base image by digestmedium
Dockerfile
python:3.11-alpine
An untagged or mutable base means today's build and last month's contain different libc and a different CVE set, with no record of which shipped.
Fix: Use image:tag@sha256:<digest> and enable Dependabot's docker ecosystem.
Gate pull requests on a dependency vulnerability scanmedium
.github/workflows
no dependency scan in CI
This is the one gate that would catch a known-vulnerable package before it reaches a build, and no repository in the sample had it.
Fix: Add dependency-review-action on pull_request, or osv-scanner on push and a schedule.
Set persist-credentials: false on checkoutmedium
.github/workflows/tests.yml
checkout keeps the token, then dependencies are installed
The token stays in .git/config for every later step, so a malicious postinstall script reads a pushable credential without one ever being passed to it.
Fix: Add with: persist-credentials: false, and pass an explicit token only to the step that pushes.
Add a non-root USER to the imagemedium
Dockerfile
CMD or ENTRYPOINT with no USER directive
A process running as root in the container is root against every mounted volume, and it turns any container escape or writable-mount mistake from a contained problem into a host one.
Fix: Create an unprivileged user, chown what it needs, and end the Dockerfile with USER.

A wedged step runs to the six-hour platform default, which on a two-hourly schedule means three runs overlap behind it.
