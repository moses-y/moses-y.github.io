mcp toolbox

MCP Toolbox for Databases is an open source MCP server for databases.

Forked from googleapis/mcp-toolbox

The Problem Enterprise applications need a controlled way for AI agents to query production databases. Direct LLM‑to‑SQL access is risky: it can expose schema details, run unvalidated queries, and bypass audit logs. Teams therefore require a gateway that enforces policy, provides reusable tooling, and integrates with existing MCP clients (Gemini, Claude, etc.).

What This Does mcp-toolbox implements an MCP‑compatible server that sits between AI agents and a variety of Google Cloud databases (BigQuery, CloudSQL, Spanner, etc.). The core server lives in the cmd/ package; the CLI entry point is cmd/root.go, which wires sub‑commands defined in cmd/internal/ (e.g., serve, invoke, skills). Pre‑built generic tools (list tables, execute SQL, semantic search) are defined under docs/en/documentation/configuration/tools/ and exposed via the invoke command.

The repository also ships a full documentation site built with Hugo (.hugo/), and language‑specific SDKs (Go, Python, JS/TS) are referenced in the docs but not part of the server binary. Docker support is provided by the top‑level Dockerfile, enabling containerised deployment.

How To Use It

Setup Build the binary (requires Go 1.22+) go build -o mcp-toolbox ./cmd

Or build the container docker build -t mcp-toolbox:latest .

The presence of go.mod files in the docs folder and the Go source under cmd/ confirms a standard Go build workflow. No Makefile is present, so go build is the canonical command.

Configuration Runtime configuration is parsed by cmd/internal/config.go. The server expects a YAML file named config.yaml placed alongside the binary or referenced via the --config flag. Example keys (derived from the code’s Config struct) include: databases.<name>.type (e.g., bigquery, cloudsqlmysql) databases.<name>.credentials (path to service‑account JSON) auth.method (e.g., google, generic)

A sample file is provided in the docs at docs/en/documentation/configuration/toolboxmcpauth.md. Environment variables can also override settings; the code checks os.Getenv for MCPTOOLBOXCONFIG.

Running Start the server (default reads ./config.yaml) ./mcp-toolbox serve

Run a pre‑built tool, e.g., list tables in the "mydb" source ./mcp-toolbox invoke --tool=listtables --source=mydb

The serve command is implemented in cmd/internal/serve/command.go; the invoke command lives in cmd/internal/invoke/command.go. Both commands are exercised by the test suite (test.go files in the same directories).

Real‑World Use A data‑science platform can launch the toolbox as a sidecar container:

services: toolbox: image: mcp-toolbox:latest volumes: ./config.yaml:/app/config.yaml:ro ports: ["8080:8080"]

An LLM‑driven notebook then calls the MCP endpoint (http://toolbox:8080) to run listtables or executesql without embedding raw credentials. The toolbox validates the request against the policy defined in config.yaml before forwarding the query to BigQuery.

Code Health & Issues Low – Missing root go.mod – No top‑level go.mod is listed; the server may rely on an implicit module. If absent, builds will fail for users outside the original workspace. Medium – Limited secret management – Credentials are referenced as file paths in config.yaml. No built‑in secret‑rotation or Vault integration; operators must secure the config file externally. Low – Test coverage – 23 test files exist (test.go), covering most CLI commands, but there are no integration tests for database adapters. Low – Dependency hygiene – Dockerfile and Go code are isolated, but the repo includes many third‑party SDK version badges; actual version pinning is only in go.mod (not shown) and package.json for docs. No automated Renovate PRs are configured for the Go module. Low – CI completeness – GitHub Actions define lint, test, and deploy workflows (.github/workflows/.yaml). CI runs on push and pull request, indicating a healthy pipeline.

Overall, the codebase follows Go best practices (separate packages, cobra CLI, unit tests) and ships a reproducible Docker image. The primary risk is the missing top‑level module file and reliance on plain‑text credential paths.

The Bottom Line mcp-toolbox provides a pragmatic, well‑documented gateway for secure AI‑driven database access, with ready‑to‑use generic tools and an extensible framework for custom skills. It is suitable for teams that already use Go and can manage configuration/credential files securely. Minor gaps (missing go.mod, secret handling) should be addressed before production rollout, but the existing CI, tests, and Docker support make the project easy to adopt and extend.
