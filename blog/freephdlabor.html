The Problem

Researchers spending evenings manually drafting literature reviews, designing experiments, and formatting manuscripts face repetitive drudgery before any original work begins. This repo addresses that by automating the full lifecycle—from ideation through writeup—using a coordinated multiagent architecture, but it comes with operational trade‑offs that affect adoption in production settings.

What This Does

freephdlabor organizes work across 120+ files in freephdlabor/ and 63 files in externaltools/runexperimenttool/, encompassing agents for ideation, experimentation, review, and writeup. The system uses prompt files under freephdlabor/prompts/ to steer each agent, while toolkits in freephdlabor/toolkits/ provide concrete utilities such as arXiv fetching (freephdlabor/toolkits/generaltools/fetcharxivpapers/), file editing (freephdlabor/toolkits/generaltools/fileediting/), and knowledge‑base management (freephdlabor/toolkits/generaltools/kbrepomanagement/). A config file .llmconfig.yaml at the root lets you select models per component, and API keys are expected in .env. The framework supports two modes: running out‑of‑the‑box with python launchmultiagent.py --task "your idea", or customizing agents for domain‑specific problems by modifying or adding agents in freephdlabor/agents/.

How To Use It

Setup git clone https://github.com/ltjed/freephdlabor.git cd freephdlabor conda env create -f environment.yml conda activate freephdlabor

Edit .env with your API keys (OPENAIAPIKEY, ANTHROPICAPIKEY, etc.) and optionally adjust model selection in .llmconfig.yaml.

Configuration

Required environment variables are defined in .env; model preferences go in .llmconfig.yaml. No lockfile is present, so pip install -r externaltools/runexperimenttool/requirements.txt may pull incompatible versions across runs.

Running it

python launchmultiagent.py --task "Your research idea or direction here"

The entry point launchmultiagent.py at the repo root orchestrates the agent workflow. For SLURM clusters, launchmultiagentslurm.sh is provided.

Real-World Use

A materials‑science team could fork the repo, define domain‑specific tools in freephdlabor/toolkits/ (e.g., a custom fetcharxivpapers filter for superconductor datasets), and add a new agent subclass in freephdlabor/agents/ to propose crystal‑structure hypotheses. The manager agent would then route ideation, experiment design, and writeup generation, producing a draft manuscript with figures and citations without manual copy‑pasting between tools.

The Bottom Line

This is a highly extensible multiagent framework that can automate end‑to‑end scientific workflows with minimal configuration, making it well‑suited for researchers who want to prototype or parallelize ideas across domains. However, the lack of a lockfile, CI/CD, and committed secrets in .env mean it demands disciplined operational practices—particularly around dependency management and credential hygiene—before it can be relied upon in production or shared collaboratively.
