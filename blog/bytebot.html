bytebot

Bytebot is a self-hosted AI desktop agent that automates computer tasks through natural language commands, operating within a containerized Linux desktop environment.

Forked from bytebot-ai/bytebot

The Problem

Organizations need AI agents that can interact with real desktop applications—browsers, email clients, IDEs, file systems—not just APIs or browser-only sandboxes. Existing RPA tools require rigid scripting, while LLM-based agents lack a persistent, containerized environment for multi-step workflows.

What This Does

Bytebot runs an AI agent inside a containerized Linux desktop (via Docker). The agent sees the screen, moves the mouse, types, and runs commands to complete natural-language tasks. The core logic lives in packages/bytebot-agent/src/agent/agent.processor.ts and agent.computer-use.ts, which orchestrate tool calls against the desktop environment.

The system supports multiple LLM providers. Provider-specific integrations are in packages/bytebot-agent/src/anthropic/, openai/, and google/, each with a service and tools file. Tasks are persisted via Prisma (schema in packages/bytebot-agent/prisma/schema.prisma) and exposed through a NestJS REST API (tasks.controller.ts). Deployment is Docker Compose (docker/docker-compose.yml) or Helm (helm/).

Real-World Use

A typical workflow: "Download all invoices from vendor portals and organize them into a folder." The agent opens a browser, navigates to each portal, handles authentication (including 2FA via password managers), downloads files to its local filesystem, and organizes them. No API integrations required.

Code Health & Issues Medium - No tests detected. Zero test files across 200 files. The agent's core loop (agent.processor.ts) and computer-use actions (agent.computer-use.ts) are untested. This is a significant risk for production use. Low - Hardcoded provider constants. anthropic.constants.ts, openai.constants.ts, and google.constants.ts contain API keys and endpoints as constants, not environment-injected config. This makes multi-tenant or dynamic provider switching harder. Low - No input validation on task DTOs. create-task.dto.ts and update-task.dto.ts appear to be plain TypeScript classes without validation decorators (class-validator). Malformed task payloads could reach the agent processor. Low - 11 migration files suggest schema instability. The Prisma migrations show ongoing schema changes (auth removal, file support, scheduling). This is acceptable for an active project but indicates the data model is not yet stable. Low - No CI test step. The three GitHub Actions workflows (build-agent.yaml, build-desktop.yaml, build-ui.yaml) build Docker images but do not run tests or linting.

The Bottom Line

Bytebot is a well-architected open-source desktop agent for teams that need an AI capable of full computer interaction—not just web browsing. The NestJS backend, multi-provider support, and Helm chart make it production-ready in structure, but the complete absence of tests and ongoing schema churn mean it's better suited for prototyping and internal tooling than customer-facing deployments today. If your team can invest in test coverage and pin the schema, this is a solid foundation.
