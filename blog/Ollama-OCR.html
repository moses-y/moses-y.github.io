Ollama-OCR: Technical Briefing

The Problem This package addresses the need to extract text from images and PDFs using vision-language models hosted via Ollama. It targets developers and teams who need OCR capabilities without relying on cloud APIs, offering local model inference through Ollama's runtime.

What This Does Ollama-OCR provides a Python package and Streamlit web application that wraps several vision models (LLaVA, Llama 3.2 Vision, Granite3.2-vision, Moondream, MinicPM-v) through Ollama's API. The core processing lives in src/ollamaocr/ocrprocessor.py with an Flask-based entry point at src/ollamaocr/app.py. It supports batch processing, image preprocessing, custom prompts, and six output formats (markdown, text, json, structured, keyvalue, table). The README documents single-file and batch workflows using OCRProcessor.processimage() and OCRProcessor.processbatch().

How To Use It Setup: Install Ollama, pull a vision model (e.g., ollama pull llama3.2-vision:11b), then install the package: pip install ollama-ocr. No lockfile is present, so dependency versions are unresolved. Configuration: The OCRProcessor initializer requires modelname and baseurl pointing at Ollama's API endpoint (default: http://host.docker.internal:11434/api/generate). Environment variables or secret keys are not referenced in the code. Running it: Import OCRProcessor from the package and call processimage() for single files or processbatch() for directories. The Flask app at src/ollamaocr/app.py presumably serves a web interface, though its routing is not exposed in the structure provided.

Real-World Use A document processing pipeline could initialize one processor instance with maxworkers=4 for parallel batch runs, feed it a folder of invoices or forms, and receive markdown-formatted text suitable for downstream data entry or archival systems. The language parameter and customprompt flags allow tailoring extraction to specific domains (e.g., "Extract invoice number and total amount").

Code Health & Issues No test files detected - untested code paths repository-wide. No CI/CD pipeline exists, so there is no automated build or test gate. Dependencies declared without a lockfile - requirements.txt lists pins but no requirements.lock or uv.lock, meaning builds are not reproducible across environments. No license file detected in the initial scan - though a LICENSE file exists at root, it was not flagged in the heuristic output. Input validation gaps - the processimage and processbatch methods accept paths and model names without apparent sanitization; malformed paths or unavailable models would likely cause unhandled exceptions. Separation of concerns - the Flask app at app.py and the processor logic in ocrprocessor.py are distinct, but the extent of their coupling (imports, shared state) is unclear without reading the source.

The Bottom Line Ollama-OCR is a functional wrapper for local vision-model OCR via Ollama, with reasonable format support and batch capabilities. It is suitable for individual developers or teams already running Ollama who need to extract text from images/PDFs without API costs. The absence of tests, a lockfile, and CI/CD represents a moderate risk for production use, and input validation is minimal. Teams requiring auditable pipelines or reproducible deployments should pin dependencies and add testing infrastructure before integrating this into critical workflows.
