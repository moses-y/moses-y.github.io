The Problem AI agents lack a local-first memory layer that integrates with existing Obsidian vaults, forcing context to exist outside the tools developers already use. The repo addresses this by turning Obsidian vaults into deterministic memory layers for AI agents through CLI and MCP tools.

What This Does Open Second Brain provides an Obsidian-native memory layer that plugs into Hermes Agent, converting your vault into a read/write memory for AI agents. The system stores preferences, signals, and evidence as real .md files under Brain/ in your vault—files you can grep, version with git, and search in Obsidian. Key components include the cli.py entry point, adapters for Claude Code (.codex-plugin/), Claude plugin (.claude-plugin/), and an MCP server configuration (.mcp.json). The recent 1.44.0 release fixed critical bugs: a transient index failure was incorrectly classified as corruption triggering silent rebuilds, and entity extraction catastrophically backtracked on Chinese/Thai/Lao text (eleven seconds per chunk, cubic growth). The codebase deliberately omits runtime embedding window probing and derived store snapshots, declaring preset windows instead.

How To Use It Setup: The project uses bun ( evidenced by bun.lock and bunfig.toml). Install dependencies with: bun install

Configuration: Required config lives in brain.yaml at the vault root, where you can declare path prefixes for writer permissions. The .mcp.json configures the Model Context Protocol server for non-native adapters. Running it: Invoke the CLI entry point: python cli.py

or for Hermes Agent integration, use the provided MCP server configuration.

Real-World Use In a development workflow, when Hermes Agent needs project context, it queries the Obsidian vault through Open Second Brain's deterministic tools rather than hallucinating from a vector black box. An agent can extract entities from a fetched article, which lands in a quarantine lane per the 1.44.0 provenance updates, then review the brain.yaml-quarantine boundary before the agent writes conclusions. The agent can also persist preferences as .md files that survive across sessions—so if you correct the agent's output twice on a topic, the nightly "dream" pass converts that into a confirmed preference with measured confidence.

Code Health & Issues Bugs/risks: The 1.44.0 CHANGELOG documents two fixed bugs: transient index failures classified as corruption causing silent data loss, and entity extraction O(n³) backtracking on non-Latin scripts making Chinese vaults impossible to index. These are now fixed but indicate previously high-risk patterns. SDLC & code violations: No test files detected in the analysis (1 test file found vs. expected coverage). CI/CD is configured via GitHub Actions (ci.yml, release.yml) but test coverage appears minimal. No security scanning evidence observed. The README mentions brain.yaml config but it may not be present in all vault configurations. Documentation: 182 doc files present in docs/—extensive but mostly brainstorm/design artifacts rather than user guides.

The Bottom Line This is a practical, local-first memory layer that works well for Hermes Agent users already invested in Obsidian vaults. The deterministic CLI/MCP approach avoids vector black box risks, and the recent bug fixes address serious indexing failures. However, the minimal test presence, limited CI coverage, and the fact that it's forked from a repo with 162 stars while this version has 0 suggests it's early-stage adoption.
