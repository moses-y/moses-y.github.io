Dishylink

An open-source desktop app for macOS, Windows and browsers to monitor the performance and health of your Starlink.

Forked from DaveyHert/Dishylink

The Problem Starlink users need a reliable way to view real‑time dish health and network metrics without relying on cloud services that disappear during outages. Existing tools either require a paid account, expose data to external servers, or lack cross‑platform support.

What This Does Dishylink is a self‑hosted monitoring suite that talks directly to a Starlink dish and router over the local LAN. The core telemetry logic lives in core/ (e.g., core/telemetry.ts, core/dishClient.ts) and stores raw records in the collector/ module (collector/historian.mts, collector/jsonLinesFile.mts).

A desktop client is built with Electron; its entry point is electron/main.ts, which spawns the UI (electron/throughputWidget.ts, electron/menuBarThroughput.ts) and handles IPC (electron/ipc.ts).

A browser extension ships from extension/entrypoints/dashboard/index.html and its TypeScript glue (extension/entrypoints/dashboard/main.tsx).

A marketing/landing site is generated with Astro (landing/astro.config.mjs, landing/src/pages/index.astro). All UI components share a React/TSX stack (src/App.tsx, src/assets/).

How To Use It Prerequisites – Node ≥ 18, npm (or npm ci‑compatible lockfile). Install – From the repository root:

npm ci # installs exact versions from package-lock.json Build – The root package.json defines a build script (inspect scripts field). Typical command:

npm run build # compiles TypeScript, bundles Electron and extension Run Desktop – Electron’s main process is electron/main.ts. The package.json usually provides an electron script:

npm run electron # starts the desktop app

Alternatively, launch directly with npx electron . after the build step. Run Extension – Load the unpacked extension from the extension/ folder in Chrome/Edge/Firefox. The UI entry point is extension/entrypoints/dashboard/index.html. Run Landing Site (optional) –

cd landing npm ci npm run dev # Astro dev server, http://localhost:4321

No environment variables are required for basic monitoring; optional Starlink‑account integration prompts for credentials at runtime and stores them locally.

Real‑World Use A home‑office router runs Dishylink on a Windows laptop. The Electron UI shows live downlink/uplink, latency spikes, and a 3‑D obstruction dome. When the ISP experiences an outage, the app continues recording locally, and the user can later review the collector/.mts logs to pinpoint the exact minute the dish lost GPS lock. A small script could ingest those logs into a home‑assistant dashboard:

import { readHistorical } from './collector/historian.mts'; const data = await readHistorical('2024-08-01'); console.log(Total downtime: ${data.totalOutageMinutes} min);

Code Health & Issues Bugs / Risks Med – Unvalidated network payloads – electron/ipc.ts forwards raw dish responses; missing schema checks could cause crashes on malformed data. Low – Platform‑specific plist – collector/com.dishylink.historian.plist is macOS‑only; Windows/Linux builds may lack equivalent service registration. SDLC / Code Violations Low – Missing explicit run scripts in README – No documented npm run start or npm run electron commands; users must infer from package.json. Low – No secret management – Optional Starlink credentials are stored locally without encryption; not a security flaw for a personal tool but worth noting. Low – Dependency hygiene – No automated Dependabot or npm audit in CI; security updates must be applied manually.

Overall the repository includes unit tests (.test.ts, .test.mts), a CI workflow (.github/workflows/ci.yml), lockfiles, and a permissive MIT license, indicating a mature baseline.

The Bottom Line Dishylink delivers a fully offline, cross‑platform Starlink monitor with a polished Electron UI and optional browser extension. The codebase is well‑structured and test‑covered, though users must rely on standard npm conventions for building and launching. Ideal for technically inclined Starlink owners who need local, uninterrupted visibility into dish performance; less suitable for teams that require formal onboarding docs or automated security scanning.
