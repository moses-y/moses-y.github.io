The Problem

3D Gaussian splatting produces large, heterogeneous point-cloud datasets that need conversion between competing formats (.ply, .spz, .ksplat, .sog) and downstream processing like decimation, quantization, and collision mesh generation. Most tools handle one format or one pipeline stage, forcing teams to stitch together fragile scripts.

What This Does

splat-transform is a TypeScript library and CLI for reading, writing, and editing Gaussian splats. It reads 7 formats and writes 9, including GLB with the KHRgaussiansplatting extension and a bundled .sog format. Core processing lives in src/lib/data-table/ (decimate.ts, transform.ts, sh-bands.ts) and src/lib/process.ts, which chains read → action → write operations. Spatial indexing (src/lib/spatial/) provides BVH, k-d tree, and k-means clustering for reordering and level-of-detail generation.

The I/O layer is split into pluggable file systems (src/lib/io/read/ and write/) supporting memory, URL, and ZIP backends, so the library works in Node and browsers. Voxelization and collision output (src/lib/voxel/, src/lib/writers/collision-glb.ts) are a notable differentiator—most splat tools don't produce collision geometry.

How To Use It

Setup: Install globally or as a dependency via npm (from package.json):

npm install -g @playcanvas/splat-transform or npm install @playcanvas/splat-transform

Configuration: No config files or environment variables required. CLI flags are passed inline.

Running it: The CLI entry point is src/cli/index.ts, exposed via bin/cli.mjs. The command structure is input [ACTIONS] output [ACTIONS], where actions apply in order and can appear after any file. Use null as output to discard results:

splat-transform input.ply -t 1,2,3 --filter-harmonics 2 output.sog splat-transform input.sog --summary null

Library usage imports from src/lib/index.ts.

Real-World Use

A photogrammetry pipeline that captures scenes as .ply, then needs web-deliverable assets: convert to .sog for size, generate an .html viewer for quick review, and emit collision-glb for physics. The CLI handles all three in one pass:

splat-transform scan.ply --decimate 0.5 output.sog --write-html viewer.html --collision-glb collision.glb

The library also supports programmatic use—merge multiple splats, reorder for GPU locality, and write LOD bundles via write-lod.ts.

Code Health & Issues

Med – WebAssembly binary committed: lib/webp.wasm and lib/webp.c are checked in. This works but bloats the repo and complicates audits; a build step would be cleaner. Low – Mixed test harness: Tests are .mjs while source is TypeScript, and fixtures are generated (test/fixtures/create-fixtures.mjs). That's workable but means tests can't be run without generating fixtures first. Low – No docs for generators/: gen-grid.mjs and gen-room.mjs are procedural splat generators with no README coverage. Minor discoverability gap. Good: CI (ci.yml), publishing (publish.yml), dependabot, renovate, 30 test files, and a license are all present. The codebase is well-structured with clear separation between readers, writers, and processing.

The Bottom Line

This is a mature, well-engineered tool from PlayCanvas—the format coverage alone makes it valuable, and the collision/voxel output is a differentiator. The WebAssembly binary and fixture-based tests are minor warts. Teams doing serious Gaussian splat processing should adopt it; casual users will find the CLI straightforward.
