The Problem

Google Flights has no official public API. Developers who need flight data for price tracking, travel planning tools, or fare comparisons are forced to either scrape HTML (fragile, breaks often) or pay for expensive enterprise APIs. This repo provides a Python library that extracts flight data directly from Google Flights' internal protobuf payloads, bypassing HTML parsing entirely.

What This Does

fastflights is a strongly-typed Python client for Google Flights. The core logic lives in fastflights/querying.py and fastflights/fetcher.py, which construct Base64-encoded protobuf requests and decode the response. The request/response schema is defined in fastflights/pb/flights.proto, with generated Python bindings in flightspb2.py.

The API is clean and ergonomic. FlightQuery in fastflights/types.py accepts per-leg filters (max stops, airlines, departure/arrival windows, layover times, emissions preference), while createquery() handles search-wide options like currency, baggage, and price caps. The package ships with two optional integrations in fastflights/integrations/: BrightData for IP rotation and SearchApi for richer response data. The getflights() entry point returns a typed FlightsResult model defined in fastflights/model.py.

How To Use It

Setup: Install via pip. The pyproject.toml specifies the package metadata and dependencies.

pip install fast-flights

Configuration: No environment variables or API keys required for the base scraper. The BrightData integration needs a zone name; SearchApi needs an API key set via environment variable (per its integration module).

Running it: The primary entry point is getflights() from fastflights/init.py. Use createquery() to build a FlightQuery and pass it to getflights().

from fastflights import FlightQuery, Passengers, createquery, getflights

query = createquery( flights=[FlightQuery(date="2025-06-15", fromairport="MYJ", toairport="TPE")], seat="economy", trip="one-way", passengers=Passengers(adults=1), ) res = getflights(query)

Real-World Use

A fare-alert service that polls getflights() on a schedule, filters results for price thresholds, and notifies users when prices drop. The BrightData integration lets you run this at scale without getting IP-blocked. The SearchApi integration adds structured data like price insights and booking options if you need richer output.

Code Health & Issues

Med - Scraper fragility: The core mechanism (protobuf extraction from Google's internal payloads) is inherently brittle. The README's roadmap admits interest in using Google's private GetShoppingResults API, which would be a ToS violation and ban risk. Med - Testing gaps: Only 4 test files exist. tests/general.py and tests/bright_data.py look like smoke tests rather than comprehensive unit tests. The protobuf parsing logic in parser.py is the highest-risk component and appears thinly tested. Low - Maintainer bandwidth: The README's contribution notes ("please no ai slop", "im really busy with life") signal a solo maintainer with limited review capacity. The 1,875 forks suggest community interest, but bus-factor risk is real. Low - Sponsored integration: The SearchApi integration is explicitly sponsored. It's functional, but be aware the README's prominent sponsorship banner biases documentation toward that vendor.

The repo is otherwise clean: CI workflows exist (.github/workflows/), a license is present, and the code is typed (py.typed marker).

The Bottom Line

This is a genuinely useful library for developers who need Google Flights data without paying for an API. The typed API and protobuf-based approach are solid engineering. The main risks are the scraper's fragility against Google changes and the thin test coverage. Use it for personal projects or internal tools where occasional breakage is acceptable; for production fare-alert services, budget for maintenance or use a commercial API.
