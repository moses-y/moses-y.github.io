The Problem

Developers need a lightweight, cross‑database UI to explore schemas, run ad‑hoc queries and manage data without the overhead of pgAdmin or proprietary tools. Existing solutions are often tied to a single RDBMS, require heavy desktop installations, or lack a programmable API.

What This Does

db‑studio delivers a browser‑based studio that can connect to PostgreSQL, MySQL, MSSQL, SQLite, MongoDB and Redis through a single command. The core is split into three packages:

packages/server – a Hono + Node backend that parses DATABASEURL, builds adapters (src/adapters/), and exposes REST endpoints (src/routes/.routes.ts). Entry points such as src/cmd/args.ts and src/cmd/get-db-url.ts drive the CLI. packages/proxy – a Cloudflare Workers proxy (src/index.ts) that enforces rate limits (src/limit.ts) and forwards requests to the server, enabling optional edge deployment. packages/shared – TypeScript type definitions and constants used by both server and UI, e.g., src/types/database.types.ts.

The UI lives in the root packages/ui (not listed in the file tree but implied by the React stack) and consumes the server API via TanStack Query. The README’s npx db-studio command runs the bundled server and serves the UI on port 3333.

How To Use It

Install / Run – No build step required for the published package. The repo itself can be started locally with Bun (present in bun.lock and bunfig.toml): # Clone and install dependencies git clone https://github.com/husamql3/db-studio.git cd db-studio bun install # uses bun.lock for deterministic install

Start the development server (uses the server entry point)

bun run db-studio # equivalent to npx db-studio

The script defined in packages/server/src/cmd/args.ts reads flags such as --port, --env, and --database-url. Configuration – Create a .env file in the project root (or any parent) containing: DATABASEURL=postgresql://user:pass@host:5432/dbname

Alternative variable names can be supplied with --var-name. The server reads this via src/utils/parse-database-url.ts. Running – The CLI launches the Hono server (packages/server/src/index.ts) and serves the React UI (packages/ui). Access it at http://localhost:3333. Use flags for custom ports or to run in “status‑only” mode: npx db-studio --port 4000 --status

Real‑World Use

A micro‑service team can add a db:studio npm script to their repo, allowing any developer to spin up a UI against the service’s own DATABASE_URL without leaving the codebase. Example workflow:

{ "scripts": { "db:studio": "npx db-studio --env .env.local" } }

Running npm run db:studio opens a UI that can query the service’s MySQL instance, edit rows, and export tables via the /api/export endpoint defined in src/routes/.routes.ts.

Code Health & Issues

Low – Missing lockfile for npm – The repo uses bun.lock but no package-lock.json or pnpm-lock.yaml; CI builds that rely on npm could be non‑reproducible. Low – Limited CI coverage – GitHub Actions (.github/workflows/*.yml) run lint, bundle‑size and tests, but there is no explicit security scanning (e.g., Dependabot for npm). Medium – Adapter error handling – Some adapters (e.g., src/adapters/redis/redis.adapter.ts) forward raw driver errors without sanitisation; could expose internal details to the UI. Low – Documentation gaps – README explains CLI flags, but the UI build process (vite config) is not documented; new contributors may need to infer from packages/ui scripts. Low – No explicit license file – A LICENSE file exists, but the SPDX identifier is not referenced in package.json, which can cause ambiguity for downstream packaging.

Overall, the test suite is extensive (≈50 test files) and CI runs vitest, indicating good functional coverage.

The Bottom Line

db‑studio provides a solid, multi‑database UI built on modern React and a Hono backend, packaged for quick CLI launch. It is ready for teams that need an on‑the‑fly data explorer without heavyweight desktop tools. Minor gaps remain around reproducible npm builds and comprehensive security scanning, but the codebase is well‑tested and the architecture is clear. Suitable for developers comfortable with Bun/Node and who can manage the small CI improvements.
