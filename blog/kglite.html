The Problem

Modern LLM agents need fast, queryable knowledge graphs that can be embedded in an application without deploying a separate database service. Existing solutions either require a running Neo4j instance or expose only a REST API, adding latency and operational overhead. A self‑contained, Cypher‑queryable graph that ships with both Rust and Python bindings eliminates those bottlenecks.

What This Does

KGLite implements an embedded graph engine that can be used directly from Rust or Python. The engine stores vertices, relationships, and properties in memory or on disk, supports Cypher queries, and exposes a lightweight MCP server for agent interactions. The same binary can be bundled in a Python wheel or a Rust crate, letting developers embed the graph in any distribution.

Key components:

  • crates/kglite-c/src/lib.rs – Rust library exposing the core graph API.
  • crates/kglite-bolt-server/src/main.rs – Bolt‑compatible server that serves Cypher over TCP.
  • crates/kglite-cli/src/main.rs – CLI tool for graph manipulation and querying.
  • kglite/ – Python package providing a thin wrapper around the Rust library (kglite.KnowledgeGraph).
  • kglite-mcp-server – bundled MCP server that can be started from the wheel (kglite-mcp-server --graph path.kgl).

How It Is Wired

Execution begins in the CLI or MCP binary.

  1. CLI: crates/kglite-cli/src/main.rs parses arguments, loads a graph file via kglite::Graph::load, then calls kglite::Graph::cypher which delegates to kglite::Engine::execute.
  2. MCP: crates/kglite-mcp-server/src/main.rs starts an async runtime, registers HTTP routes, and on a request to /cypher calls kglite::Graph::cypher in the same way.
  3. Rust Library: crates/kglite-c/src/lib.rs contains pub fn execute(&self, query: &str) -> ResultView, which parses Cypher, walks the graph structure, and returns a lazy ResultView.
  4. Bolt Server: crates/kglite-bolt-server/src/main.rs listens on a TCP port, accepts Bolt frames, and forwards Cypher strings to kglite::Engine::execute.
  5. Persistence: kglite::Graph::save writes a binary format via kglite::engine::Serializer. Reading uses the same serializer.

The widest blast radius is the execute function in kglite-c/src/lib.rs; it is the single point where query parsing, graph traversal, and result materialization occur. Changing it affects all consumers. The kglite-mcp-server/src/main.rs is a thin wrapper that only routes HTTP/Bolt requests to that function.

How To Use It

Setup

# Clone
git clone https://github.com/moses-y/kglite
cd kglite

# Build Rust crates (requires Rust 1.75+)
cargo build --release

# Install Python wheel
pip install --no-build-isolation kglite  # uses prebuilt wheel

Configuration No external config files are required. The MCP server reads the graph path from the command line (--graph). The Rust library has no env vars.

Running

# Start MCP server with a pre‑built graph
kglite-mcp-server --graph examples/demo.kgl

# Or use the CLI to query a graph
kglite-cli --graph examples/demo.kgl cypher "MATCH (p:Person) RETURN p.name"

Python usage follows the README example: instantiate kglite.KnowledgeGraph(), load data, and run graph.cypher(...).

Real-World Use

A data‑science platform can ship a lightweight knowledge base with analytics notebooks. The notebook author writes Python code that loads a pre‑built demo.kgl and performs Cypher queries, all in‑process. An LLM agent can be given the same file and use the bundled MCP server to answer user questions without setting up Neo4j on the host.
