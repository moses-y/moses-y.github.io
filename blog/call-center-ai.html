The Problem

Many organizations need to embed AI‑driven voice interactions into existing telephony workflows but lack a ready‑to‑deploy, containerized solution that ties together phone provisioning, LLM orchestration, and persistent storage. The pain point is the absence of a single API surface that can both initiate an outbound call and stream the conversation back to a client, while handling authentication, caching, and fallback to a human agent without custom glue code.

What This Does

The repository provides a Python‑based AI call‑center platform that orchestrates outbound and inbound calls through Azure Communication Services, routes each conversation through an OpenAI LLM (gpt‑4.1 or gpt‑4.1‑nano), and persists transcript data in Cosmos DB or Redis. Key components include: app/main.py – entry point that exposes a /call endpoint accepting JSON payloads to trigger a call. app/helpers/config.py and app/helpers/configmodels/ – read configuration from config-local-example.yaml / config-remote-example.yaml and validate required keys (Azure connection strings, OpenAI deployment names, phone numbers). app/helpers/llmworker.py – thin wrapper around the OpenAI chat completions API, supporting streaming responses and prompt injection of feature‑flag controlled system messages. app/persistence/cosmosdb.py, app/persistence/redis.py, app/persistence/twilio.py – concrete implementations for storing call metadata, caching recent transcripts, and handling Twilio webhook events. app/models/call.py – Pydantic‑based data model for a call request, including claim schema fields (hardwareinfo, firstseen, buildinglocation).

The system streams conversation text in real time, supports resuming after disconnections, and records calls for later analysis. Feature flags stored in the config allow experimentation with different LLM models or prompt variants without code changes.

How To Use It

Setup

Install Python dependencies (uv is used for lockfile‑driven installs) uv sync --frozen # or pip install -e . if you prefer pip

(Optional) Build the Docker image defined in cicd/Dockerfile docker build -t call-center-ai -f cicd/Dockerfile .

Configuration

Copy the example files and fill in your Azure and OpenAI credentials: cp .env.example .env Edit .env with values for AZURECOMMUNICATIONCONNECTIONSTRING, OPENAIAPIKEY, OPENAIDEPLOYMENTNAME, and phone numbers. Additional per‑environment settings live in config-local-example.yaml.

Running it

Start the built container or run the Python module directly: Using Makefile target (if available) make run

Or launch the FastAPI app manually

uvicorn app.main:app --host 0.0.0.0 --port 8000

The README demonstrates a curl call to trigger a call:

curl \ --header 'Content-Type: application/json' \ --request POST \ --url https://<host>/call \ --data '{ "botcompany": "Contoso", "botname": "Amélie", "phonenumber": "+11234567890", "task": "Help the customer with their digital workplace.", "agentphonenumber": "+33612345678", "claim": [ {"name":"hardwareinfo","type":"text"}, {"name":"firstseen","type":"datetime"}, {"name":"buildinglocation","type":"text"} ] }'

The service will return a call SID and begin streaming transcript events to the client endpoint configured in the payload.
