The Problem

Financial institutions need LLMs tuned for domain-specific tasks—sentiment analysis, forecasting, report generation—but proprietary models are costly and closed. FinGPT provides open-source, fine-tunable financial LLMs and a benchmark suite, letting teams build and evaluate models without relying on Wall Street's locked-down APIs.

What This Does

FinGPT is a collection of financial AI projects, not a single library. The fingpt/ directory holds the core work: FinGPT_Benchmark for evaluating models on financial tasks, FinGPT_Forecaster for stock prediction, FinGPT_RAG for retrieval-augmented generation, and FinGPT_Sentiment_Analysis_v1 for sentiment classification. The finogrid/ directory is a separate, newer codebase with database models, services, and MCP servers—likely a production-oriented extension.

The repo includes training scripts (train_lora.py), inference notebooks, and a Flask-based forecaster app (fingpt/FinGPT_Forecaster/app.py). A React frontend exists, though its role isn't clear from the structure.

How To Use It

Setup: Install dependencies per project, e.g., pip install -r fingpt/FinGPT_Forecaster/requirements.txt. No lockfiles exist, so builds aren't reproducible.

Configuration: fingpt/FinGPT_RAG/.env.example shows required environment variables. Model configs live in config.json files.

Running it: For the forecaster, run python fingpt/FinGPT_Forecaster/app.py. For training, use fingpt/FinGPT_RAG/instruct-FinGPT/training/supervised_finetuning/main.py with the train.sh scripts in training_scripts/. The README's exact commands aren't documented in the excerpt—check each subproject's README.

Real-World Use

A team building a financial sentiment tool could fine-tune a Llama-2 model using FinGPT_Sentiment_Analysis_v1, evaluate it on FinGPT_Benchmark, then deploy the forecaster as a Flask API. The finogrid services handle agent identity and payment validation, so a production system could chain: kya_validator checks identity → agent_ledger_api tracks usage → forecaster serves predictions.

Code Health & Issues

Static analysis found 84 issues: 47 high, 37 medium. Key findings:

  • High - Deep nesting (44 instances): pyfolio/utils.py, txn.py hit indentation depth 9. Hard to follow control flow.
  • High - Import cycles (4): pyfolio/__init__.py, utils.py, plotting.py are mutually reachable.
  • High - Duplicated code: 922 repeated 6-line blocks across 112 files in FinGPT_Benchmark/benchmarks/.
  • High - Oversized file: pyfolio/plotting.py at 1,560 lines.
  • Medium - Broad exception handling: payment_required.py, kya_validator/server.py swallow errors.
  • Medium - Unmanaged file handles: eval_mmlu.py, gen_mmlu.py use open() without context managers.
  • SDLC gaps: No CI/CD, no lockfiles, no Dependabot. Tests exist (22 files) but nothing runs them automatically.

The Bottom Line

FinGPT is a valuable research resource with real, working training and inference code, but it's a research monorepo, not a polished product. The finogrid codebase looks more production-ready but shares the repo's hygiene problems. Use it for experimentation and benchmarking; budget time for dependency and code cleanup before production deployment.
