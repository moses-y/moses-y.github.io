whatsapp api

Rest API to send messages through whatsapp

Forked from felipeDS91/whatsapp-api

The Problem

Sending WhatsApp messages programmatically typically requires either the official Business API (with complex approval processes) or unreliable browser automation. This repo provides an alternative: a REST API backed by whatsapp-web.js that connects via a QR code scan of the WhatsApp Web session.

What This Does

This is a Node.js/TypeScript Express API that manages WhatsApp Web sessions and queues outgoing messages. The core logic lives in src/whatsapp/client/index.ts, which initializes the WhatsApp Web client, and src/whatsapp/index.ts, which polls for pending messages. The API exposes CRUD endpoints in src/routes/ for sessions (sessions.routes.ts), messages (messages.routes.ts), contacts, users, and tokens. Authentication uses JWT (src/middlewares/ensureAuthenticated.ts) with role-based admin checks (ensureAdminOnly.ts). Data persistence uses TypeORM with MySQL migrations in src/database/migrations/.

Real-World Use

A support team could use this to send appointment reminders or order confirmations. The workflow: POST to /sessions to generate a QR code, scan it with WhatsApp, then POST to /messages with a recipient and text. The background process in src/whatsapp/index.ts polls the database and sends queued messages. An Insomnia collection (Insomnia.json) is provided for testing endpoints.

Code Health & Issues Medium - No tests detected - The entire codebase lacks test files. src/services/, src/controllers/, and src/whatsapp/ have no unit or integration tests. This makes refactoring risky. Medium - No CI/CD pipeline - No .github/ workflows or CI configuration. No automated build, lint, or test gates. Low - Hardcoded seed data - src/database/seeds/adminUser.seed.ts contains plaintext admin credentials. This is acceptable for local dev but should not reach production. Low - No input validation - Controllers like MessagesController.ts and SessionsController.ts appear to accept raw request bodies without schema validation (no Joi, Zod, or class-validator visible). Low - Single-process architecture - The background message processor runs in the same process as the API (src/whatsapp/index.ts). A crash or restart could lose in-flight messages.

The Bottom Line

A functional proof-of-concept for sending WhatsApp messages via a REST API, suitable for learning or low-volume personal projects. Missing tests, CI, and production hardening (validation, process isolation) make it unsuitable for customer-facing or high-reliability use without significant investment.
