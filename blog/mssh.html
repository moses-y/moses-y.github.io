The Problem

SSH access to hosts behind NAT or firewalls normally requires a VPN, port‑forwarding, or manual reverse tunnels. Setting up and maintaining those solutions adds operational overhead and breaks the standard ssh workflow.

What This Does

mssh provides a minimal rendezvous service that lets a NATed machine keep a persistent outbound connection to a public server. The server then proxies inbound SSH sessions to the agent, so users can run the ordinary ssh client or use a ProxyCommand without extra networking tricks.

  • The CLI lives in cmd/mssh/main.go and parses sub‑commands (server, agent, proxy).
  • Core networking is in internal/server/server.go (server listener, client registration) and internal/agent/agent.go (agent keep‑alive and reverse connection).
  • Stream handling (Wrap, Pipe) and SSH key loading (internal/sshutil/auth.go) are factored into small utility packages.

How To Use It

# Clone the repo
git clone https://github.com/moses-y/mssh
cd mssh

# Build the binary
go build ./cmd/mssh

# Install (optional systemd wrapper)
sudo bash install/install.sh          # drops /usr/local/bin/mssh

# Start the rendezvous server (public host)
sudo mssh server --host 0.0.0.0 --port 8443

# On a NATed host, start the agent (node ID optional)
sudo mssh agent prod-db-1 --server <public‑host>:8443 --ssh-port 22

# From a client, connect via built‑in client
mssh alice@prod-db-1

# Or via ProxyCommand (no binary on client needed)
ssh -o ProxyCommand="mssh proxy prod-db-1 --server <public‑host>:8443" alice@localhost

Configuration files live under ~/.mssh/config.yaml and are created with mssh config init (the command exists in the source but is not exercised in the current binary). Keys are auto‑loaded from the standard ~/.ssh directory or via SSH_AUTH_SOCK.

Real‑World Use

A cloud‑based monitoring server runs mssh server behind an Nginx TLS terminator. Each on‑premise database instance runs mssh agent to maintain a reverse tunnel. Operators can then ssh db-admin@prod-db-1 from any workstation without opening inbound ports on the databases, preserving existing firewall policies.

The Bottom Line

mssh delivers a lightweight, Go‑based SSH rendezvous service that eliminates the need for VPNs or manual reverse tunnels, with a clear CLI and modest codebase. It lacks automated tests, a license, and some CI hardening, so teams should add those before adopting it in production. Suitable for engineers comfortable extending Go code and managing simple systemd services.
