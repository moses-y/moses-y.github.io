bracket

Selfhosted tournament system

Forked from evroon/bracket

The Problem

Running a multi-stage tournament (single elimination, round-robin, swiss) with multiple courts, teams, and clubs is a logistics problem. Spreadsheets and manual scheduling break down when matches need rescheduling, rankings need recalculating, and public dashboards need updating in real time. Bracket is a self-hosted system that handles the scheduling, ranking, and public-facing dashboards for you.

What This Does

Bracket is a full-stack tournament management system. The backend (backend/bracket/) is an async Python/FastAPI app with a clear separation of concerns: routes/ for API endpoints, logic/ for scheduling and ranking algorithms, sql/ for database queries, and models/db/ for ORM models. The frontend (not fully shown in this analysis) is a Vite/React app using Mantine. The repo also includes a docs/ folder with a Next.js documentation site.

The core scheduling logic lives in backend/bracket/logic/scheduling/ — round_robin.py, elimination.py, and builder.py handle the three tournament formats. Ranking calculations are in logic/ranking/calculation.py. The system supports multi-stage tournaments with multiple groups per stage, drag-and-drop match rescheduling, and public dashboard pages. A cli.py script at the repo root provides utility commands like creating a dev database.

How To Use It

Setup: The README documents a Docker Compose workflow. Clone the repo and run: git clone git@github.com:evroon/bracket.git cd bracket sudo docker compose up -d

This starts the backend, frontend, and a Postgres instance. The docker-compose.yml file at the root orchestrates the services.

Configuration: The backend reads environment variables from .env files (e.g., prod.env, dev.env) or directly from the environment. The backend/bracket/config.py file handles configuration. For a production deployment, you'll need to set database credentials and other secrets.

Real-World Use

A sports club runs a weekend tournament with 16 teams. An admin creates a club, a tournament, and two stages: a round-robin group stage followed by single-elimination playoffs. Teams and players are added via the API (routes/teams.py, routes/players.py). The system auto-schedules group matches across available courts (routes/courts.py), and the admin can drag-and-drop matches to different times. Public dashboard pages (routes/tournaments.py) show live standings. When the group stage ends, the admin activates the next stage, and the system seeds the elimination bracket from the group rankings.

The Bottom Line

Bracket is a well-structured, feature-complete tournament system with solid scheduling logic and a clean API layer. It's a good fit for a club or small organization that wants to self-host tournament management without paying for a SaaS product. The main concerns are the fork's maintenance status and the lack of a documented persistence strategy for Docker deployments. If you need multi-format tournaments with public dashboards and are comfortable managing a Docker deployment, this is a practical choice.
