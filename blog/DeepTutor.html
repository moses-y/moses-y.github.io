DeepTutor

"DeepTutor: Agent-Native Personalized Learning Assistant"

Forked from HKUDS/DeepTutor

The Problem Students and educators need a tutoring system that can adapt to individual knowledge gaps, handle multi‑modal content (text, math, code, diagrams), and stay usable on local hardware. Existing platforms are either closed‑source, require cloud APIs, or lack an extensible agent architecture.

What This Does DeepTutor implements a modular “agent‑native” tutoring stack. The core entry point deeptutor/main.py bootstraps a CLI that orchestrates a hierarchy of agents (chat, math‑animation, notebook analysis, question generation, research, solve, vision‑solver, visualizer). Each agent lives in its own package under deeptutor/agents/ and loads prompts from language‑specific YAML files (e.g., deeptutor/agents/chat/prompts/en/chatagent.yaml).

The architecture diagram in assets/figs/deeptutor-architecture.png shows a flow: user input → session manager → appropriate agent pipeline → response. Persistent knowledge bases, RAG indexing, and memory scratchpads are managed by utilities in agents/solve/memory/ and agents/research/utils/. Docker support (Dockerfile, .dockerignore) allows full‑stack local deployment without external services.

How To Use It

Setup Build the container (Dockerfile defines the environment, Python 3.11+) docker build -t deeptutor:latest .

Or run locally with the provided env template cp .env.example .env # edit the copy with your API keys (e.g., OPENAIAPIKEY) python -m pip install -r requirements.txt # requirements.txt is generated in the Docker build

If a requirements.txt is not present, extract dependencies from the Dockerfile’s RUN pip install ... line.

Configuration Key variables are documented in .env.example and .env.exampleCN. Typical entries include: OPENAIAPIKEY – for LLM calls EMBEDDINGENDPOINT – optional custom embedding service Place the edited .env in the project root; the code loads it via python-dotenv (imported in various agents).

Running Launch the CLI (the main module parses arguments and starts the session manager) python -m deeptutor

The CLI offers sub‑commands such as chat, solve, visualize, and tutorbot as defined in deeptutor/main.py. Use --help for details.

CI / Tests GitHub Actions workflows (.github/workflows/tests.yml, docker-release.yml) run the single test suite located in tests/. Ensure Docker is available locally to reproduce the CI environment.

Real‑World Use A university’s learning platform can embed DeepTutor as a microservice. After building the image, the platform starts a container, mounts a volume for persistent KB indexes (/app/data), and forwards HTTP requests to the CLI via a lightweight FastAPI wrapper (not shipped but easy to add). Example snippet:

import subprocess, json

def asktutor(question: str): result = subprocess.run( ["python", "-m", "deeptutor", "chat", "--question", question], captureoutput=True, text=True ) return json.loads(result.stdout)

Code Health & Issues High – Secrets exposure – .secrets.baseline suggests credential files may have been committed. Verify no real keys are present. Med – Limited test coverage – Only one test file (tests/) for a 200‑file codebase; many agents lack unit tests. Med – Dependency hygiene – No explicit requirements.txt or pyproject.toml in the repo; Dockerfile is the sole source of dependencies, making reproducibility outside Docker harder. Low – Documentation gaps – README gives high‑level usage but lacks concrete CLI flag references; some agents (e.g., visionsolver) have only markdown prompts, no clear invocation guide. Low – License present – Apache‑2.0 is included, satisfying legal requirements. Low – CI configured – GitHub Actions runs tests and Docker builds, indicating an automated pipeline is in place.

The Bottom Line DeepTutor provides a well‑structured, extensible agent framework for personalized tutoring and supports local deployment via Docker. It is suitable for teams that can invest in adding tests and tightening secret management. For production use, supplement the existing CI with broader test coverage and publish a stable Python package or requirements.txt to simplify non‑Docker installations.
