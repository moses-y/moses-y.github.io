Abstract

An Excel AI agent that uses MCP tools to let LLMs read, edit, and automate Excel spreadsheets.

The Problem

Business users need a way to let LLMs manipulate real Excel workbooks—reading data, applying formulas, and preserving formatting—without writing custom code for each spreadsheet. Existing “prompt‑only” solutions cannot guarantee that the generated changes are applied correctly inside Excel.

What This Does

The repository ships two complementary components:

Excel MCP server – a lightweight Python server that exposes ~30 spreadsheet‑editing tools via Server‑Sent‑Events. The server is started with the example in demo/ExcelAssistant/server.py (see the runmcpserver coroutine in the README). Excel Agent Runner – a Python wrapper (excelagent/agentrunner.py, excelagent/config.py) that sends a user instruction plus input‑/output file paths to the MCP endpoint and returns the LLM’s response.

A runnable web UI lives in demo/ExcelAssistant/. The front‑end is built with React/Vite (src/App.jsx, src/ChatSidebar.jsx) and talks to the Python backend via the SSE endpoint (http://127.0.0.1:8765/sse). A Slack‑based workflow is provided in demo/SlackExcelWorkflow/ (excelagentbot.py).

How To Use It

Python environment (as documented) conda create -n excel python=3.11 conda activate excel pip install -r requirements.txt # requirements.txt is in the repo root pip install -e . # installs excelmcp and excelagent packages Start the MCP server (example from README) python demo/ExcelAssistant/server.py # runs the async SSE server on 127.0.0.1:8765 Launch the web demo cd demo/ExcelAssistant npm install # reads demo/ExcelAssistant/package.json npm run dev # starts Vite dev server, opens index.html Run the agent programmatically python - <<'PY' import asyncio from excelagent.agentrunner import ExcelAgentRunner, TaskInput from excelagent.config import ExperimentConfig

runner = ExcelAgentRunner( config=ExperimentConfig(model='openrouter:openai/gpt-5.1'), mcpserverurl="http://127.0.0.1:8765/sse", )

task = TaskInput( instruction="Add a column that calculates profit = revenue - cost", inputfile="samples/input.xlsx", outputfile="samples/output.xlsx", )

result = asyncio.run(runner.runexcelagent(task)) print(result) PY

The evaluation harness (evals/comparison.py) can be invoked similarly after installing the optional openpyxl/xlwings dependencies; it loads the verified SpreadsheetBench subset from evals/data/.

Real‑World Use

A financial reporting pipeline could call ExcelAgentRunner after nightly data export. The LLM receives a prompt such as “Reconcile the P&L sheet and flag any negative margins,” the agent edits the workbook in place via the MCP tools, and the downstream ETL reads the resulting file. The Slack bot (demo/SlackExcelWorkflow/excelagentbot.py) provides an interactive “ask‑Excel” channel for non‑technical analysts.

Code Health & Issues

Medium – No automated tests – there are no test.py or Jest files; code paths for the MCP server and agent runner are untested. Medium – No CI/CD pipeline – repository lacks .github/workflows or other CI config, so quality gates are missing. Low – Missing type hints – core modules (excelmcp/excelserver.py, excelagent/agent_runner.py) are pure Python without static typing, raising the risk of runtime errors. Low – Sparse documentation – README covers demos but does not describe required environment variables for the MCP server (e.g., no .env.example). Low – Front‑end build script not version‑pinned – vite.config.js references default Vite plugins; lockfile (package-lock.json) exists but no explicit Node version is enforced.

The Bottom Line

The repo provides a functional proof‑of‑concept for LLM‑driven Excel manipulation, with a usable web demo and Slack integration. It is ready for exploratory pilots but lacks production‑grade safeguards (tests, CI, typed interfaces). Teams that can allocate engineering effort to add testing and CI will find the core idea solid; solo developers should treat it as a starting scaffold rather than a drop‑in solution.
