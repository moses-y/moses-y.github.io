The Problem

Developers and power‑users need a local, privacy‑first store of their digital activity (files edited, web pages viewed, terminal commands, etc.) so that LLM‑driven agents can retrieve personal context without sending raw data to the cloud. Existing solutions either rely on external vector databases or require heavyweight agents, making them costly and difficult to audit.

What This Does

CatchMe records a wide range of user interactions (clipboard, keyboard, mouse, window focus, file changes, URLs) into a local SQLite store (catchme/store.py). The data can be queried by LLM‑backed agents via a simple CLI (python -m catchme) or through the bundled web UI (catchme/static/index.html).

Key modules:

  • catchme/recorders/ – platform‑specific listeners (keyboard_*.py, mouse.py, idle.py, notification.py). Each recorder writes events to the store via catchme/recorder.py.
  • catchme/extractors/ – turn raw events into structured objects (file.py, url.py).
  • catchme/pipelines/ – chain processing steps: filter.py (time / type filters), retrieve.py (search over stored events), summarize.py (LLM‑driven summarisation), tree.py (hierarchical view).
  • catchme/services/ – LLM integration (llm.py) and prompt templates (prompts.yaml).
  • catchme/web.py – lightweight FastAPI server exposing the same endpoints over HTTP for the browser UI.

The CLI entry point (catchme/__main__.py) parses sub‑commands, loads catchme/config.py, starts the requested recorder(s), and optionally launches the web server.

How It Is Wired

python -m catchme               # __main__.py
 └─ config.load()               # catchme/config.py
 └─ run.main(args)              # catchme/run.py
     ├─ recorder.start()        # catchme/recorder.py
     │   ├─ platform.<os>.py    # platform specific listener
     │   └─ store.save(event)   # catchme/store.py (SQLite)
     └─ pipeline.execute()      # catchme/pipelines/*.py
         ├─ filter.apply()
         ├─ retrieve.search()
         └─ summarize.llm_call()   # services/llm.py → external LLM API
  • Data flow: raw OS events → platform listener → Recorder → Store → optional pipeline → LLM → CLI/web response.
  • High‑impact files: store.py (persistent state), services/llm.py (external API calls), run.py (orchestrator). Changing any of these alters the core persistence or external dependency surface.
  • Coupling: Recorders depend on the platform package; pipelines depend on extractors; the web UI (static/*.js) talks to web.py via /api/* routes. No circular imports are evident, but run.py acts as a hub, pulling in most sub‑modules.

How To Use It

# Clone the repo
git clone https://github.com/moses-y/CatchMe.git
cd CatchMe

# Install in an isolated environment (pyproject.toml defines deps)
python -m venv .venv
source .venv/bin/activate
pip install -e .   # editable install pulls in all Python deps

# Optional: copy the example service config
cp catchme/services/config.example.json catchme/services/config.json
# Edit catchme/services/config.json to add your LLM endpoint / API key

# Start a recorder (e.g., keyboard + clipboard) and the web UI
python -m catchme --record keyboard clipboard --serve

# Or run a single query from the CLI
python -m catchme query "What files did I edit yesterday?"

If the --serve flag is omitted, the process runs headless and writes events only. The web UI is reachable at http://localhost:8000 (FastAPI default).

Real‑World Use

A remote‑work developer runs catchme in the background on their laptop. When a code‑review LLM assistant asks “What was the last function I edited in utils.py?”, the assistant calls catchme query "last edit utils.py"; the request travels through run.py → pipeline.retrieve → store.fetch and returns a concise LLM‑summarised snippet, all without leaving the machine.

Code Health & Issues

  • Low – Missing lockfile – Dependencies are declared only in pyproject.toml; reproducible builds would benefit from a lockfile (poetry.lock or uv.lock).
  • Low – No explicit type hints – Only a few modules contain type annotations; adding them would improve IDE support and static analysis.
  • Low – Minimal CI coverage – GitHub Actions (.github/workflows/ci.yml) runs the test suite, but there is no linting or security scanning stage.
  • Low – No Dockerfile – Although Kubernetes is mentioned, the repo lacks containerisation artefacts, making deployment to clusters manual.

No critical security flaws are evident from the file list, but the LLM integration (services/llm.py) likely holds API keys in user‑provided config files; ensure those are excluded from version control.

The Bottom Line

CatchMe provides a well‑structured, locally‑hosted activity capture layer that can be queried by LLM agents, with clear separation between data collection, storage, and retrieval. It is ready for developers comfortable with Python environments, but it lacks reproducible dependency locking and container support, which may hinder large‑scale or production deployments. Suitable for personal workflows or research prototypes where privacy is paramount.
