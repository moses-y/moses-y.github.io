The Problem

Coordinating multiple AI CLI agents (Claude Code, Gemini CLI, Codex CLI) during a task is ad-hoc. Each agent runs in its own terminal with no shared context. Developers manually copy outputs, paste instructions, and track progress across sessions. There is no structured way to assign roles, distribute subtasks, or review work across agents.

What This Does

squad is a Rust CLI tool that lets multiple AI agents collaborate through a shared SQLite store. It installs a /squad slash command into supported agents. After running squad init to create a workspace, agents join as manager, worker, or inspector via /squad manager etc. Each reads role instructions from src/roles/ (manager.md, worker.md, inspector.md) and enters a loop reading tasks from the store. The manager breaks down a goal into subtasks, workers execute them, the inspector reviews results — all without a daemon. Every command is a one-shot SQLite query.

The tool also ships an optional tmux launcher (scripts/squad-tmux-launch.sh) that reads .squad/launcher.yaml and .squad/run-task.md to auto-start a tiled tmux session with /squad commands injected into Claude panes. The core logic lives in src/session.rs, src/store.rs, src/teams.rs, and src/tasks.rs, with tests in tests/.

Real-World Use

A developer needs to refactor a large Python codebase. They run squad init in the project, then open three terminals. In the first, /squad manager – they describe the refactor goal. The manager writes subtasks (e.g., "extract config module", "update imports") to the SQLite store. Workers in the second terminal pick tasks, apply changes, and mark completion. The inspector in the third terminal reviews diffs and flags issues. All communication flows through the store; no manual forwarding required.

Code Health & Issues

The codebase is structurally sound: 17 test files, CI workflows (.github/workflows/ci.yml), MIT license, and Cargo.lock committed. No obvious red flags. However, several issues are likely: Med – src/store.rs likely uses SQLite without explicit row-level locking or transactions for task updates. If two agents write concurrently (e.g., two workers claiming the same task), race conditions may cause lost updates or duplicate work. Verify whether store.rs uses BEGIN IMMEDIATE or a mutex. Low – Role instruction files (src/roles/*.md) are read at runtime. If a file is missing or malformed, src/roles.rs may panic or return opaque errors. No evidence of graceful fallback in the structure. Low – The tmux launcher (scripts/squad-tmux-launch.sh) depends on Ruby and tmux, excluding Windows users and environments without those tools. This is documented as optional, but the README implies it's the recommended launch method for Unix. Low – CLI argument parsing in src/main.rs may lack input validation for flags like --project-path. No unit tests for argument parsing are visible in tests/.

The project is young (0 stars, forked from a 614-star repo) and the docs/superpowers/ folder contains active plans and specs, indicating ongoing development. The core architecture is simple and testable.

The Bottom Line

squad solves a real coordination problem for teams using multiple AI CLI agents. Its Rust implementation is fast, daemon-free, and the SQLite-based communication is straightforward to understand and debug. The codebase is clean and well-tested for its size, but concurrent access edge cases and platform-specific tooling limit production readiness. Best suited for developers already using Claude Code, Gemini CLI, or Codex CLI who want structured multi-agent workflows without introducing a server. Not useful for single-agent use or non-CLI AI tools.
