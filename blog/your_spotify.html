your spotify

Self hosted Spotify tracking dashboard

Forked from Yooooomi/your_spotify

The Problem Spotify does not expose a personal, self‑hosted history dashboard. Users who want to keep their listening data private, run custom analytics, or integrate it with on‑premise tooling have no out‑of‑the‑box solution.

What This Does yourspotify provides a two‑service stack: a server that periodically polls the Spotify Web API and stores raw play events in MongoDB, and a React client that visualises the collected data via a rich set of charts and tables.

Server build artefacts live in the root Dockerfiles (Dockerfile.server, Dockerfile.server.production). The client source is under apps/client/, with the main entry point apps/client/src/App.tsx. UI components such as AddToPlaylist, BackgroundCard, and BlacklistArtistDialog are exported through index.ts files in their respective folders, making them easy to import elsewhere in the codebase.

All UI code is written in TypeScript/TSX (≈125 files) and styled with CSS modules.

How To Use It

Setup The repository ships Dockerfiles and a docker‑compose example, so the recommended path is containerised deployment.

Clone the repo git clone https://github.com/Yooooomi/yourspotify.git cd yourspotify

Copy the example compose file and edit the env vars cp docker-compose-example.yml docker-compose.yml Edit docker-compose.yml: set SPOTIFYPUBLIC, SPOTIFYSECRET, CLIENTENDPOINT, APIENDPOINT

Build and start the stack docker compose up -d --build

If you prefer a local build of the client, the presence of apps/client/package.json and apps/client/.prettierrc implies an npm‑based workflow:

cd apps/client npm ci # note: no lockfile is present, npm will resolve latest versions npm run build # uses rsbuild.config.ts npm start # runs the dev server (see scripts/run/rundev.sh)

Configuration Environment variables required by the server are documented in the README table and consumed in the server code (not shown here but referenced by Dockerfile.server). Required keys:

VariablePurpose
SPOTIFYPUBLICSpotify client ID
SPOTIFYSECRETSpotify client secret
APIENDPOINTURL of the server (used by the client)
CLIENTENDPOINTURL of the client (used by the server for redirects)
MONGOENDPOINTMongoDB connection string (defaults to mongodb://mongo:27017/yourspotify)
TIMEZONEOptional timezone override

These variables are injected via the environment: block in docker-compose.yml.

Running It Server: the container entrypoint defined in Dockerfile.server starts the Node.js service that polls Spotify and writes to MongoDB. Client: the container built from Dockerfile.client serves the compiled React assets on port 3000; the dev server can be started with npm start as shown above.

Real‑World Use A hobbyist could deploy the stack on a home NAS (Docker‑enabled) to retain a private log of their listening habits. After deployment, the user accesses http://<host>:3000 to view charts such as “Best Artist of the Week” or to export CSV reports for personal analysis.

Example: Export a CSV of all tracks from the last month curl -H "Authorization: Bearer <accesstoken>" \ "${APIENDPOINT}/api/v1/tracks?from=$(date -d '-30 days' +%s)"

Code Health & Issues Low – Missing lockfile – apps/client/package.json has no package-lock.json or pnpm-lock.yaml; builds may yield different dependency versions. Medium – No test suite – The repository contains zero .test. files and the CI workflows (nightly.yml, release.yml) do not run tests, leaving code paths unverified. Low – License present – LICENSE file exists, satisfying basic open‑source compliance. Low – Docker images are versioned – Separate production Dockerfiles (Dockerfile.client.production, Dockerfile.server.production) indicate a clear deployment path. Low – Configuration exposure – Environment variables are the sole secret handling method; no secret‑management guidance is provided. Medium – Potential runtime errors – UI components import CSS modules (e.g., index.module.css) but there is no TypeScript declaration (*.d.ts) for CSS modules, which may cause type errors in strict builds.

Overall the codebase follows a conventional React + Node.js structure, but the lack of automated tests and lockfile reduces confidence for production use.

The Bottom Line your_spotify delivers a functional self‑hosted Spotify analytics platform with clear Docker deployment instructions and a well‑organized UI codebase. It is suitable for technically comfortable users who can tolerate the current lack of tests and lockfile‑driven reproducibility. For mission‑critical or large‑scale deployments, adding a test suite, lockfile, and tighter secret management would be advisable.
