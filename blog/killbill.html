The Problem

Companies that sell recurring services need a billing engine that can handle complex subscription rules, proration, and payment retries without locking them into a proprietary SaaS contract. Maintaining a custom solution is costly and error‑prone, especially when regulatory compliance and financial reporting are required.

What This Does

The repository contains the core Java modules of Kill Bill, an extensible platform for subscription billing and payments. account/ implements the Account API, DAO layer (AccountDao.java, AccountSqlDao.java) and migration scripts (V20160822115745_accountnotes.sql). api/ defines the public contract for all services (e.g., AccountService.java, InvoiceInternalApi.java, EntitlementInternalApi.java) and the event model used by the internal bus. beatrix/ provides the “Beatrix” event‑bus extension (DefaultBeatrixService.java, BeatrixListener.java).

All modules are built with Maven (pom.xml in each folder) and wired together through Guice modules (DefaultAccountModule.java, BeatrixModule.java). The codebase follows a clean separation between API, implementation, and persistence.

How To Use It

Setup

Build each module (the root has no pom, so run per module) cd account && mvn clean install -DskipTests cd ../api && mvn clean install -DskipTests cd ../beatrix && mvn clean install -DskipTests

The GitHub Actions workflow (.github/workflows/ci.yml) runs the same Maven commands with tests enabled, so the build process is reproducible on CI.

Configuration

Kill Bill reads runtime settings from external YAML/DB sources that are not checked into this repo. Typical keys (e.g., org.killbill.payment.provider) must be supplied via a killbill.properties file placed on the classpath or via environment variables. No sample config is present, so you will need to create one based on the documentation in the separate killbill-docs repository.

Running It

The platform’s entry point lives in a separate “killbill‑server” module (not included here). After building the core libraries, you would normally start the server with:

java -jar killbill-server.jar

Because the server artifact is absent, you cannot launch a full instance from this repository alone. Use the official Docker image (killbill/killbill) or the killbill-server source to obtain the executable.

Real‑World Use

A SaaS provider can embed Kill Bill to manage customer subscriptions:

AccountInternalApi accountApi = Guice.createInjector(new DefaultAccountModule()).getInstance(AccountInternalApi.class); UUID newAccountId = accountApi.createAccount(new DefaultAccount(...)); EntitlementInternalApi entitlementApi = Guice.createInjector(new EntitlementModule()).getInstance(EntitlementInternalApi.class); entitlementApi.createBaseSubscription(newAccountId, "premium-plan", ...);

The APIs emit events (InvoiceCreationInternalEvent, PaymentInfoInternalEvent) that downstream services (e.g., a payment gateway) can listen to via the Beatrix bus.

The Bottom Line

The repo provides a well‑structured set of Java modules that implement the core billing and event APIs of Kill Bill. It builds cleanly with Maven and includes unit tests and CI pipelines, but it does not contain the runnable server component or default configuration files, so it is best used as a library dependency within the full Kill Bill distribution or Docker image. Teams comfortable with Java/Guice and needing a self‑hosted, extensible billing engine will find it suitable; smaller projects may prefer the pre‑packaged Docker release to avoid the missing entry point.
