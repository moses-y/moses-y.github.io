The Problem Sampler addresses the pain of setting up heavyweight monitoring stacks like Prometheus+Grafana just to sample a few shell commands locally. The README notes that when "spinning up and configuring Prometheus with Grafana is complete overkill," Sampler provides a lightweight alternative for observing dynamic processes—database changes, in-flight messages, deployment completion—directly from the terminal.

What This Does At its core, Sampler reads a YAML configuration file and executes shell commands at a specified interval, rendering output via Go-based user interface components located in component/: runchart, sparkline, barchart, gauge, textbox, and asciibox. Configuration lives in config/ (e.g., config.go, default.go, validator.go), while the data layer in data/ handles item tracking, triggers, and console interaction via console.go. The UI is assembled through component/component.go and rendered with terminal geometry from component/util/geometry.go. Trigger support and conditional actions are defined in event/handler.go and data/trigger.go, enabling audible alerts or side-effect execution when command output meets criteria.

How To Use It Setup is well-documented. The Docker path (evidenced by Dockerfile and go.mod) involves creating a config.yml in the working directory, building the image with docker build --tag sampler ., and running with: docker run --interactive --tty --volume $(pwd)/config.yml:/root/config.yml sampler --config /root/config.yml

Alternatively, Homebrew (brew install sampler) or direct binary installation from releases provides the sampler CLI. The entry point is main.go, invoked as sampler -c config.yml. A sample config file is included as example.yml.

Real-World Use A developer wanting to monitor a PostgreSQL connection pool can define a command like psql -c 'SELECT count() FROM pgstatactivity' in config.yml, run sampler -c config.yml, and watch the sparkline in component/sparkline/sparkline.go update in real time. If the count drops below a threshold, the trigger configuration can play a sound or execute a remediation script, handled by data/trigger.go and event/handler.go.

The Bottom Line* Sampler is a focused, Go-built terminal dashboard for shell command sampling, ideal for developers who need quick, visual feedback on dynamic processes without provisioning a full monitoring stack. Its YAML-driven config and modular component layout make it easy to extend, though it’s less suited as a long-term production monitoring solution. Teams needing rapid, local terminal visualization will find it practical; organizations requiring enterprise-grade metrics and alerting should look elsewhere.
