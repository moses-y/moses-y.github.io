The Problem

Teams building LLM‑based products need a single place to capture traces, compute metrics, run evaluations, and manage prompts – without stitching together separate observability, prompt‑management and dataset tools. Langfuse addresses this by bundling observability, evals, prompt‑registry and dataset handling in one open‑source platform.

What This Does

  • web/ (1540 files, 1484 code files) – Next.js/React UI for viewing traces, running the playground, managing datasets and billing (EE). Key UI modules live under web/src/components, web/src/features/dashboard and web/src/ee/features/billing.
  • packages/ (875 files, 840 code files) – Shared TypeScript library containing the core domain model, DB schema, encryption, and Zod validation. Entry points such as packages/shared/src/domain/index.ts and packages/shared/src/encryption/index.ts are imported by both the worker and the web front‑end.
  • worker/ (232 files, 219 code files) – Background job processor (Redis‑queued) that handles migrations, secret encryption and LLM‑request routing. Notable file worker/src/backgroundMigrations/encryptBlobStorageSecrets.ts performs the secret‑shaped path audit mentioned in the heuristic issues.
  • ee/ (8 files, 3 code files) – Enterprise‑only licensing and feature‑flag gate kept at ee/src/index.ts and ee/src/ee-license-check/index.ts.
  • .claude/ (30 files, 2 code files) – Claude‑hook configuration used by the internal assistant tooling.

The platform integrates with OpenTelemetry, LangChain, the OpenAI SDK and LiteLLM, exposing a unified API surface that the UI and worker consume.

How It Is Wired

The internal import graph resolves 1490 modules with 922 edges; 55 modules live inside circular dependencies.

  • Hub modules (52 modules depend on each):
  • packages/shared/src/server/logger.ts – central logging abstraction.
  • packages/shared/src/utils/zod.ts – Zod schema definitions used across the codebase.
  • packages/shared/src/db.ts – database client and query builders.
  • Import cycles (51 modules): the cycle includes packages/shared/src/db.ts, packages/shared/src/domain/index.ts, and packages/shared/src/tableDefinitions/index.ts. Changing any of these requires careful re‑wiring because many downstream modules rely on the mutual reachability.
  • Entry point: ee/src/index.ts bootstraps the server, which then mounts the Express/Next app (packages/shared/src/server/index.ts). The worker starts from worker/src/index.ts (implied by the worker directory) and processes Redis‑queued jobs.
  • External touches: the platform emits OpenTelemetry spans, writes to PostgreSQL (via packages/shared/src/db), caches results in Redis (packages/shared/src/server/redis/getQueue), and serves API requests from web/src/pages/api/....

A change to the hub logger or DB schema ripples through 52+ dependent modules, illustrating the “blast radius” risk highlighted in the analysis.

How To Use It

Setup

# Install dependencies (pnpm is the declared package manager)
pnpm install

# Start the full stack (Docker Compose file present)
docker compose -f docker-compose.dev.yml up -d

The docker-compose.dev.yml file provisions Redis, PostgreSQL and the worker; the web UI becomes reachable at http://localhost:3000.

Configuration Copy .env.dev.example to .env.dev and set the following variables (the file lists the required keys):

  • DATABASE_URL – PostgreSQL connection string used by packages/shared/src/db.ts.
  • REDIS_URL – Redis endpoint for the worker queue.
  • OPENAI_API_KEY / ANTHROPIC_API_KEY – credentials for LLM providers.

Running it

  • To start just the API and UI: pnpm dev (as defined in the root package.json scripts).
  • To run only the background worker: pnpm worker:start (script references worker/src/index.ts).

Real‑World Use

A machine‑learning team instrumenting a RAG pipeline can instrument calls with the Langfuse SDK, which automatically creates traces stored in the platform’s PostgreSQL backend. The team then:

  1. Create a dataset via the UI (web/src/features/datasets) – a CSV of input/prompt pairs.
  2. Run an evaluation that queries the dataset, invokes the LLM through the SDK, and records cost, latency and correctness metrics.
  3. Inspect results in the playground (web/src/playground) and iterate on prompt templates stored under packages/shared/src/utils/chatml.

The same workflow works for both Langfuse Cloud (SaaS) and a self‑hosted instance (Docker compose).

The Bottom Line

Langfuse delivers a rare all‑in‑one open‑source stack for LLM observability, prompt management and evaluation, with a solid TypeScript foundation and Docker‑based dev experience. The main risks are the tightly‑coupled hub modules and circular imports in the shared package, which raise the cost of any schema or logging change; the CORS wildcard in worker/src/app.ts and the unpinned GitHub Actions also merit immediate attention. It is well‑suited for teams that need integrated tracing + evals without managing separate SaaS contracts, provided they invest in decoupling the shared core before scaling.

Pin third-party GitHub Actions to a commit SHAhigh5 occurrences
.github/workflows
winterjung/split@v2, aws-actions/configure-aws-credentials@v4, aws-actions/amazon-ecr-login@v2, aws-actions/amazon-ecs-render-task-definition@v1
A tag can be moved, so the action running with your token and secrets is whatever its owner last pushed; this is how tj-actions/changed-files leaked secrets from thousands of repos.
Fix: Replace each @vN with the 40-character commit SHA, keep # vN as a comment, and let Dependabot bump the SHAs.
Replace the wildcard CORS origin with an explicit allow listhigh
worker/src/app.ts
cors()
Any page on the internet can call the API with the browser's cookies attached, so a logged-in visitor to an unrelated site performs authenticated requests without knowing, and the wildcard combined with credentials is the exact configuration browsers refuse for that reason.
Fix: List the origins the API actually serves, and never pair a wildcard with credentials.
Declare least-privilege permissions for GITHUB_TOKENmedium3 occurrences
.github/workflows/_deploy_ecs_service.yml
3 workflow(s) declare no permissions, 2 of them reference secrets
With no declaration the token inherits the repository default, so any injected step can push commits or mint releases from inside your own CI.
Fix: Add permissions: contents: read at the top of the workflow and widen per job only where needed.
Pin the container base image by digestmedium
.devcontainer/Dockerfile
mcr.microsoft.com/vscode/devcontainers/typescript-node:20-bookworm
An untagged or mutable base means today's build and last month's contain different libc and a different CVE set, with no record of which shipped.
Fix: Use image:tag@sha256:<digest> and enable Dependabot's docker ecosystem.
Gate pull requests on a dependency vulnerability scanmedium
.github/workflows
no dependency scan in CI
This is the one gate that would catch a known-vulnerable package before it reaches a build, and no repository in the sample had it.
Fix: Add dependency-review-action on pull_request, or osv-scanner on push and a schedule.
Review the install lifecycle script and disable scripts in CImedium
package.json
preinstall
Install scripts are the execution vector for every npm compromise from event-stream onward, and a postinstall that fetches a binary makes the build depend on a URL nobody reviews.
Fix: Move the work into an explicit build step, or set ignore-scripts in CI and run it by name.
Set timeout-minutes on the workflow jobslow4 occurrences
.github/workflows/_deploy_ecs_service.yml
4 workflow(s) declare no job timeout
A wedged step runs to the six-hour platform default, which on a two-hourly schedule means three runs overlap behind it.
Fix: Add timeout-minutes with a realistic bound to each job.
