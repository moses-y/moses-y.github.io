OpenResearcher: A Fully Open Pipeline for Long-Horizon Deep Research Trajectory Synthesis

Forked from TIGER-AI-Lab/OpenResearcher

The Problem

Generating high-quality synthetic trajectories for training deep-research AI agents is fragmented and closed-source. Most pipelines rely on proprietary tool-use data, making it difficult for teams to reproduce or extend research-agent training data at scale. OpenResearcher addresses this by providing a fully open pipeline for long-horizon deep-research trajectory synthesis.

What This Does

OpenResearcher is a Python-based pipeline (10 Python files, 5 shell scripts) that synthesizes multi-step research trajectories. The core logic lives in backend.py, browser.py, and datautils.py — these handle agent orchestration, browser automation for web research, and data processing respectively. The utils/ directory contains two generator backends: openaigenerator.py and vllmgenerator.py, letting you plug in either API-based or self-hosted LLM inference.

The repo is an active research artifact, not a polished library. It includes eval.py for benchmarking, deployagent.py for serving, and scripts/ with deployment helpers for search and vLLM services. The README indicates the dataset has been adopted by NVIDIA's Nemotron model family, which lends credibility to the approach.

How To Use It

The repo is research-grade; setup is manual and not fully documented. There is no Makefile or Dockerfile.

Setup: pyproject.toml is the only dependency manifest, so install with pip install -e . or uv sync. The setup.sh script likely handles environment preparation. No lockfile exists, so builds are not reproducible.

Configuration: .env.template defines required environment variables. You must copy it to .env and populate API keys and service endpoints before running.

Running it: runagent.sh is the primary entry point. Deployment scripts in scripts/ handle search and vLLM service startup. The README does not document exact CLI invocations, so you will need to inspect runagent.sh and backend.py to determine required arguments.

Expected flow (verify against actual scripts) cp .env.template .env pip install -e . bash runagent.sh

Real-World Use

A research team training a domain-specific research agent can use OpenResearcher to generate training trajectories. For example, a legal-tech company could run the pipeline with a vLLM-hosted model to produce hundreds of multi-step legal research traces, then fine-tune their own agent on that data. The deployvllmservice.py script handles self-hosted inference, keeping sensitive legal queries on-premises.

Low - Non-reproducible builds: pyproject.toml without a lockfile means dependency versions can drift. The repo does not appear to contain secrets — .env is correctly gitignored.

The Bottom Line

OpenResearcher is a credible research artifact with real-world adoption (NVIDIA Nemotron), but it is not production software. It suits research teams wanting to reproduce or extend the trajectory-synthesis approach, not teams needing a drop-in tool. The missing license and tests are the primary blockers for commercial adoption.
