The Problem

Developers who want to drive LLM agents from a terminal must juggle a shell, a prompt editor, and ad‑hoc UI code. The result is fragmented workflows, duplicated tooling, and fragile scripts that break when the UI changes.

What This Does

toad delivers a single Textual‑based TUI that embeds a fully‑functional shell, a markdown prompt editor, a fuzzy file picker, and a diff viewer. Core UI components live under src/toad/widgets/ (e.g. conversation.py, diff_view.py, prompt.py). The agent‑client protocol implementation resides in src/toad/acp/ and the top‑level CLI lives in src/toad/cli.py. Running python -m toad launches src/toad/__main__.py, which parses command‑line flags and hands control to cli.run().

How It Is Wired

  1. Entry point – src/toad/__main__.py calls cli.main() (defined in src/toad/cli.py at line 75). The run sub‑command (line 114) is the most used path, reaching 60 functions.
  1. Application bootstrap – cli.run() creates a ToadApp (class in src/toad/app.py). The on_mount hook (line 588) is invoked by Textual during UI start‑up and reaches 52 functions. This hook wires the main screen (src/toad/screens/main.py) and registers callbacks that ultimately call post_message, focus, and wait.
  1. Core message flow – The internal call graph shows post_message is invoked from 46 distinct callers (e.g. src/toad/widgets/flash.py, src/toad/widgets/command_pane.py). It propagates UI events to the agent layer.
  1. Agent interaction – src/toad/acp/agent.py defines start (line 171) which builds an Agent object, writes a session file (self._log_file_path.parent.mkdir) and issues network calls via client.post (see src/toad/app.py → jsonrpc). The most‑connected agent functions (generate_datetime_filename, command) are called from 16 other modules.
  1. Side effects Filesystem – 28 functions open or write files; examples are src/toad/history.py (open) and src/toad/db.py (db.execute). Network – 4 functions perform outbound HTTP (client.post) in src/toad/jsonrpc.py and src/toad/app.py. * Database – 6 functions interact with SQLite via src/toad/db.py.
  1. High‑impact modules – src/toad/widgets/conversation.py (109 functions, 8 classes) touches files and is called from 5 other files, making it a change‑hotspot. src/toad/ansi/_ansi.py (56 functions, 25 classes) and src/toad/acp/agent.py (36 functions, 2 classes) also have wide reach.

No circular import cycles were detected, so the import graph is flat, but deep nesting (up to 8 levels) and oversized files (>1 k lines) increase cognitive load.

How To Use It

# Clone the repo
git clone https://github.com/moses-y/toad
cd toad

# Install in editable mode (pyproject.toml defines the build)
pip install -e .

# Run the TUI
python -m toad          # equivalent to `toad` if a console script is installed
# Or invoke a specific command, e.g. start an agent session
python -m toad --help    # shows CLI flags defined in src/toad/cli.py

Configuration files for agents live under src/toad/data/agents/ (e.g. openai.com.toml). The application reads its settings from src/toad/settings.py and src/toad/settings_schema.py. No additional environment variables are required out‑of‑the‑box.

Real‑World Use

A developer can launch Toad, press @ in the prompt editor to open the fuzzy picker, select src/toad/data/agents/openai.com.toml, and then issue a shell command (!git status). The shell runs inside the TUI, preserving cd and environment changes, while the agent receives the full terminal output via the integrated JSON‑RPC layer.

The Bottom Line

toad provides a feature‑rich terminal UI that unifies shell interaction, prompt editing, and LLM agent calls, but the codebase suffers from missing tests, lack of reproducible builds, and high cognitive complexity. It is suitable for teams comfortable with Python/TUI development who can invest in adding tests and CI before relying on it in production.
