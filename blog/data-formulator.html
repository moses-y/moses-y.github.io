data formulator

🪄 Data Formulator is an interactive AI-powered data analysis system makes it easy to connect, explore and visualize data.

Forked from microsoft/data-formulator

The Problem Data analysts spend disproportionate time wiring disparate data sources together and keeping track of evolving query threads. Switching between notebooks, dashboards, and CLI tools makes it hard to maintain context, especially when the same dataset must be explored from multiple angles.

What This Does Data Formulator ships a Flask‑based backend (py-src/dataformulator/app.py) and a React UI (static files under public/). The backend exposes a unified Data Agent API that can load data via plug‑in loaders (e.g., py-src/dataformulator/dataloader/bigquerydataloader.py, .../azureblobdataloader.py) and answer natural‑language questions. Visualizations are generated by the Flint chart engine (agents/agentchartrestyle.py).

Key files: py-src/dataformulator/main.py – CLI entry point that starts the Flask server. docker-compose.yml – orchestrates the Python service and a possible UI container. package.json – defines the React build script (used when the UI is served locally).

The repository also bundles sample datasets (public/demos/*.zip and JSON files) and demo videos, enabling quick proof‑of‑concept runs.

How To Use It

Setup Install the Python package (stable release) pip install dataformulator

Or install the pre‑release used in the repo pip install --pre dataformulator==0.8.0b1

The README also mentions the uvx launcher: uvx dataformulator # runs the latest stable uvx dataformulator@0.8.0b1 # runs the beta

If you prefer containerised execution: docker compose build # uses Dockerfile at repo root docker compose up -d

The repo provides an .env.template; copy it to .env and fill any required secrets (e.g., Azure/OIDC credentials referenced in py-src/dataformulator/auth/).

Running CLI: python -m dataformulator (invokes main.py) starts the Flask API on http://localhost:8000. Web UI: After the server is up, open http://localhost:8000 (the UI is served from public/ by Flask). Docker: Access the same endpoint on the host port mapped in docker-compose.yml.

Configuration Data‑loader plugins read connection strings from environment variables defined in auth/ modules (e.g., AZURECLIENTID). The UI language injection and i18n settings are driven by docs/dev-guides/6-i18n-language-injection.md.

Real‑World Use A retail analytics team can drop a CSV of daily sales into public/dfstockpriceslive.json or point the BigQuery loader to their warehouse. After starting the service, a data analyst asks: “What were the top‑selling categories last quarter?” The backend agent runs a generated SQL query, returns a Pandas DataFrame, and Flint renders an interactive bar chart in the UI. The analyst then branches the thread to compare “sales vs. marketing spend” without leaving the workspace.

from data_formulator import DataFormulator df = DataFormulator().ask("show quarterly revenue by region") df.plot(kind="bar") # fallback if UI not needed

Code Health & Issues Low – Missing npm lockfile – package.json exists but no package-lock.json/pnpm-lock.yaml; reproducible UI builds are not guaranteed. Medium – No Python lockfile – No requirements.txt, poetry.lock, or uv.lock; CI builds rely on the latest versions from PyPI, increasing supply‑chain risk. Low – Limited test coverage – Only 4 test files; they cover core agents but not the full data‑loader suite or Flask routes. Low – Secrets handling – .env.template is present, but the repo does not enforce secret scanning; accidental commit of real credentials is possible. Info – CI configured – GitHub Actions (python-build.yml, desktop-build.yml) run linting and unit tests, indicating a basic CI pipeline. Info – Documentation – 45 markdown files, including detailed dev guides and a changelog, provide solid onboarding material.

The Bottom Line Data Formulator delivers a usable, AI‑augmented data‑exploration stack with a clear separation between backend agents and a React UI. It is well‑documented and CI‑tested, making it suitable for teams that need rapid prototyping across heterogeneous data sources. The main drawbacks are the lack of lockfiles for reproducible dependency builds and modest test coverage; address these before deploying in production or in regulated environments.
