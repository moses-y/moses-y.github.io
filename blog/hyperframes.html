hyperframes

Write HTML. Render video. Built for agents.

Forked from heygen-com/hyperframes

The Problem

Generating video programmatically typically requires either complex compositing pipelines (After Effects scripting, FFmpeg filters) or heavyweight media frameworks (Remotion, MoviePy). For AI coding agents, the gap between generating HTML and producing a rendered MP4 is wide—agents can write markup but have no native way to turn it into video with deterministic timing, captions, and transitions.

What This Does

HyperFrames is a Node.js framework that renders HTML, CSS, and seekable animations into deterministic MP4 video. The core workflow lives in the CLI (npx hyperframes preview, npx hyperframes render) and the docs/ directory contains over 140 catalog entries showing specific visual effects: transitions (blur, dissolve, grid, mechanical), captions (kinetic, neon, particle burst, karaoke), and UI blocks (liquid glass, macOS notifications, Spotify cards).

The repo is structured for agent-driven workflows. The .claude-plugin/, .cursor-plugin/, and .codex-plugin/ directories provide skill definitions that teach AI coding agents the production loop: plan, write HTML, wire animations, lint, preview, render. The AGENTS.md and CLAUDE.md files document how agents interact with the framework.

Real-World Use

A product team can describe a video in natural language to an AI agent, which uses HyperFrames skills to generate the HTML, validate it with the linter, preview in the browser, and render to MP4. The docs/catalog/ provides ready-to-remix blocks—data charts, code diffs, map animations, social video templates—that agents can compose into longer sequences.

Code Health & Issues

The repo appears well-maintained for a v0 project. Strengths include: Full CI pipeline in .github/workflows/ci.yml with multiple jobs Code scanning (CodeQL) configured in .github/workflows/codeql.yml Renovate dependency automation in .github/renovate.json License (Apache 2.0), code of conduct, contributing guide, and security policy present Linting configs (oxlint, prettier, commitlint) in root

Notable concerns: Med - No test files visible in the file tree beyond what the analysis counts as "2 test files." For a rendering framework, absence of render-output comparison tests or snapshot testing is a risk. The Dockerfile.test exists but test structure isn't clear from the file listing. Med - No lockfile (bun.lock is listed but may be Bun-specific; no package-lock.json or yarn.lock visible). This creates non-deterministic installs across environments. Low - The docs/ directory dominates the repo (149 of 200 files). This suggests the framework itself may be thin and the catalog/guide content is the primary deliverable at this stage.

The Bottom Line

HyperFrames solves a real problem—bridging HTML generation and video rendering for AI agents—with a pragmatic approach and solid documentation. The framework is early-stage; the catalog of effects is impressive but the core rendering engine's reliability and performance in production remain unverified without visible test coverage. Best suited for teams exploring AI-assisted video generation or building automated content pipelines, not for mission-critical video production without additional validation.
