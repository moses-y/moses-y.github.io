The Problem

OpenEvolve is an open-source implementation of AlphaEvolve, an evolutionary coding agent that turns LLMs into autonomous code optimizers. The repository contains 465 files across three projects (examples, openevolve core, and scripts), with Python as the dominant language (214 files). The core challenge for anyone working with this codebase is navigating the cognitive load: two files exceed 1800 lines (openevolve/database.py and openevolve/process_parallel.py), three hub modules have 52+ dependent modules each, and 22 files exhibit deep nesting at 6+ levels. These structural properties mean that changes ripple widely and control flow is hard to follow.

What This Does

The repository provides an evolutionary system for automated code optimization and discovery. The openevolve core (42 files) defines the evolutionary algorithm, configuration, database management, and evaluation pipeline. Key entry points include openevolve/cli.py which reaches 400 functions, and openevolve/run_evolution for library usage. The examples directory (329 files) contains concrete problem instances—circle packing, affine transforms, eigenvalue problems, and math inequalities—each with initial programs, evaluators, and configs. The scripts directory (16 files) contains JavaScript-based tooling. The system resolves 222 internal modules with 200 import edges and 5 circular dependencies, and 20 functions call external models for inference while 66 functions read/write files.

How To Use It

Setup: Install via pip: pip install openevolve. The Dockerfile uses python:3.12-slim; pin this by digest for reproducibility. The repository has a pyproject.toml but no committed lockfile—run the package manager once and commit the generated lockfile.

Configuration: Required environment variable OPENAI_API_KEY (the README notes Gemini can use OPENAI_API_KEY env var). Config files live in configs/ (default_config.yaml, early_stopping_example.yaml, island_config_example.yaml, island_examples.yaml). Example problem configs are under examples/alphaevolve_math_problems/ and examples/algotune/.

Running it: Command from the README:

python openevolve-run.py examples/function_minimization/initial_program.py \
  examples/function_minimization/evaluator.py \
  --config examples/function_minimization/config.yaml \
  --iterations 50

Library usage: from openevolve import run_evolution, evolve_function. The CLI entry point is openevolve/cli.py.

The Bottom Line

This is a functional evolutionary code optimization system with a working AlphaEvolve implementation and substantial example coverage across math, GPU, and algorithm design domains. The codebase shows signs of rapid growth—large files, deep nesting, and many interdependencies—which makes modification higher-effort than a typical 465-file repo. The critical credential exposure risk in the GitHub Actions workflow and the absent lockfile are the most urgent SDLC fixes. Teams comfortable with LLM-driven optimization and willing to navigate the cognitive load of the core modules will find value here; others should expect a significant ramp-up period.

anthropics/claude-code-action@beta, pypa/gh-action-pypi-publish@release/v1, docker/setup-qemu-action@v3, docker/setup-buildx-action@v3
A tag can be moved, so the action running with your token and secrets is whatever its owner last pushed; this is how tj-actions/changed-files leaked secrets from thousands of repos.
