OpenSeeFace

Robust realtime face and facial landmark tracking on CPU with Unity integration

Forked from emilianavt/OpenSeeFace

The Problem

Real-time 3D facial landmark tracking typically requires a GPU or produces jittery results on CPU. Existing solutions like MediaPipe degrade in low light, high noise, or extreme head poses, and few offer a straightforward pipeline from webcam to Unity for avatar animation. Developers building VTuber-style applications need a CPU-only tracker that stays stable under poor conditions and integrates cleanly with game engines.

What This Does

OpenSeeFace is a CPU-based facial landmark tracker built on MobileNetV3, converted to ONNX and run via onnxruntime. The core Python script facetracker.py captures webcam input (or video files) and streams tracking data over UDP. It supports multiple ONNX models (models/lmmodel0opt.onnx through models/lmmodelVopt.onnx) that let users trade speed for accuracy. A Unity package under Unity/ provides the OpenSee C# component that receives UDP packets and exposes trackingData for avatar puppeteering. The repo also includes prebuilt Windows DLLs (Unity/Plugins/) for DirectShow camera capture (dshowcapture_x64.dll) and the ESCAPI fallback.

Real-World Use

A VTuber runs facetracker.py on a separate Windows PC (or the same machine) pointed at a webcam. The script sends normalized landmark positions, gaze vectors, and blendshape weights over UDP. In Unity, the OpenSee component listens on the same port and feeds data into OpenSeeShowPoints for debugging or into a VRM driver like Examples/OpenSeeVRMDriver.cs. The OpenSeeInterpolation.cs and OpenSeeKinematicInterpolation.cs components smooth the raw points to reduce jitter before applying them to a 3D avatar.

Code Health & Issues Low — Single test file found (facetracker.spec is a PyInstaller spec, not a test). No unit tests for the Python tracker or Unity components. Relies on manual verification. Low — Windows-only camera capture (DirectShow/ESCAPI DLLs). No cross-platform camera support in the Unity plugin; Linux/macOS users must write their own capture pipeline. Low — README specifies Python 3.7, but pyproject.toml uses poetry without pinning a Python version. Dependency conflicts likely with newer Python releases. Low — Prebuilt DLLs (SVMModel.dll, thundersvm.dll) are opaque binary blobs. No source for SVM model inference in the Unity plugin; updates require rebuilding from an external project.

The Bottom Line

OpenSeeFace delivers reliable, CPU-only face tracking that outperforms MediaPipe in challenging lighting and head poses. The Unity integration is well-structured and production-ready for Windows VTuber applications. However, the lack of automated tests and cross-platform camera support limits its use to Windows-only, manual-validation workflows. Teams targeting Windows with a dedicated tracking PC will find this a solid, proven foundation.
