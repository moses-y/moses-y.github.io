checkcle

CheckCle is a self-hosted, open-source monitoring platform for seamless, real-time full-stack systems, applications, and infrastructure. It provides real-time uptime monitoring, distributed checks, incident tracking, and alerts. All deployable anywhere.

Forked from operacle/checkcle

The Problem Organizations that need real‑time visibility across servers, APIs, and containers often rely on SaaS monitoring tools that lock data into proprietary pipelines. A self‑hosted alternative that can run on modest hardware, expose a full‑stack dashboard, and integrate with existing alert channels is scarce without heavy custom engineering.

What This Does CheckCle is a React‑based web application (≈100 TSX files under application/src) that provides uptime checks, incident tracking, and a public status page. The front‑end communicates with a backend API located at application/src/api/ – index.ts aggregates endpoints, while realtime/index.ts and settings/index.ts handle streaming data and configuration respectively.

Deployment is containerised: application/Dockerfile builds the image, and application/package.json (npm) manages the JavaScript dependencies. The repository also ships a GitHub Actions workflow (.github/workflows/build-frontend-image.yml.dev) that compiles and pushes the image on each push. Data such as persistent storage and user settings are held on a host volume (/opt/pbdata) mapped in the Docker Compose example found in the README.

How To Use It

Setup The simplest path is the Docker Compose snippet documented in the README:

version: '3.9' services: checkcle: image: operacle/checkcle:latest containername: checkcle restart: unless-stopped ports: "8090:8090" volumes: /opt/pbdata:/mnt/pbdata ulimits: nofile: soft: 4096 hard: 8192

Alternatively, a one‑liner docker run command is provided:

docker run -d \ --name checkcle \ --restart unless-stopped \ -p 8090:8090 \ -v /opt/pbdata:/mnt/pbdata \ --ulimit nofile=4096:8192 \ operacle/checkcle:latest

Configuration No .env files are committed; the application reads its default settings from the backend API (application/src/api/settings/). The settings/actions/getSettings.ts and updateSettings.ts endpoints allow administrators to adjust user management, data retention, theme, and notification channels through the UI or via the API.

Running it After the container starts, the web UI is reachable at http://0.0.0.0:8090. The initial credentials are admin@example.com / Admin123456 (as noted in README.md). From there you can add monitors, configure regional agents under application/src/components/regional-monitoring/, and create incidents via application/src/components/schedule-incident/.

Real‑World Use A DevOps team running a mix of Linux servers and Docker containers can deploy CheckCle on a single low‑cost VM. They point the /opt/pbdata volume to a durable disk, then use the UI to add HTTP/TCP checks for each service. When a check fails, the system creates an incident record (application/src/components/schedule-incident/incident/) and can push notifications to Slack, Telegram, or email through the settings panel. The regional monitoring feature (RegionalAgentCard.tsx, RegionalMonitoringContent.tsx) lets them distribute checks across multiple geographic nodes, providing a view of global uptime without third‑party SaaS.

Code Health & Issues Tests & CI – Four test files exist under application/src/components/…/hooks/ and a GitHub Actions workflow builds the frontend image on every push, giving basic confidence that the build pipeline works. License & Security – LICENSE.md, SECURITY.md, and CODEOF_CONDUCT.md are present, indicating an open‑source governance model. Dependency hygiene – package-lock.json is checked in, locking resolved versions. No obvious vulnerable dependencies were flagged in the quick scan, but a full npm audit is recommended before production use. Configuration exposure – The default admin credentials are documented in the README; teams should rotate these and bind the container to a trusted network only. Missing secrets handling – No .env or secret management is committed; any API keys or tokens for external services (e.g., Slack webhooks) must be injected at runtime or via external secret stores.

The Bottom Line CheckCle delivers a functional, self‑hosted monitoring stack with a modern React front‑end, Docker‑based deployment, and built‑in incident/notification workflows.
