explore claude code

Learn Claude Code by exploring it as it was designed - interactive IDE-style docs for commands, MCP, skills, CLAUDE.md and more.

Forked from LukeRenton/explore-claude-code

The Problem

Teams adopting Claude Code often struggle to understand the full configuration surface area — .claude/settings.json, .claude/commands/, .claude/skills/, and MCP integrations — without digging through official documentation or trial-and-error. This project exists to flatten that learning curve by presenting every concept as a live, inspectable file.

What This Does

The site renders a navigable tree of Claude Code's configuration surface. Everything under .claude/ represents project-level config you create and commit: settings.json for permissions and guardrails, rules/ for file-type-scoped conventions, commands/ for custom slash commands, agents/ for delegated sub-tasks, skills/ for autonomous knowledge folders, and hooks/ for lifecycle shell scripts. The built-in/ section covers features shipping with Claude Code out of the box — /simplify, /batch, /debug, /loop, /claude-api — requiring no setup. A visual separator divides project config from built-in features. The manifest.json under site/data/ drives the entire UI, mapping every file and badge. The content-loader.js handles custom markdown parsing and rendering, while app.js serves as the main controller for routing and keyboard navigation. The live demo at exploreclaudecode.com requires no install; locally, any static server pointed at site/ works — the README documents npx serve site or python -m http.server -d site 8080.

How To Use It

Clone the repo and serve the site/ directory. No build step, no framework installation:

git clone https://github.com/LukeRenton/explore-claude-code.git cd explore-claude-code npx serve site or python -m http.server -d site 8080

Open the browser at the displayed address. Click the sidebar to explore .claude/ and built-in/ sections, read annotated config files, and copy scaffolding into your own projects. The content is sourced real — each markdown file is a genuine Claude Code config example, not a description of one.

Real-World Use

A new hire joining a team can clone the repo, click through .claude/settings.json to understand permission boundaries, review .claude/commands/ to see saved workflows, and examine .claude/skills/ to learn what autonomous skills the team's Claude instances load. Instead of reading theory, they inspect live config they'll commit to their own repo. Meanwhile, a staff engineer can use the built-in/bundled-skills/code-review.md as a reference when designing a custom review skill, copying the pattern into their project's .claude/skills/ directory.

Code Health & Issues No CI/CD pipeline — the .github/ directory contains only FUNDING.yml; there is no automated build, test, or lint gate. Any contributor can push config changes without validation. No test files — the heuristic detects exactly two test files; the repo contains none. Changes to the JavaScript logic (app.js, content-loader.js) have no automated regression guard. Static site, no framework — the zero dependencies badge is accurate; the UI is vanilla HTML/CSS/JS with no bundler. This reduces attack surface but means no code splitting or build-time checks. License present — LICENSE file is included, which is a minimum expectation for code redistribution.

The Bottom Line

This is a well-executed learning tool that successfully demystifies Claude Code's configuration surface. It's ideal for teams onboarding to Claude Code or wanting to audit their existing .claude/ setup. The absence of CI/CD and tests means it's not a production codebase — use it as a reference sandbox, not a starter kit for mission-critical tooling. Teams comfortable copying annotated markdown into their own repos will get the most value; those seeking a full-featured Claude Code starter project will need to add build gates and testing themselves.
