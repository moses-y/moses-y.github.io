The Problem

Developers using cloud‑based LLMs must keep secrets, credentials and internal URLs out of the request payloads that leave their local machine. A naïve approach is to manually scrub data or to run the model in‑house, both of which break workflow or introduce security gaps. The need is a lightweight, bidirectional proxy that can replace sensitive values before the request is sent and restore the originals on the response, all without changing the client code.

What This Does

The repository implements a privacy proxy that intercepts HTTP requests from supported AI clients (Codex, Claude, Pi/Oh My Pi, OpenAI‑compatible SDKs) and rewrites them in two phases:

  1. Pre‑flight redaction – internal/redact/redact.go replaces matched secrets, IPs, URLs, etc. with deterministic pseudonyms or placeholders.
  2. Post‑flight restoration – the same logic in internal/redact/redact.go is applied in reverse to any response that contains the generated stand‑ins.

The core server lives in cmd/cover/main.go, which starts an HTTP listener defined by internal/proxy/proxy.go. Policy rules are loaded from YAML files (configs/config.example.yaml and configs/codex-router.example.yaml) and parsed by internal/codexconfig/config.go. The daemon logic (internal/daemon/daemon.go) manages the proxy process and its PID file, while internal/daemon/port.go handles port allocation.

How It Is Wired

Execution begins in cmd/cover/main.go (main function). The CLI parses sub‑commands (installCmd, envCmd, initCmd, startCmd), each delegating to functions in the same file or to helpers in internal/daemon and internal/proxy. A typical run follows:

  1. main → startCmd → internal/proxy/proxy.go:New → ServeHTTP
  2. ServeHTTP → serveContentMonitor → internal/activity/monitor.go:Run
  3. Run → Parse → internal/redact/redact.go:RedactForProxy (pre‑flight)
  4. Response passes back through ServeHTTP → publishContent → internal/redact/redact.go:Restore (post‑flight)
  5. PublishContent writes the transformed body to the client.

The call graph shows Close, New, Redact, Load, and Transform as the most heavily used functions, each invoked by dozens of callers. File‑level responsibility:

  • internal/proxy/proxy.go owns the HTTP handling and policy application (17 functions, 4 types).
  • internal/redact/mapping.go manages the pseudonym store (17 functions, 3 types).
  • internal/daemon/daemon.go manages process state (9 functions).

The code touches the filesystem for configuration (Load in internal/redact/mapping.go), pseudonym key (LoadOrCreatePseudonymKey in internal/config/pseudonym_key.go), and daemon PID files (via Write/Read in internal/daemon/daemon.go). It performs one outbound network call per request to the target AI endpoint, while all other I/O is local.

How To Use It

Setup

# From a fresh checkout
git clone https://github.com/moses-y/cover
cd cover
go build -o cover ./cmd/cover
install -m 0755 cover ~/.local/bin/cover

Or use the provided installer script:

curl -fsSL https://raw.githubusercontent.com/moses-y/cover/main/scripts/install.sh | bash

Configuration Edit configs/config.example.yaml to set target_url, port, and policy rules. Copy it to ~/.config/cover/config.yaml or set COVER_CONFIG to point to it.

Running

cover start

This launches the daemon (internal/daemon/daemon.go) and begins listening on the configured port. The proxy is now ready to be pointed to by any of the supported LLM clients via the target_url in the config.

Real‑World Use

A team uses OpenAI’s openai Python SDK. They point the SDK’s base_url to http://localhost:8080/v1. Code that normally contains an API key or internal host is automatically redacted; responses with placeholder values are transparently restored, keeping the runtime logic intact.

The Bottom Line

Cover offers a clear, Go‑based privacy proxy that works out of the box for common LLM clients. It is well‑structured, tested, and CI‑protected, though some refactoring could reduce cognitive load. Teams that need to keep secrets local while still using cloud LLMs will benefit from its deterministic pseudonymization and seamless integration.
