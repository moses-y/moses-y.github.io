The Problem

LLM agents routinely inject tool outputs, logs, RAG chunks, and file contents into prompts. Most of that text is boilerplate—repeated error codes, verbose stack traces, redundant log lines. Every token costs latency and money, and for reasoning models the cost compounds with each reasoning step.

What This Does

Headroom is a context optimization layer that compresses prompt content before it reaches the LLM. It runs a learned compression model (kompress-base, hosted on HuggingFace) against tool outputs, logs, and structured text, then reconstructs the prompt with the noise removed. The compression is lossless in practice—the project's own benchmarks show GSM8K accuracy unchanged at 0.870 and TruthfulQA actually improving by 0.030.

The system operates in three modes: a Python/TypeScript SDK (headroom.compress in examples/contextcompressiondemo.py), a CLI wrapper for coding agents (headroom wrap), and a transparent proxy (headroom proxy in docs/proxy.ts). A cross-agent memory layer (headroom learn) mines failed sessions and writes corrections to agent-specific markdown files like CLAUDE.md or GEMINI.md.

Real-World Use

A developer running Claude Code on a codebase with verbose test output would install Headroom with pip install "headroom-ai[all]" then run headroom wrap claude. All subsequent Claude sessions route through the compression layer. The README reports a needle-in-haystack test dropping from 10,144 tokens to 1,260—an 87% reduction—while both runs found the same FATAL error buried in 100 log lines.

Code Health & Issues

The repository is well-structured with tests (24 files), CI (GitHub Actions), Docker support, and documentation (101 files). The benchmarks/ directory contains 20+ benchmark scripts covering adversarial tests, latency, relevance, and regression. The e2e/ directory has end-to-end test harnesses with Docker-based setup.

Concrete concerns: High – No unit tests visible for the core compression logic in headroom/. The 24 test files appear to be benchmarks and e2e tests, not unit tests. This is a gap for a library that makes accuracy claims. Medium – The docs/proxy.ts file is a TypeScript proxy implementation but docs/ is a Next.js documentation site—unclear if this is the actual production proxy or a stub. The architecture doc at docs/content/docs/architecture.mdx should clarify but is not reviewed. Low – The .actrc and .actrc.local.example files suggest local GitHub Actions testing, but .env.act.example implies environment variables are committed as examples—acceptable if not containing secrets.

The Bottom Line

Headroom solves a real cost problem for LLM agents with a practical, accuracy-preserving approach. The compression benchmarks are credible and reproducible. The lack of unit tests for the core compression logic is a gap worth investigating before production use, but the project structure and documentation quality suggest a mature codebase maintained by a team that understands the domain.

Remove the committed dependency directoryhigh1649 occurrences
node_modules
1649 files committed under node_modules
The code that actually runs was never resolved from a manifest, so no scanner, lockfile or update bot has any view of it.
Fix: Gitignore the directory, git rm -r --cached it, and reinstall from the lockfile.
Pin third-party GitHub Actions to a commit SHAhigh10 occurrences
.github/workflows
codecov/codecov-action@v4, wagoid/commitlint-github-action@v5, docker/setup-qemu-action@v4, docker/setup-buildx-action@v4
A tag can be moved, so the action running with your token and secrets is whatever its owner last pushed; this is how tj-actions/changed-files leaked secrets from thousands of repos.
Fix: Replace each @vN with the 40-character commit SHA, keep # vN as a comment, and let Dependabot bump the SHAs.
Replace the wildcard CORS origin with an explicit allow listhigh
headroom/proxy/server.py
allow_origins=["*"] together with credentials enabled
Any page on the internet can call the API with the browser's cookies attached, so a logged-in visitor to an unrelated site performs authenticated requests without knowing, and the wildcard combined with credentials is the exact configuration browsers refuse for that reason.
Fix: List the origins the API actually serves, and never pair a wildcard with credentials.
Remove continue-on-error from steps that gate correctnesshigh
.github/workflows/release.yml
line 223 on a correctness step
A failing test suite reports a green check, which is precisely the path this audit exists to close.
Fix: Delete continue-on-error, or move a genuinely advisory step into a separate non-required job.
Declare least-privilege permissions for GITHUB_TOKENmedium
.github/workflows/ci.yml
1 workflow(s) declare no permissions
With no declaration the token inherits the repository default, so any injected step can push commits or mint releases from inside your own CI.
Fix: Add permissions: contents: read at the top of the workflow and widen per job only where needed.
Install from the lockfile in CImedium
.github/workflows
npm install with a committed package-lock.json
A fresh resolution in CI means the tested dependency set is not the locked one, so the failure only appears after merge.
Fix: Use npm ci, yarn install --immutable, or pnpm install --frozen-lockfile.

An untagged or mutable base means today's build and last month's contain different libc and a different CVE set, with no record of which shipped.
