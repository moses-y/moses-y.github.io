Overview

The repository contains 165 files, 125 of which are Go source. It is a crawling and spidering framework forked from projectdiscovery/katana, designed for automation pipelines with both standard and headless execution paths. The codebase is organized under pkg/, cmd/, and internal/, with a clear separation between engine logic, parsing, output formatting, and navigation.

The Problem

Organizations needing automated web discovery often require a tool that supports JavaScript rendering, configurable scope filtering, and structured output without the overhead of heavier frameworks. The README positions katana as a fast, configurable alternative focused on pipeline execution, with input from STDIN/URL/list and output to STDOUT/file/JSON.

What This Does

Modes: Standard and headless crawling (cmd/katana/main.go is the primary entry point). Headless mode relies on system Chrome (Dockerfile and Ubuntu install notes confirm this dependency). JavaScript support: Handled via pkg/engine/headless/browser/ and pkg/engine/headless/captcha/ (capsolver integration, JS injection files under pkg/engine/headless/captcha/js/). Form filling: pkg/utils/formfill/ and pkg/utils/formfields/ provide customizable automatic form population. Scope control: pkg/utils/scope/ and pkg/types/options.go enable preconfigured field/regex filtering. Output: pkg/output/formatjson.go, formatscreen.go, format_template.go support markdown/JSON/screen formats. Custom fields are defined in pkg/output/fields.go.

How To Use It

Install: go install github.com/projectdiscovery/katana/cmd/katana@latest (go.mod and go.sum are present at root). Docker available as projectdiscovery/katana:latest (Dockerfile present at root). Configuration: Resolvers via -r flag; exclude filters (-e) for host matching (cdn, private-ips, cidr, regex). Output format configurable through CLI flags documented in katana -h. Running: katana -u https://example.com or katana -list urls.txt. Resume scans supported via -resume string flag. Entry point is cmd/katana/main.go.
