The Problem

Teams need to interact with APIs but face a choice between raw HTTP clients (which require API knowledge) and AI-assisted workflows (which lack consistent command interfaces). This gap means every new API integration requires either manual CLI construction or context-switching to AI tools without persistent command schemas. The pain point is concrete: onboarding a new API typically requires 2-3 hours of endpoint discovery, type definitions, and CLI scaffolding before any actual work gets done.

What This Does

api2cli is a Claude Code skill that automates API-to-CLI conversion. The repository contains 8 files across a skill/ directory (5 files) and root (3 files), all Markdown-based documentation. The core flow, per the README, is: point the tool at API docs, a live URL, or a peek-api capture; it discovers endpoints and builds an endpoint catalog capturing auth, pagination, and rate limit info; then generates a Commander.js CLI with one subcommand per endpoint, plus a dual-mode output (human-readable terminal + JSON envelope when piped); finally generates a SKILL.md teaching Claude how to use the CLI. The skill lives in skill/ and can be copied into a Claude Code project. Example: pointing at the Resend API yields 15 endpoints across 5 resources (emails, domains, api-keys, audiences, contacts) with generated CLI at scripts/resend.ts and skill at .claude/skills/resend/SKILL.md.

Key files from structure: .gitignore, LICENSE, README.md, skill/SKILL.md, skill/references/agent-first-patterns.md, skill/references/api-client-template.md, skill/references/commander-patterns.md, skill/references/discovery-strategies.md.

Real-World Use

A practical scenario: a developer needs to manage the Resend email API. Instead of manually constructing HTTP requests or writing type definitions, they point api2cli at the Resend docs. The tool discovers 15 endpoints across 5 resources and generates a CLI where npx tsx scripts/resend.ts domains list returns human-readable output, or piped output returns JSON with auto-derived next-actions. Simultaneously, a SKILL.md is generated so future Claude sessions can invoke resend emails send --to user@example.com --subject "Hello" --html "<p>Hi there</p>" without re-reading the code. The skill is then copied into the project's .claude/skills/ directory, and the API interaction becomes a persistent, discoverable command set.
