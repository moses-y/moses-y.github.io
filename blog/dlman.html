The Problem

Users who need reliable, high‑speed file downloads on Windows, macOS or Linux currently rely on heavyweight Electron‑based managers or built‑in browser tools that lack multi‑segment downloading, crash‑safe persistence, and easy automation. The gap is a lightweight, native manager that can be scripted and integrated into CI pipelines.

What This Does

dlman delivers a native download engine written in Rust (apps/cli/src/main.rs, apps/cli/src/commands.rs) that handles parallel segmented downloads, SQLite‑backed state, and automatic resume after crashes. The desktop UI is a Tauri application (apps/desktop/src-tauri/src/lib.rs, apps/desktop/src/App.tsx) that bundles the Rust backend with a React + Tailwind front‑end, avoiding the memory overhead of Electron. A browser extension (apps/extension/src/entrypoints/) exposes the same engine to Chrome/Firefox/Edge, and a CLI (apps/cli/src/main.rs) lets scripts trigger downloads, schedule queues, or query status.

How To Use It

Setup

Install Rust toolchain (required for the core engine and Tauri) curl https://sh.rustup.rs -sSf | sh Install Node (used by the desktop UI and extension) npm or pnpm works; the repo includes a package-lock via npm npm install -g npm

Build the CLI

From repository root

cargo build --release --manifest-path apps/cli/Cargo.toml Binary placed at target/release/dlman-cli (or dlman‑cli depending on Cargo.toml)

Build the Desktop UI

cd apps/desktop npm ci # installs React, Tailwind, Vite, Tauri dev deps npm run tauri dev # launches a hot‑reloaded dev window For a production bundle npm run tauri build

Build the Browser Extension

cd apps/extension npm ci npm run build # creates a zip in dist/ (refer to package.json scripts)

Configuration

SQLite database path is defined in apps/desktop/src/lib/version.ts (defaults to a file in the user’s data directory). Tauri’s runtime options live in apps/desktop/src-tauri/tauri.conf.json. Adjust bundle.identifier or security.csp there if you need custom permissions. CLI flags are listed via cargo run --manifest-path apps/cli/Cargo.toml -- --help; no external config file is required.

Running

CLI – Example to download a file with 8 segments:

./target/release/dlman-cli download -u https://example.com/file.iso -s 8

Desktop – After npm run tauri dev, the UI is reachable at http://localhost:1420 (Vite dev server) and the native window appears automatically. Extension – Load the built zip in Chrome/Firefox “Load unpacked” mode or publish via the respective stores.

Real‑World Use

A CI job that mirrors build artifacts can invoke the CLI to fetch large binaries in parallel, then store the SQLite state for later reuse:

steps: uses: actions/checkout@v3 name: Install Rust run: rustup default stable name: Build CLI run: cargo build --release --manifest-path apps/cli/Cargo.toml name: Download assets run: | ./target/release/dlman-cli download -u https://cdn.example.com/artifact.tar.gz -s 16

The same binary can be called from a custom script to schedule nightly queue processing on a headless server.

Code Health & Issues

Medium – No test suite – No tests/ directory or #[cfg(test)] modules; CI only builds, not verifies behavior. Low – Limited CI coverage – GitHub Actions (.github/workflows/build-extensions.yml) compile extensions but do not run unit or integration tests for the Rust core or the React UI. Medium – Potential race conditions – Multi‑segment download logic in apps/cli/src/progress.rs spawns threads; lack of explicit synchronization testing may expose data races. Low – Documentation gaps – README shows feature list but lacks concrete CLI usage examples; CHANGELOG.md exists but no API docs for the Rust library. Low – License present – MIT license is included (LICENSE). Low – Dependency hygiene – package.json pins many UI libraries; no automated audit step in CI (e.g., npm audit).

Overall the repo compiles cleanly on Rust 1.71+ and Node 18+, indicating a functional baseline.

The Bottom Line

dlman provides a solid, native download engine with a modern UI and extensible CLI, suitable for power users or teams needing scripted download automation. The primary drawback is the absence of automated tests, which raises risk for future changes. It is a good fit for projects that can tolerate a modest testing gap in exchange for speed and low resource usage.
