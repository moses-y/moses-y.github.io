Abstract

Drop-in memory harness for AI agents — 3-tier memory, compaction tree, hybrid search. One command to set up. Works with Claude Code and OpenClaw.

The Problem

AI agents lose context between sessions. Search-based retrieval (BM25, vector) only works when you know what to look for—it fails on implicit context where the user never mentions the relevant topic. The repo's own benchmark shows search alone scores 2.8% on implicit recall tasks versus 0.8% with no memory at all.

What This Does

hipocampus is a file-based memory layer that maintains a 3-tier hierarchy: templates/WORKING.md for active state, templates/MEMORY.md for consolidated knowledge, and a ROOT.md that holds a compacted topic tree. A compaction process (cli/compact.mjs) periodically summarizes older context into higher-level topics, so the agent retains a holistic view without keeping full history in context.

The system hooks into agent sessions via hooks/session-start.sh and platform-specific skill files under platforms/ (Claude Code, OpenCode, OpenClaw). Five skills in skills/ define the agent's memory behaviors: recall, search, compaction, flush, and a core skill that ties them together.

How To Use It

Setup — Install via the Claude Code plugin marketplace or standalone npm:

npx hipocampus init

Options include --no-vector (BM25 only, saves ~2GB) and --no-search (compaction tree only).

Configuration — No environment variables required. The system is file-based; templates in templates/ define the memory structure. The ROOT.md budget (3K vs 10K tokens) is a key tuning parameter—the benchmark shows larger budgets improve recall on easy/medium questions.

Running it — After init, the session-start hook loads memory into agent context automatically. The compaction CLI (cli/compact.mjs) runs to consolidate older entries. Platform-specific skills tell the agent when and how to use each memory layer.

Real-World Use

A developer works with an agent across weeks on an API. Session logs contain a decision about token-bucket rate limiting, but the user never mentions it again. When the user later asks to "refactor the payment endpoint," the compaction tree in ROOT.md surfaces the rate-limiting topic as related context—something search cannot do because no query connects "payment flow" to "rate limiting."

Code Health & Issues

Med — No CI/CD pipeline — no .github/ or CI config exists, so there's no automated test gate. Five test files exist (cli/compact.test.mjs and others), but nothing runs them automatically. Low — No lockfile — package.json exists without a lockfile, making builds non-reproducible. Low — Mostly documentation — 19 of 31 files are Markdown. The actual implementation is thin: one JavaScript CLI file, one shell hook, one plugin JS file. The core logic lives in prompts and skill definitions rather than code. Low — Single maintainer — forked from a 177-star repo; no contributor signals.

The Bottom Line

The core idea is sound: a compaction tree that maintains a holistic topic map is genuinely better than search for implicit recall, and the benchmark numbers support it. The implementation is lightweight—mostly Markdown prompts and a small CLI—which makes it easy to audit but means the "memory" is only as good as the agent's adherence to the skill definitions. Worth trying for teams running Claude Code or OpenCode on long-lived projects where context persistence matters, but treat the benchmark numbers as indicative rather than definitive until independently reproduced.
