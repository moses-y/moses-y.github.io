The Problem

AI agents lose session context the moment a conversation ends. Cursor, Claude Code, and Codex each maintain isolated, ephemeral transcripts — no structured memory, no cross-client persistence, no portable identity. Re-onboarding means re-explaining the same architectural decisions, preferences, and codebase context every time. SharedContext addresses this by providing a local-first, encrypted memory layer that persists across sessions and machines, synced via Arweave so the agent's context travels with the user.

What This Does

SharedContext is an MCP server that AI clients connect to for fact storage and conversation recall. It consists of a TypeScript codebase (37 files) organized into core modules (src/core/) and CLI/tools (src/cli/). A background watcher (src/core/watcher.ts) monitors conversation directories — Cursor, Claude Code, and Codex transcripts — and feeds facts into SQLite (src/core/db.ts), which stores three tables: facts, pending_deletes, and meta. Encryption happens client-side via src/core/crypto.ts (AES-256-GCM with Argon2id-derived keys), and synced facts become Arweave upload operations through src/core/arweave.ts. Identity is derived from a 12-word recovery phrase into a secp256k1 keypair (src/core/identity.ts), with the private key stored encrypted in the OS keychain. The MCP server entry point is src/mcp/server.ts, which exposes tools for fact management, conversation retrieval, and shard sync.

Real-World Use

An AI agent running through Cursor connects to the SharedContext MCP server. The user runs sharedcontext init to establish an identity (12-word phrase → secp256k1 keypair → encrypted keychain storage). As the agent works, it stores structured facts via MCP tools — e.g., storeFact({key: "arch.decision", value: "use tRPC", confidence: 0.9}) — which write to src/core/db.ts and mark dirty for sync. A background loop in src/core/sync.ts collects dirty facts, converts them to shard operations (buildShardTags, pushShard), and uploads encrypted blobs to Arweave via src/core/arweave.ts. On a new machine, the user recovers the same context by entering the 12-word phrase, which derives the same keypair, decrypts the stored identity, and restores the SQLite schema and Arweave-synced data. To share a conversation, the user invokes sharedcontext share, which encodes an encrypted token (src/cli/share.ts:encodeShareToken) the recipient imports with one command.

The Bottom Line

This is a functional local-first memory layer for AI agents with solid encryption, SQLite sync, and Arweave persistence — the kind of infrastructure that saves real time when running across multiple clients or machines. The import cycles, missing license, and absent CI are blockers for team adoption or client engagements, but the core design is sound and the test coverage (10 test files) gives confidence the logic works. Use it if you need portable agent memory and are comfortable running the sync infrastructure yourself; hold off until a license and CI gate are in place for anything beyond personal experimentation.
