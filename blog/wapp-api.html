The Problem

Building a WhatsApp bot or multi-service chat usually requires deep knowledge of the WhatsApp Web protocol and the underlying Node.js library (Baileys). Without a standard REST/WebSocket API, teams must write custom integration code for every feature—message sending, group management, instance control—and handle session persistence, reconnection, and webhooks themselves. This repo provides a ready-made, containerized RESTful API that abstracts those complexities.

What This Does

wapp-api is a TypeScript-based REST API (with WebSocket support) that wraps the WhiskeySockets/Baileys library. It exposes endpoints for sending messages, managing groups and instances, handling webhooks, and viewing QR codes for authentication. The project uses NestJS-style modules (see src/app.module.ts, src/whatsapp/controllers/, src/whatsapp/services/) and Prisma ORM for PostgreSQL persistence (prisma/schema.prisma). It includes Docker Compose files for the API and PostgreSQL, plus a Traefik reverse proxy configuration (proxy/). The WebSocket server (src/websocket/server.ts) provides real-time event streaming, and the API is documented via Swagger (docs/swagger.yaml) and a Postman collection.

Real-World Use

A team running a customer-support platform can deploy this API behind Docker, create a WhatsApp instance via POST /instance/create, receive incoming messages through a configured webhook (src/whatsapp/controllers/webhook.controller.ts), and reply using POST /message/send. Low – No lockfile committed – package.json exists but no package-lock.json or yarn.lock. Builds are non-reproducible; dependency drift can cause unexpected failures. No real credentials are exposed, but the practice is discouraged. Positive – CI/CD is configured via GitHub Actions (.github/workflows/docker-image.yml), but the workflow only builds the Docker image—it does not run tests or linting. No license file is present (LICENSE file exists, but it’s a GPL-3.0 license, which is fine).

The Bottom Line

This is a functional, well-structured WhatsApp API wrapper that saves weeks of integration work—provided you accept the lack of automated tests and the need to add a lockfile. It’s best suited for teams comfortable with Docker and PostgreSQL who want a ready-to-deploy solution. Before production, add tests, lock dependencies, and review the .env.dev file for any placeholder credentials.
