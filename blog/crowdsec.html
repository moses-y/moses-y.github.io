The Problem

Organizations need a participative way to detect and block malicious IP addresses across diverse environments. CrowdSec provides crowdsourced threat intelligence, allowing each node to contribute observed bad behaviour and receive community blocklists in real time.

What This Does

CrowdSec is an open‑source security engine that functions as an IDS/IPS and WAF. It ingests log sources and HTTP requests, evaluates detection rules, and triggers remediation through bouncers that firewall, reverse‑proxy, or container runtimes can consume. The core detection logic lives in pkg/acquisition/modules/, where parsers and buckets collect and score events. Remediation components such as bouncers are defined in cmd/crowdsec-cli/clibouncer/. The Security Engine’s rule evaluation is orchestrated from cmd/crowdsec/serve.go:307 (Serve) and cmd/crowdsec/main.go:212 (main), which start the API server, metric provider, and output routines. Configuration is driven by YAML files under config/ and parsed by pkg/csconfig/. The community blocklist is fetched via the central API and merged into the in‑memory allow/deny state.

How To Use It

  • Setup: Clone the repo verbatim: git clone https://github.com/moses-y/crowdsec. Build with the provided Makefiles (cmd/crowdsec/Makefile, cmd/crowdsec-cli/Makefile) or use Docker: docker build -t crowdsec -f build/docker/Dockerfile ..
  • Configuration: Primary config lives in config/. Environment variables and secrets are referenced in workflow files under .github/workflows/. Ensure go.mod dependencies are up‑to‑date (go mod tidy).
  • Running it: Start the daemon with go run ./cmd/crowdsec or, after building, ./crowdsec. For Windows services use Execute from cmd/crowdsec/win_service.go:27. The CLI entry add (cmd/crowdsec-cli/cliallowlists/allowlists.go:454) can register allow‑list entries.

Real‑World Use

A security team deploys CrowdSec on a fleet of web servers. Logs from nginx are tailed by the file acquisition module (pkg/acquisition/modules/file/). The Security Engine flags repeated failed login attempts, creates a bucket, and after the threshold is met, emits an alert. The bouncer (cmd/crowdsec-cli/clibouncer/) automatically updates the host’s iptables or Nginx deny directive, blocking the offending IP. The same alert also pushes the IP to the community blocklist, benefiting all other participants.

The Bottom Line

CrowdSec delivers a functional, crowdsourced security engine with solid Docker and Kubernetes integration, but the codebase shows signs of cognitive‑load hotspots, duplicated logic, and oversized files that hinder maintainability. The CI hygiene gaps (missing dependency scans, root‑as‑default container user, untokenled GITHUB_TOKEN) are easy to remediate. It is well‑suited for teams that want participative IP blocking and are comfortable contributing to, and consuming from, the community blocklist.

With no declaration the token inherits the repository default, so any injected step can push commits or mint releases from inside your own CI.

build/docker/Dockerfile

An untagged or mutable base means today's build and last month's contain different libc and a different CVE set, with no record of which shipped.
Fix: Use image:tag@sha256:<digest> and enable Dependabot's docker ecosystem.

build/docker/Dockerfile
CMD or ENTRYPOINT with no USER directive
A process running as root in the container is root against every mounted volume, and it turns any container escape or writable-mount mistake from a contained problem into a host one.
Fix: Create an unprivileged user, chown what it needs, and end the Dockerfile with USER.
