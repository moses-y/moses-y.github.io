dmux

A dev agent multiplexer for git worktrees and coding agents.

Forked from standardagents/dmux

The Problem

Running multiple AI coding agents on the same codebase causes file conflicts, branch collisions, and context pollution. Developers either serialize their agent work or risk agents overwriting each other's changes. There is no standard tool for orchestrating parallel agent sessions with proper git isolation.

What This Does

dmux is a tmux-based multiplexer that creates isolated git worktrees for each AI coding agent session. When you press n to create a new pane, it provisions a fresh worktree and branch, then launches your chosen agent CLI (Claude Code, Codex, Gemini CLI, etc.) inside that pane. The tests/ directory contains 107 test files covering pane lifecycle, agent launch, git operations, and merge workflows.

The .dmux-hooks/ directory exposes lifecycle hooks (worktreecreated, premerge, post_merge) for custom scripting. The actions/ directory under tests/ shows the action system: merge, create PR, rename, duplicate, close, and toggle autopilot. The codebase is TypeScript (95 files) with React components (11 TSX files) for the UI layer.

Real-World Use

A team working on three features simultaneously runs dmux in their repo, creates three panes, and assigns each to a different agent. Agent A refactors the auth module in its worktree, Agent B adds a new API endpoint, Agent C fixes a bug. No agent sees the others' changes until each pane is merged via the menu (m → Merge). The team reviews each merge independently, avoiding the typical "merge hell" of parallel agent work.

Code Health & Issues

The repo appears well-structured with no obvious red flags. Evidence: 109 test files present, GitHub Actions CI configured in .github/workflows/publish.yml, MIT license included, and a lockfile present. However, the test count (109 files) against 95 TypeScript files suggests thorough coverage. The arnis-tile-cache/ directory (36 PNG files) is likely generated map tiles that should be in .gitignore — this adds ~1MB of binary artifacts to the repo. No secrets or config leaks detected.

The Bottom Line

dmux solves a real operational problem for teams running multiple AI coding agents. The worktree isolation pattern is sound, and the hook system allows integration into existing workflows. Best suited for teams that already use tmux and want to parallelize agent work without collisions. Solo developers may find the tmux dependency heavy — a terminal multiplexer on top of a multiplexer adds complexity that a simpler CLI might avoid.
