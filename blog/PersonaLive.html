The Problem

PersonaLive addresses the challenge of real-time, expressive portrait image animation for live streaming. Existing diffusion-based animation models are typically too slow for interactive use or produce degraded results over long sessions. PersonaLive targets infinite-length, streamable animation with a single reference portrait image and a driving video source, aiming to maintain identity fidelity and expression quality without latency buildup.

What This Does

PersonaLive is a diffusion-based framework that animates a static portrait image using motion cues from a driving video. The core pipeline is split into three stages (configs/train/personalivestage1.yaml, stage2, stage3), each handling a distinct part of the generation process—likely coarse motion, fine detail, and temporal consistency. The src/ directory contains the full model stack: U-Net variants (src/models/unet2dcondition.py, unet3d.py), motion encoders, pose guiders, and StyleGAN2 discriminators for training.

The repo ships three inference paths: a standard offline script (inferenceoffline.py), a streaming variant (inferenceonline.py), and a real-time webcam pipeline under webcam/. The webcam frontend is a SvelteKit app with TypeScript (webcam/frontend/src/lib/index.ts), providing a browser-based UI for controlling the animation pipeline. TensorRT and ONNX export support exists via src/modeling/onnxexport.py and torch2trt.py for optimized deployment.

How To Use It

Setup: Install Python dependencies with pip install -r requirementsbase.txt (training requires requirementstrain.txt). The webcam frontend uses npm—run npm install inside webcam/frontend/.

Configuration: Model weights go in pretrainedweights/ (download via python tools/downloadweights.py). Inference parameters are set in the YAML files under configs/inference/ (e.g., inferencestage1&2.yaml). The webcam backend reads webcam/config.py for runtime settings.

Running it: For offline animation, run inferenceoffline.py with a reference image and driving video. For the webcam interface, start the backend and Svelte frontend:

Offline inference

python inferenceoffline.py --config configs/inference/inferencestage1&2.yaml

Webcam backend (Svelte frontend served via vite)

cd webcam/frontend && npm run dev

Training scripts are trainstage1.py, trainstage2.py, trainstage3.py.

Real-World Use

A live-streaming platform could deploy PersonaLive to let creators animate a custom avatar from their webcam feed. The webcam pipeline (webcam/vid2vid.py) takes the user's camera stream, extracts motion, and drives the reference portrait in near real-time. For production, the TensorRT path (webcam/vid2vidtrt.py) would be used to hit latency targets on GPU servers. The streaming strategy in inferenceonline.py is designed to run on 12GB VRAM, making it feasible on mid-range GPUs.

Code Health & Issues

High - No test files detected - The entire repo lacks a test suite. Given the complexity of the diffusion pipeline and webcam streaming, untested code paths are a significant risk for regressions. High - No CI/CD pipeline - No .github/ workflows or CI config exist. There is no automated gate for build or test validation. Med - Training reproducibility - The three-stage training setup requires careful configuration and pretrained base models (sd-image-variations-diffusers, sd-vae-ft-mse). Without a documented training walkthrough or logs, reproducing results will be difficult. Med - Dependency hygiene - Multiple requirement files (requirementsbase.txt, requirementstrain.txt, requirements_trt.txt) suggest a complex dependency matrix. The C++/CUDA files under src/stylegan2/ require a compatible build environment. Low - Documentation gaps - The README covers installation and inference but lacks detailed docs for the webcam pipeline setup, TensorRT conversion, and training data preparation.

The Bottom Line

PersonaLive is a serious research implementation with a clear architecture and working inference paths. The webcam frontend and TensorRT support indicate real deployment intent, not just paper code. It is best suited for researchers and engineers who need a working portrait animation baseline and are comfortable debugging a research-grade codebase without tests or CI. Production teams should budget time for hardening before relying on it.
