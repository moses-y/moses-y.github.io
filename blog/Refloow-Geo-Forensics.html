The Problem

Investigators and OSINT analysts often need to pull EXIF metadata from large batches of images or videos, map GPS points, and build a chronological view of events. Doing this manually is time‑consuming, error‑prone, and requires juggling several command‑line tools.

What This Does

Refloow‑Geo‑Forensics automates the full workflow. The core logic lives in src/src/utils/scanner.js, which wraps the exiftool‑vendored library to read metadata from any supported file type. Extracted coordinates are fed to a front‑end UI built with React (see src/public/index.html, src/public/styles.css, and the React entry in src/main.js). The UI renders an interactive map (multiple layer options) and a timeline view, allowing analysts to explore spatial and temporal relationships without leaving the application.

The back‑end server (src/src/server.js) serves the static UI and exposes an API defined in src/src/routes/api.js. The API receives a list of file paths, invokes the scanner, and returns JSON containing GPS data, timestamps, and thumbnail references. This separation lets the UI remain responsive while heavy EXIF parsing runs in the Node process.

How To Use It

Setup – Install Node ≥ 20.10 (the badge in README.md specifies this version). cd src npm ci # installs exact versions from package‑lock.json

The repository supplies pre‑built binaries for Windows, macOS, and Linux via the GitHub releases, but building from source follows the same steps. Configuration – No explicit configuration file is required out of the box. The server expects a folder path supplied in the request body; if you need to point to a custom ExifTool binary, set the environment variable EXIFTOOL_PATH before starting the server (the exiftool‑vendored wrapper respects this variable). Running – Start the back‑end and UI with the script defined in src/package.json (typically "start": "node src/src/server.js"). npm start

The server listens on http://localhost:3000 (default) and serves the UI from src/public. Open a browser to that address, drag‑and‑drop a folder of images/videos, and the application will display map markers and a timeline. Packaging – Pre‑compiled installers (src/install.bat, Snap and Microsoft Store workflows in .github/workflows/) are provided for end‑users who prefer a no‑code install.

Real‑World Use

A law‑enforcement analyst can point the tool at a seized phone’s media folder. The scanner extracts GPS points from 2 000 photos, the map instantly shows the suspect’s movement across city districts, and the timeline highlights gaps that correspond to alibi claims. The analyst can export the JSON payload (via the API) for ingestion into a case‑management system.

// Example API call from a custom script fetch('http://localhost:3000/api/scan', { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ folder: '/evidence/media' }) }) .then(r => r.json()) .then(data => console.log('Geodata:', data));

Code Health & Issues

Med – No automated tests – The repository contains zero *.test.js files; CI workflows only build packages, leaving functional regressions unchecked. Low – Limited input validation – src/src/routes/api.js forwards user‑provided paths directly to the scanner; malformed paths could trigger uncaught exceptions. Med – External binary reliance – The tool depends on ExifTool; if the vendored binary is missing or incompatible with the host OS, the scanner will fail at runtime. No fallback or clear error message is documented. Low – Hard‑coded ports – Server starts on a fixed port (likely 3000) with no environment override, which can clash in shared environments. Low – License duplication – Both root and src contain a LICENSE file; while both are AGPL‑3.0, duplication may cause confusion for downstream distributors. Med – CI only builds – GitHub Actions workflows (linux-build.yml, macos-build.yml, snap-build.yml) compile installers but do not run linting or security scans (e.g., npm audit).

The Bottom Line

Refloow‑Geo‑Forensics delivers a functional, locally‑run pipeline for bulk EXIF extraction, map visualization, and timeline reconstruction, with a clear separation between back‑end API and React front‑end. It is suitable for solo investigators or small teams that need an out‑of‑the‑box UI and are comfortable managing Node dependencies. However, the lack of tests, minimal input sanitization, and reliance on an external binary mean the project should be vetted and possibly hardened before deployment in high‑risk or production environments.
