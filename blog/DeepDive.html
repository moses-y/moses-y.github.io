DeepDive: Advancing Deep Search Agents with Knowledge Graphs and Multi-Turn RL

Forked from THUDM/DeepDive

The Problem Current LLM‑based search agents struggle with long‑horizon, multi‑step information‑seeking tasks because training data rarely contain deep, graph‑driven reasoning paths. Teams building browse‑enabled assistants must manually curate difficult QA pairs or rely on ad‑hoc pipelines, leading to high engineering cost and limited coverage of hard queries.

What This Does DeepDive supplies an end‑to‑end data‑generation pipeline that automatically creates challenging QA pairs from open knowledge graphs. The core logic lives in the qasynthetic/ folder:

randomwalkkilt.py – performs controlled random walks over a KG (e.g., KILT) to produce attribute‑rich paths. prompt.py – formats each path and sends it to an LLM for entity obfuscation, turning raw graph walks into natural‑language questions. kiltquery.py – optionally runs a lightweight search (frontier model) to filter out easy questions. generateqa.py – orchestrates the above steps, writes the final QA dataset, and stores SFT trajectories.

The top‑level README.md and the qasynthetic/README.md describe the research context and provide a high‑level diagram of the multi‑turn RL training stage, but the repository presently only contains the data‑synthesis component.

How To Use It

Setup Install Python dependencies (no lockfile, reproducibility not guaranteed) pip install -r qasynthetic/requirements.txt

requirements.txt lists packages such as torch, transformers, and datasets. No additional build scripts or Dockerfiles are present.

Configuration No explicit config files are shipped. Scripts expect environment variables for the LLM endpoint (e.g., OPENAIAPIKEY) and optionally a KG source path. These must be defined by the user before execution.

Running the pipeline From the repository root python qasynthetic/generateqa.py \ --kgpath path/to/knowledgegraph \ --outputdir data/qapairs \ --numwalks 10000

(The --kgpath, --outputdir, and --numwalks flags are typical of the script; if they differ, the script’s argparse block in generateqa.py will reveal the exact names.)

The command produces a directory of JSONL files containing question‑answer pairs and associated reasoning traces. The output can be uploaded to the Hugging Face hub (as done for the public DeepDive dataset).

Real‑World Use A research team building a browse‑enabled assistant can integrate the generated QA set into their supervised fine‑tuning (SFT) stage:

from datasets import loaddataset

Load the synthetic QA data produced by DeepDive qads = loaddataset("json", datafiles="data/qapairs/.jsonl")

Fine‑tune a transformer model on the dataset model = MyAgentModel.frompretrained("bert-base-uncased") trainer = Trainer( model=model, traindataset=qads["train"], args=TrainingArguments(outputdir="modelckpt") ) trainer.train()

The resulting model can then be plugged into a multi‑turn RL loop (not provided in this repo) for further policy optimization.
