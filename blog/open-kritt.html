The Problem

Security researchers and developers need to find code vulnerabilities at scale, but pointing a single model at an entire repository produces noisy, unverified results. open·kritt addresses this by breaking research into focused, parallelizable tasks, then de-duplicating and ranking findings with configurable validation. It is built for teams that need control over prompts, model providers, and workflow orchestration rather than opaque, black-box scanning.

What This Does

open·kritt is a self-hosted platform comprising a Node.js backend (73 files under backend/) and a React documentation/site frontend (56 files under docs-site/). The backend orchestrates agent workflows, manages scan state, and handles findings serialization. Core infrastructure includes Prisma ORM with 38 database migration files under database/init/, Docker Compose for local development (docker-compose.yml, docker-compose.dev.yml), and npm-managed dependencies (backend/package.json). Scans analyze remote or local repositories using model providers including Codex, Claude Code, OpenAI, Anthropic, and OpenRouter. Findings are enriched via post-scripts, ranked by custom severity rankers, and exported as ZIP archives with manifests through backend/src/lib/serialize.js. The workflow builder and step configuration live in backend/src/lib/defaultWorkflows.js and backend/src/lib/defaultSeverityRankers.js.

How To Use It

Setup: Clone the repository and run ./kritt setup to configure model access (Codex login or OpenAI/Anthropic/OpenRouter API keys). The .env.example at the root and backend/.env.example provide template configuration. A GITHUBTOKEN is optional for private repos.

Configuration: Required environment variables and API keys are defined in .env.example and backend/.env.example. The Prisma schema is at backend/prisma/schema.prisma with migrations in backend/prisma/migrate.js.

Running it: Start the full stack with ./kritt start (Docker Compose) or use the headless CLI with ./kritt-headless for server-only operation. The web UI runs at http://localhost:5173. Scans are created via the backend routes under backend/src/routes/ (scans, generations, vulnerabilities, workflows).

Real-World Use

A security team can define a workflow in JSON under backend/src/lib/defaultWorkflows.json, pointing at a private codebase via GITHUBTOKEN, and trigger a scan that parallelizes focused prompts across multiple agents. Post-scripts in backend/src/lib/defaultPostScripts.js validate findings, generate proofs-of-concept, and enrich the schema before export. Results including de-duplicated findings, severity rankings, and PoC source are packaged in a ZIP with a share-safe manifest—completed scans produce full exports, failed or stopped scans produce partial exports with clear markings.

Code Health & Issues

Tests: 23 test files exist under backend/test/ covering accounts, model providers, environment files, and scan pagination—CI is configured via .github/workflows/ci.yml and .github/workflows/release.yml. License: AGPL-3.0 is present in LICENSE; the repo includes CODEOFCONDUCT.md, CONTRIBUTING.md, and SECURITY.md. Dependency hygiene: backend/package-lock.json is committed, and Dependabot is configured via .github/dependabot.yml. Structural concerns: The separation between backend services, database migrations, and the docs-site is clear. No obvious unsafe patterns are visible in the file listing, but the AGPL-3.0 license requires derivative works to remain open source, which is a consideration for commercial adoption. Missing evidence: No runtime security scanning or secrets-detection configuration is apparent beyond the .env.example templates.

The Bottom Line

open·kritt is a well-structured, self-hosted vulnerability research platform that trades ease-of-use for control—researchers define workflows, choose models, and retain full ownership of findings and reports. The AGPL license, Docker-based deployment, and robust test/CI suite make it suitable for teams that can self-host and need custom prompt orchestration. It is less appropriate for users seeking a hosted, turnkey solution or those restricted by AGPL compliance requirements.

Pin third-party GitHub Actions to a commit SHAhigh
.github/workflows
googleapis/release-please-action@v5
A tag can be moved, so the action running with your token and secrets is whatever its owner last pushed; this is how tj-actions/changed-files leaked secrets from thousands of repos.
Fix: Replace each @vN with the 40-character commit SHA, keep # vN as a comment, and let Dependabot bump the SHAs.
Commit a lockfile beside the manifesthigh
docs-site/package.json
manifest with no lockfile in scope
An unlocked range means the artifact you tested and the artifact you ship can contain different transitive code, so a malicious patch release reaches production with no diff.
Fix: Run the package manager once and commit the generated lockfile.
Drop privileged mode and host networkinghigh
docker-compose.yml
the docker socket mounted
privileged hands the container every capability including direct device access, which makes escaping to the host a documented one-liner, and host networking removes the network boundary so every port the container opens is open on the host.
Fix: Grant the specific capability the workload needs with cap_add, and publish ports explicitly.
Replace the wildcard CORS origin with an explicit allow listhigh
backend/src/app.js
origin: '*'
Any page on the internet can call the API with the browser's cookies attached, so a logged-in visitor to an unrelated site performs authenticated requests without knowing, and the wildcard combined with credentials is the exact configuration browsers refuse for that reason.
Fix: List the origins the API actually serves, and never pair a wildcard with credentials.
Use bound parameters instead of building the SQL stringhigh
executor-view/server.py
.execute() with an interpolated query
A value spliced into SQL is read as syntax, so one quote in a name ends the literal and everything after it is executed as the query, which is how a search box becomes a table drop.
Fix: Pass placeholders and hand the values to the driver as parameters.
Pin the container base image by digestmedium
backend/Dockerfile
node:24.1.0-alpine3.20
An untagged or mutable base means today's build and last month's contain different libc and a different CVE set, with no record of which shipped.
Fix: Use image:tag@sha256:<digest> and enable Dependabot's docker ecosystem.
Gate pull requests on a dependency vulnerability scanmedium
.github/workflows
no dependency scan in CI
This is the one gate that would catch a known-vulnerable package before it reaches a build, and no repository in the sample had it.
Fix: Add dependency-review-action on pull_request, or osv-scanner on push and a schedule.
Give the outbound request a timeoutmedium6 occurrences
executor-view/server.py
5 outbound call(s) with no timeout
requests has no default timeout, so a peer that accepts the connection and then says nothing holds the worker forever, and with a small worker pool a single slow dependency takes the whole service down without anything appearing to fail.
Fix: Pass timeout= on every call, or use a session with one configured.
Set persist-credentials: false on checkoutmedium
.github/workflows/ci.yml
checkout keeps the token, then dependencies are installed
The token stays in .git/config for every later step, so a malicious postinstall script reads a pushable credential without one ever being passed to it.
Fix: Add with: persist-credentials: false, and pass an explicit token only to the step that pushes.
Add a non-root USER to the imagemedium
backend/Dockerfile
CMD or ENTRYPOINT with no USER directive
A process running as root in the container is root against every mounted volume, and it turns any container escape or writable-mount mistake from a contained problem into a host one.
Fix: Create an unprivileged user, chown what it needs, and end the Dockerfile with USER.
Set timeout-minutes on the workflow jobslow2 occurrences
.github/workflows/ci.yml
2 workflow(s) declare no job timeout
A wedged step runs to the six-hour platform default, which on a two-hourly schedule means three runs overlap behind it.
Fix: Add timeout-minutes with a realistic bound to each job.
