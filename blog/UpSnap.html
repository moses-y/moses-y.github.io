UpSnap

A simple wake on lan web app written with SvelteKit, Go and PocketBase.

The Problem

Managing Wake-on-LAN (WoL) for multiple machines typically requires either command-line tools, dedicated hardware, or manual ARP table lookups. Teams managing fleets of headless or remote servers need a centralized, web-accessible way to wake, ping, and optionally shut down machines without SSH access to each one.

What This Does

UpSnap is a self-hosted web application that provides a dashboard for Wake-on-LAN operations. The backend/ directory contains a Go server built on PocketBase, handling device CRUD, scheduled wake events via cron (backend/cronjobs/cronjobs.go), and network scanning (backend/pb/handlerscanlinux.go). The frontend/ directory is a SvelteKit application with 23 translation files (frontend/translations/) and 35 themes.

The app supports manual device entry, network scanning (nmap required on the host), port-based ping checks (backend/networking/ping.go), and custom shutdown commands (backend/networking/shutdown.go). Authentication and user management are built into PocketBase. Deployment is via Docker with multi-arch images (amd64, arm64, arm/v7, arm/v6) or a standalone binary.

Real-World Use

A small IT team managing 50 remote servers across three sites can run UpSnap in Docker with docker run --network=host seriousm4x/upsnap:latest. The network scan discovers devices by subnet, and cron jobs can wake machines before business hours. The team grants read-only access to junior staff and admin rights to senior engineers via the user management panel.

Code Health & Issues

High - Secrets committed: frontend/.env contains environment variables that are likely API keys or database credentials. This file should be in .gitignore and removed from history. Med - No CI for frontend: The go-test.yml workflow only runs Go backend tests. There are no Svelte/TypeScript lint or test steps in CI, despite 17 Svelte and 15 TypeScript files. Med - nmap dependency: Network scanning requires nmap installed on the host, which is not included in the Docker image. This will silently fail or require custom Dockerfiles. Low - Limited test coverage: Only 3 test files exist (magicpackettest.go, ping_test.go), covering networking utilities. No tests for cron jobs, handlers, or middleware. Low - Hardcoded port in Docker: The default port 8090 is not configurable via environment variable in docker-compose.yml; users must edit the compose file directly.

The Bottom Line

UpSnap is a well-structured, feature-complete WoL dashboard that solves a real operational need. The SvelteKit frontend is clean and the PocketBase backend provides solid auth and data management out of the box. It is best suited for small-to-medium teams comfortable with self-hosting and Docker. The main concerns are the committed secrets file and lack of frontend CI, both easily fixable.
