kimi k3 in c

A 2.78-trillion-parameter Kimi K3 running inference on a single CPU in 8.24 GB of RAM. Portable C99: no BLAS, no framework, no GPU.

Forked from FareedKhan-dev/kimi-k3-in-c

The Problem Running inference for a multi‑trillion‑parameter LLM typically requires GPUs, large RAM pools, or specialized frameworks. Organizations that need on‑device or low‑cost CPU‑only inference cannot deploy such models because they exceed memory limits or depend on unavailable libraries.

What This Does kimi-k3-in-c implements a 2.78 T‑parameter Kimi K3 inference engine entirely in portable C99. The core engine lives in include/k3/k3.h and include/k3/k3cfg.h, while the reference implementation and benchmarks are in src/ (built via CMakeLists.txt / Makefile). No BLAS, CUDA, or external runtime is required; the binary (bin/k3) streams the 1.56 TB checkpoint from disk and keeps a configurable “trunk” in RAM, achieving a peak RSS of 8.24 GB on a laptop.

The repository ships a full technical report (docs/kimi-k3-tech-report.pdf) and a large set of visualizations in docs/images/, showing the memory‑budgeting strategy, quantisation pipeline, and performance numbers. All measurements are reproducible from the data files under docs/data/.

How To Use It Clone and enter the repo git clone https://github.com/FareedKhan-dev/kimi-k3-in-c.git cd kimi-k3-in-c Build the binary (CMake or Make both work) mkdir -p build && cd build cmake .. -DCMAKEBUILDTYPE=Release cmake --build . -j$(nproc) # produces ./bin/k3 or simply: make -j$(nproc) Download a model checkpoint (script provided) ./scripts/download-model.sh # places model in $HOME/k3model by default Prepare a trunk directory (stores the resident part) mkdir -p $HOME/k3trunk Run a quick test (the repo includes a self‑test) ./scripts/k3-doctor.sh # validates build and basic inference Generate text (example from README) ./bin/k3 $HOME/k3model \ --trunk $HOME/k3trunk \ --preset laptop \ --tok $HOME/k3model \ --prompt "The capital of France is" \ --gen 8 --incremental

Key flags are documented in docs/QUICKSTART.md and docs/API.md. No environment variables are required; the binary reads configuration directly from command‑line arguments.

Real‑World Use A data‑center service that streams large LLM checkpoints to edge nodes can embed k3 to serve low‑latency, CPU‑only completions on commodity hardware. Example integration (pseudo‑code):

#include "k3/k3.h"

int main() { k3cfg cfg = k3cfgdefault(); cfg.trunkpath = "/var/k3trunk"; cfg.modelpath = "/var/k3model"; k3handle h = k3init(&cfg); const char out = k3generate(h, "Explain quantum tunneling", 64); printf("%s\n", out); k3free(h); }

The handle can be incorporated into any C or C++ service without linking to external libraries.

The Bottom Line kimi-k3-in-c delivers a functional, framework‑free CPU inference engine for a 2.78 T‑parameter model, proving that massive LLMs can run in <10 GB RAM when streamed from disk. It is well‑documented and builds cleanly, but the single‑CPU throughput is modest and test coverage is thin. It is suitable for research, proof‑of‑concept deployments, or edge services where GPU resources are unavailable and latency requirements are relaxed.
