Technical Briefing: dimos Repository

The Problem

The repository contains 22 modules in circular import dependencies, with dimos/msgs/sensor_msgs/__init__.py, dimos/msgs/geometry_msgs/__init__.py, and dimos/core/module.py mutually reachable. Additionally, 155 modules depend on dimos/msgs/sensor_msgs/__init__.py and 138 on dimos/msgs/geometry_msgs/__init__.py, creating high-blast-radius hubs where changes ripple broadly. Max indentation depth reaches 6 in dimos/core/module.py, making control flow hard to follow. These structural issues increase cognitive load and risk unintended breakage when modifying core message or module systems.

What This Does

dimos is a collection of 4 self-contained projects totaling 1244 files: the core dimos system (958 files, 857 code files), examples (21 files), docker (22 files), and bin (21 files). It functions as an agentive operating system for physical robotics, enabling Python-based control of humanoids, quadrupeds, and drones without requiring ROS. Core capabilities include navigation and mapping (SLAM, dynamic obstacle avoidance), perception (detectors, 3D projections, VLMs, audio processing), agentive control via natural language, and spatial memory (spatio-temporal RAG, object localization). The codebase integrates React, Svelte, Flask, FastAPI, Transformers, YOLO, and vector stores, with Python (828 files) as the dominant language.

How To Use It

Setup: Clone via git clone https://github.com/moses-y/dimos. The presence of pyproject.toml indicates pip-based installation; package.json files indicate npm dependencies for web components. No ROS is required per the README.

Configuration: Environment variables and keys are loaded from docker/navigation/.env.hardware (evidenced as a committed .env file). The API server at dimos/web/dimos_interface/api/server.py uses allow_origins=["*"] with credentials enabled — this configuration should be reviewed. dimos/web/command-center-extension/package.json, vite.config.ts, and tsconfig.json configure the web extension.

Running it: The entry point start in dimos/agents/agent.py:75 initiates the agent system. For manipulation, run in dimos/manipulation/control/coordinator_client.py:459 is the designated start function. The README documents additional hardware-specific setups.

Real-World Use

A robotics team needs to deploy a navigation stack across a fleet of heterogeneous robots. Using dimos, they write Python agents that subscribe to lidar streams (via dimos/msgs/sensor_msgs), integrate YOLO-based perception, and issue motor commands through the control loop. The agent's spatial memory module queries the timeseries database (dimos/memory/timeseries/base.py) for localization data. The system runs natively on target hardware without ROS infrastructure, and the multi-agent architecture allows coordinating multiple robots from a single natural language prompt.

Code Health & Issues

CODE HEALTH AUDIT — 9 findings (0 critical, 4 high, 4 medium, 1 low), ranked by severity, confidence and production reach:

  • [HIGH] Pin third-party GitHub Actions to a commit SHA — .github/workflows: docker/login-action@v3, crazy-max/ghaction-github-runtime@v3, docker/setup-buildx-action@v3, docker/build-push-action@v6. A tag can move, so the action running with your token and secrets is whatever its owner last pushed.
  • [HIGH] Drop privileged mode and host networking — docker/dev/docker-compose.yaml: network_mode: host. Privileged hands every capability including direct device access; host networking removes the network boundary.
  • [HIGH] Remove the committed .env and rotate what it holds — docker/navigation/.env.hardware. A tracked .env is the most common route for working keys to reach a public clone; the app actually loads this file.
  • [HIGH] Replace the wildcard CORS origin with an explicit allow list — dimos/web/dimos_interface/api/server.py: allow_origins=["*"] together with credentials enabled. Any page on the internet can call the API with the browser's cookies attached.
  • [MEDIUM] Enable Dependabot or Renovate — 4 manifest(s), no update bot configured. Without a bot a published advisory sits unpatched.
  • [MEDIUM] Pin the container base image by digest — dimos/manipulation/grasping/docker_context/Dockerfile: nvidia/cuda:12.8.1-cudnn-devel-ubuntu22.04. An untagged base means today's build and last month's contain different libc and a different CVE set.
  • [MEDIUM] Gate pull requests on a dependency vulnerability scan — .github/workflows: no dependency scan in CI.
  • [MEDIUM] Add a non-root USER to the image — dimos/manipulation/grasping/docker_context/Dockerfile: no USER directive. A process running as root in the container is root against every mounted volume.
  • [LOW] Set timeout-minutes on the workflow jobs — .github/workflows/_docker-build-template.yml: 4 workflow(s) declare no job timeout.

Additionally, MEASURED FINDINGS from static analysis: 338 total (95 high, 239 medium, 4 low) including import cycle members, broad exception handling, deep nesting, hub modules, and file opened without context manager.

The Bottom Line

The repository delivers a functional agentive OS for physical robotics with genuine multi-hardware support and a working Python-first workflow. However, the circular import structure and hub modules create significant maintainability risk — changes to dimos/msgs/sensor_msgs or dimos/core/module affect 155+ and 138+ dependent modules respectively. The SDLC gaps (pinned Action SHAs, privileged Docker mode, committed .env, wildcard CORS) are actionable and should be addressed before production deployment. Teams needing rapid prototyping across diverse robot platforms will find value here, but those requiring long-term maintainability should budget refactor time for the import cycle and hub consolidation.

docker/login-action@v3, crazy-max/ghaction-github-runtime@v3, docker/setup-buildx-action@v3, docker/build-push-action@v6
A tag can be moved, so the action running with your token and secrets is whatever its owner last pushed; this is how tj-actions/changed-files leaked secrets from thousands of repos.
Fix: Replace each @vN with the 40-character commit SHA, keep # vN as a comment, and let Dependabot bump the SHAs.
Drop privileged mode and host networkinghigh2 occurrences
docker/dev/docker-compose.yaml
network_mode: host
privileged hands the container every capability including direct device access, which makes escaping to the host a documented one-liner, and host networking removes the network boundary so every port the container opens is open on the host.
Fix: Grant the specific capability the workload needs with cap_add, and publish ports explicitly.

docker/navigation/.env.hardware
docker/navigation/.env.hardware
A tracked .env is the most common route for a working key to reach a public clone, and it is the file the app actually loads, so the value is usually live.
Fix: git rm --cached the file, add it to .gitignore, rotate every credential it names, commit a .env.example with empty values.
Replace the wildcard CORS origin with an explicit allow listhigh
dimos/web/dimos_interface/api/server.py
allow_origins=["*"] together with credentials enabled
Any page on the internet can call the API with the browser's cookies attached, so a logged-in visitor to an unrelated site performs authenticated requests without knowing, and the wildcard combined with credentials is the exact configuration browsers refuse for that reason.
Fix: List the origins the API actually serves, and never pair a wildcard with credentials.
