The Problem

Sim-to-real transfer for robot learning usually fails because simulators lack visual fidelity. Standard renderers produce synthetic-looking images, and physics engines struggle with contact-rich tasks at scale. Training vision-based policies requires both high-throughput rendering and physically consistent scenes—existing tools optimize for one at the expense of the other.

What This Does

GS-Playground is a photorealistic robot simulator that couples batch 3D Gaussian Splatting (3DGS) rendering with a parallel physics engine. It renders RGB and depth observations at reported rates up to 10^4 FPS at 640x480 resolution. The demo/livedemo/ folder contains a live replay system using Franka Panda and Robotiq 3DGS assets stored as .ply files per link. The benchmark/ directory includes a rendering throughput notebook (mtxbatchminimal.ipynb) and a Gaussian pruning script (scripts/prunegaussians.py).

The system binds 3DGS clusters to simulator rigid bodies, so robot motion stays visually synchronized across frames. Assets live under benchmark/assets/ and demo/livedemo/assets/, with MJCF-style XML scene files and per-link .ply and .obj meshes. The project is accepted at RSS 2026 and has a companion renderer library at GaussianRenderer.

Real-World Use

You would use this to train visual policies for contact-rich manipulation or locomotion at scale. The batch renderer replaces traditional mesh rasterization with 3DGS, so the agent sees realistic lighting, texture, and occlusion during training. The physics engine uses a velocity-impulse solver tuned for stable large-timestep simulation. The paper's experiments cover quadrupeds, humanoids, and arms—this repo provides the core API and benchmark suite.

Code Health & Issues

Medium - No tests detected across 200 files. There are zero test files in the repo. This means all physics and rendering code paths are untested in the public release. Integration issues are likely when adapting to new scenes or robot configurations. Medium - No CI/CD pipeline. No .github/ or CI config files exist. There is no automated build, lint, or test gate. Reproducibility of the benchmark results depends on manual environment setup. Low - Documentation is sparse. Only 3 doc files exist (README, READMECN, LICENSE). The README references external repos for the renderer, physics benchmarks, and LiDAR module, but the core API is not documented beyond the installation guide. Onboarding requires reading multiple external repositories. Low - Large binary asset duplication. The benchmark/ and demo/live_demo/ directories contain near-identical copies of 3DGS .ply files and mesh assets (~100 MB each). This inflates the repo and creates sync risk if assets are updated in one location but not the other.

The Bottom Line

GS-Playground is a serious research contribution—accepted at RSS 2026, with published throughput numbers and multi-embodiment experiments. The public repo is a preview: the core API and benchmarks work, but the Real2Sim pipeline, training scripts, and Hugging Face assets are not yet released. If you need a high-fidelity visual simulator for robot learning research and can tolerate a pre-release codebase with no tests and thin documentation, this is worth evaluating. It is not production-ready for deployment.
