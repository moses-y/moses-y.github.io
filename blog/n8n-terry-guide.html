n8n AI Agent (Terry) - Technical Briefing

Repository: n8n-terry-guide (fork of theNetworkChuck/n8n-terry-guide, 598 stars)

What This Does

This repository is a single README.md that documents how to build "Terry," an AI agent in n8n that monitors and fixes homelab services. The guide walks through five evolution stages - from a basic HTTP monitor to a human-in-the-loop agent that can diagnose and remediate issues across UniFi, Proxmox, NAS, and Plex.

The content is a companion to a video tutorial, not a standalone codebase. There is no source code, no workflow JSON exports, and no configuration files. The value is the system prompts and the architectural progression they demonstrate.

How To Use It

Setup: There is no build step. The guide assumes you already have n8n running and Docker installed.

Configuration: You need an OpenAI API key (or compatible LLM), a Telegram account for notifications, and optionally Twingate for secure remote access. The README references YOURSERVERIP as a placeholder throughout - you will replace this with your actual server address.

Running it: The core workflow is assembled manually in the n8n UI: Create a workflow with a Manual Trigger node Add an AI Agent node with GPT-4o-mini and Simple Memory Attach an HTTP Request tool named website tool Paste the provided system prompts, starting with Stage 1 and progressing through the stages

The README contains the exact system prompts for each stage, which is the primary asset. For example, Stage 1's prompt instructs Terry to check http://YOURSERVERIP:8090/ and verify the response contains <h1>NetworkChuck Coffee</h1>.

Real-World Use

This is a practical tutorial for homelab operators who want an AI agent to handle routine IT tasks. The staged progression is the key insight: start with a narrow monitoring task, expand to diagnostics, then to remediation with approval gates. The "God-Mode Prompt" section shows how to consolidate all capabilities into a single, more autonomous agent.

A concrete scenario: Terry checks a website every 5 minutes via a Schedule Trigger. If it fails, Stage 2 prompts have Terry run diagnostics via SSH or HTTP tools. Stage 3 adds fix actions (e.g., docker restart website) but only after human approval through Telegram. This is a workable pattern for production use, provided you trust the tool permissions you grant the agent.

Code Health & Issues

Low - No version pinning - The README references specific n8n features (AI Agent node, Simple Memory) without specifying n8n versions. These features are relatively new and may change.

The Bottom Line

This is a well-structured tutorial for n8n users who want to build an AI agent for homelab automation. The staged prompt design is genuinely good - it teaches a sane progression from monitoring to autonomous action. It is not a drop-in solution; you must manually build the workflow and adapt the prompts to your environment. If you follow NetworkChuck's video and want the prompts in text form, this is exactly what you need. If you are looking for a ready-to-import n8n workflow, this repo will not satisfy you.
