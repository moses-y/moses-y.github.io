The Problem

Machine‑learning researchers need a unified UI/API to explore model activations, steer generation, and run interpretability pipelines. Building such a stack from scratch requires wiring a Python inference service, a graph server, a React front‑end, and a set of utility scripts for data export – all while keeping the pieces testable and container‑ready.

What This Does

neuronpedia is a monorepo that bundles four self‑contained services:

  • apps/autointerp – FastAPI server that receives activation requests, calls a language model (model.generate) and returns scored explanations. Entry point: apps/autointerp/server.py.
  • apps/inference – Core inference API exposing endpoints for persona‑driven chat, SAE (Sparse Auto‑Encoder) handling, and batch activation export. Entry point: apps/inference/neuronpedia_inference/server.py.
  • apps/graph – Graph‑generation microservice that builds circuit visualisations and talks to external storage via HTTP (requests.put). Entry point: apps/graph/neuronpedia_graph/server.py.
  • apps/experiments/steerify – A Next.js + Tailwind front‑end (TSX) that demos steering UI; built with npm/next.

Common libraries live under packages/ (TypeScript inference client, Python web‑app client, autointerp client) and utils/ (batch‑autointerp, export‑data). Dockerfiles for each service and a Kubernetes manifest directory (k8s/) enable cloud deployment.

Typical request flow (e.g., an activation scoring call):

  1. HTTP request → FastAPI endpoint in apps/autointerp/neuronpedia_autointerp/routes/score/embedding.py.
  2. Calls call_api (called from 45 places) → internal helper response_deserialize (30 places) → model.generate (external model call, see “What this touches outside itself”).
  3. Result passes through to_json / to_dict (each called >50 times) before being returned.
  4. Shared utilities such as apps/inference/neuronpedia_inference/sae_manager.py:get_instance are invoked by 14 other files, making them high‑blast‑radius modules.

The most connected module is packages/typescript/neuronpedia-inference-client/src/models/index (45 inbound, 2 outbound imports, instability 0.96). Its volatility affects many TypeScript consumers. A circular import exists among apps/webapp/app/sae-bench/evals-table.tsx, evals-plot.tsx, and evals-table-presets.tsx, inflating coupling and risk of breakage.

All outbound effects are mapped:

  • Model inference – model.generate invoked from startup_event → preload_model and from async_handler → _generate_both_types.
  • Network – requests.put in apps/graph/runpod-gemma-2-2b/rp_handler.py:graph_generation_handler.
  • Filesystem – os.makedirs in apps/inference/neuronpedia_inference/server.py:main -> process_data.
  • Database – utils/neuronpedia-utils/export-data.py writes/reads SQLite (single call).

How To Use It

# Clone (use the exact URL from the spec)
git clone https://github.com/moses-y/neuronpedia
cd neuronpedia

# Install Python services (Poetry)
cd apps/autointerp
poetry install   # reads apps/autointerp/pyproject.toml
# Repeat for other Python apps (inference, graph) as needed

# Build and run a service with Docker (example: autointerp)
docker build -t neuronpedia-autointerp -f apps/autointerp/Dockerfile .
docker run -p 8000:8000 --env-file .env.inference.deepseek-r1-distill-llama-8b.llamascope-slimpj-res-32k neuronpedia-autointerp

# Front‑end dev (steerify)
cd apps/experiments/steerify
npm ci           # lockfile present
npm run dev      # starts Next.js on localhost

Required secrets are read from the .env.* files listed in the repo root (e.g., API keys for OpenAI). Copy the example .env.example files, fill in real values, and ensure the files stay ignored by Git.

Real‑World Use

A research team can spin up the inference service locally, point their Jupyter notebooks at http://localhost:8000/api/activation, and feed the results to the React dashboard (apps/experiments/steerify) for interactive steering. The same endpoints can be containerised and deployed via the provided Kubernetes manifests for production workloads.

Code Health & Issues

  • High – .env.inference.deepseek-r1-distill-llama-8b.llamascope-slimpj-res-32k tracked despite .gitignore. git rm --cached and rotate credentials.
  • High – GitHub Actions use mutable tags (snok/install-poetry@v1, softprops/action-gh-release@v1). Pin to SHA.
  • High – Committed .env files expose live secrets. Remove, add to .gitignore, rotate, and commit an .env.example.
  • High – Wildcard CORS (allow_origins=["*"]) in apps/inference/neuronpedia_inference/server.py. Replace with explicit origins.
  • Medium – No least‑privilege GITHUB_TOKEN permissions in .github/workflows/autointerp-tests.yml. Add permissions: contents: read.
  • Medium – No Dependabot/Renovate configuration. Add .github/dependabot.yml.
  • Medium – CI installs npm dependencies with npm install instead of npm ci. Switch to npm ci.
  • Medium – Base images in Dockerfiles are mutable tags (python:3.10-slim, CUDA). Pin by digest.
  • Medium – No dependency‑vulnerability scan in CI. Add dependency-review-action or osv-scanner.
  • Medium – No pre‑commit secret‑scan hook. Install a secret‑scanning hook (e.g., detect-secrets).
  • Low – (two additional low‑severity findings omitted for brevity; see full audit report).

Overall, the repository ships a functional, well‑tested stack with CI, Docker, and a rich test suite, but it contains several production‑readiness gaps around secret handling, CI reproducibility, and module coupling.

The Bottom Line

neuronpedia delivers a complete, container‑ready interpretability platform; its modular services and extensive test coverage are strengths. However, the high‑blast‑radius hub modules, circular imports, and security hygiene issues (exposed .env files, mutable CI actions) require remediation before a production deployment. Engineers comfortable with Python FastAPI, Next.js, and Docker will find the codebase approachable, but should address the listed high‑severity findings early.

Untrack the file your own .gitignore says to ignorehigh
.env.inference.deepseek-r1-distill-llama-8b.llamascope-slimpj-res-32k
tracked although .gitignore excludes it
The author already decided this file must never be committed, so its presence is an accident nobody noticed, which means the credentials in it are the ones actually in use.
Fix: git rm --cached the path and rotate; the ignore rule is already correct.
Pin third-party GitHub Actions to a commit SHAhigh2 occurrences
.github/workflows
snok/install-poetry@v1, softprops/action-gh-release@v1
A tag can be moved, so the action running with your token and secrets is whatever its owner last pushed; this is how tj-actions/changed-files leaked secrets from thousands of repos.
Fix: Replace each @vN with the 40-character commit SHA, keep # vN as a comment, and let Dependabot bump the SHAs.
Remove the committed .env and rotate what it holdshigh6 occurrences
.env.inference.deepseek-r1-distill-llama-8b.llamascope-slimpj-res-32k
.env.inference.deepseek-r1-distill-llama-8b.llamascope-slimpj-res-32k, .env.inference.gemma-2-2b-it.gemmascope-res-16k, .env.inference.gpt2-small.res-jb, .env.localhost
A tracked .env is the most common route for a working key to reach a public clone, and it is the file the app actually loads, so the value is usually live.
Fix: git rm --cached the file, add it to .gitignore, rotate every credential it names, commit a .env.example with empty values.
Replace the wildcard CORS origin with an explicit allow listhigh
apps/inference/neuronpedia_inference/server.py
allow_origins=["*"]
Any page on the internet can call the API with the browser's cookies attached, so a logged-in visitor to an unrelated site performs authenticated requests without knowing, and the wildcard combined with credentials is the exact configuration browsers refuse for that reason.
Fix: List the origins the API actually serves, and never pair a wildcard with credentials.
Declare least-privilege permissions for GITHUB_TOKENmedium3 occurrences
.github/workflows/autointerp-tests.yml
3 workflow(s) declare no permissions
With no declaration the token inherits the repository default, so any injected step can push commits or mint releases from inside your own CI.
Fix: Add permissions: contents: read at the top of the workflow and widen per job only where needed.
Enable Dependabot or Renovatemedium
18 manifest(s), no update bot configured
Without a bot a published advisory sits unpatched until someone audits by hand, which across 1,322 repositories means never.
Fix: Commit .github/dependabot.yml covering the repo ecosystems plus github-actions.
Install from the lockfile in CImedium
.github/workflows
npm install with a committed package-lock.json
A fresh resolution in CI means the tested dependency set is not the locked one, so the failure only appears after merge.
Fix: Use npm ci, yarn install --immutable, or pnpm install --frozen-lockfile.
Pin the container base image by digestmedium3 occurrences
apps/autointerp/Dockerfile
python:3.10-slim, nvidia/cuda:${CUDA_VERSION}-runtime-ubuntu${UBUNTU_VERSION}, base-${BUILD_TYPE:-nocuda}
An untagged or mutable base means today's build and last month's contain different libc and a different CVE set, with no record of which shipped.
Fix: Use image:tag@sha256:<digest> and enable Dependabot's docker ecosystem.
Gate pull requests on a dependency vulnerability scanmedium
.github/workflows
no dependency scan in CI
This is the one gate that would catch a known-vulnerable package before it reaches a build, and no repository in the sample had it.
Fix: Add dependency-review-action on pull_request, or osv-scanner on push and a schedule.
Add a pre-commit secret gatemedium
a secret-shaped file is tracked and no repo-level gate is visible
Without a gate the same class of leak recurs on the next commit, so a leak finding is the symptom and this is the cause.
Fix: Add a pre-commit hook scanning staged content, and enable push protection.
Give the outbound request a timeoutmedium
apps/graph/neuronpedia_graph/server.py
1 outbound call(s) with no timeout
requests has no default timeout, so a peer that accepts the connection and then says nothing holds the worker forever, and with a small worker pool a single slow dependency takes the whole service down without anything appearing to fail.
Fix: Pass timeout= on every call, or use a session with one configured.
Set persist-credentials: false on checkoutmedium
.github/workflows/webapp-vitest.yml
checkout keeps the token, then dependencies are installed
The token stays in .git/config for every later step, so a malicious postinstall script reads a pushable credential without one ever being passed to it.
Fix: Add with: persist-credentials: false, and pass an explicit token only to the step that pushes.
