The Problem

Frappe Insights was built to let non‑technical users create reports and dashboards without writing SQL, yet the underlying data‑access layer still requires knowledge of database schemas and join logic. Teams that already use the Frappe framework face a gap: extracting meaningful insights from existing apps typically means either learning SQL or building custom ETL pipelines, both of which slow down adoption.

What This Does

Insights provides a visual query builder (frontend/src2/query/Query.vue) that walks users through table selection, joins, filters, and calculations, generating Ibis‑composed SQL behind the scenes. The chart builder (frontend/src2/charts/ChartBuilder.vue) auto‑suggests appropriate visualisations (BarChart, DonutChart, etc.) and renders them with eCharts. Dashboards are assembled via a drag‑and‑drop layout (frontend/src2/dashboard/VueGridLayout.vue) and can include shared filters (frontend/src2/dashboard/DashboardFilter.vue). Data can be pulled from MySQL, PostgreSQL, DuckDB, or BigQuery; connections are configured through UI dialogs (frontend/src2/datasource/Connect*Dialog.vue) or via Docker‑compose (docker/docker-compose.yml) for self‑hosted deployments.

How To Use It

Setup: Run the provided easy‑install script to provision a production instance. wget https://frappe.io/easy-install.py python3 ./easy-install.py deploy \ --project=insightsprod_setup

The script pulls the Docker compose file (docker/docker-compose.yml) and starts the required services (frontend, database connectors). Configuration: No secret files are checked in. Environment variables for database credentials are supplied through the compose file or at runtime via the UI connection dialogs. Running it: After the containers are up, open frontend/index.html in a browser. The app boots via frontend/src2/main.ts, which initialises the Vue router and loads the home workbook list (frontend/src2/home/HomeWorkbookList.vue).

Real‑World Use

A marketing analyst at a mid‑size firm can connect Insights to the company’s PostgreSQL sales and inventory databases. Using the query builder, they join orders → customers → products, apply a date‑range filter, and calculate year‑over‑year growth. The resulting table is visualised with a BarChart (frontend/src2/charts/components/BarChart.vue) and placed on a dashboard (frontend/src2/dashboard/Dashboard.vue) that the executive team accesses via a shared link. No SQL is written; the analyst only drags fields and sets conditions.

Code Health & Issues

[Medium/SDLC] No LICENSE file – root directory lacks a license, so usage and redistribution rights are unclear. [Low/Risk] Dependencies declared without a lockfile – frontend/package.json lists npm packages but no package-lock.json or pnpm-lock.yaml, risking non‑reproducible builds. [Low/Risk] Sparse test coverage – only two test files are present; CI pipelines (frontend/.github/workflows/) run lint and build checks but lack unit or integration tests. [Medium] CI/CD maturity – GitHub Actions workflows exist (lint, frontend‑build, playwright) but no explicit security scanning or dependency‑audit steps are configured.

The Bottom Line

Insights delivers a low‑friction entry point for teams already invested in the Frappe ecosystem to add BI capabilities without SQL expertise. The Vue‑heavy frontend, Docker‑based deployment, and visual query builder are solid foundations. However, the absence of a license, lockfile, and meaningful test suite limits immediate adoption in regulated or mission‑critical environments. It is well‑suited for internal tooling, prototyping, or teams that can tolerate the current SDLC gaps while they establish proper licensing and dependency management.
