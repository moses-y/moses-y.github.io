The Problem

ML agents frequently need to reuse low‑level capabilities (e.g., “open a fridge”, “measure a temperature”) but each project rebuilds these skills from scratch. This duplication wastes engineering effort and makes it hard to assess safety or cost of a skill before deployment.

What This Does

SkillNet supplies an open‑source “skill marketplace” and a lightweight SDK for discovering, installing, authoring, evaluating, and composing those skills. The repository is organized around two main entry points:

examples/ – runnable notebooks and scripts (createexample.py, evaluateexample.py, searchdemo.py) that demonstrate the SDK workflow. experiments/src/skills/ – a library of concrete skill definitions (e.g., alfworld/alfworld-clean-object/SKILL.md, scienceworld/scienceworld-circuit-builder/SKILL.md). Each skill folder contains a SKILL.md manifest and optional reference documents that the SDK can parse.

The top‑level README.md shows the public API (SkillNetClient) and CLI (skillnet search …, skillnet download …). The package is published on PyPI as skillnet-ai, but the source code for that SDK is not bundled in this fork; it is pulled in via pip install skillnet-ai.

How To Use It

Setup

Install the published SDK pip install skillnet-ai # requires Python 3.10+

Install the experiment‑specific dependencies (optional, for running the demos) pip install -r experiments/requirements.txt

The requirements.txt lists openai, anthropic, tiktoken, etc., and is the only declared dependency source.

Configuration

No API key is needed for public search or GitHub downloads. For evaluation/orchestration, the SDK expects the standard OpenAI‑compatible environment variables (APIKEY, BASEURL, SKILLNETMODEL). These are referenced in the README but not hard‑coded anywhere in the repo.

Running It

Search and download a skill – via the SDK (shown in README.md):

from skillnetai import SkillNetClient

client = SkillNetClient() results = client.search("pdf understanding", limit=5) client.download(results[0].skillurl, targetdir="./myskills")

Run the provided demos – e.g., create a skill from a trace:

python examples/createexample.py

Evaluate a skill – e.g.:

python examples/evaluateexample.py

Explore the interactive notebooks – examples/skillnetusagedemo.ipynb and examples/scientificworkflowdemo.ipynb illustrate end‑to‑end pipelines.

If you need to run the AlfWorld or ScienceWorld experiments, invoke the scripts in experiments/:

python experiments/alfworldrun.py # AlfWorld demo python experiments/scienceworldrun.py # ScienceWorld demo

Real‑World Use

A data‑science platform can embed SkillNet to let analysts pull “CSV summarizer” or “PDF extractor” skills from the public library, evaluate them against internal safety policies, and compose them into a workflow. The platform would: Call SkillNetClient.search() for needed capabilities. Use client.download() to fetch the skill package into a sandboxed execution environment. Run client.evaluate(skillpath) to obtain a safety/completeness score. Dynamically generate a prompt that strings together the selected skills for a downstream LLM orchestrator.

Code Health & Issues

Medium – Missing CI/CD – No .github/ workflows, tox, or pytest CI configuration; automated testing is not enforced. Low – No lockfile – Dependencies are listed only in experiments/requirements.txt; reproducible builds require a requirements.lock or pip-tools output. Low – SDK source absent – The repo does not contain the skillnetai package code; users must rely on the PyPI distribution, limiting local debugging. Low – Sparse test coverage – Ten test files exist, but their locations are not obvious from the tree; no test runner configuration is present. Low – Documentation fragmentation – Skill manifests (SKILL.md) are plentiful but not programmatically linked; the SDK must parse free‑form markdown, increasing parsing brittleness.

No obvious security secrets are committed; the repository respects the MIT license.

The Bottom Line

SkillNet offers a concrete, community‑driven catalogue of reusable agent skills together with a thin Python SDK that can be integrated into larger LLM‑orchestrated systems. The demos and skill library are well‑structured, but the lack of an in‑repo SDK, CI pipeline, and dependency lockfile make it less suitable for production‑grade deployment without additional engineering effort. Teams that need a searchable skill marketplace and are comfortable adding their own CI and packaging layers will find it a solid foundation.
