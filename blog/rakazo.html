The Problem

Enterprises that want “AI teammates” must either rely on proprietary SaaS control planes or build a custom stack from scratch. Both options add cost, lock‑in, and operational overhead for managing sandboxed execution, model selection, and persistence.

What This Does

rakazo delivers a self‑hosted, modular platform that lets you run AI agents (bots) with a dedicated Linux desktop sandbox. The core services live under apps/:

API – apps/api/src/app.ts (Express/Hono) + Graphile Worker (apps/worker/src/index.ts). Web client – Vite‑powered React (apps/web/src/main.tsx, apps/web/src/App.tsx). Desktop client – Electron entry apps/desktop/src/main.ts. Mobile client – Expo app (apps/mobile/app/*/.tsx).

Infrastructure lives in infra/compose/ (Dockerfiles, docker‑compose.yml) and infra/sandboxes/ (Docker‑based computer sandbox and a supervisor service). The repository includes a static site (apps/www/) built with Astro.

Configuration defaults are defined in .env.example; the README walks through copying it to .env and setting secrets such as BETTERAUTHSECRET, ENCRYPTIONKEY, and an OpenRouter key.

How To Use It

Setup

From repo root cp .env.example .env # create runtime config pnpm install # install workspace deps (pnpm 9 required) pnpm db:generate # Prisma client generation pnpm db:migrate # apply migrations to local Postgres pnpm sandbox:build # build Docker‑based sandbox images pnpm dev # start API, worker, web UI, sandbox supervisor

The pnpm dev script (see package.json in the root) launches: API on :3100 (apps/api/src/index.ts) Graphile Worker (via apps/worker) Vite dev server on :5173 (apps/web) Sandbox supervisor on :7091 (infra/sandboxes/supervisor/src/index.ts)

Configuration

Edit .env to provide: BETTERAUTHSECRET – long random string for JWT signing. ENCRYPTIONKEY – AES key for server‑side encrypted storage. OPENROUTERAPIKEY (or rely on UI sign‑in flow). Optional COMPOSIOAPIKEY for plugin integration.

All services read these variables via apps/api/src/env.ts.

Running

Web UI: open <http://127.0.0.1:5173>. API health check: curl http://127.0.0.1:3100/health. Expected JSON includes "runtime":"pi", "sandbox":"docker".

Desktop and mobile clients are built with their respective package scripts (pnpm desktop, pnpm mobile – defined in each package.json).

Real‑World Use

A SaaS product can embed rakazo as an on‑premise “AI assistant” for each tenant. After provisioning a Postgres instance and a Docker host, the tenant runs the same pnpm dev (or a Docker‑Compose production variant in infra/compose/docker-compose.prod.yml). The tenant’s backend then calls the API (/api/v1/bots) to create bots, which run isolated Docker desktops, ensuring no cross‑tenant data leakage while still allowing the tenant to choose any LLM provider via the UI.

// Example: create a bot from a backend service await fetch(${API_URL}/bots, { method: 'POST', headers: { Authorization: Bearer ${token} }, body: JSON.stringify({ name: 'SalesBot', model: 'gpt-4o' }) });

Code Health & Issues

Low – Missing lockfile – apps/api/package.json (and other packages) have no pnpm-lock.yaml or package-lock.json; reproducible builds depend on the root lockfile only. Low – Test coverage gaps – Tests exist for core modules, but UI components (apps/web/src/pages/) lack unit tests. Medium – Secrets in docs – README references placeholder keys; no .env.example encryption, risk of accidental commit of real keys. Low – CI configuration – GitHub Actions (.github/workflows/.yml) run lint, typecheck, and Playwright e2e, indicating a functional CI pipeline. Low – License present – LICENSE file exists, compliance is clear. Low – Dependency hygiene – No automated Dependabot or Renovate config; security updates must be tracked manually.

Overall the repo builds cleanly, includes type‑checked TypeScript, and ships with end‑to‑end Playwright tests.

The Bottom Line

rakazo provides a complete, self‑hosted stack for AI agents with sandboxed desktop execution, making it suitable for organizations that need full control over data and runtime environments. The codebase is reasonably healthy—typed, tested, and CI‑enabled—but the lack of per‑package lockfiles and limited UI test coverage are modest risks. It is a good fit for teams comfortable with Docker and TypeScript who want an open‑source alternative to hosted AI‑agent platforms.
