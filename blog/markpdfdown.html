The Problem

Teams that need to extract editable, structured text from PDFs (e.g., research papers, reports, invoices) currently rely on OCR pipelines that produce noisy markdown or require manual cleanup. Inconsistent table and formula rendering adds further overhead.

What This Does

markpdfdown wraps a multimodal LLM (via LiteLLM) to transcribe PDF pages (or images) into clean Markdown. The core conversion flow lives in src/markpdfdown/core/llmclient.py, which sends image fragments to the model and assembles the response. CLI handling is in src/markpdfdown/cli.py; the entry‑point script src/markpdfdown/main.py forwards arguments to src/markpdfdown/main.py.

The repository ships a Dockerfile for containerised execution and a Makefile with typical targets (make install, make test). Configuration is driven by environment variables loaded from a .env file (sample in .env.sample).

How To Use It

Setup

Install uv (recommended) curl -LsSf https://astral.sh/uv/install.sh | sh

Clone and install in editable mode

git clone https://github.com/MarkPDFdown/markpdfdown.git cd markpdfdown uv sync # resolves dependencies from pyproject.toml, uses uv.lock uv pip install -e .

Alternatively, the Docker image can be built with docker build -t markpdfdown ..

Configuration

Create a .env file from the provided sample and supply at least the model name and an API key:

.env MODELNAME=gpt-4o OPENAIAPIKEY=sk-... optional TEMPERATURE=0.3 MAXTOKENS=8192 RETRYTIMES=3

The file is read by src/markpdfdown/config.py at runtime.

Running

CLI (file mode)

markpdfdown --input document.pdf --output document.md page range markpdfdown --input doc.pdf --output part.md --start 2 --end 5 image input markpdfdown --input diagram.png --output diagram.md

Pipe mode (useful in CI or Docker)

cat document.pdf | markpdfdown > document.md

Programmatic use

from markpdfdown.main import convert markdown = convert(inputpath="doc.pdf", start=1, end=3)

The commands above are defined in src/markpdfdown/cli.py and wired through src/markpdfdown/main.py.

Real‑World Use

A data‑processing pipeline for a market‑research firm can invoke the tool inside a Docker step: name: Extract markdown from PDF run: | docker run --rm -v $PWD:/work -e OPENAIAPIKEY=$OPENAIAPIKEY \ markpdfdown markpdfdown --input /work/report.pdf --output /work/report.md

The resulting report.md feeds directly into downstream NLP summarisation scripts without manual reformatting.

Code Health & Issues

Low – Missing lockfile for pip – pyproject.toml declares deps but no requirements.txt lock; however an uv.lock exists, mitigating reproducibility concerns. Medium – API key handling – src/markpdfdown/core/llmclient.py assumes environment variables are present; missing keys raise a generic KeyError instead of a user‑friendly message. Low – Limited input validation – CLI arguments for page numbers are passed directly to the PDF parser; negative or out‑of‑range values could cause uncaught exceptions. Low – Test coverage – 16 test files cover CLI, config, file worker, and LLM client, but integration tests that hit the actual LLM endpoint are absent (expected due to external API). Low – CI completeness – GitHub Actions run linting and tests, but no security scanning or dependency audit step is defined. Low – Documentation – README provides comprehensive usage examples; additional docstrings in core modules would improve discoverability.

Overall the repository follows a modular layout, includes a CI pipeline, and provides both source and container execution paths.

The Bottom Line

markpdfdown delivers a focused, LLM‑backed PDF‑to‑Markdown conversion with a usable CLI and Docker support. It is suitable for teams that already have access to supported LLM providers and need automated markdown extraction. Minor gaps around input validation and explicit dependency locking should be addressed before production deployment, but the codebase is otherwise clean and well‑tested.

requarks/changelog-action@v1, ncipollo/release-action@v1.12.0, stefanzweifel/git-auto-commit-action@v4, docker/setup-qemu-action@v3
