The Problem

Building and reproducing trading environments in TensorTrade is hampered by un‑pinned dependencies. The docs/requirements.txt file lists many of the packages the project relies on, but there is no lockfile (e.g., requirements.lock or Pipfile.lock) to guarantee identical dependency resolution across CI, local development, and production containers. This leads to non‑reproducible builds and subtle version‑drift bugs when the framework is installed on fresh machines or deployed to Docker hosts.

What This Does

TensorTrade is a composable reinforcement‑learning framework for trading agents. The core package lives in tensortrade/ and is split into six primary component families, each exposed as a Python module: Exchanges – simulated and live back‑ends reside under tensortrade/exchanges/. The simulated simulatedexchange.py provides a generic SimulatedExchange that can be seeded with market data, while live adapters such as ccxtexchange.py, robinhoodexchange.py, and interactivebrokersexchange.py wrap third‑party APIs. Feature pipelines – data transformation and technical indicators are defined in tensortrade/features/featurepipeline.py and tensortrade/features/indicators/. Example indicators include simplemovingaverage.py and talibindicator.py; scalers such as standardnormalizer.py and minmaxnormalizer.py normalize price streams. Action strategies – decide how an agent moves in the environment. discreteactionstrategy.py, continuousactionstrategy.py, and multidiscreteactionstrategy.py implement the ActionStrategy abstract base, letting users choose position sizing, order‑type selection, or multi‑dimensional control. Reward strategies – shape the learning signal. simpleprofitstrategy.py returns cumulative profit, while riskadjustedreturnstrategy.py incorporates Sharpe‑like metrics. Trading environment – glues the above together. tradingenvironment.py orchestrates step loops, state observation, and termination conditions. Strategies – high‑level wrappers that combine agents, environments, and training loops. stablebaselinesstrategy.py and tensorforcetradingstrategy.py integrate external RL libraries.

All modules follow a consistent API: each class inherits from a base defined in the corresponding init.py, and documentation is auto‑generated from docstrings into docs/source/api/.

How To Use It

Setup

Install the exact Python version required (>=3.6) and pull the unpinned requirements pip install -r requirements.txt

If you need the package in development mode (e.g., to edit source locally): pip install -e .

Docker

The project includes a Dockerfile at the repo root. Build and run: docker build -t tensortrade . docker run -it --rm tensortrade

The Docker image bundles the base dependencies; however, because no lockfile is committed, you may need to regenerate requirements.txt inside the container after pip install -r requirements.txt to lock versions.

Configuration

Live exchanges require API credentials. The live adapter files (ccxtexchange.py, robinhoodexchange.py, interactivebrokersexchange.py) read keys from environment variables named CCXTAPIKEY, ROBINHOODAPIKEY, and IBAPIKEY respectively. No secrets are stored in the repository; users must export these variables before invoking any live‑trading script.

Running it

The quickest way to explore the framework is through the Jupyter notebooks in examples/. For a minimal end‑to‑end run, open examples/TensorTradeTutorial.ipynb or execute the trainandevaluate.ipynb notebook, which demonstrates: Instantiating a SimulatedExchange with fake price data. Building a FeaturePipeline that appends a 20‑period SMA and normalizes the series. Wiring a DiscreteActionStrategy that selects hold, buy, or sell.
