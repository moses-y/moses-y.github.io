Ix

Understand any codebase instantly. System intelligence for codebases, built for humans and AI.

Forked from ix-infrastructure/Ix

The Problem

Modern codebases are too large for LLMs to reason about within context windows. Developers burn tokens re-reading files, searching symbols, and reconstructing architecture that an AI should already understand. The result is slow, expensive AI-assisted development and persistent context loss across sessions.

What This Does

Ix is a system intelligence layer for codebases. It ingests source code, builds a persistent structural map of symbols, dependencies, and roles, then exposes that map through a CLI (ix-cli/src/cli/main.ts) and an API (ix-cli/src/client/api.ts). The core-ingestion/ package handles parsing via tree-sitter queries (core-ingestion/src/queries.ts), chunking, and edge resolution (core-ingestion/src/resolve-edges.ts). The CLI exposes 40+ commands—overview, map, impact, trace, explain, search, rank—that let both humans and AI agents query the system without re-reading source files.

The architecture is deliberately split: a standalone ingestion engine (core-ingestion/) and a client-facing CLI (ix-cli/) that can run against a local or Dockerized backend (docker-compose.standalone.yml). The explain/ module (ix-cli/src/cli/explain/) adds semantic reasoning on top of the raw graph, inferring roles, importance, and subsystem meaning.

How To Use It

Setup — The repo is TypeScript with npm workspaces. Install dependencies and build with:

cd ix-cli && npm install && npm run build

The README documents a curl-based installer for Linux/macOS and a PowerShell equivalent for Windows. A Homebrew formula (Formula/ix.rb) exists for macOS users.

Configuration — GitHub integration (ix-cli/src/cli/github/auth.ts) requires a GitHub token for remote repository operations. No other environment variables are documented in the repo.

Running it — The CLI entry point is ix-cli/src/cli/main.ts. Initialize a project with ix init, then run ix ingest to build the index. From there, commands like ix map, ix explain, or ix impact operate on the ingested graph. A Docker backend is available via docker-compose.standalone.yml for persistent storage.

Real-World Use

A developer working on a large monorepo runs ix ingest once, then asks Claude or Codex to "explain the impact of changing Bar.ts". The agent queries Ix via the CLI or API instead of reading the entire codebase, receiving a focused answer with callers, dependencies, and risk assessment. The claimed result is 30-99.7% token reduction on development tasks.

Code Health & Issues Med - Alpha maturity - README badges mark status as "alpha". Core APIs may change without notice. Med - Single maintainer risk - CODEOWNERS and commit history suggest a small team. Bus factor is a concern for production adoption. Low - Test coverage is broad (76 test files) but concentrated in unit tests for parsing and CLI logic. Integration tests against a real backend are limited to resolveEdges.integration.test.ts. Low - The core-ingestion and ix-cli packages have separate package-lock.json files, suggesting they may drift in dependency versions. Watch for inconsistent behavior between them. Low - No documented rate limiting or caching strategy for the GitHub API integration (ix-cli/src/cli/github/fetch.ts), which could cause throttling issues at scale.

The Bottom Line

Ix is a serious attempt at solving the context-window problem for AI-assisted development. The architecture is sound—separating ingestion from querying is the right call—and the test coverage is better than most alpha-stage projects. The main risks are the alpha status and small team size. Teams heavily using Claude or Codex on large codebases should evaluate it; solo developers on small projects will find the setup overhead hard to justify.
