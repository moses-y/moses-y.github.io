dotlottie web

Official LottieFiles player for rendering Lottie and dotLottie animations in the web. Supports React, Vue, Svelte, SolidJS and Web Components.

Forked from LottieFiles/dotlottie-web

The Problem

Web developers embedding Lottie animations face a fragmented landscape: multiple renderers with inconsistent feature coverage, no unified way to handle .lottie archives (which bundle multiple animations, themes, and state machines), and performance limits when rendering many animations on the main thread. Existing players often require separate handling for JSON vs. archive formats and lack modern rendering backends.

What This Does

dotlottie-web is the official LottieFiles player for web. The core is Rust compiled to WASM via dotlottie-rs, using the ThorVG vector graphics engine. It renders both classic Lottie .json files and .lottie archives through a single DotLottie class, with three interchangeable rendering backends: Software (Canvas2D), WebGL2, and WebGPU.

The repo is structured as a monorepo with the core library plus first-party SDKs for React, Vue, Svelte, Solid, and Web Components. The apps/viewer/ directory contains a full-featured browser viewer (Vite + React + Tailwind) with pages for home, list, embed, performance testing (perf.tsx), and a playground with live code editing. examples/ holds framework-specific demos including Next.js SSR and Node.js usage.

Key features include off-main-thread rendering via DotLottieWorker with OffscreenCanvas, theming, slots, markers, segments, playback modes, and 25+ typed events. dotLottie v2 support covers state machines and audio.

How To Use It

Setup: Install the core package: npm install @lottiefiles/dotlottie-web. Framework-specific packages exist (@lottiefiles/dotlottie-react, etc.). The repo uses npm workspaces and pnpm; run pnpm install at root to build all packages.

Configuration: No environment variables or API keys required. The DotLottie constructor takes a canvas element and src URL or data. For WebGL2 or WebGPU, import from the respective subpath (e.g., @lottiefiles/dotlottie-web/webgl).

Running it: Create a canvas element and instantiate:

import { DotLottie } from '@lottiefiles/dotlottie-web';

const dotLottie = new DotLottie({ canvas: document.getElementById('canvas'), src: 'https://your-animation-url.lottie', autoplay: true, loop: true, });

For the viewer app, run pnpm dev inside apps/viewer/ (Vite config present). The Next.js example runs with standard pnpm dev in examples/next/.

Real-World Use

A marketing site with a hero animation, an interactive product configurator, and a loading screen. Use the React SDK for the hero (SSR-safe for Next.js), DotLottieWorker for the configurator to keep UI responsive with multiple animations, and the Web Component for CMS-embedded animations. All three can point at the same .lottie file—themes and state machines travel with the asset, eliminating per-integration wiring.

The Bottom Line

This is a production-grade animation player with real architectural depth—Rust/WASM core, three rendering backends, and first-party SDKs for every major framework. The lack of tests is the main concern for a library this complex. Teams already using LottieFiles or needing .lottie archive support should adopt it; teams on a single simple JSON animation may find the existing lottie-web sufficient.
