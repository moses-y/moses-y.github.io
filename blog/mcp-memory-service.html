The Problem AI agent pipelines operate without persistent shared memory, causing each run to start from zero. Decisions, causal knowledge, and context are lost between executions, forcing repetitive work across LangGraph, CrewAI, and AutoGen agents. This fragmentation increases API costs and creates siloed knowledge that no single agent can access.

What This Does mcp-memory-service provides a self-hosted persistent memory backend with a REST API and knowledge graph capability, accessible via MCP protocol. The service supports OAuth 2.0 with DCR (Documentary Concern Review) for authentication and integrates with Claude Desktop, claude.ai (browser), and various AI agent frameworks. Key components include the .claude/ directory with agents, commands, and directives configuration; claude-hooks/ containing 30 core hook files for auto-capture, session management, and memory retrieval; and GitHub Actions workflows across .github/workflows/ for CI/CD, deployment, and testing. The architecture uses Docker and supports Kubernetes deployment, with Litestream configurations in archive/litestream-configs-v6.3.0/ for database replication and persistence.

How To Use It Start server with Remote MCP enabled MCPSTREAMABLEHTTPMODE=1 \ MCPSSEHOST=0.0.0.0 \ MCPSSEPORT=8765 \ MCPOAUTHENABLED=true \ python -m mcpmemoryservice.server

Expose via Cloudflare Tunnel cloudflared tunnel --url http://localhost:8765

Configuration is managed through .env.example in the root directory, which documents required environment variables including MCPSTREAMABLEHTTPMODE, MCPSSEHOST, MCPSSEPORT, and MCPOAUTHENABLED. For production deployment, the Remote MCP Setup Guide (docs/remote-mcp-setup.md, referenced though removed from current structure) covers Let's Encrypt, nginx, and firewall configuration.

Real-World Use In a LangGraph workflow, after an agent makes a decision about refactoring a codebase, that decision is stored in the memory service's knowledge graph. On subsequent runs, any agent in the pipeline can retrieve the prior decision in approximately 5ms, avoiding redundant analysis. For example, an AutoGen team of three agents working on a code review task can share findings about common bugs, previously approved pull request patterns, and architectural constraints without re-querying external services or re-running identical analyses.
