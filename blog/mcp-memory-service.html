mcp memory service

Open-source persistent memory for AI agent pipelines (LangGraph, CrewAI, AutoGen) and Claude. REST API + knowledge graph + autonomous consolidation.

Forked from doobidoo/mcp-memory-service

The Problem

AI agents are stateless by default. Each run starts from zero, and any context gathered in a previous session is lost unless you build custom persistence. The typical workaround—gluing together Redis, a vector database, and hand-written retrieval code—adds operational overhead and couples you to a specific agent framework. Teams using multiple frameworks (LangGraph, CrewAI, AutoGen) end up maintaining separate memory solutions per stack.

What This Does

mcp-memory-service is a self-hosted memory backend that exposes a single service over multiple transports: REST API, MCP, OAuth, CLI, and a web dashboard. Agents store decisions and retrieve context from a shared causal knowledge graph, with retrieval documented at ~5ms. The service is framework-agnostic—any HTTP client can use it, and the MCP transport makes it a drop-in for Claude Desktop or claude.ai browser via Remote MCP.

The repo structure shows a mature project. The core server logic appears to be Python (mcpmemoryservice/server.py), with JavaScript-based Claude hooks in claude-hooks/core/ handling auto-capture, session-end harvesting, and mid-conversation memory retrieval. The .claude/ directory contains extensive agent definitions and directives for development workflows. The archive/ folder holds 84 files of historical docs and configs, suggesting active cleanup and consolidation over time.

How To Use It

Setup: The README documents a 5-minute setup for Remote MCP. Python is the primary runtime (PyPI package mcp-memory-service), so pip install mcp-memory-service is the expected path, though no pyproject.toml or requirements.txt appears in the root listing.

Configuration: Environment variables control behavior—MCPSTREAMABLEHTTPMODE, MCPSSEHOST, MCPSSEPORT, MCPOAUTHENABLED are documented in the README. The .env.example file exists for base configuration. OAuth 2.0 + DCR is supported for production auth.

Running it: The entry point is python -m mcpmemoryservice.server. For claude.ai browser integration, you need HTTPS exposure via Cloudflare Tunnel or equivalent:

MCPSTREAMABLEHTTPMODE=1 \ MCPSSEHOST=0.0.0.0 \ MCPSSEPORT=8765 \ MCPOAUTHENABLED=true \ python -m mcpmemoryservice.server

cloudflared tunnel --url http://localhost:8765

Real-World Use

A multi-agent system where a LangGraph workflow and a CrewAI crew share context. The LangGraph agent stores a decision about data pipeline configuration; a CrewAI agent running later retrieves that decision via the REST API and avoids re-deriving it. For Claude Desktop users, the claude-hooks/ directory provides session-start and session-end hooks that automatically capture conversation context into the knowledge graph without manual intervention.

Low - The archive/investigations/MACOSHOOKSINVESTIGATION.md and claude-hooks/WINDOWS-SESSIONSTART-BUG.md suggest cross-platform issues in the hooks layer that may still be open. Positive - Tests are present (25 test files), CI is configured via GitHub Actions, and the repo has a LICENSE, SECURITY.md, and CODEOFCONDUCT.md. No structural red flags.

The Bottom Line

This is a functional, well-documented memory service for teams running multiple agent frameworks and wanting a single persistence layer. The MCP transport and Claude hooks make it immediately useful for Claude users, and the REST API keeps it framework-agnostic. The heavy Claude-centric development workflow and documentation churn are minor concerns; the core service is solid and worth evaluating if you need shared, persistent agent memory.
