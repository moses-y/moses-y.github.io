Technical Briefing: clawdcursor

Overview

clawdcursor is a desktop automation server that gives AI agents eyes, hands, and ground-truth verification on Windows, macOS, and Linux. It wraps the desktop as 42 callable tools (mouse, keyboard, screen, windows, browser) that any function-calling AI model can use. The repository is model-agnostic and works with Claude, GPT, Gemini, Llama, or any compatible model, with free operation using local models.

Key metrics: 234 files total, 140 in src/, 163 code files analyzed. Primary language: TypeScript (145 files). Package manager: npm. CI: GitHub Actions.

Architecture & Entry Points

Execution starts from several entry points. The primary is run at src/pipeline/index.ts:104, which reaches 171 functions and is called by nothing else in the repo. Other entry points include:

The v2 architecture (--v2 flag) introduces a PlatformAdapter abstraction with platform-specific code in src/v2/platform/{macos,windows,linux}.ts, replacing 142+ scattered if (IS_MAC) branches across 34 files.

Projects & Hygiene

Three internal projects: src (140 files), scripts (25 files), perf (9 files). Repository hygiene: tests present, CI present, Dockerfile absent, license present, lockfile present, no committed secrets.

Setup & Running

Installation commands are provided via the project website (clawdcursor.com), with platform-specific setup scripts. Configuration requires environment variables for AI provider selection and API keys. First run auto-detects the AI provider from environment variables.

Bottom Line

This repository provides a functional desktop automation layer for AI agents with reasonable OS coverage and model agnosticism. The v2 architecture refactor addresses long-standing code quality issues around platform branching and cognitive load. However, the import cycles, duplicated code blocks, and absence of dependency vulnerability scanning in CI represent tangible risks for maintenance and security. Teams requiring stable, extensible desktop automation should evaluate the v2 path while accounting for the measured code health findings.

Declare least-privilege permissions for GITHUB_TOKENmedium
.github/workflows/cross-platform.yml
1 workflow(s) declare no permissions
With no declaration the token inherits the repository default, so any injected step can push commits or mint releases from inside your own CI.
Fix: Add permissions: contents: read at the top of the workflow and widen per job only where needed.
Enable Dependabot or Renovatemedium
1 manifest(s), no update bot configured
Without a bot a published advisory sits unpatched until someone audits by hand, which across 1,322 repositories means never.
Fix: Commit .github/dependabot.yml covering the repo ecosystems plus github-actions.
Gate pull requests on a dependency vulnerability scanmedium
.github/workflows
no dependency scan in CI
This is the one gate that would catch a known-vulnerable package before it reaches a build, and no repository in the sample had it.
Fix: Add dependency-review-action on pull_request, or osv-scanner on push and a schedule.
Set persist-credentials: false on checkoutmedium
.github/workflows/cross-platform.yml
checkout keeps the token, then dependencies are installed
The token stays in .git/config for every later step, so a malicious postinstall script reads a pushable credential without one ever being passed to it.
Fix: Add with: persist-credentials: false, and pass an explicit token only to the step that pushes.
Review the install lifecycle script and disable scripts in CImedium
package.json
postinstall
Install scripts are the execution vector for every npm compromise from event-stream onward, and a postinstall that fetches a binary makes the build depend on a URL nobody reviews.
Fix: Move the work into an explicit build step, or set ignore-scripts in CI and run it by name.
Set timeout-minutes on the workflow jobslow
.github/workflows/cross-platform.yml
1 workflow(s) declare no job timeout
A wedged step runs to the six-hour platform default, which on a two-hourly schedule means three runs overlap behind it.
Fix: Add timeout-minutes with a realistic bound to each job.
Add the repository convention files this project lackslow3 occurrences
missing .editorconfig, .gitattributes, a formatter config
Without them one contributor's editor writes tabs into a Python file, a shell script commits with CRLF and fails in the container, and a notebook diff is unreviewable.
Fix: Add .editorconfig, .gitattributes with text=auto eol=lf, and a formatter config.
