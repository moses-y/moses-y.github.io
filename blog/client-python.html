The official Python client library for the Massive.com REST and WebSocket API.

Forked from massive-com/client-python

The Problem Clients need a thin, Pythonic wrapper around Massive (formerly Polygon.io) REST and WebSocket endpoints that hides pagination, rate‑limit handling, and request construction. Manually building URLs, handling pagination loops, and keeping the base URL up‑to‑date after the rebrand creates boiler‑plate code and integration friction.

What This Does The massive package implements RESTClient and WebSocketClient classes that expose high‑level methods such as listaggs, getlasttrade, and listtrades. Core logic lives in massive/rest/ (base.py, aggs.py, economy.py, etc.) and massive/websocket/ (generated from .massive/websocket.json). Example scripts in examples/rest/ and examples/websocket/ demonstrate each endpoint.

massive/init.py exports the public client classes. massive/rest/base.py handles HTTP session setup, pagination toggling, and error mapping. examples/tools/docker/app.py shows a minimal Flask‑based container that can run a client script inside Docker, useful for CI or isolated execution.

How To Use It

Setup Install the published package (includes compiled source) pip install -U massive # requires Python >=3.9

If you want to work from source, install the development requirements: python -m venv .venv source .venv/bin/activate pip install -r docs/requirements.txt # note: no lockfile, see issues section

Configuration API key – required for every client. Provide it as the apikey argument or via the MASSIVEAPIKEY environment variable (the client reads os.getenv('MASSIVEAPIKEY') in massive/rest/base.py). Base URL – defaults to https://api.massive.com; you can override with baseurl= when constructing the client if you still need the legacy api.polygon.io.

Running it Typical usage is a short script that imports the client:

examples/rest/simple-get.py from massive import RESTClient

client = RESTClient() # picks up API key from env for agg in client.listaggs(ticker="AAPL", multiplier=1, timespan="minute", from="2023-01-01", to="2023-01-02"): print(agg)

Execute the script directly:

python examples/rest/simple-get.py

For a containerised run, build and start the Docker helper:

docker build -t massive-demo examples/tools/docker docker run -e MASSIVEAPIKEY=YOURKEY massive-demo

The Dockerfile (examples/tools/docker/Dockerfile) installs the package and runs app.py, which contains a minimal Flask endpoint that can trigger any client call.

Real‑World Use A data‑engineering pipeline can pull daily aggregates for a watchlist and store them in a data lake:

from massive import RESTClient import json, datetime, pathlib

client = RESTClient() today = datetime.date.today().isoformat() watchlist = ["AAPL", "MSFT", "TSLA"]

for sym in watchlist: aggs = list(client.listaggs(ticker=sym, multiplier=1, timespan="day", from=today, to=today)) pathlib.Path(f"data/{sym}{today}.json").write_text(json.dumps(aggs))

Schedule the script via Airflow or a cron job; the built‑in pagination will retrieve the full day's data in a single call per symbol.

Code Health & Issues Low – Missing lockfile – docs/requirements.txt lists development dependencies without a requirements.lock or pipfile.lock; reproducible builds are not guaranteed. Medium – Sparse test coverage – Only one test file is present; core REST logic (massive/rest/base.py, aggs.py) lacks unit tests, raising confidence gaps for edge‑case handling. Low – No explicit packaging config – The repo does not contain setup.py, pyproject.toml, or requirements.txt for the library itself; installation relies on the published PyPI wheel. This is acceptable for consumption but limits local development. Low – CI configuration – GitHub Actions workflows (.github/workflows/.yml) run linting, code‑QL, and a single test job, indicating basic CI hygiene. Low – Documentation – 27 ReST/Markdown files cover each endpoint; the docs are generated from the source and kept up‑to‑date, but there is no versioned API reference.

Overall, the codebase follows a clear separation (client vs. examples) and includes practical Docker tooling, but it would benefit from a lockfile, expanded test suite, and an explicit local packaging manifest.

The Bottom Line massive delivers a straightforward, well‑documented Python wrapper for Massive’s market data APIs, handling pagination and base‑URL changes out of the box. It is ready for production use where rapid data retrieval is needed, provided you accept the limited internal test coverage and add a lockfile for reproducible development builds. Ideal for teams that want a thin client without building their own HTTP layer.
