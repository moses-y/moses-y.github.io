Overview

fable-method distills the working approach of Claude Fable 5 into three composable skills: fable-method (think), fable-loop (act), and fable-judge (prove). The repo includes an adversarial eval suite that runs agents against 8 trap scenarios and logs failures honestly. It is a methodology repository, not a software library – the value is in the instruction files and the evidence of their effect.

What It Does

The skills define a strict sequence: classify the ask, define done with a named verification, gather evidence from primary sources in parallel, commit to one recommendation, make the smallest correct edit, verify by observation, report outcome first with caveats. The eval cases (e.g. eval/cases/s2-surprise-trap.md) are concrete failure modes the method is designed to catch. The results table in the README shows that applying the method improves Haiku and Sonnet on authority conflicts and fraud detection, while having no lift on trivial tasks – that null result is reported transparently.

Real-World Use

A practical scenario: an unattended agent receives a request to "fix the pricing bug." Without the method, it might silently correct a test that is actually correct, because the test appears wrong. With the method, it must first classify the ask, define done (e.g. "verify that pricing.py and testpricing.py agree on the discount formula"), gather evidence by executing both files, then commit to one action. The eval scenario s2-surprise-trap tests exactly this.

Code Health & Issues

The repo is structurally clean: CI configured (.github/workflows/checks.yml), license present, lockfile absent but not needed for a Markdown‑heavy project. The 5 test files are part of the eval scenarios (e.g. testpricing.py), not unit tests for the repo itself – that is appropriate for a methodology project. No secrets or config files leaked. The only risk is that the instructions are model‑specific; the eval results may not transfer to models that cannot follow multi‑step instructions reliably.

The Bottom Line

A well‑documented, empirically grounded instruction set for making weaker models more reliable on tricky tasks. The honest reporting of null results and the adversarial eval design make it credible. Best suited for teams running unattended agents on code‑or‑data problems where authority conflicts or false completion claims are common. Not useful for simple, single‑file tasks.
