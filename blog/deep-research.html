The Problem

The ability to break down complex questions into manageable sub-questions is a significant challenge in research and decision-making. This process can be time-consuming and may not always lead to comprehensive answers.

What This Does

The deep-research repository provides a solution to this problem by utilizing recursive Claude agents that spawn sub-agents to explore questions in a fractal manner. The src/deepresearch/cli.py file serves as the entry point for the application, and the recipes folder contains various examples of how to use the tool. The src/deepresearch/core directory contains the core functionality, including the graph.py and node.py files, which handle the recursive exploration of questions.

Real-World Use

For example, a user can run the command deep-research research -d 1 -m haiku -r haiku "A small question" to start exploring a question using the Haiku model. The tool will then break down the question into sub-questions and spawn child agents to explore each sub-question in parallel.

Code Health & Issues

Low - Missing dependency lockfile - pyproject.toml: The repository does not include a lockfile, which can lead to non-reproducible builds. Low - Limited input validation - src/deepresearch/validation.py: The validation module does not cover all possible input scenarios, which may lead to errors or unexpected behavior. Medium - Potential for unbounded fan-out - src/deepresearch/core/operations/decompose.py: The recursive nature of the tool can lead to an unbounded number of sub-questions and child agents, potentially causing performance issues or excessive costs.

The Bottom Line

The deep-research repository provides a unique solution for breaking down complex questions into manageable sub-questions. While the codebase is generally well-structured, there are some areas that require attention, such as the missing dependency lockfile and limited input validation. Overall, this tool is suitable for users who need to explore complex questions in a fractal manner, but may require additional configuration and monitoring to avoid potential issues.

With no declaration the token inherits the repository default, so any injected step can push commits or mint releases from inside your own CI.
Fix: Add permissions: contents: read at the top of the workflow and widen per job only where needed.
