sonarqube cli

Command-line interface for SonarQube with AI agent integration. Scan for secrets and get fast feedback on code quality and security from your terminal.

Forked from SonarSource/sonarqube-cli

The Problem Developers need immediate feedback on code‑quality and security issues before they reach CI/CD or production. Traditional SonarQube usage requires a server round‑trip and manual UI checks, which slows the edit‑compile‑test loop and makes it easy to miss hard‑coded secrets that could be sent to LLMs.

What This Does sonarqube-cli is a TypeScript‑based command‑line tool that talks to a SonarQube server and returns issue data as JSON for easy scripting. Secret detection lives in src/commands/analyze/secrets.ts and the Git‑hook helpers src/commands/hook/git-pre-commit-secrets.ts / git-pre-push-secrets.ts. The core analysis flow starts at src/commands/analyze/analyze-all.ts, which orchestrates the SQA‑API client (src/commands/analyze/sqaa‑.ts) and the dependency‑risk helpers under src/commands/analyze/dependency‑risk‑helpers/. Agent integration points (Claude, Copilot, Codex, Cursor, Antigravity) are implemented as hook modules in src/commands/hook/ and are wired through the integrate command tree (src/commands/integrate/common/).

How To Use It

Setup The project uses Bun as the package manager (see bun.lock and bunfig.toml). Install dependencies with:

bun install # creates nodemodules and resolves the lockfile

If you prefer npm/pnpm, the package.json also defines a standard dependencies block, but the lockfile is Bun‑specific.

Build (optional) The CLI is distributed as a compiled binary for faster start‑up. Build it with the provided script:

bun run build-binary # defined in build-scripts/build-binary.ts

The output is placed in dist/ and referenced by the bin field in package.json (e.g. sonar).

Configuration SonarQube host – SONARHOSTURL environment variable. Authentication token – SONARTOKEN environment variable (used by src/commands/analyze/sqaa-auth.ts). Telemetry opt‑out – see src/commands/config/telemetry.ts for the SONARTELEMETRY flag.

No additional config files are required; the CLI reads the environment at runtime.

Running it The primary entry point is the sonar binary (installed via bun install or after a successful build). Typical commands, taken directly from the README, are:

List issues for a project sonar list issues --project my-app

Run a local analysis on a file or directory sonar analyze --file src/index.ts

Scan for secrets only sonar analyze secrets --path .

Enable Claude integration (agentic use) sonar integrate claude -g

All commands emit machine‑readable JSON unless --format=text is supplied, making them script‑friendly.

Real‑World Use A CI step that blocks PRs if new secrets are introduced:

.github/workflows/secret‑scan.yml jobs: secret-scan: runs-on: ubuntu-latest steps: uses: actions/checkout@v3 name: Install CLI run: bun install && bun run build-binary name: Scan for secrets env: SONARHOSTURL: ${{ secrets.SONARHOSTURL }} SONARTOKEN: ${{ secrets.SONARTOKEN }} run: | ./dist/sonar analyze secrets --path . \ | jq -e '.secrets | length == 0' \ || (echo "Secrets found – aborting" && exit 1)

The hook files (git-pre-commit-secrets.ts, git-pre-push-secrets.ts) enable the same protection locally without CI.

Code Health & Issues High – Possible secrets in source – src/commands/analyze/secrets.ts and hook scripts contain placeholder patterns; verify that no real credentials are committed. Medium – Untested code paths – The repository lacks a test/ directory and no test scripts appear in package.json; critical logic (e.g., sqaa‑api.ts and secret guards) runs without unit coverage. Low – Missing lockfile for npm – A lockfile exists for Bun (bun.lock), but no package-lock.json or pnpm-lock.yaml. If users install via npm, reproducibility may suffer. Low – Limited lint/format enforcement – ESLint config (eslint.config.js) is present, but there is no CI step that fails the build on lint errors; only a GitHub Action build.yml is defined. Low – Documentation alignment – The README references sonar integrate claude -g, which maps to src/commands/integrate/_common/agent‑integrate‑prelude.ts; the command works, but the docs do not list all available integrations (e.g., Copilot, Cursor).

Overall, the codebase follows a clean modular layout, with clear separation between API client, analysis helpers, and hook integration. TypeScript typing is used throughout, and the CI pipeline builds the binary on every push.

The Bottom Line sonarqube-cli delivers fast, terminal‑based SonarQube analysis and built‑in secret protection, making it valuable for developers who need immediate feedback or want to embed quality gates in Git hooks. The project is well‑structured but currently lacks automated tests and explicit npm lockfile support; those gaps should be addressed before adopting it in high‑risk production environments.
