The Problem

Project knowledge lives across wikis, comments, and people's heads. Every new agent session re-discovers context from scratch. Teams lack a structured, versioned, portable format for the curated knowledge that sits next to code — architecture decisions, runbooks, dataset schemas, and metrics definitions.

What This Does

okf-skills is a Claude Code plugin and agent skill set that teaches coding agents to author, validate, and visualize Open Knowledge Format (OKF) bundles. OKF is a directory of markdown files with YAML frontmatter — no schema registry, no runtime, just files in git. The repo ships three skills under skills/: okf (bundle initialization via okfinit.py), validate (conformance checking via okfvalidate.py), and visualize (self-contained graph rendering via okfvisualize.py). The .okf/ directory documents the toolkit's own architecture and decisions, and CI validates that bundle on every push (.github/workflows/ci.yml). A live demo at docs/index.html renders a real OKF bundle as an interactive graph with provenance edges and trust tiers.

Real-World Use

A team maintains an OKF bundle at examples/sample-bundle/ containing service docs, runbooks, decisions, and metrics alongside their code. An engineer asks Claude to "add a runbook for payment failures." Claude reads the existing runbooks/payment-failures.md template, creates a new entry with correct frontmatter, and validates it with okfvalidate.py. The bundle stays consistent across PRs because CI runs the same validator. When a new agent joins the session later, it reads the index.md and log.md to reconstruct context — no wiki export needed.

Code Health & Issues

The codebase is structurally clean. Tests exist (tests/testokfvalidate.py), CI is configured, and a license is present. No red flags in dependency hygiene or configuration. Low — No tests for okfinit.py or okfvisualize.py. Only the validator has a test file. The init and visualization scripts are untested against edge cases (malformed paths, missing directories, empty bundles). Low — The benchmark (benchmark/) reports mixed results: "ground-truth claims hit" is incomplete in the README excerpt. The actual methodology and failure mode ("the bit that went wrong") need review before relying on the numbers. Low — No input sanitization visible in the Python scripts. okf_validate.py reads arbitrary markdown files; a malicious bundle with pathological frontmatter could cause unexpected behavior.

The Bottom Line

This is a well-scoped, pragmatic toolkit for teams that want structured, versioned knowledge alongside code. It is not a knowledge base replacement — it complements CLAUDE.md and wikis by giving agents a machine-readable, diffable knowledge graph. Best suited for teams already using Claude Code or similar agent tools; overkill for solo projects or teams without CI discipline. The benchmark claims need independent verification, but the core idea is sound and the implementation is honest.
