The Problem

Websites disappear, change, or get taken down daily. Legal evidence, research materials, and personal bookmarks that exist only as live URLs are fragile. Standard browser bookmarks offer no offline copy, and commercial archiving services control your data and limit what you can save.

What This Does

ArchiveBox is a self-hosted Django application that downloads complete copies of web pages in multiple formats: HTML, PDF, screenshots (PNG), WARC, and plain text. The core logic lives in archivebox/core/models.py and archivebox/core/views.py, with CLI commands in archivebox/cli/archiveboxadd.py and archivebox/cli/archiveboxschedule.py. Data is stored in SQLite with Django ORM models for Snapshot, ArchiveResult, and Crawl objects.

The project provides a REST API (archivebox/api/v1_core.py), a web UI (archivebox/core/urls.py), CLI tools, and Docker deployment (Dockerfile, Dockerfile.multistage). It accepts URLs from browser history exports, bookmark services like Pocket/Pinboard, RSS feeds, and browser extensions.

Code Health & Issues

The codebase is well-structured and maintained. Evidence of good practices: CI workflows in .github/workflows/test.yml and .github/workflows/lint.yml, dependabot config, pre-commit hooks, and 48 database migrations showing active schema evolution. Low - No dedicated test suite visible beyond 2 test files. The archivebox/core and archivebox/api directories lack tests/ subdirectories. This is a risk for a data-preservation tool. Low - archivebox/core/settings.py and archivebox/config/ contain configuration logic that mixes Django settings with application config. Separation of concerns is weak here. Med - The migration history (archivebox/core/migrations/0040 through 0048) shows many schema changes for ArchiveResult and Snapshot models. This suggests the data model is still evolving, which could mean breaking changes for existing archives.

The Bottom Line

ArchiveBox is a mature, practical tool for anyone who needs to preserve web content under their own control. The Django codebase is well-organized and actively maintained, but the sparse test coverage and still-evolving data model warrant caution for production deployments handling critical data. Best suited for teams that can absorb occasional schema migrations and run their own backups.
