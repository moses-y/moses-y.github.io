Abstract

High-performance wait-free memory reclamation for wait-free data structures (ASMR). Bounded memory usage, predictable latency.

Forked from vertexclique/kovan

The Problem

Kovan addresses the fundamental synchronization problem in wait-free programming: safely reclaiming memory when multiple threads access shared data without locks. In lock-free types, a drop() or free() can invalidate a pointer another thread still holds. Without tracking in-progress accesses, reclamation risks use-after-free bugs. Kovan provides a mechanism to determine when retired memory is safe to reclaim, offering bounded memory usage and predictable latency near read-only overhead.

What This Does

Kovan is a portfolio of 6 self-contained Rust crates, all built around the same memory-reclamation core. The root crate (kovan) defines the Atom<T> API and low-level pin()/load()/retire() protocol. Five ecosystem crates embed it: kovan-channel provides multi-producermulti-consumer channels (kovan-channel/src/lib.rs), kovan-map implements concurrent hash maps (kovan-map/src/hashmap.rs, kovan-map/src/hopscotch.rs), kovan-mvcc delivers Percolator-style MVCC (kovan-mvcc/src/percolator.rs, kovan-mvcc/src/storage.rs), kovan-queue offers queue primitives and a disruptor (kovan-queue/src/disruptor.rs, kovan-queue/src/array_queue.rs), and kovan-stm implements TL2-style software transactional memory (kovan-stm/src/lib.rs). The README documents Atom<T> as the simplest entry point and a low-level pin()/load()/retire() API for types embedding RetiredNode. Performance comparisons against epoch-based, hyaline, and hazard-pointer schemes show kovan’s pin + drop at 2.79 ns versus 13.66–18.09 ns for alternatives.

How To Use It

Setup: Add the crate to Cargo.toml:

[dependencies]
kovan = "0.1"

For the full ecosystem, add kovan-channel, kovan-map, kovan-mvcc, kovan-queue, or kovan-stm as separate dependencies. The root Cargo.toml and each crate’s Cargo.toml are present; no global config beyond standard Rust tooling is required.

Configuration: No environment variables or secret keys are documented. The repo has a .cargo/config.toml and Cargo.lock; build is cargo build / cargo test from the root or any crate directory.

Running it: The README’s quick-start example uses Atom::new:

use kovan::Atom;
let shared = Atom::new(42_u64);
let guard = shared.load();
println!("Value: {}", *guard);
drop(guard);
let old = shared.swap(100_u64);

For low-level control, the pin()/load()/retire() API requires types with RetiredNode as the first field, as shown in the README’s examples/ section.

Real-World Use

A telemetry pipeline buffering inbound packets across threads could use kovan-channel as a lock-free multi-producer channel. Producers pin() a guard, load() the shared head pointer, splice new nodes, and retire() old nodes — the guard ensures no consumer is mid-traversal, and memory reclaimed automatically once all guards drop. The near-zero read overhead means the critical path adds only one atomic load and a comparison, suitable for high-QPS paths.

The Bottom Line

Kovan delivers a focused, high-performance memory-reclamation layer that several concurrent-data-structure crates depend on. The core API is small, the overhead is measurable and low, and the ecosystem is coherent. Health findings are dominated by CI hygiene (pinned Actions, dependabot, token permissions) and code-maintainability issues (deep nesting, duplicated blocks, outsized files) that are straightforward to address. Teams building lock-free structures who need bounded memory and predictable latency will find kovan a practical foundation; those needing a fully integrated, out-of-the-box data-service platform will look elsewhere.
