ccglass

See what your coding agent (Claude Code, Codex, Kimi) sends to the model — local proxy + web dashboard

Forked from jianshuo/ccglass

The Problem

Coding agents like Claude Code and Codex send large, opaque payloads to model APIs. Debugging what actually gets sent — system prompts, tool schemas, message history, token usage — is painful because these CLIs ignore HTTPPROXY/HTTPSPROXY and often use TLS pinning, so standard proxy tools (Charles, mitmproxy) never see the traffic. ccglass solves this by intercepting only the plain HTTP hop to localhost.

What This Does

ccglass is a local reverse-proxy + web dashboard. It sets the client's base-URL env var (e.g. ANTHROPICBASEURL, OPENAIBASEURL) to point at a local proxy (src/forward-proxy.js), which forwards to the real API over HTTPS. The client does its own TLS to localhost, so no CA certs or TLS-pinning bypasses are needed. The dashboard (web/app.js, web/index.html) shows live requests, token/cache/cost, message history with tool calls, agent-loop flow, and turn-to-turn diffs (src/diff.js).

The repo supports 15+ providers via src/providers.js and format parsers in src/formats/ (anthropic.js, openai.js, reasonix.js). It also includes session stats (src/session-stats.js), export (src/export.js), and content-addressed storage (src/ca.js, src/blobs.js) per design docs in docs/superpowers/.

How To Use It

Setup: Install globally via npm (per README): npm install -g ccglass. The package.json confirms npm as the package manager.

Configuration: No config file required. Env vars are set automatically by the tool per provider. For Codex, API-key mode is required (OPENAIAPIKEY); ChatGPT-login mode uses WebSocket and won't be captured. Kimi runs through Claude Code against Moonshot's Anthropic-compatible endpoint.

Running it: The entry point is bin/ccglass.js, which delegates to src/cli.js. Run with no arguments to pick a client interactively, or name one directly:

ccglass claude ccglass codex ccglass deepseek

This starts the proxy, launches the client, and opens the dashboard at http://127.0.0.1:57633 (port varies).

Real-World Use

A developer debugging why Claude Code is sending a bloated system prompt or unexpected tool calls to a model. Run ccglass claude, reproduce the issue in the agent, then inspect the dashboard's request view and turn-to-turn diff to see exactly what changed between iterations. This also works for cost tracking — the dashboard buckets by model and session (docs/cost-and-model-bucketing.md), useful for auditing spend across a team's agent usage.

Code Health & Issues Med — WebSocket gap: Codex in ChatGPT-login mode bypasses OPENAIBASEURL entirely (documented in README). The dashboard will silently show nothing. This is a known limitation, not a bug, but worth flagging. Med — src/forward-proxy.js handles plain HTTP only. Any client that insists on HTTPS to localhost will fail. The README says this is intentional, but it narrows compatibility. Low — 25 test files exist covering most modules, but web-live.test.js suggests some tests depend on a running server, which could be flaky in CI. No obvious missing test coverage for src/export.js or src/mcp.js. Low — No secrets or config files in the repo. CI is present (.github/workflows/ includes publish.yml). License is present. Dependency hygiene looks reasonable given the lockfile.

The Bottom Line

ccglass is a well-scoped, genuinely useful debugging tool for anyone working deeply with coding agents. The architecture is sound — intercepting plain HTTP to localhost avoids the TLS-pinning problem entirely. The main limitation is provider-specific transport quirks (Codex's WebSocket mode), which are documented rather than hidden. Recommended for agent developers, LLM ops engineers, and teams auditing model spend.
