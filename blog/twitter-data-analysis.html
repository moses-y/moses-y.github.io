The Problem

Clients that need to monitor public sentiment on X (formerly Twitter) must collect raw tweet streams, enrich them with sentiment scores, and surface engagement metrics. Doing this manually requires API plumbing, data cleaning, and ad‑hoc analysis notebooks, which slows reporting cycles and introduces inconsistency.

What This Does

The repository supplies a minimal end‑to‑end pipeline for pulling tweets via the Twitter v2 API and exploring the results in two Jupyter notebooks.

Twitter.py implements a thin wrapper around the API endpoints (authentication, recent search, user timeline). It returns raw JSON that downstream notebooks consume. TwitterDataAnalysisTutorial.ipynb and EnhancedTwitterDataAnalysisTutorial.ipynb demonstrate basic sentiment analysis (likely using TextBlob/VADER), engagement calculations, and a simple topic model. The notebooks import the helper functions from Twitter.py. .env.example shows the expected environment variables (e.g., TWITTERBEARERTOKEN) but no production .env is committed.

Together the files let a data analyst quickly spin up a reproducible notebook that fetches live tweets and runs the illustrated analyses.

How To Use It

Setup – Install a recent Python (≥3.9). The repo does not contain a requirements.txt or pyproject.toml, so you must create one based on the imports observed in the notebooks (e.g., pandas, numpy, tweepy/requests, textblob, scikit‑learn, matplotlib). python -m venv venv source venv/bin/activate pip install pandas numpy requests textblob scikit-learn matplotlib Configuration – Copy .env.example to .env and insert a valid bearer token from the Twitter developer portal. The notebooks load the file via python-dotenv (if present) or os.getenv.

cp .env.example .env # edit .env: TWITTERBEARERTOKEN=YOURTOKEN Running – Open either notebook in Jupyter Lab/Notebook. The first cells import Twitter from Twitter.py and call the provided functions, e.g.:

from Twitter import fetchrecenttweets tweets = fetchrecenttweets(query="#AI", maxresults=100)

Execute the remaining cells to compute sentiment, engagement stats, and topic clusters. No CLI entry point exists; the notebooks are the sole execution surface.

If any of the above files are missing (e.g., a requirements.txt), the repository will need to be supplemented before it can run.

Real‑World Use

A market‑research team could schedule a daily cron job that runs the notebook headlessly (e.g., via papermill) to generate a CSV of sentiment scores for a brand’s hashtag, then ingest that CSV into a BI dashboard. Example snippet:

papermill TwitterDataAnalysisTutorial.ipynb output.ipynb -p query "#Acme" -p max_results 500

The Bottom Line

The repo provides a functional, notebook‑centric example for pulling and analysing tweets, suitable for quick prototyping or educational purposes. However, the lack of tests, CI, dependency manifest, and licensing limits its readiness for production use. Teams that can invest a few hours to add a requirements file, basic error handling, and proper documentation can safely adopt it for ad‑hoc sentiment monitoring.
