Invio

Self-hosted invoicing without the bloat.

Forked from kittendevv/Invio

The Problem

Small businesses and freelancers need to send professional invoices without committing to subscription SaaS platforms that hold their financial data hostage. Most invoicing tools are either bloated enterprise suites or cloud services with recurring fees and opaque data policies. Invio targets the gap between spreadsheet invoices and full accounting platforms: a self-hosted, single-purpose invoicing tool that keeps customer and invoice data under the owner's control.

What This Does

Invio is a full-stack invoicing application with a SvelteKit frontend (frontend/src/routes/) and a Deno-based backend (backend/src/app.ts). The frontend handles customer, product, invoice, and user management through standard CRUD routes, while the backend exposes REST endpoints under backend/src/routes/ (admin, auth, public) and handles PDF generation, XML formats (UBL, Factur-X, FatturaPA), and email delivery. The public route (frontend/src/routes/public/invoices/[token]/) lets clients view invoices via a secure token link without creating an account.

The system includes multi-language support (frontend/src/lib/i18n/locales/), invoice templates (backend/static/templates/), and Docker deployment (docker-compose.yml). A notable feature is the dual-template approach: backend/src/controllers/invoices.ts and invoicesclean.ts suggest ongoing refactoring. The backend uses SQLite (backend/invio-demo.db) with migrations in backend/src/database/migrations.sql.

How To Use It

Setup: The project supports Docker Compose. Run docker compose up -d from the root, or use docker-compose-dev.yml for development. The backend uses Deno (see backend/deno.json), while the frontend uses Bun (frontend/bun.lock). Local development requires both runtimes or the containerized approach.

Configuration: Copy .env.example to .env and set required values. The backend reads environment variables through backend/src/utils/env.ts. Expect database paths, JWT secrets, and SMTP settings. The docker-compose.yml files show the service wiring.

Running it: The containerized approach is the primary path. For local development, start the backend with deno run --allow-all backend/src/app.ts and the frontend with bun run dev from frontend/. A demo database ships with the repo, so it runs out of the box.

Real-World Use

A consultant hosting Invio on a small VPS behind Caddy or Nginx can create invoices, share tokenized links with clients, and receive payment without exposing the admin interface. The docker-compose.yml handles the deployment; the token-based public invoice route handles client access. For a solo freelancer, this replaces a SaaS subscription with a single container on hardware they already rent.

Code Health & Issues High - No automated tests: The repo has zero test files. Core financial logic (invoice totals, tax calculations, PDF generation) is untested. This is a real risk for production billing use. Medium - Missing lockfile for frontend: frontend/package.json exists without a committed lockfile, though bun.lock is present. If npm is used instead of Bun, builds are not reproducible. Medium - Duplicate controller logic: invoices.ts and invoicesclean.ts suggest an in-progress refactor. The "clean" variants may be incomplete or orphaned. Low - Demo database committed: backend/invio-demo.db is in the repo. Verify it contains no real customer data before production use. Low - No CI beyond Docker build: .github/workflows/docker.yml builds images but doesn't run tests or linting. The translations.yml workflow handles i18n sync only. Positive: The codebase is well-organized with clear separation between routes, controllers, models, and utilities. Docker configuration is complete, and i18n is properly structured.

The Bottom Line

Invio is a solid, feature-complete invoicing tool for solo operators and small teams who want self-hosting without the setup cost of ERP systems. The lack of tests is the main concern for production billing use, but the architecture is clean and the Docker deployment is straightforward. It's better suited to a freelancer or tiny agency than a company with complex multi-entity invoicing needs.
