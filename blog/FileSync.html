The Problem

Organizations and individuals need reliable real-time file sharing across distributed devices without compromising privacy or requiring third-party infrastructure. Traditional solutions either centralize data on corporate servers, impose size limits, or require client software installation—barriers that hinder spontaneous collaboration across diverse network environments.

What This Does

FileSync is a peer-to-peer file sharing system that operates entirely in the browser. The web frontend (web/index.html with modular code in web/js/modules/) implements WebRTC data channels for direct browser-to-browser transfer. The backend (api/main.py and api/signaling.py) handles only the initial handshake and TURN relay negotiation; it never processes file contents. Docker configuration (deploy/docker-compose.yml, deploy/docker-compose-ssl.yml) provides a single-image self-hosted deployment model. The system streams received files straight to disk via blob.stream(), enabling multi-gigabyte transfers with minimal memory footprint—a key differentiator from solutions that buffer entire files in RAM.

How To Use It

Setup: Clone the repository and install dependencies. The API runs on Python (api/requirements.txt lists aiohttp, aiohttp-cors, websockets), while the frontend uses npm-managed React dependencies (e2e/package.json confirms the build toolchain).

Configuration: Generate a secret key for TURN credential signing: python3 -c "import secrets, base64; print(base64.b64encode(secrets.tokenbytes(32)).decode())"

Replace both <SECRETKEY> placeholders in deploy/docker-compose.yml with your generated value.

Running it: HTTP (local network / quick start) docker compose up -d Opens at http://localhost

HTTPS (public domain, recommended)

Caddy obtains and renews TLS certificates automatically docker compose -f deploy/docker-compose-ssl.yml up -d

Real-World Use

A distributed product team needs to share a 2GB design assets folder across five workstations on different networks. One team member self-hosts FileSync via the HTTPS Docker Compose configuration, shares the generated room link, and colleagues access it instantly from their browsers—no VPN, no account creation, no upload queue. The TURN relay fallback in api/signaling.py ensures connectivity through restrictive corporate firewalls where direct WebRTC peer connections would otherwise fail.

Code Health & Issues

SDLC & code violations: CI is configured (.github/workflows/ contains check, dependabot, and release workflows). License (MIT) and lockfile (e2e/package-lock.json) are present. However, the secret key generation command and both placeholder values appear in deploy/docker-compose.yml — committing generated secrets to version control is a medium-severity risk. Bugs / risks: No client-side input validation beyond basic HTML5 file API; large file transfers over plain HTTP (>500 MB) are noted as unreliable in the README. The WebRTC data channel has no progress event handling for transfer resumption if a connection drops mid-transfer. Evidence supporting quality: End-to-end tests exist (e2e/run.mjs), GitHub Actions CI runs on every push, and the codebase has clear structural separation between signaling (api/signaling.py), WebRTC modules, and frontend UI.

The Bottom Line

FileSync delivers on its core promise: private, limitless, one-to-many file sharing entirely in-browser with straightforward self-hosting. It's well-suited for teams that need occasional large-file transfers without third-party infrastructure, provided the secret key is managed externally and deployments use HTTPS. Organizations requiring transfer resumption, fine-grained access controls, or audit logging should look elsewhere.
