The Problem

Teams with code spread across multiple hosts (GitHub, GitLab, Bitbucket, ADO, Gerrit) lack a single, fast way to search and understand it. Generic web search and IDE tools don't index cross-repo context, and LLM answers without grounded citations are unreliable for code questions.

What This Does

Sourcebot is a self-hosted code intelligence platform combining three capabilities: natural-language Q&A over your codebase ("Ask Sourcebot"), fast regex-capable code search across all repos and branches, and IDE-level code navigation (goto definition, find references). It indexes code from any Git host and exposes results through a web UI.

The repo is the deployment and documentation layer. Core logic lives in submodules (.gitmodules is present), while this repository provides: Deployment: docker-compose.yml, Dockerfile, Makefile, and Kubernetes configs under docs/docs/deployment/k8s.mdx. Configuration: JSON config files in configs/ (e.g., basic.json, auth.json, multi-branch.json) documented in docs/docs/configuration/config-file.mdx. CI/CD: 20+ GitHub Actions workflows in .github/workflows/ covering build, test, release, and CVE remediation. Docs: 118 files under docs/ including connection guides for every major code host.

How To Use It

Setup: Deploy via Docker Compose. The README documents downloading docker-compose.yml directly from the repo.

Configuration: Create a JSON config file (schema-referenced in the README) specifying repos to index, auth providers, and LLM providers. Example configs exist in configs/.

Running it:

curl -o docker-compose.yml https://raw.githubusercontent.com/sourcebot-dev/sourcebot/main/docker-compose.yml create config.json per docs/docs/configuration/config-file.mdx docker compose up -d

Real-World Use

A mid-size engineering org with repos in GitHub and GitLab deploys Sourcebot on a single VM. Engineers use the web UI for cross-repo code search (e.g., finding every usage of a deprecated API across all services). The Ask Sourcebot feature lets developers query "where do we handle payment webhooks and what's the retry logic?" and get an answer with inline citations to specific files and line numbers. The MCP server (docs/docs/features/mcp-server.mdx) exposes the same search to AI coding agents.

Code Health & Issues

High - Potential secrets committed: .env.development is present in the repo root. Even if it only contains development values, this is a credential-leak risk and should be verified and removed. Med - Monorepo opacity: The actual application code lives in git submodules, making the main repo a thin wrapper. Dependency and security auditing is harder to verify from this repo alone. Med - Heavy automation complexity: 20+ workflows including automated CVE remediation (cve-remediation.yml), AI bug-fixing (claude-bug-fixer.yml), and vulnerability triage suggest a mature but operationally complex pipeline. Low - Test coverage visibility: Only 3 test files are visible in this repo, though tests likely live in submodules. CI workflow test.yml exists, which is positive. Low - License present: LICENSE.md and _typos.toml (typo checking) indicate good hygiene.

The Bottom Line

Sourcebot addresses a real gap: unified, fast, citation-grounded code search and Q&A across heterogeneous code hosts. The deployment story is simple (Docker Compose), and the documentation is thorough. The main concern is the .env.development file and the submodule structure, which makes independent security review harder. It's well-suited for teams with multi-host codebases who want self-hosted code intelligence without per-seat SaaS costs.
