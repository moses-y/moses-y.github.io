The Problem

Deep research—collecting, synthesizing, and verifying dozens to hundreds of web sources—is messy. Standard LLM workflows produce shallow, hallucinated reports with no provenance. Manual research is slow and doesn't carry context across sessions. Researchers need a structured pipeline that enforces source verification, avoids duplicate or derivative content, and persists findings for reuse.

What This Does

Hyperresearch orchestrates a 16-step agent pipeline that takes a single research prompt and produces an adversarially-audited report. The pipeline is defined in src/hyperresearch/skills/ as a series of Markdown skill files (e.g., hyperresearch-2-width-sweep.md, hyperresearch-4-loci-analysis.md). Each skill is loaded into Claude Code only when its step runs, preventing context drift in long sessions. The core logic lives in src/hyperresearch/core/—modules like citecheck.py, claims.py, graphrank.py, and quality.py handle citation verification, claim extraction, source ranking, and report quality checks. The src/hyperresearch/web/ directory contains providers for fetching content (crawl4ai, Exa, Tavily). A persistent vault (Markdown files + SQLite) stores every source, searchable via src/hyperresearch/search/fts.py.

The CLI (src/hyperresearch/cli/main.py) exposes commands for research, search, vault management, and resume of crashed runs. The mcp/server.py provides a Model Context Protocol interface for integration with other tools.

Real-World Use

A user runs hyperresearch research "impact of carbon tariffs on steel exports" --profile premier. The system decomposes the query into atomic items, performs a width sweep fetching 100+ sources, extracts claims, checks citations, and produces a report with verified provenance. All sources land in the vault. The next query on a related topic reuses cached sources before fetching new ones. If the run crashes, hyperresearch run resume picks up at the exact step.

Code Health & Issues

Low – No dependency lockfile. pyproject.toml pins no transitive versions. Builds are not reproducible across environments. Adding a lockfile (e.g., uv.lock or poetry.lock) is advisable before production use. Low – Heavy external API dependency. The web providers (crawl4aiprovider.py, exaprovider.py, tavilyprovider.py) are untested beyond testfetchsettings.py and testjunkdetection.py. Real-world reliability depends on API uptime and rate limits. Good test coverage. 58 test files cover CLI commands, core logic, search, and web providers. CI runs on every push (.github/workflows/ci.yml). The tests/fixtures/goldenprompts/ directory snapshots agent prompts for regression testing. Clean structure. Separation of CLI, core, models, and web providers is clear. No secrets or config files committed. License (MIT) and contributing guide are present.

The Bottom Line

Hyperresearch is a well-architected, opinionated research tool that enforces rigorous source verification and persistent knowledge management. It is best suited for users who need reproducible, citation-audited reports from large numbers of web sources and are comfortable with a complex Python CLI. The lack of a lockfile and reliance on third-party APIs are the main risks. For teams doing systematic literature reviews or competitive intelligence, it offers a credible pipeline that reduces hallucination and duplicates effort.

Pin third-party GitHub Actions to a commit SHAhigh
.github/workflows
pypa/gh-action-pypi-publish@release/v1
A tag can be moved, so the action running with your token and secrets is whatever its owner last pushed; this is how tj-actions/changed-files leaked secrets from thousands of repos.
Fix: Replace each @vN with the 40-character commit SHA, keep # vN as a comment, and let Dependabot bump the SHAs.
Commit a lockfile beside the manifesthigh
pyproject.toml
manifest with no lockfile in scope
An unlocked range means the artifact you tested and the artifact you ship can contain different transitive code, so a malicious patch release reaches production with no diff.
Fix: Run the package manager once and commit the generated lockfile.
Use bound parameters instead of building the SQL stringhigh
src/hyperresearch/mcp/server.py
.execute() with an interpolated query
A value spliced into SQL is read as syntax, so one quote in a name ends the literal and everything after it is executed as the query, which is how a search box becomes a table drop.
Fix: Pass placeholders and hand the values to the driver as parameters.

.github/workflows/ci.yml
1 workflow(s) declare no permissions
With no declaration the token inherits the repository default, so any injected step can push commits or mint releases from inside your own CI.

The token stays in .git/config for every later step, so a malicious postinstall script reads a pushable credential without one ever being passed to it.
