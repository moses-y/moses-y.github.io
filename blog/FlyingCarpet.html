FlyingCarpet

Abstract

Cross-platform AirDrop. File transfer between Android, iOS, Linux, macOS, and Windows over ad hoc WiFi. No network infrastructure required, just two devices with WiFi chips (and optionally Bluetooth) in close range.

The Problem

Moving files between devices without shared infrastructure is still painful. USB drives fail across filesystems, cloud services need accounts and bandwidth, and AirDrop is Apple-only. FlyingCarpet solves this by creating an ad hoc WiFi link between any two devices with wireless chips—no router, no internet, no account.

What This Does

FlyingCarpet is a cross-platform file transfer tool covering Android, iOS, Linux, macOS, and Windows. The repository contains a Rust core library (core/) that handles the transfer logic, a Tauri-based desktop app (Flying Carpet/src-tauri/) with a web frontend (Flying Carpet/src/index.html, main.js), and a Kotlin Android app (Android/). The core is split per-OS: core/src/linux/ and core/src/windows/ each have network.rs, bluetooth.rs, central.rs, and peripheral.rs modules.

Version 9 added Bluetooth for transfer negotiation—the WiFi hotspot handles bulk data, while Bluetooth exchanges keys and device info first. The core/src/sending.rs and core/src/receiving.rs modules handle chunked, encrypted file transfer.

How To Use It

git clone https://github.com/moses-y/FlyingCarpet
cd FlyingCarpet
cargo install tauri-cli
cargo tauri dev        # development
cargo tauri build      # release artifacts

Linux requires system dependencies listed in the README (libsoup2.4*, libwebkit2gtk*, etc.). The Android app builds via Gradle in Android/FlyingCarpet/. No environment variables or config files are required—the app handles everything at runtime.

Real-World Use

A consultant needs to move a 4GB database dump from a client's Windows laptop to a Linux server in a room with no network. Both machines run FlyingCarpet, one hosts a hotspot, the other joins it, and the transfer completes over direct WiFi. No flash drive, no cloud, no filesystem format issues.

  • Medium — High branching density — 56 branch points over 181 lines in core/src/linux/central.rs and the Windows modules.
  • Low — TODO/FIXME markers — 8 unresolved markers in core/src/windows/network.rs and core/src/windows/peripheral.rs.

SDLC observations: no CI/CD pipeline exists—26 source files merge without an automated build gate. No Dependabot or Renovate is configured despite 3 manifest files. Tests exist (2 test files) but are minimal.

The Bottom Line

Solid, practical codebase for a genuinely useful tool. The core logic is well-factored per-OS, but the Windows and Linux modules carry duplicated logic and deep nesting that will slow future changes. The lack of CI is the biggest risk—any change can break the build silently. Worth using for the transfer capability; worth adding CI before contributing.
