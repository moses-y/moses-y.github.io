opencodex

Universal provider proxy for OpenAI Codex & Claude Code — use any LLM (Claude, Gemini, Grok, DeepSeek, Ollama…) with Codex CLI, App, SDK, and Claude Code

Forked from lidge-jun/opencodex

The Problem

OpenAI Codex and Claude Code are locked to their respective LLMs. Teams that want to use a different model—Claude with Codex, or Grok with Claude Code—have no supported path. The official tools only talk to their own backends.

What This Does

opencodex is a local proxy that sits between Codex (CLI, App, SDK) or Claude Code and any LLM provider. It translates Codex’s Responses API into whatever the target provider speaks. The proxy handles streaming, tool calls, reasoning tokens, and image inputs. It also manages a ChatGPT account pool for Codex auth: it refreshes quotas, pins sessions to accounts, and failsover on rate limits.

The core proxy logic lives in bin/ocx.mjs and bin/package-main.mjs. Configuration is in bunfig.toml and a per-user config file (created by ocx init). The dashboard UI is a React app (likely in assets/ or a separate frontend directory). The repo includes 169 devlog files under devlog/ that document every design decision and implementation step—unusually thorough for an open-source project.

Real-World Use

Install with npm install -g @bitkyc08/opencodex, run ocx init, then ocx start. Point Codex CLI to localhost:10100. Now Codex talks to Claude, Gemini, Grok, DeepSeek, or any of the supported providers. The proxy also works with Claude Code, routing its requests to non-Anthropic models.

Code Health & Issues

The codebase is structurally sound: CI workflows exist (ci.yml, release.yml), a license is present, and the project has a lockfile (bun.lock). However, test coverage is minimal—only 1 test file detected for 200 files. This is a red flag for a proxy that handles auth tokens, credential rotation, and streaming reliability. High – Missing test coverage for auth routing and account pool logic. The devlog/ files describe extensive edge cases (rate limits, 401/403 reauth, session pinning), but there is no evidence those paths are tested in CI. Med – Bundling the Bun runtime automatically (npm install downloads Bun) adds an opaque dependency. If the bundled binary fails on a given platform, the proxy won’t start. Med – The project is a fork (5539 stars upstream, 0 stars on this fork). It’s unclear how much the fork diverges and whether upstream fixes are being tracked. Low – 169 devlog files are useful for auditing but add noise. Some might contain secrets or internal notes; a quick scan of devlog/chase/model/ shows no obvious leaks, but it’s worth reviewing.

The Bottom Line

opencodex solves a real pain point—vendor lock-in for Codex and Claude Code—with a practical, well-documented proxy. The architecture is straightforward and the devlogs show disciplined engineering. The main risk is the lack of test coverage for critical auth and routing paths. This is suitable for teams that can invest in their own testing and security review before production use.
