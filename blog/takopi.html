Technical Briefing – takopi Concise, consultant‑grade; all file paths and counts come from the repository’s static analysis.

The Problem

Engineers who use LLMs (Codex, Claude, OpenAI, Pi) need a single entry point that can run agents across many git worktrees, stream progress back to a Telegram chat, and resume sessions later without losing state. takopi fills that gap, but its internal structure and CI hygiene need scrutiny before production adoption.

What This Does

takopi is a Telegram‑bridged runner that lets you start, monitor, and resume agent sessions from chat. Key components live under src/takopi/:

  • src/takopi/telegram/loop.py – 50 functions/10 classes; the main message‑poller and dispatch loop.
  • src/takopi/config.py – 9 functions/3 classes; reads/writes the persistent config (via read_config, load_or_init_config).
  • src/takopi/runner.py – 39 functions/7 classes; orchestrates run_with_resume_lock and worktree management.
  • src/takopi/telegram/bridge.py – 17 importers, 15 exports; bridges Telegram updates to the internal command pipeline.

The repo also ships scripts/ (5 files) for release/onboarding helpers and a pyproject.toml that pins the tool as a uv‑installed package.

How To Use It

  • Setup – Install with the documented command: ``sh uv tool install -U takopi ` Then run the setup wizard (takopi`) to create a BotFather token, pick a workflow (assistant/workspace/handoff), and connect your chat.
  • Configuration – The wizard writes a config file (see src/takopi/config.py). Environment variables for engine binaries (codex, claude, opencode, pi) must be on PATH.
  • Running it – After setup, invoke: ``sh takopi ` Send messages to your bot; prefix with /codex, /claude, /opencode, or /pi to select an engine. Use /<project> <command> to target a registered project (e.g., /happy-gadgets hard reset the timeline`).
  • Development – See docs/developing.md and docs/reference/specification.md for contributor onboarding; the repo uses GitHub Actions CI (.github/workflows/ci.yml).

Real‑World Use

A team maintaining several feature branches can takopi init my‑project to register the repo, then from any chat send /my‑project @feat/new‑ui implement the new dashboard. The agent runs in a dedicated worktree, streams progress (logs, file changes, elapsed time) back to the Telegram topic, and a resume line can be copied to continue the same session from a terminal later.

The Bottom Line

takopi delivers a practical Telegram‑bridged runner for LLM‑driven agents, handling worktrees, progress streaming, and resume lines with a clear feature set. The codebase is functional but carries several high‑severity maintainability risks—import cycles, oversized files, duplicated logic, and unpinned GitHub Actions—that should be addressed before relying on it in a mission‑critical pipeline. Teams that need rapid, chat‑driven agent orchestration across multiple repos will find immediate value, provided the listed hygiene items are resolved.

Pin third-party GitHub Actions to a commit SHAhigh3 occurrences
.github/workflows
astral-sh/setup-uv@v7, pypa/gh-action-pypi-publish@release/v1, softprops/action-gh-release@v2
A tag can be moved, so the action running with your token and secrets is whatever its owner last pushed; this is how tj-actions/changed-files leaked secrets from thousands of repos.
Fix: Replace each @vN with the 40-character commit SHA, keep # vN as a comment, and let Dependabot bump the SHAs.
Stop discarding the exit code of steps whose failure mattershigh
.github/workflows/ci.yml
lines 69 discard failure
The job reports green while the artifact it was supposed to produce was never produced, so a crash becomes a successful run built on stale data.
Fix: Let the step fail, or test the specific expected condition instead of discarding all exit codes.
Declare least-privilege permissions for GITHUB_TOKENmedium
.github/workflows/ci.yml
1 workflow(s) declare no permissions, 1 of them reference secrets
With no declaration the token inherits the repository default, so any injected step can push commits or mint releases from inside your own CI.
Fix: Add permissions: contents: read at the top of the workflow and widen per job only where needed.

1 manifest(s), no update bot configured
Without a bot a published advisory sits unpatched until someone audits by hand, which across 1,322 repositories means never.
