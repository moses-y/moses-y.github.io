freellmapi

OpenAI-compatible proxy that stacks the free tiers of 16 LLM providers (~1.7B tokens/month) behind one /v1 endpoint — plus any custom OpenAI-compatible endpoint. Smart routing, automatic failover, encrypted keys. Personal experimentation only.

Forked from tashfeenahmed/freellmapi

The Problem The proliferation of free AI model tiers from various providers has created a new challenge: managing multiple SDKs, rate limits, and failure points. This complexity can be overwhelming, especially for individuals or small teams.

What This Does The freellmapi repository provides an OpenAI-compatible proxy that aggregates the free tiers of 16 LLM providers behind a single /v1/chat/completions endpoint. The server/src/app.ts file serves as the main entry point, while the server/src/providers folder contains implementations for each provider, such as google.ts and cohere.ts. The server/src/routes folder defines the API endpoints, including proxy.ts and analytics.ts.

Real-World Use For example, a developer can use the freellmapi proxy to route requests from an OpenAI client library to the aggregated endpoint. This allows them to leverage the combined capacity of multiple providers without worrying about individual rate limits or SDK complexities. A sample workflow might involve setting up the proxy using the docker-compose.yml file and then integrating it with an OpenAI client library.

Code Health & Issues Low - Missing input validation - server/src/routes/proxy.ts Medium - Potential race conditions in server/src/services/router.ts Low - Some dependencies are not pinned in package.json The codebase appears to be generally well-organized, with a clear separation of concerns and adequate testing coverage (45 test files found). The presence of a LICENSE file and a configured CI pipeline (github/workflows/ci.yml) also suggests a commitment to code health and security.

The Bottom Line The freellmapi repository provides a valuable solution for managing multiple free AI model tiers, offering a convenient and scalable way to aggregate capacity. While some minor issues and potential improvements exist, the codebase is generally well-maintained and suitable for use in production environments. Developers and teams looking to leverage the combined power of multiple AI providers should consider using this proxy.
