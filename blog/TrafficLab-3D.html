TrafficLab 3D

Create a digital-twin style traffic visualization using only mp4 CCTV footage and its Google Maps location.

Forked from duy-phamduc68/TrafficLab-3D

The Problem Field engineers and researchers often need a quick “digital‑twin” of a road intersection but lack calibrated cameras, synchronized satellite imagery, or a full‑stack vision pipeline. Building such a demo from raw CCTV MP4s and a Google‑Maps coordinate manually involves camera calibration, projection math, model integration, and custom visualisation code—all of which are error‑prone and time‑consuming.

What This Does TrafficLab‑3D automates the end‑to‑end workflow:

Calibration – GUI stages in trafficlab/gui/tabs/calibrationstage/ (e.g. lensstage.py, undistortstage.py, roistage.py) guide the user through intrinsic/extrinsic estimation and produce a Gprojection.json that maps CCTV pixels to satellite coordinates. Inference – trafficlab/inference/pipeline.py loads a YOLO model (checkpoint under models/) and a tracker, then processes the MP4 footage, outputting per‑frame JSON‑gz files into output/. The model and tracker names are configurable via inferenceconfig.yaml. Visualization – trafficlab/visualization/cctvrenderer.py and satrenderer.py render synchronized side‑by‑side views with 3‑D bounding boxes, speed vectors, and floor‑plan overlays, all driven from the GUI tab tabvisualization.py.

The repository layout isolates concerns: trafficlab/io/ handles config and replay writing, trafficlab/motion/kinematics.py supplies speed/orientation calculations, and trafficlab/projection/ contains the core gprojection.py math.

How To Use It Create the conda environment (environment.yml lists all deps) conda env create -f environment.yml conda activate trafficlab-3d Prepare location data (see README location layout) Example directory: location/NYC001/ footage/.mp4 cctvNYC001.png # critical CCTV image satNYC001.png # critical satellite image GprojectionNYC001.json # optional if already calibrated optional SVG/AI assets for custom ROI (Optional) Adjust inference settings in inferenceconfig.yaml modelpath, trackername, confidence thresholds, etc. Launch the GUI python main.py

The GUI opens with four tabs (Welcome, Calibration, Inference, Visualization). Calibration writes Gprojection.json into the same location folder; inference writes per‑run JSON‑gz files under output/. Visualization reads those outputs automatically.

Real‑World Use A city‑planning office could drop a week‑long traffic cam MP4 into location/Downtown/footage/, run the GUI to calibrate against a Google‑Maps snapshot, and generate a 3‑D replay that overlays vehicle trajectories on the satellite map. The resulting JSON can be fed to a GIS system for further analysis:

from trafficlab.visualization.replayloader import ReplayLoader loader = ReplayLoader('output/model-yolov5tracker-deepsort/Downtown/run1') loader.exporttogeojson('downtowntraffic.geojson')

Code Health & Issues

Medium – No automated tests – repository lacks tests/ folder or pytest configs. Medium – No CI/CD – no .github/workflows/ or other pipeline files; releases rely on manual steps. Low – Limited documentation for API – README covers GUI usage but functions like trafficlab/inference/pipeline.run() lack docstrings. Low – Hard‑coded file paths – some stages (e.g., trafficlab/gui/tabs/tablocation.py) assume specific directory names; may break with unconventional layouts. Low – License present but no explicit version notice in source files – only top‑level LICENSE exists; per‑file headers missing.

Overall the code follows a clear modular structure, and the GUI provides an intuitive calibration flow. Dependency list is explicit in environment.yml, reducing surprise at install time.

The Bottom Line TrafficLab‑3D delivers a practical, GUI‑driven pipeline to turn raw CCTV footage into a synchronized 3‑D traffic twin with minimal upfront data. It is well‑suited for research labs, small consulting teams, or educational settings that can tolerate the lack of automated tests and CI. For production‑grade deployments, adding unit/integration tests and a CI pipeline would be essential.
