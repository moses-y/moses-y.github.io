The Problem

Financial time-series forecasting is dominated by models that treat price data as continuous numeric sequences, which performs poorly on the high-noise, multi-dimensional nature of candlestick (OHLCV) data. General-purpose time-series foundation models are not built for this domain, and building a custom model from scratch requires massive compute and data. Kronos addresses this by providing a pre-trained, open-source foundation model specifically for K-line sequences, so teams can skip the expensive pre-training phase.

What This Does

Kronos is a decoder-only Transformer that uses a two-stage architecture. A specialized tokenizer (in model/kronos.py and model/module.py) quantizes continuous OHLCV data into hierarchical discrete tokens. An autoregressive Transformer is then pre-trained on those tokens to produce a unified model for tasks like forecasting and backtesting. The repo includes a family of pre-trained models (Kronos-mini, etc.) hosted on Hugging Face.

The codebase is split into clear functional areas: finetune/ and finetunecsv/ contain training scripts (trainpredictor.py, traintokenizer.py, finetunebasemodel.py) for adapting the model to custom data; examples/ holds prediction and backtest scripts (e.g., predictionexample.py, runbacktestkronos.py); webui/ provides a Flask-based interface (app.py, templates/index.html) for interactive use. A regression test suite lives in tests/testkronosregression.py.

How To Use It

Setup: Install dependencies from requirements.txt (root) and webui/requirements.txt for the web UI. There is no lockfile, so pin versions manually for reproducible builds. The repo lacks a Dockerfile or Makefile, so a standard pip install -r requirements.txt is the expected path.

Configuration: Fine-tuning is configured via YAML files, e.g., finetunecsv/configs/configali09988candle-5min.yaml, which the configloader.py script reads. The finetune/config.py handles core training hyperparameters.

Running it: The primary entry point is the web UI. Start it with python webui/app.py or run webui/start.sh. For headless prediction, use the example scripts directly, e.g., python examples/predictionexample.py. The README does not document a single canonical CLI command, so refer to the individual scripts for their exact arguments.

Install dependencies

pip install -r requirements.txt pip install -r webui/requirements.txt

Launch the web UI

python webui/app.py

Run a prediction example

python examples/predictionexample.py

Real-World Use

A quantitative research team can use Kronos to generate next-day price forecasts for a portfolio of stocks without training a model from scratch. Load a pre-trained checkpoint from Hugging Face, feed in OHLCV data (e.g., via the akshare scripts in examples/), and consume the output JSON reports (as seen in webui/predictionresults/). The finetunecsv/ workflow lets the team adapt Kronos to a specific exchange or asset class (e.g., Alibaba 5-minute K-lines) using a simple CSV input and a YAML config, producing fine-tuned models for internal backtesting.

Code Health & Issues

Med - No CI/CD pipeline: No .github/ or CI config detected. There is a regression test suite (tests/), but no automated gate ensures it runs on new commits. Low - No dependency lockfile: requirements.txt files pin versions loosely, so builds are not fully reproducible across environments. Low - Large number of generated artifacts committed: 25+ JSON prediction files and PNG charts in webui/predictionresults/ and finetunecsv/examples/ clutter the repo and inflate its size. These should be gitignored. Low - No explicit license file visible in the structure: The README references a license badge, but the LICENSE file is listed in the root, so this is likely fine.

The repo is otherwise well-structured with clear separation between model code, fine-tuning, examples, and UI. The presence of a regression test suite and documented fine-tuning scripts is a positive sign.

The Bottom Line

Kronos is a serious, research-grade foundation model for financial K-line data, with a clean codebase and a practical fine-tuning pipeline. It is best suited to quant teams or ML engineers who want a pre-trained financial model to adapt, rather than build from scratch. The lack of CI and lockfiles makes it less turnkey for production deployment, but the core model and training scripts are solid.
