wifui

Abstract

A lightweight, keyboard-driven Terminal User Interface (TUI) for managing Wi-Fi connections on Windows.

Forked from sohamw03/wifui

SectionsThe ProblemWhat This DoesReal-World UseCode Health & IssuesThe Bottom Line

The Problem

Windows users lack a fast, keyboard-driven tool for managing Wi-Fi connections from the terminal. The standard GUI (netsh, Settings app) requires mouse interaction or verbose command-line incantations. Network engineers and developers who live in the terminal need something faster.

What This Does

WifUI is a Rust TUI that wraps Windows Wi-Fi APIs via windows-rs and renders a ratatui-based interface. src/main.rs is the entry point; the app loop lives in src/app.rs. Network operations are split across src/wifi/scanning.rs, src/wifi/connection.rs, and src/wifi/profile.rs—scan, connect, forget, and toggle auto-connect. src/wifi/listener.rs monitors network state changes in real time.

It supports QR code sharing (the Share view), manual network entry (addnetwork.png), search with /, and Vim-style navigation. The --ascii flag avoids Nerd Font dependency. Packaging covers Winget, Scoop, Chocolatey, and a WiX installer (wix/main.wxs). GitHub Actions in .github/workflows/release.yml handle builds and releases.

Real-World Use

A developer working in a headless WSL or SSH session can run wifui, press / to filter networks, hit Enter to connect, and s to share credentials via QR—all without touching a mouse. For a sysadmin managing a lab of Windows machines, this replaces netsh wlan show profiles and manual credential entry.

Code Health & Issues

Medium - No tests – Zero test files in the repo. The scanning, connection, and state-machine logic in src/wifi/* is untested. This is a production risk for any team relying on this tool. Low - Windows-only, no platform abstraction – All Wi-Fi code is Windows-specific. That's fine for the stated goal, but the src/wifi/ module has no trait abstraction, making future cross-platform support a rewrite. Low - No input sanitization visible – Manual network entry (addnetwork flow) accepts SSID/password input. No validation or length checks are evident from the file listing. Ratatui input handling is generally safe, but edge cases with Unicode or very long SSIDs could cause issues. Low - Single CI pipeline – Only release.yml is present. No PR checks, linting, or test stages. The pipeline builds and publishes but doesn't validate code quality.

The Bottom Line

WifUI is a polished, practical TUI for Windows Wi-Fi management that fills a real gap. It's well-packaged and the codebase is cleanly organized. The lack of tests and single-platform focus limit it to individual developers or small teams on Windows who value terminal workflow over GUI. If you need a cross-platform Wi-Fi TUI or production-grade reliability, look elsewhere.
