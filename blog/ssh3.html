ssh3

SSH3: faster and rich secure shell using HTTP/3, checkout our article here: https://arxiv.org/abs/2312.08396 and our Internet-Draft: https://datatracker.ietf.org/doc/draft-michel-ssh3/

Forked from francoismichel/ssh3

The Problem Traditional SSHv2 requires 5–7 round‑trip times to establish a session and relies on its own authentication stack, making it slow to start and opaque to modern identity providers. Port‑scanning can reveal the server, and only TCP forwarding is available.

What This Does SSH3 re‑implements the SSH semantics on top of HTTP/3 (QUIC + TLS 1.3), delivering a faster handshake (3 RTT) and opening the door to HTTP‑based authentication. The code base maps SSH channel logic onto QUIC streams (server.go, client.go, message/channelrequest.go). New auth methods are provided by the auth/ package – OIDC (auth/oidc/openidconnect.go) and plugin‑style public‑key handling (auth/plugins/pubkeyauthentication/). The server can be made invisible to scanners because it only answers QUIC connections that carry the proper HTTP Authorization header, and it also supports UDP port forwarding alongside the classic TCP forwarding.

How To Use It

Build – The project uses Go modules. From the root:

go build -o ssh3 ./cmd/ssh3 go build -o ssh3-server ./cmd/ssh3-server

(Alternatively, make build works if the Makefile targets are exercised; the Makefile is present but its exact targets are not documented in the excerpt.)

Generate TLS material – Self‑signed certificates can be produced with the included script:

./generateopensslselfsignedcertificate.sh

Certificate paths are resolved by resourcesmanager.go; the server expects the PEM files at the locations defined there.

Run the server – Start the SSH3 endpoint:

./ssh3-server

The binary is produced from cmd/ssh3-server/main.go. By default it listens on 0.0.0.0:2022 (adjustable via flags or environment variables wired into server.go).

Connect with the client – Use the compiled client:

./ssh3 user@hostname

The client entry point is cmd/ssh3/main.go. Authentication can be password‑based, public‑key (RSA/EdDSA), or delegated to OAuth2/OpenID Connect through the OIDC plugin.

Configuration – Key environment variables are not explicitly listed in the README, but the auth stack reads TLS cert/key paths from the generated files and OIDC client secrets from the standard Go config patterns (auth/plugins/plugins.go). If you wish to plug in a custom identity provider, modify auth/oidc/openidconnect.go and rebuild.

Real‑World Use A development team wants rapid SSH‑style access to a fleet of sandbox VMs behind a NAT, with single‑sign‑on via Google Workspace. They deploy an SSH3 server on a bastion host, point the OIDC plugin at the corporate IdP, and developers authenticate with ./ssh3 user@host. Session setup completes in under a second even over high‑latency WAN links, and the server does not appear in routine port scans because it only responds to QUIC connections carrying a valid OAuth token.
