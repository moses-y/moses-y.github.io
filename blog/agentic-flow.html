Abstract

Easily switch between alternative low-cost AI models in Claude Code/Agent SDK. For those comfortable using Claude agents and commands, it lets you take what you've created and deploy fully hosted agents for real business purposes. Use Claude Code to get the agent working, then deploy it in your favorite cloud.

The Problem

Building agents in Claude Code is fast, but moving them to production means re-implementing against a different runtime and paying for expensive hosted models. agentic-flow aims to bridge that gap: develop the agent locally with Claude Code, then deploy the same logic as a hosted agent with cheaper model backends. The repo is a portfolio of related experiments around that goal, not a single product.

What This Does

The repository is a collection of 12 self-contained projects. The core agentic-flow/ package provides agent orchestration: task routing, self-learning hooks (.claude/ contains 350 files of agent definitions), a vector/graph database (packages/agentdb/), and a reasoning backend (reasoningbank/). It also includes a medical AI example (src/types/medical.types.ts), a CRISPR pipeline in Rust (examples/crispr-cas13-pipeline/), and a federated agent demo (examples/federated-agentdb/).

The README claims 66 agents, 213 MCP tools, and SONA (a self-optimizing neural architecture). The code supports these claims: agentic-flow/src/index.ts is the main entry point, and packages/agentdb/ contains substantial vector/graph database code with ONNX and WASM acceleration.

How To Use It

From the README:

npx agentic-flow init
npx agentic-flow hooks pretrain
claude

The package is on npm (agentic-flow), so npm install agentic-flow works. The TypeScript API is new AgenticFlow() then await flow.initialize() and flow.route('task'). Dockerfiles exist for various test scenarios. Configuration is via environment variables in .env.test and agentic-flow/config/.env.fastmcp.

Real-World Use

A team builds a medical diagnosis agent in Claude Code with the medical types from src/types/medical.types.ts. They test locally, then deploy the same logic to a serverless function (examples/federated-agentdb/serverless-lambda.ts) with a cheaper model backend via the router in agentic-flow/src/router/providers/anthropic.ts. The agent stores episodes in the graph database for future learning.

The Bottom Line

This is a large, ambitious portfolio with substantial working code — the agentdb, router, and orchestration pieces are real. But it's a collection of experiments, not a polished product: 4,455 files, duplicated code, secret-shaped files committed, and CI that can report green on failure. Use it as a reference for agent architecture patterns, not as a dependency.

Pin third-party GitHub Actions to a commit SHAhigh9 occurrences
.github/workflows
docker/setup-buildx-action@v3, docker/setup-qemu-action@v3, dtolnay/rust-toolchain@stable, Swatinem/rust-cache@v2
A tag can be moved, so the action running with your token and secrets is whatever its owner last pushed; this is how tj-actions/changed-files leaked secrets from thousands of repos.
Fix: Replace each @vN with the 40-character commit SHA, keep # vN as a comment, and let Dependabot bump the SHAs.
Add a LICENSE; redistribution rights are undefinedhigh
no licence file at the repository root
With no licence the default is all rights reserved, so this code cannot legally be reused, which matters most for the owner's own work carried into client engagements.
Fix: Add MIT or Apache-2.0 at the repository root.
Remove the committed .env and rotate what it holdshigh3 occurrences
.env.test
.env.test, agentic-flow/.env.docker-test, agentic-flow/config/.env.fastmcp
A tracked .env is the most common route for a working key to reach a public clone, and it is the file the app actually loads, so the value is usually live.
Fix: git rm --cached the file, add it to .gitignore, rotate every credential it names, commit a .env.example with empty values.
Stop discarding the exit code of steps whose failure mattershigh
.github/workflows/docker-publish.yml
lines 169 discard failure
The job reports green while the artifact it was supposed to produce was never produced, so a crash becomes a successful run built on stale data.
Fix: Let the step fail, or test the specific expected condition instead of discarding all exit codes.
Remove continue-on-error from steps that gate correctnesshigh
.github/workflows/build-agentic-jujutsu.yml
line 160 on a correctness step
A failing test suite reports a green check, which is precisely the path this audit exists to close.
Fix: Delete continue-on-error, or move a genuinely advisory step into a separate non-required job.
Declare least-privilege permissions for GITHUB_TOKENmedium3 occurrences
.github/workflows/agentdb-docker-test.yml
3 workflow(s) declare no permissions, 2 of them reference secrets
With no declaration the token inherits the repository default, so any injected step can push commits or mint releases from inside your own CI.
Fix: Add permissions: contents: read at the top of the workflow and widen per job only where needed.

35 manifest(s), no update bot configured
Without a bot a published advisory sits unpatched until someone audits by hand, which across 1,322 repositories means never.

An untagged or mutable base means today's build and last month's contain different libc and a different CVE set, with no record of which shipped.

a secret-shaped file is tracked and no repo-level gate is visible
Without a gate the same class of leak recurs on the next commit, so a leak finding is the symptom and this is the cause.
Fix: Add a pre-commit hook scanning staged content, and enable push protection.
Move large binaries to Git LFS or out of the repositorymedium4 occurrences
packages/agentic-jujutsu/agentic-jujutsu.linux-x64-gnu.node
4 blobs over 5MB: agentic-jujutsu.linux-x64-gnu.node 25.8MB, agentic-jujutsu-2.0.3.tgz 9.8MB, agentic-jujutsu-2.0.2.tgz 9.8MB

Set persist-credentials: false on checkoutmedium
.github/workflows/agentdb-docker-test.yml
checkout keeps the token, then dependencies are installed
The token stays in .git/config for every later step, so a malicious postinstall script reads a pushable credential without one ever being passed to it.
Fix: Add with: persist-credentials: false, and pass an explicit token only to the step that pushes.
Add a non-root USER to the imagemedium
agentic-flow/Dockerfile.alpha-test
CMD or ENTRYPOINT with no USER directive
A process running as root in the container is root against every mounted volume, and it turns any container escape or writable-mount mistake from a contained problem into a host one.
Fix: Create an unprivileged user, chown what it needs, and end the Dockerfile with USER.
