edgevpn

:sailboat: The immutable, decentralized, statically built p2p VPN without any central server and automatic discovery! Create decentralized introspectable tunnels over p2p with shared tokens

Forked from mudler/edgevpn

The Problem Enterprises that need private, peer‑to‑peer networks often resort to centralized VPN appliances or cloud‑based proxies. Those solutions introduce a single point of failure, require ongoing license costs, and make it hard to run workloads on edge devices that lack reliable internet connectivity.

What This Does edgevpn implements a fully decentralized VPN and reverse‑proxy built on libp2p. Nodes discover each other via a shared token and establish encrypted tunnels without any central server. The core logic lives in pkg/ (e.g., pkg/blockchain/ledger.go, pkg/crypto/aes.go) and is exposed through a CLI in cmd/ (cmd/app.go, cmd/api.go, cmd/dns.go).

A web UI for monitoring the mesh is compiled from the React source under api/react-ui/ and served by the built‑in API (api/api.go). The UI assets (api/react-ui/index.html, src/pages/.tsx) render dashboards for peers, services, DNS entries and the underlying blockchain.

How To Use It

Setup The repository ships a Dockerfile and a Makefile. To build a statically linked binary locally:

Install Go modules go mod download

Build the CLI (produces ./edgevpn) go build -o edgevpn ./cmd/app

Or containerise it:

docker build -t edgevpn .

Configuration Runtime configuration is read from pkg/config/config.go. The CLI expects a YAML file passed with --config <path> (e.g., config.yaml). The file defines:

token – shared secret for discovery (required) listenaddr – local address for the VPN interface dnsport – port for the embedded DNS server

A minimal example (config.yaml) can be found in the docs folder (docs/content/en/docs/how-to/run-with-docker.md).

Running Start a node with the built binary:

./edgevpn --config config.yaml start

The command maps to cmd/app.go which parses sub‑commands (start, join, proxy, dns). To expose a local TCP service over the mesh:

./edgevpn proxy --listen 8080 --target 127.0.0.1:80

For the web dashboard, run the API server:

./edgevpn api --config config.yaml

Then open http://localhost:8080 (the UI is served from api/react-ui/).

Real‑World Use A Kubernetes edge cluster can use EdgeVPN to provide intra‑cluster networking without a central control plane. Each node runs edgevpn join --token <shared>; the cluster’s service mesh is then reachable via the embedded DNS (dns.go). Application code can import the ledger library (import "github.com/mudler/edgevpn/pkg/blockchain") to store immutable state across the mesh, as demonstrated in the LocalAI integration.

Code Health & Issues

Bugs / Risks Med – Token‑based zone enforcement is only advisory – pkg/config/relayacl.go notes that token holders can still join zones; see the security model docs. Low – Limited input validation – CLI flags are parsed in cmd/util.go with minimal checks; malformed configs could cause panics.

SDLC / Code Violations Low – Comprehensive test suite – 39 test files across test.go and CI workflows (.github/workflows/.yml) indicate good coverage. Low – License present – Apache‑2.0 declared in LICENSE. Low – Dependency hygiene – go.mod and go.sum are version‑pinned; Dependabot workflow (dependabot_auto.yml) keeps them up‑to‑date.

Overall, the codebase follows Go conventions, ships with static builds, and includes CI for lint, test, and release.

The Bottom Line edgevpn delivers a usable, open‑source decentralized VPN and reverse‑proxy with a ready‑made UI and a Go library for blockchain‑backed state. It is solid for teams that can manage token distribution and accept the advisory nature of zone enforcement. Organizations needing a zero‑server edge network will find it practical; however, users must audit the token model if strict access control is required.

Pin third-party GitHub Actions to a commit SHAhigh3 occurrences
.github/workflows
goreleaser/goreleaser-action@v7, JamesIves/github-pages-deploy-action@releases/v3, codecov/codecov-action@v7.0.0
A tag can be moved, so the action running with your token and secrets is whatever its owner last pushed; this is how tj-actions/changed-files leaked secrets from thousands of repos.
Fix: Replace each @vN with the 40-character commit SHA, keep # vN as a comment, and let Dependabot bump the SHAs.
Declare least-privilege permissions for GITHUB_TOKENmedium4 occurrences
.github/workflows/build.yml
4 workflow(s) declare no permissions, 2 of them reference secrets
With no declaration the token inherits the repository default, so any injected step can push commits or mint releases from inside your own CI.
Fix: Add permissions: contents: read at the top of the workflow and widen per job only where needed.
Pin the container base image by digestmedium3 occurrences
Dockerfile
node:22-alpine, golang:1.26-alpine, alpine (mutable tag)
An untagged or mutable base means today's build and last month's contain different libc and a different CVE set, with no record of which shipped.
Fix: Use image:tag@sha256:<digest> and enable Dependabot's docker ecosystem.
